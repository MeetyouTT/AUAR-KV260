# AI 协作记录

本次任务来自用户对交付的明确要求：「一定要完成tcl脚本验证，现在把工程包做出来」。版本选择来自之前确认的 9a4f 正式对话基线。原始逐项取件、不同部署根和两个对话版本见 `provenance_9a4f.json`。

| 审查中遇到的问题 | 处理与对应验证 |
|---|---|
| 把历史 PASS 复制到新工程无法证明 Tcl 有效 | 本轮从独立输出目录实际运行四个 bench。另用缺项、非零退出码和篡改回执测试失败路径；Vivado 批处理拒绝错误结果。 |
| 首次软件演示在角色选择阶段失败 | 找回相同 SHA 的公共角色配置，按原加载器实际文件名归位，重新运行原 doctor 与 demo。 |
| 公开工程树缺少正式 GUI 固定位置的 4 份设置 | 用原 SettingsStore、ConnectionStore、TranscriptionStore 生成默认值和回读。离线部署后，在只读容器挂载真实原路径，由原 prepare_pair 完成正式配对。 |
| ARM64 编译首次缺少目标依赖和 SDK 链接路径 | 从固定 EXT4 的开发文件提取交叉 sysroot，补齐 GStreamer、Mali GLES、glib 和链接器路径。用包内入口重新从完整源码编译原生库。 |
| 历史向量文件内含基准人脸像素 | 查看数组格式并核对生成脚本的分发标记，归档仅保留 SHA 与生成方法。 |

`ai_evidence/` 收录以往团队工程协作的精选摘录与索引，日期、测量及当时的结论保留其历史语义。
