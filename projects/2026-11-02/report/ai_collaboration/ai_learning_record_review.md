## 二、AI01：FPGA运动监督与联合工程交付

**工程任务：**在DPU联合平台中实现宽范围运动监督，保持寄存器、驱动和上层控制配套，并输出可核对的硬件工件。

**AI协作形成的主要文件：**

| 文件 | 工程作用 |
| --- | --- |
| visual_servo.sv | 宽范围PWM与命令监督实现 |
| prepare.tcl | 自研IP封装、BD连接及参数核对 |
| implement.tcl | 综合、实现、时序/DRC检查与导出 |
| export_resume.tcl | 从已路由检查点恢复导出 |
| .bit.bin、.dtbo、.xclbin、.xsa及清单 | 配套上板与软硬件接口交付 |

对应历史记录包含4套RTL测试、204项控制器回归和18项C模拟；独立实现审查记录WNS 0.001ns、路由错误0。原项目模式XSA导出失败后，保留已通过的路由结果，改为重开同一DCP导出，并核对XSA嵌入位流配置载荷一致。

**工程判断与价值：**宽范围修改同时处理位宽、接口和上层配置；导出故障与综合实现结果分开定位，避免无依据地重复整个构建。当前已证明的数字控制与真实机械行程分别验收，未把脉宽读回写成角度。

## 三、AI02：YuNet/SFace的DPU移植与质量验证

**工程任务：**把既有模型适配为目标B4096可执行的INT8工件，并保留从数值到任务质量的验证链。

**AI协作形成的主要文件：**

| 文件 | 工程作用 |
| --- | --- |
| rewrite_sface_v2.py、reconstruct_yunet.py | 等价改写/网络提取与CPU边界 |
| quantize_sface_public.py、quantize_yunet.py | 校准、量化模拟与质量比较 |
| compile_candidate.py | 目标编译及XIR接口记录 |
| hardware_vectors.py、板测结果JSON | 固定输入与输出一致性 |
| compiler-manifest.json、评测报告 | 模型版本、分区、指纹和结果关联 |

现有YuNet/SFace工件分别以54d348…、12b2ff…版本追溯，均有目标编译与固定输入板端对照。SFace独立1000对的FP32与INT8模拟总体准确率均为98.8%，但误接收由0/500变为1/500、误拒绝由12/500变为11/500。该评测不等同1000对全部上板或现场无损识别。

**工程判断与价值：**将模型兼容、等价改写、校准、编译、执行和识别质量逐层验证；不只依赖“编译成功”或总体准确率。校准、选阈值和独立测试分离，模型与模板版本配套。新增声纹DPU仍列待适配，不计入已完成模型。

## 四、AI03：LLM结构化输出与语音等待优化

**工程任务：**保持原27B、业务字段和语音要求，减少正文被附属字段阻塞的等待，保留对话与播放合同。

**AI协作修改及测量文件：**

| 文件 | 工程作用 |
| --- | --- |
| aura/tools/dialogue_stream.py | 正文优先、内部短字段解析和原字段映射 |
| aura/tests/framework/test_voice_latency.py | 分包、字段语义、取消与播放相关回归 |
| profile_compact_fields.py、paired_profile.json | 配对模型阶段测量 |

对应旧/新格式各4次模型阶段中位数：

| 指标 | 原格式 | 短字段格式 |
| --- | ---: | ---: |
| 首正文 | 1754.07ms | 1344.27ms |
| 台词字段就绪 | 2762.88ms | 2287.70ms |
| 完整结构结束 | 4737.30ms | 3745.70ms |

**工程判断与价值：**优化着眼于有效正文交付，同时保留情绪、动作和完整内容校验。该组回复措辞/长度存在变化，数字按小样本阶段结果解释；不将其写成语音模型本体或所有对话的固定提速。

## 五、AI04：LLM/TTS显存协调与生命周期控制

**工程任务：**在原27B、OmniVoice和其他模型共存条件下控制显存压力，处理排队、取消和流式背压，保持原音色与合成要求。

**AI协作形成的主要文件：**

| 文件 | 工程作用 |
| --- | --- |
| common/gpu_coordination.py | 资源观测、准入、租约及有界排队 |
| config/gpu_runtime.local.json | 对应平台的预算与策略配置 |
| board/runtime/audio/omnivoice_voice.py | TTS生命周期与资源接点 |
| final_manifest.json、GPU测量与测试结果 | 冻结实现、非缓存运行和回归依据 |

对应历史adaptive配置的三组非缓存语音测试记录最低空闲1656MiB；最终合并回归637项、0失败，覆盖面包含其他既有业务，不能全部算成GPU专项测试。

**工程判断与价值：**显存整理、模型常驻、冷暖加载与实际解码分别评价；保留其他模型，不通过降低语音要求制造速度优势。DFlash、CPU停车、串行TTS和CUDA Graph的结果作为取舍依据，未采用的方案不计入正式收益。旧平台预算和结论需在新5090上重新验证。

## 六、AI05：有来源的记忆存储与摘要回收

**工程任务：**实现会话/来源约束、事实与摘要处理、完整播放后的助手历史提交，以及摘要校验后再回收原文的流程。

**AI协作形成或修改的主要文件：**

| 文件 | 工程作用 |
| --- | --- |
| common/board_memory.py | 来源、状态、提交及回收的存储逻辑 |
| board/runtime/board_memory_policy.py | 对应版本摘要策略与处理约束 |
| test_public_worker.py及公开验证材料 | 策略边界与失败检查 |
| RETENTION_RESULT.json | 自然到期存储验证 |

公开输入的保存记录显示：约115.80秒时用户/助手正文各1行，自然约333.44秒后各0行，同一有效摘要保留、任务已提交。该结果标为STORAGE_PASS_RECALL_PENDING：存储链已有证据，真实同会话召回另验。

**工程判断与价值：**把来源、撤销、播放确认和摘要提交串成可追溯链，失败时保留待处理信息；区别“有摘要”和“问答确实召回正确”。这样优化上下文与存储时，仍能检查更正、遗忘和迟到结果的一致性。
