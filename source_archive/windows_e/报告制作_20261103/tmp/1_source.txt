1 验证环境
本章明确了验证过程所需的软硬件运行环境、验证文件结构、数据集预处理与权重
结构。通过完整定义验证全流程的基础条件，确保了实验方案的绝对封闭性、可复现性
与结果的可追溯性。
1.1 运行环境
本验证过程基于曦智科技官方光计算仿真平台 LT − Simulator _v1.4.3 完成。该验
证在搭载 Linux 或 Windows 通用操作系统的终端上即可高效执行。软件环境方面，要
求系统配置 Python 3.9 及以上版本，并依赖 PyTorch 2.0 及以上版本的深度学习框架。
此外，验证脚本仅调用 Python 标准库与仿真平台官方 API，无额外库环境依赖。

1.3 验证数据集与预处理
本次验证采用 MNIST 手写数字 10,000 张测试集。输入的单通道 28 × 28 原始灰度
图像。首先执行中心裁剪，保留 22 × 22 核心区域，随后利用 LANCZOS 高阶插值算法
高保真压缩至 14 × 14 分辨率。数据集存放于 data/MNIST/raw/ 目录。
1.4 模型权重
验证模型的网络为单层 CNN-FC 架构，包含一层 3 × 3 卷积、最大池化及一层全连
接输出。模型权重存放于 cnn_small_qat.pth。为降低推理时延，该权重文件集成了模
型网络参数与 PACT 量化的截断标尺 α。 在推断启动阶段， 脚本可直接从中解析离散化

2.2 光占比计算
光计算占比 （Ro） 定义为可部署至光计算阵列的线性算子计算量占模型总线性计算
量的比例。理论上，线性层的乘加累积操作数（MACs）核心计算公式如下：
Ro = 光线性算子 MACs 总和
线性算子 MACs 总和 × 100% (1)
针对本框架设计的极简架构， 卷积层 （MACsconv = Cout ×Hout ×Wout ×kh ×kw ×Cin）
与全连接层（MACsfc = Dout × Din）的理论计算量分别为 28, 224 与 7, 840。 由于本模型
所有线性算子均可映射至光阵列，最终理论光计算占比为：
Ro = 28224 + 7840
36064 × 100% = 100.00% (2)
光计算占比通过挂载 PyTorch 的 register_forward_hook 钩子函数，解析计算量。
当 dummy_input 流经网络时，钩子函数会实时捕获 nn.Linear 和 nn.Conv2d 的特
征图尺寸，并计算乘加累积操作数 MACs，从而计算出光计算线性占比。
84 def hook_fn (module , input , output ):
85 name = {m: n for n, m in model . named_modules () }[ module ]
86 if isinstance (module , nn. Linear ):
