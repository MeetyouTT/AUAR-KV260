## 一、两周结束时要达到什么水平

这两周不以“刷完 HDLBits”为目标，而以“能够独立完成 Verilog 基础考核，并做出项目相关的小模块”为目标。

两周后应完成：

- [ ] 35～45 道高相关度 HDLBits 题目。
- [ ] 能独立写模块实例化、组合逻辑、时序逻辑、计数器和简单 FSM。
- [ ] 能正确使用 `assign`、`always @(*)`、`always @(posedge clk)`。
- [ ] 能解释并正确使用阻塞赋值 `=` 和非阻塞赋值 `<=`。
- [ ] 能避免 latch、位宽不匹配、多驱动和复位优先级错误。
- [ ] 能编写基础 testbench，并通过波形定位错误。
- [ ] 完成一个可仿真的简化版 `限位 + watchdog + 急停锁存 + PWM` 系统。
- [ ] 完成一次 120 分钟、全程不使用 GPT 的闭卷模拟考核。

本项目后续确实还需要 AXI-Lite、FIFO、CDC、时序约束和板端联调，但两周内先把 RTL 基础与 PWM 安全逻辑做扎实，不提前进入 HDMI 或复杂 AXI 开发。

## 三、GPT的正确使用规则

GPT 在本计划中承担四个角色：

1. **概念老师**：用电路、状态图和时序解释知识。
2. **分级提示教练**：卡题时先给提示，不直接给答案。
3. **代码审查员**：检查你已经写出的代码。
4. **模拟考官**：出题、计时、评分，但考核过程中不给提示。

### 每道题与GPT配合的顺序

```text
读题
→ 自己画电路/时序
→ 自己写第一版
→ HDLBits提交或运行仿真
→ 卡住20分钟后向GPT请求一级提示
→ 自己修改
→ 通过后让GPT检查代码风格和边界条件
→ 删除答案，闭卷重写关键部分
```

### 三级提示规则

- **一级提示**：只判断思路是否正确，并提示检查方向。
- **二级提示**：指出错误所在的语句或电路部分，不给完整代码。
- **三级提示**：给伪代码或局部写法。
- **完整答案**：只有复盘阶段才能请求；看完后必须重新闭卷写。

### 通用卡题提问模板

```text
我在学习Verilog，请不要直接给完整答案。

（粘贴题目）

我的电路理解：
（用自己的话说明）

我的代码：
（粘贴代码）

错误信息/波形现象：
（粘贴信息）

我的预期：
（写出预期结果）

请只给一级提示：
1. 判断我的电路理解是否正确；
2. 将问题归类为端口、位宽、组合逻辑、时序、复位或状态机；
3. 告诉我下一步应检查什么；
4. 不要提供完整代码。
```

### 代码审查模板

```text

1. 功能是否符合需求；

3. 阻塞/非阻塞赋值是否正确；
4. 位宽、符号位和溢出是否正确；
5. reset优先级是否正确；
6. 是否存在多驱动或不可综合写法；
```

### 今日核心

```verilog
assign out = expression;

always @(*) begin

end

always @(posedge clk) begin
```

- [ ] Simple FSM 2（同步复位）

### 项目安全状态机

```text
NORMAL
  ├─ emergency_stop   → FAULT_LATCHED
  └─ watchdog_timeout → FAULT_LATCHED

FAULT_LATCHED
  └─ stop_released && manual_ack → NORMAL
```

设计要求：

- 急停优先级最高。
- 急停释放后不自动恢复。
- 普通命令不能清除故障。
- 复位后进入安全状态还是正常状态，必须在设计说明中明确。
- 状态寄存器和下一状态逻辑分开。

### GPT配合任务

```text

1. 是否存在没有定义的输入组合；
2. 急停和watchdog同时发生时结果是否明确；
3. 急停释放后是否可能自动恢复；
4. reset状态是否满足默认安全；
5. 还缺哪些故障场景。
```

## Day 12｜周三｜Watchdog与故障锁存（2小时）

### 详细时间表

| 时间 | 任务 |
|---:|---|
| 0:00～0:20 | 写watchdog需求和优先级表 |
| 0:20～1:00 | 实现`heartbeat_watchdog` |
| 1:00～1:30 | 实现`fault_sticky`或完善`safety_fsm` |
| 1:30～1:50 | 注入超时、急停和恢复测试 |
| 1:50～2:00 | GPT检查遗漏场景 |

### Watchdog要求

- heartbeat发生有效更新时重新计时。
- 超过阈值后产生timeout。
- 不能因为CPU重复写相同旧值就永远不超时。
- 复位和非法配置期间输出保持安全。

### 故障锁存要求

- 急停或watchdog会锁存故障。
- 普通enable不能清除故障。
- 清除必须满足“停止已释放 + 人工确认”。
- 同时发生多种故障时原因必须可解释。

### GPT配合任务

```text
请作为安全测试工程师，针对我的watchdog和故障锁存列出8个故障注入场景。
只写输入顺序和预期结果，不给实现代码。特别覆盖临界超时、同时故障和错误恢复顺序。
```

### 通过标准

能够通过仿真证明：控制程序停止发送heartbeat后，系统在规定周期内进入并保持安全状态。
