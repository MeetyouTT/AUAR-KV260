## 播放层已经完成的修改

进入段从原始帧连续到达主循环窗口，不再给循环叠加随机起始相位。主窗口使用余弦往返，在两个折返点减速。其他窗口保留在历史 `segments.json` 中，当前不轮换；它们没有通过跨姿势兼容检查，直接切换曾造成抬手姿势和放手姿势之间的大跳。

慢放使用连续的源帧位置，在相邻两张原始帧之间插值。只融合相邻帧，不把两个差别很大的姿势淡化重叠。插值仍可能在原素材手指已经变形时形成轻微重影；它没有修复或重画这些手指。

停止和取消从当前源帧位置沿原始帧收回：选择首尾两个恢复姿势中较近的一端，必要时反向播放原动作。很短的应答不会在结束后继续表演完整抬手动作。素材池轮换则沿源帧前进到末端，再从下一素材首帧开始。六秒是提出轮换请求的时间，实际换素材要等待收尾。

历史阶段名 `blend` 保留用于日志兼容，含义已改成 150 毫秒速度渐入，`alpha` 为零，不再做跨姿势淡化。`blend` 和 `exit` 使用同一时间原点，退出段不会在阶段交界处倒退重播。现有 39 帧素材的停止收尾通常不超过约 0.87 秒，加一帧界面采样时间；这是显示动作收尾，语音停止仍由原事件处理。

潜动层改为一次连续仿射变换，避免整数像素取整造成呼吸位置突然移动一像素。Tk 的下一帧等待时间扣除了本帧绘制耗时，避免每次绘制后再完整等待 33 毫秒。Qt 继续使用原定时器和同一播放核心。

业务仍为 15 个运行时状态；现有 16 套素材、573 张原始 PNG、24 fps、464×480 的口径不变。没有重新生成图片，也没有新增业务状态。新素材 ID 是待制作目录名，尚未加入 `STATE_ASSET` 或素材池。

## 验证结论

固定种子 7、相同源 PNG、关闭潜动，连续说话 24 秒后停止，分别按 12 Hz 和 30 Hz 采样。大跳定义为同一说话素材相邻采样的索引差大于 `24 / 采样频率 + 1`，用于识别超出正常时间推进的窗口硬切。

| 诊断项 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 30 Hz 大跳次数 | 15 | 0 |
| 12 Hz 大跳次数 | 13 | 0 |
| 30 Hz 最大相邻画面 RGB 平均差 | 32.56 | 7.07 |
| 30 Hz 相邻画面差 P95 | 6.13 | 3.48 |
| 潜动变换耗时中位数 | 14.56 ms | 5.35 ms |

画面差是在 116×120 缩略图、`#FCFCF3` 合成背景上计算的 0 至 255 灰度级差值，不是百分比，也不是自然度评分。修改后差值最大的一些帧仍是源素材本身的手部变化。两种采样率均正常收尾进入 IDLE。

真实 Tk 事件循环跑完 66 秒剧本并按按钮重播：首轮 1674 次显示采样，平均约 25.21 Hz，采样间隔中位数 32 ms。唤醒完成、点头后续播、三档说话、停止和取消收尾、结束后重播均通过。短暂加载和绘制仍会影响实际频率，不能宣称稳定达到 30 fps。窗口测试中的事件错误列表在重播时会清空；全剧无拒绝事件同时由虚拟时钟回放和回归测试验证。

板端 C 参考实现已在 PC 编译，开启警告视为错误；1803 个游标样本与 Python 对照，包括长循环、停止、池轮换，最大数值误差约 `4.97e-13` 帧。C 参考提供源位置和阶段，板端消费方还需实现相邻 RGB565 帧插值、事件处理、流式双缓冲和实际刷新。没有 KV260 显示性能或实机音画同步证据。

完整自动测试 509 项通过，结果见交付集合中的 `验证/pytest.log`。本轮新增测试直接约束连续游标、采样频率一致性、最短收尾、池轮换、潜动亚像素变化和生成工作流，不以像素差下降代替视觉验收。

| P1 | 偶尔眨眼的同姿势口型变体 | 单次眨眼，不附带低头或手势；未来按较低频率选择 | 待生成和后续调度接线 |
| P1 | 温和愉快及低落口型循环 | 通过表情和口型体现情绪，沿用静息姿势，不反复动肩抬手 | 待生成 |
| P2 | 独立口型层或音素口型素材 | 如需真实对嘴，需要音频时序及嘴部独立层；整张 PNG 循环不能实现 | 另行设计 |

优先完成前四类，每类先做三种种子候选。先验收静息循环再做保持循环，最后围绕同一组锚点补进入和退出。不得为丰富程度先生成一大批新的大动作。

现有 neutral B 原始相邻帧最大缩略图 RGB 差约 8.85，neutral C 约 6.59；检查图中仍能看到手部和整体比例变化。原始不透明面积变化只是一项诊断，不能当作真实身体缩放测量。新素材要目测确认脸、肩线、腰线和手指位置稳定。

## 后续接线边界

当前播放器仍消费一套素材内的分段。v3 的进入、保持和退出分文件后，需要明确的动画素材计划表，再把闭嘴退出片段接到停止事件；当前没有假装这项接线已完成。新计划表可保持 15 态业务合同，只在显示层选择动画片段。

基础口型片段不眨眼，偶尔眨眼片段的选择频率需要后续代码控制。提示词中的频率建议不能自动变成调度功能。真正的语音口型同步、KV260 实机音画时序、录放音和长时间整机稳定性仍待验证。

## 下一位接手者的操作顺序

1. 使用本轮演示窗口先看中性长句、说完和取消的收尾；需要精确比较时使用交付里的诊断报告和预览。
2. 按 v3 工作流准备缺失的静息原始绿幕参考和保持锚点，不改变已有角色风格及取景。
3. 从四类 P0 候选中选出同一组锚点兼容的素材；在候选目录体检和目测，失败候选不得覆盖正式素材。
4. 素材通过后再实现分文件动画计划表，更新 PC 和板端合同，并重新跑完整剧本、真实停止及取消。
5. 接入板端时使用本轮合同 1.2 和 C 参考，不能继续按旧的“多窗口直接轮换加姿势淡化”规则消费资源。
