玩偶界面部署到板卡符合当前方案；`src/ui` 是源码职责位置，运行目标为 KV260 PS。素材属于 `data/assets`，发布时作为板端运行资源回收。PC 上已有演示用于复用，正式系统的玩偶显示与播放仍在板端执行。

## 已核对的移植边界

1. 当前 `tools/realtime_stage.py` 同时导入本机 `SpeechJobs/VoiceWorker`。`board/runtime/audio/selected_voice.py:SelectedVoiceSynthesizer.load()` 要求 `torch.cuda.is_available()` 并以 `device_map='cuda:0'` 加载模型。此 PC 合成入口须与板端播放器解耦；复制完整桌面入口不能证明板端语音合成已可运行。
2. 现有共用播放核心在 `board/interaction/avatar_player.py`，Qt 绘制在 `qt_widgets.py`，板端资源表在 `avatar_board.py`。后者提供帧流与几何输入合同，不是已经验收的显示驱动。最终渲染后端及依赖在目标板镜像验证后冻结。
3. 口型以板端实际音频播放进度为时间基，暂停、打断、重播须同步改变声音与口型。Windows 的生成进度和网络到达时刻不能代替板端播放进度。
4. 动画解码、缩放、缓存与刷新需要和真实相机/DPU/音频一起测帧间隔、CPU、内存和响应；不把 PC 流畅度或此前静态 HDMI 显示当成板端动画验收。
5. 本地待机、眨眼与连接状态继续由板端推进；断网或取消后禁止旧结果重新开始播放。UI 不直接持有相机或写运动寄存器，按统一接口读取图像和提交操作。
