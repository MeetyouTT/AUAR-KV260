### 2.3 踩坑（本轮新增）

1. **`powershell -File '脚本路径'` 用单引号包裹会秒退**：`-File` 的参数不经 PowerShell 引号解析，
   单引号被当作路径字符 ⇒ 进程 exit 1、无任何输出。**WMI 创建进程时路径必须用双引号**
   （在 cmd 包裹的 `-Command` 里用 `[char]34` 拼引号，避免与外层引号冲突）。
2. **`CreateProcess` 传数组参数会被合并成单串**：`-Names "a.md","b.md"` 到达子进程时变成
   一个字符串 `a.md,b.md` ⇒ 改成 `-List "a;b;c"` 在脚本内 `-split ';'`。
3. **PowerShell 保留/自动变量不能当参数名**：`param([string]$Args, ...)` 绑定不到值（自动变量优先）
   ⇒ 改名 `-ArgLine`。
4. **Word COM 渲染期间不要跑其它前台命令**；本轮把 3 份渲染串进**一个脱离终端**的脚本，
   期间只用 `read_files` 轮询日志 ⇒ 3 份全部成功、`WINWORD=0`（无僵尸）。

**本轮新增踩坑（收尾阶段，均已验证解法）**：

1. **`.ps1` 不能直接 `&` 调用**：本机执行策略会报 `PSSecurityException`（"在此系统上禁止运行脚本"）→
   必须 `powershell -NoProfile -ExecutionPolicy Bypass -File <脚本> -参数...`（旧文档里的直接 `& x.ps1` 写法会失败）。
2. **PS 变量名不区分大小写**：`param([string]$Out)` 后又写 `$out = @()` ⇒ 参数被覆盖成数组，
   报错是误导性的"路径中具有非法字符" → 参数与局部变量改名区分（`$OutFile`）。
3. **单行 `-Command` 里的内联数组字面量会被压平成单串**（`@($a+'\x.md', $b)` 实测两次失败）→
   先赋给 `$v1,$v2` 再 `foreach($x in $v1,$v2)`。
4. **docx 内容核对**（`python-docx` 本机 `.venv` 里没有）：改用"复制为 zip → `Expand-Archive` → 正则读
   `word\document.xml`"；实测 MANIFEST.docx 里 `w:pStyle w:val="1"/"2"` 计数＝md 的 `#`/`##` 数（1/5）、
