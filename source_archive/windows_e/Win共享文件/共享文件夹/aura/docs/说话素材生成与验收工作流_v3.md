# AURA 说话素材生成与验收工作流

版本 v3，2026 年 10 月 5 日。适用于本轮 P0 和 P1 待制作素材。目标是在固定角色、固定取景和固定姿势下生成自然口型，再围绕同一姿势锚点制作进入和退出。不要继续把“抬手、两次强调、十几次口型、两次眨眼、放手”压进同一段约 1.625 秒的循环。

本轮已经提供七类完整英文提示词及 21 份 API 工作流图。工作流只是文件，尚未提交 ComfyUI，尚未生成新图片，也尚未接入运行时。

## 准备输入

当前共享工程没有找到原始 `doll_green_9x16.png`，历史批处理引用的外部 `tools/run_doll_green.py` 也不在共享目录。现有 PNG 是入库后的腰部以上透明帧，不能直接当成同尺寸原始全身绿幕参考替代。应由素材制作者从原生成工程补回原始参考，并记录其 SHA256；本轮新构建器复用工程内现有 API 图函数，不依赖缺失的外部脚本。

准备两张同构图原始绿幕图，放入实际 ComfyUI 的 input 目录：

- `doll_green_9x16.png`：角色静息姿势，双手自然放置、嘴闭合、眼睛睁开。若找回的原图不符合这些条件，应另存新的合格静息参考，并通过构建器参数指定名称。
- `doll_green_9x16_hold.png`：同一个角色，姿势已建立，但面部、头顶、肩线、腰线、身体大小、相机、背景和服装都与静息图一致。只调整必要的手臂和手部。

保持参考先与静息参考叠加检查，避免用两次完全独立的生成得到不同体型。参考制作提示可用：“Preserve the exact same character, face, body proportions, clothing, lighting, camera and all screen positions. Change only the arms and hands to the requested small held gesture. Keep lips closed and eyes open. Do not move or resize the head or torso. Keep the identical uniform green background.” 这一步的姿势由制作者选择，优先小幅腰际手势。

参考的路径名只是 API 图输入；构建器不能验证远端 ComfyUI 是否真的拥有这些图片或模型。提交前要在生成机检查文件、节点和模型是否齐全。

## 使用已验证的本地生成预设

| 项目 | 沿用值 |
| --- | --- |
| UNET | `minimax_h3_fl2va_pruned_int8_convrot.safetensors` |
| CLIP | `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors` |
| VAE | `minimax_h3_video_vae_int8_convrot.safetensors` |
| LoRA | `minimax_h3_fl2v_turbo_8step_v1.0_comfyui_bf16.safetensors`，强度 1 |
| 原始画幅 | 864×1536 |
| 本轮候选帧数 | 39 |
| 采样 | `res_multistep`，`simple`，8 steps，denoise 1 |
| 候选种子 | 421001、421002、421003 |
| API 输出前缀 | `AURA_NATURAL_V3_<ID>_s<seed>` |

39 帧是在本项目使用过的预设，不是模型的普遍最大长度。不要把本地显存或节点限制写成模型能力结论。需要加长时另开小样实验，并记录节点版本、显存、帧数、时间和质量，不要直接批量改长度。

39 帧按目标 24 fps 播放约为 1.625 秒；这项 fps 在帧序列入库时指定，API SaveImage 输出本身不是带帧率的视频。新进入和退出也是 39 帧候选，但语义为播放一次；它们不是现有 AWAKE/ACK_NOD 等 22 帧业务 burst 素材，不要自动裁成 22 帧。

## 构建和提交

源码目录中执行下列示例。`$py` 为工作区验证环境，不是损坏的工程内旧 `.venv`。输出目录需为新的候选批次，构建器拒绝覆盖已有文件。

```powershell
$py = 'E:\项目\tmp\aura-validation-venv\Scripts\python.exe'
Set-Location -LiteralPath 'E:\项目\共享文件夹\aura'
& $py -B tools/build_naturalness_workflows.py `
  --outdir 'E:\项目\共享文件夹\deliverables\avatar_candidates\batch_001\workflows' `
  --rest-reference 'doll_green_9x16.png' `
  --held-reference 'doll_green_9x16_hold.png' `
  --only talking_calm_rest_v3
```

先生成静息循环的三种种子候选。满意后依次构建保持循环、进入和退出；不指定 `--only` 会构建全部七类、每类三个种子，共 21 图。已构建的一整套参考图在本轮交付集合的 `素材生成工作流` 中，默认参考名需要实际存在。

图格式为 ComfyUI API JSON。输入链为模型、CLIP、VAE、LoRA、LoadImage、MiniMaxH3ImageToVideo、Scheduler、Sampler、Guider、Noise、SamplerCustomAdvanced、VAEDecode、SaveImage。进入和退出使用两个 LoadImage，分别约束首尾；循环使用同一参考约束首尾。当前 BasicGuider 没有独立负向提示词输入，限制语句已写在正向提示词中，不能宣称配置了一个不存在的 negative 节点。

生成机确认服务、模型和输入齐全后，可以单图提交：

```powershell
$graphPath = 'E:\项目\共享文件夹\deliverables\avatar_candidates\batch_001\workflows\talking_calm_rest_v3_s421001_api.json'
$graph = Get-Content -LiteralPath $graphPath -Raw -Encoding UTF8 | ConvertFrom-Json
$body = @{prompt=$graph; client_id='aura-naturalness-v3'} | ConvertTo-Json -Depth 100
$reply = Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:8188/prompt' `
  -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($body))
$reply.prompt_id
```

查看 ComfyUI 执行历史确认真实成功，不能仅凭拿到 prompt_id 就记为生成完成。每个种子的文件要单独归集，只接受该次精确前缀及编号，不允许通配符把不同种子混在一起。归集为 `000000.png` 到 `000038.png` 后记录原始帧和参考的 SHA256、模型和节点版本、种子、完整提示词、输出前缀和耗时。不得覆盖已有 `DOLLGV2` 结果。

## 在候选目录入库

先目测原始图：脸是否一致，身体有没有缩放、镜头有没有动、双手是否真保持。失败就换种子或调整动作句，不用代码裁剪掩盖明显失败。

对通过原始检查的一组 39 帧，使用已有准备工具在候选根目录抠像，不直接写正式 `assets/avatar`。实际抠像工程路径由生成机提供，下列路径仅为待填写示例。

```powershell
& $py -B scripts/prepare_avatar_frames.py `
  --src 'E:\项目\共享文件夹\deliverables\avatar_candidates\batch_001\raw\talking_calm_rest_v3_s421001' `
  --name talking_calm_rest_v3_s421001 `
  --matte-src --mode adaptive --post-despill ad1 `
  --matting-project 'X:\实际抠像工程' `
  --framing waist-up --max-side 480 --fps 24 --src-fps 24 `
  --formats png --budget-mb 12.5 `
  --out-root 'E:\项目\共享文件夹\deliverables\avatar_candidates\batch_001\prepared' `
  --temp-dir 'E:\项目\共享文件夹\deliverables\avatar_candidates\batch_001\temp' --keep-temp
```

保持原始画幅及相同裁切后，目标为 464×480、24 fps、39 帧透明 RGBA。waist-up 保留上部 58%，裁掉下部 42%，不是“保留 42%”。本轮候选不启用自动降帧率 `--fit-budget`；体积超预算应明确处理，避免候选悄悄变成低帧率。不要加 `--force` 覆盖正式素材。

## 体检和目测验收

```powershell
& $py -B tools/check_naturalness_candidate.py `
  'E:\项目\共享文件夹\deliverables\avatar_candidates\batch_001\prepared\talking_calm_rest_v3_s421001' `
  --report 'E:\项目\共享文件夹\deliverables\avatar_candidates\batch_001\qc\rest_s421001.json'
```

结构门槛检查帧数、fps、RGBA、尺寸、透明主体和 PNG 体积，失败返回非零。成功状态是 `STRUCTURE_VALID_REQUIRES_VISUAL_REVIEW`，不是视觉通过。工具报告相邻画面差、下部三分之二区域差、首尾差和不透明面积波动，均为诊断。可选 `--max-body-mad` 和 `--max-area-range` 设置本批次明确的上限，超过即 FAIL；这些数值需依据参考小样校准，不内置随意的“自然度通过线”。

参考设计目标为手腕在 464×480 显示中只移动约 1 至 2 像素、头部和躯干轮廓基本固定；这不是已经由程序测量通过的事实。像素面积变化不能证明真实体型稳定，脸和手指仍必须逐帧检查。

循环候选按实际目标速度看首尾连续至少 20 秒，再把进入、保持、退出按顺序组合。重点检查：口型是否小且可读、手势是否在保持段停稳、有没有手指重影或额外手指、头和胸有没有反复放大、首尾嘴形和眼睛是否一致、眨眼是否伴随全身动作。不能只看缩略图或只计算首末帧。

四类 P0 必须作为一套验收：静息末帧到进入首帧，进入末帧到保持首帧，保持末帧到退出首帧，退出末帧到静息首帧。逐对叠加检查相同画布上的脸、肩、腰线、手腕和手指；不要用远距离姿势淡化掩盖接缝。形成 QC 记录，给出通过或退回以及具体失败帧。

验收合格后再提交候选给代码接手者，接入分文件动画计划表。用真实播放层跑短句、20 秒和 30 秒长句、说完、保持中取消、进入中取消及再次开口；同时在低刷新率下复查连续性。现有 66 秒剧本只覆盖当前素材结构，不会自动测试尚未接入的新片段。

## 放入正式版本与交接

一次交付包含原始参考及 SHA256、全部采用的生成 API 图及 SHA256、种子和执行记录、原始帧、抠像后 PNG/meta/manifest、逐帧检查意见、首尾与跨片段接缝结果、运行时验收记录。保留失败样本，不能只报告“已出图”。

正式替换前保留上一版素材和元数据。更新素材映射、分文件计划及板端资源表后，重新导出 RGB565、执行自动测试、核验包校验和，并用实机验证显示、音频停止和长期稳定性。现有板端包是资源输入及参考代码，不是已经部署的设备镜像。
