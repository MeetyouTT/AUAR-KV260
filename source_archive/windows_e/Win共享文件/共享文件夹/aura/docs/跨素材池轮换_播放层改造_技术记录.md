# 跨素材池轮换（播放层改造）技术记录

> 日期：2026-10-05　范围：`aura/tools/demo_stage.py`（播放核心 `StageCore`）
> 目标：解决"长时间说话只能播同一个素材、动作反复"的不自然感（方案 C：池内素材交替）。

## 一、背景与目标

单一说话素材即便做了**多窗口轮换**（`segments.json.windows`），长时间播报仍会看出重复。
方案 C = **同语义素材池轮换**：为同一状态准备多个语义等价素材，播放层"一个素材播满 N 秒换下一个"。

`avatar_assets.POOLS` 先行定义（池内素材**未生成时自动忽略**，可先写池后补素材）：

| 状态 | 池 |
|---|---|
| `SPEAKING_NEUTRAL` | `talking_neutral`、`talking_neutral_b`、`talking_neutral_c` |
| `SPEAKING` | `talking_normal`、`talking_normal_b` |

## 二、换素材的时序规则（数值依据）

`%TEMP%\zz_link.py`（2026-10-05）测灰阶差（判据阈值 6）：

| 对比 | 灰阶差 |
|---|---|
| 自环 `talking_neutral` 首↔末 | 1.21 |
| 自环 `talking_neutral_b` 首↔末 | 1.31 |
| 换素材 上末帧→下首帧 | 1.56 / 1.39 |
| 最佳切换点 | 1.18 |

**结论**：跨素材差异**低于素材内部 loop 接缝** ⇒ 池内混用安全；
但为肉眼零跳变，仍遵守：**只在当前素材 `exit` 走完后换，新素材必从 `enter`（帧 0）起播**。

## 三、实现（`StageCore`，9 处改动）

| 位置 | 改动 |
|---|---|
| 类属性 | `POOL_SWITCH_SECONDS = 6.0`（单素材连播时长；池内素材约 1.6 s/圈 ⇒ 6 s ≈ 4 圈） |
| `__init__` | `_seq_cache`/`_sop_cache` 键 `state` → `(状态, 素材名)`；新增 `_pool_names`/`_asset_of`/`_pool_i`/`_asset_t0`/`_time_key`/`_switch_pending`/`_exit_done` |
| 新增 `pool()` | 包装 `avatar_assets.pool_assets()` + 缓存（可轮换素材名） |
| 新增 `asset_of()` | 状态 → 当前生效素材名（池游标所指；未初始化 / 失效时取池首） |
| 新增 `advance_asset()` | 池游标前进一格，并刷新 `_asset_t0`（下一轮计时起点） |
| `sequence()` / `sop()` | 新增**可选** `asset` 参数（省略 = 当前池素材）；素材目录缺帧 → **回退原回退链** |
| `frame_at()` | 时间基 / 相位按 `(状态, 素材名)` 归零；新增池轮换时序 |
| `segment_stage_time()` | 阶段机键 `state` → `(状态, 素材名)`；`exit` 播完置 `_exit_done` |

### 关键设计决策

1. **换素材 = 换阶段机键**：`segment_stage_time` 里 `sid != _stage_key → stage_reset()`，
   于是"换素材 ⇒ 从 `enter`（帧 0）起播"**免费获得**，不必另写一套起播逻辑。
2. **零回归**：无池状态 `pool()` 返回 `(主素材,)`；`asset` 参数可省略；素材缺帧回退 `frames_dir()`。
   ⇒ `IDLE` / `THINKING` / burst 走的仍是原路径。
3. **降级保护**：无 `segments.json` 时没有 `exit` 可等 ⇒ 到点**直接换**
   （跨素材差异本就小于素材内部 loop 接缝）。
4. **状态切换清理**：`_switch_pending` 在状态变更时复位 —— 否则"待换素材"期间状态被切走，
   该状态以后**再也不换素材**（自检时发现的缺陷）。
