# 板端身份与触摸界面

2026-10-18：Ubuntu 已实现并完成软件回归、真实 CPU 模型的离线参考图检查。**尚未上板，未验收真人登记/重返，也未标定准确率。**

## 当前实现

现有 `ui_camera_service` 仍是相机唯一所有者。DPU YOLO/ByteTrack 产生当前目标，身份工作线程接收检测使用的同一幅原始镜像帧和同源轨迹，不打开第二个摄像头，不使用画过框的预览图。

YuNet 2022mar 检测五点人脸，SFace 2021dec 提取 128 维特征；两模型使用既有哈希校验和 OpenCV 4.5.2 兼容实现。此版身份推理在 CPU，不能称为共享 DPU 身份模型或全模型 PL 调度完成。

只有选中且可见/确认的当前轨迹参与身份识别。人脸过小、模糊、多人重叠或一人框对应多张脸时拒绝登记；其他可见但尚未确认的人体也参与重叠歧义检查。匹配不够或有歧义显示 UNKNOWN，不自动登记，不从其他轨迹继承姓名。

身份输入只有一个最新待处理帧，默认每次任务结束后至少间隔 500ms。原人体检测和预览不等待身份推理；CPU 竞争的实际帧率/延迟影响仍需板测。源时间、相机/轨迹代次、当前选择及数据库版本全部核验；选择变化、失跟、画面或检测过期时立即隐藏旧姓名。慢任务在目标/数据库变化或期限到达后完成，其结果被丢弃。

## 界面用法

“视觉追踪”页底部提供“选择目标 / 当前图问答 / 身份管理 / 设置”，原调试页登记、删除入口保留。

1. 选择当前对象，正对相机，等待合格人脸。身份卡显示识别结果，下方提示具体等待/质量原因。
2. 点击“身份管理→登记当前对象”，输入称呼，再明确确认保存人脸特征。只登记当前目标，等待过程中换人、失跟或状态过期会拒绝提交。
3. 登记提交成功后，状态显示对应称呼。同一人离场后重新出现，需要重新取得其当前人脸再匹配。
4. 删除时先选择已登记身份，再确认。使用身份库版本执行事务；版本过期要求刷新，不删除错误版本。提交后清除结果及待处理候选，迟到推理不能恢复被删除的身份。

传输受理回执不表示事务完成。界面只有收到同一 command_id、同一操作和当前库版本的 COMMITTED 状态，才显示登记/删除完成。

## 配置与数据

`config/board_camera_ui.json` 的 `identity.enabled/config` 开启该服务，参数位于 `config/board_identity.json`。切回旧相机基线可设 `identity.enabled=false`；启动器如核对源码或配置 SHA，需由实际发布流程同步更新，不能只在线覆盖单文件。

默认数据库为设备当前用户的 `~/.local/share/aura/identities.sqlite3`，路径必须为绝对设备本地路径（解析 `~` 后）。新库权限 0600；新模板需显式确认，最多显示/登记 32 个当前模型身份。数据不放入微力共享目录或发布 ZIP，不在日志输出特征向量或用户照片。登记只保存称呼和模型专属特征，不额外存储人脸照片；已有用户主动保存诊断画面的功能独立保留。

当前相似度阈值 0.85、歧义间隔 0.1、最小人脸48像素、模糊阈值40均为保守初始参考参数，**不是由本轮真实多人数据校准的阈值**。不得据单图自匹配宣称身份准确率、真人泛化或防伪能力。

身份模型加载/运行失败不应停止原相机预览；界面显示身份异常/质量提示，登记不可用。删除在有已登记身份时仍可执行。

## 验证入口

Ubuntu 软件检查：

```bash
python3 -B -m unittest tests.framework.test_camera_identity tests.framework.test_camera_ui_service tests.framework.test_board_ui_services -v
```

安装有项目 OpenCV/NumPy 的环境可以运行真实权重离线检查，输入公开参考人脸图片：

```bash
python3 -B tools/check_board_identity.py --image /path/to/public-reference-face.jpg --output /path/to/check.json
```

该命令实际加载 YuNet/SFace，在隔离临时库验证 UNKNOWN、显式登记、SQLite 重开、换轨迹匹配、失跟隐藏、空白图拒绝和删除后 UNKNOWN。它不打开相机、不操作用户身份库，输出不包含特征向量。这仍然是静态图片参考，不是板端真人验收。
