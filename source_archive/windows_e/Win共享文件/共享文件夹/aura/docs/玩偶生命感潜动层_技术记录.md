## 1. 背景与目标

体检结论（见前置文档 §6）：素材并非静止贴图（`amp_p90` 33~57 = 门槛 3.0 的 **11~19 倍**），
但**待机族 5 个素材彼此差 < 1.5 灰阶**，且素材是「39 帧 @24fps = 1.625 秒做一次明显动作」。
演示观感 = **像做操，而不是"在场"**。

目标：在不改素材的前提下，让玩偶获得「生命感」——即**长周期、低幅度、永不精确重复的底噪**
（呼吸 / 重心 / 微摆）。**大动作少而准（burst 已有），微动持续不断（新增）**。

## 2. 核心判断

| 判断 | 依据 |
|---|---|
| 缺的不是"动作量"，而是**底噪** | 动作幅度已是门槛 11~19 倍 → 再加幅度只会更像做操 |
| 底噪必须**长周期 + 互质** | 素材循环节 1.625s，任何单一周期都会被看出"固定节奏" |
| 可以在**播放层**叠加整体微动 | 体检 v3 实测素材帧间 `shift = 0,0`（仅 AWAKE/ACK_NOD/ERROR 为 `0,1`）→ 素材**没有**整体位移，叠加不打架 |
| 幅度必须**亚像素级** | 24fps 下帧间变化 0.18px：平滑；若 > 1px 就变"抖"，反而更假 |
| 锚点必须是**底边中心** | 素材 waist-up 且底部对齐（423×436）→ 呼吸表现为胸腔起伏，不是整个人上浮 |

## 3. 方案：三层合成

```
L0 潜动层（程序化 · 零素材 · 永远在动）   ← 本次实现
L1 素材层（现有 13 素材名：loop 作状态底色 / burst 作一次性动作）
L2 反应层（TTS 包络驱动口型 / 事件弹入 / 交叉过渡）   ← 后续
```

潜动层四通道（`avatar_timing.py`）：

| 通道 | 幅度 | 周期 | 形态 |
|---|---|---|---|
| 呼吸（纵向缩放） | `1.000 → 1.006`（±0.6%） | **3.7 s** | 单向隆起 `(1-cos)/2` |
| 重心·横向 | `±1.2 px` | **5.3 s** | 双向 `sin` |
| 重心·下沉 | `0 → 0.5 px` | **7.9 s** | 单向 |
| 微摆（旋转） | `0 → 0.35°` | **6.7 s** | 单向 |

四个周期**互质** → 复合周期 **8008 s（133 分钟）**，肉眼永远看不到重复。

## 4. 本次落地

### 4.1 `avatar_timing.idle_offsets()`（口径单一来源）

- 纯解析函数、无状态 → **播放层（qt_widgets / demo_stage）与出片脚本共用同一份**，
  与 `frame_index()` 同样的"单点定义"做法（沿用 P0-2 的经验：验收必须测到播放层口径）。
- `t <= 0` / `gain = 0` → **中性位**（位移 0 / 缩放 1.0）：进场不跳变、可一键关闭。
- `IdleOffsets(dx, dy, scale_y, tilt_deg)`：`gain` 只用于样品对比档（×1/×2/×4），生产恒 1.0。
- 时间基必须是**全局单调时间**（`time.monotonic()`），**不是** `_state_time` 状态内时间
  —— 否则每次状态切换都会"重新吸一口气"。
- `idle_composite_period()`：供验收断言"底噪长时间不重复"。

### 4.4 循环顿点修复（用户反馈驱动）

**现象**：用户实测"播完一轮会顿一下"（2026-10-04）。

**根因（量化，`tools/verify_loop_seam.py`）**：
- 逐帧差曲线（人物区 alpha>100 平均绝对灰度差）：
  `3.17 3.70 5.69 7.27 8.83 … 3.08 2.14 1.13 0.83 0.75` → **末尾 2 帧静止**（<1.0 灰阶 ≈0.08s）；
- 首末帧差 **3.22** ／ 平均帧间差 **5.59** → 比值 **0.58**（首末近似同一姿态）；
- ⇒ 正放循环时"末帧 → 首帧" = 回到起点重来，且末尾本来就不动 → **必然顿一下**。

**修法（两层，缺一不可）**：
1. **裁尾**：去掉末尾静止帧（N 由实测得出，不写死）；
2. **折返（乒乓）**：`avatar_timing.pingpong_time()` 把推进时间映射为三角波 → 动作"做完再收回"。

**关键实现细节（本轮踩坑，务必记住）**：
- 有效时长必须取 **`eff = (n_eff - 1) / fps`**（"到最后一帧为止"）：取 `n_eff/fps` 会让折返点正好落在帧边界，
  `frame_index` 取模后跳回第 0 帧 → 实测**跳变 36 帧**；
- 周期取 **`span = 2 * eff`**（**不是** `2*eff - 1/fps`）：后者会跳掉一帧（实测 36 → 34）。
  末帧只在折返点被取一次（这才是"不顿"的关键），起点帧出现两次（周期首尾，循环的本质，帧序前后连续无跳变）；
- **播报族不折返**（倒放会让口型反向）：`PINGPONG_STATES` = 待机族 7 态；burst 不适用（只播一次）。

**验收**（`tools/verify_loop_seam.py` → **RESULT: OK，0 项失败**）：S3 折返序列最大帧索引跳变 = **1**、
末帧出现 **1 次**、首帧 **2 次**；S4 `span = 3.0000 s`（n_eff=37）周期性质成立；S5 状态名单正确。

**样品**：`docs/demo_alive/` 新增 `pp_before.webp`（现状：正放循环）／`pp_after.webp`（折返 + 裁尾 2 帧）
—— 两档**都关掉潜动层与 drift**，所以差别只来自"循环方式"本身。

### 4.5 乒乓被实测否决 → **稀疏动作（single-shot + hold）**：推荐方案

**用户实测（2026-10-04）**："乒乓也会这样顿一下、明显看出循环结束"。

**为什么乒乓不行（我上一轮的论证盲点）**：乒乓让**速度大小连续**（+0.75 → −0.75），
但**"方向反转"本身是极强的视觉事件**（"它怎么又倒回去了"）。根因是**素材类型**：
`idle_normal` 是"起→高潮→收"的**一次性事件型**动作（不是周期性摆动），
所以任何"循环它"的做法都必然暴露"又做了一次"。

**正解 = 不循环素材，把它当偶发事件播**：
- `single_shot_time(t, duration, hold)`：`u = t % (duration + hold)`，输出 `min(u, duration)`
  ⇒ 动作播一次后**停在首帧保持 `hold`（默认 3 s）**；
- **循环点落在完全静止的保持段内部** ⇒ 循环点两侧所取帧**逐像素相同（差 = 0.0）**
  ⇒ **结构上不可能被看见**（现状是 3.22 灰阶 + 速度突变 4 倍）；
- 周期 = 1.625 + 3.0 = **4.625 s**（"每 3 秒动一下"恰是活物的自然节奏）；
- **持续动感交给潜动层（L0）** ⇒ 观感 =「**在呼吸的小玩偶，偶尔动一下**」；
- `hold_for_state()`：待机族启用（沿用 `PINGPONG_STATES` 名单），**播报族恒 0**（口播不能停）。

**零素材改动**，并**顺带解决"看不到呼吸"**：素材不再持续循环后，呼吸（2.6 px）成为唯一可见的运动。

**样品**：`docs/demo_alive/shot_hold.webp`（= 2 个周期 = 9.25 s）。

### 4.6 稀疏动作被否决 → **匀速化（时间重映射）**：最新推荐方案

**用户实测（2026-10-04）**："静止保持 3 秒对光感自然度影响太大" —— 完全静止像卡住；
用户要的是**持续缓慢运动** + 循环点看不出接缝。

**正解 = 按累积运动量重参数化时间（匀速化）**：
- 顿的根源是**速度突变**（末段 0.75 ÷ 首段 3.17 = **0.22**），不是位置跳（仅 3.22）；
- `cumulative_motion(diffs)` → 累积运动量表 S；`warp_time(t, diffs, fps, slowdown)`：
  按 S **匀速推进** ⇒ 末尾减速段被加速通过、高速段被放慢
  ⇒ **循环点两侧速度相等** ⇒ 结构上看不出"一次循环结束"；
- `slowdown` 可整体放慢（用户要的"晃动更慢更自然"），且**放慢不破坏速度匹配**；
- 全程**持续运动、不静止** ⇒ 满足"光感自然度"。

**验收**（`tools/verify_loop_seam.py` 新增 **S6**，**RESULT: OK**）：

| 循环点速度突变比 | 值 | 含义 |
|---|---|---|
| 现状（正放循环） | **0.22** | 偏离 1 越远越顿 |
| 匀速化 `warp_time` | **1.18** | ≈1 ⇒ 速度连续、看不出接缝 |
| 匀速化 + 放慢 1.5× | **0.88** | 放慢不破坏匹配 |

⚠ **判据本身的坑（本轮踩到）**：第一版用"帧索引差"当速度 → 恒为 1（采样步长决定）、什么都测不出；
必须用**画面运动量**（累积帧间差）`S[next] - S[now]`。

**潜动层同步放慢**：呼吸周期 6.0 → **8.0 s**（≈7.5 次/分），重心/微摆同比（放慢只降"变化率"，幅度不变）。
**样品**：`docs/demo_alive/warp.webp`（匀速化 + 放慢 1.5×，4 个周期 = 9.75 s）。




## 5. 关键技术决策与踩坑

1. **`gain`（×1/×2/×4）是为了"让用户选幅度"**：合适幅度是主观量，数值定不死；验收只能保证落在合理区间（A4），
   最终由肉眼挑 → 选定后把生产值固化进常量。
2. **画布留白 `PAD = 10` 是必需的**：位移 + 旋转会超出素材边界，不留白会被裁掉；
   旋转中心取**底边中心**（`Image.rotate(center=...)`），与缩放锚点同一点。
3. **透明帧先合成底色（米白）再编码**：页面观感 = 真机"玩偶叠在面板上"，同时避开 alpha 边缘噪点。
4. **出片用 WebP 而非 GIF**：GIF 的 8-bit 调色板会把 ±2.6px 的亚像素慢变化量化掉；WebP 动画画质/体积更优。
5. **`print` 重定向到文件会缓冲** → 长任务中途"无输出"不代表卡住（本轮曾据此误判，结束时会一次性刷出）。
6. **本机无 pytest**（`.venv` 未装）→ `tests\test_avatar_timing_idle.py` 已写但**本机跑不了**；
   等价断言已由 `tools\verify_idle_alive.py`（纯逻辑、零依赖）全量覆盖并通过。
7. **HTML 模板是 `%` 格式化字符串 → CSS 里的 `%` 必须写成 `%%`**：新加的
   `transform-origin:50% 100%` 与 `@keyframes{0%,100%{...}}` 漏了转义 → 运行时
   `ValueError: unsupported format character '%'`。**改 CSS 时务必检查每个 `%`**（既有模板里已有多处 `100%%` 的写法可参照）。
8. **同一元素叠多条 CSS `animation` 会互相覆盖 `transform`** → 必须**嵌套三层 `div`**
   （`.sway` / `.tilt` / `.breath`），每层一个动画、各自 `transform-origin:50% 100%`（底边中心，与生产锚点一致）。
9. **`@keyframes` 里不要用 `var()` / `calc()`**：首版用 `calc(1 + 0.006 * var(--k))` 做三档幅度，
    兼容性差（部分浏览器在 keyframes 内不解析 var → 动画**完全不动**，观感就是"没看到差别"）
    → 改为**写死三套字面量 keyframes**（`breath1/2/4`、`sway1/2/4`、`tilt1/2/4`），100% 会动。
10. **"看不出差别"的两个干扰源**（用户实测反馈）：① 动画图的循环接缝；② 素材自身 1.625s 动作主导观感。
   → 样品必须**冻结素材动作（中位帧）+ 无接缝播放（CSS）**，才能让人只看到潜动层。

## 8. 素材动作**标准处理（SOP）**（2026-10-04 用户定案）

**背景**：源素材（i2v 生成，约 5 秒量级）**动作又快又大** → 直接循环播放会出现
① **循环点速度突变**（"顿一下"）、② **整体节奏急促** → 实际演示不自然。

**标准处理：对所有待机族素材统一执行**（不做减法、保留素材表现力）：

| 步骤 | 做法 | 实现 |
|---|---|---|
| ① **匀速化** | 按**累积运动量**重参数化时间（低速段加速通过、高速段放慢）⇒ 循环点速度连续 | `avatar_timing.warp_time()` |
| ② **整体放慢** | 乘 `LOOP_SLOWDOWN`（默认 **1.5**）⇒ 节奏舒缓、每帧变化更小 | 同上 `slowdown` 参数 |
| ③ **潜动层** | 呼吸 **8.0 s** / 重心 / 微摆叠加，提供持续生命感（不靠素材循环） | `avatar_timing.idle_offsets()` |

**统一入口（播放层只调它）**：
`avatar_timing.playback_time(state_time, state=..., diffs=..., fps=..., duration=..., burst=...)`
—— burst 原样返回；loop 走"匀速化 + 放慢"；`diffs` 缺失时自动退回普通循环（不会失效）。

**预计算与体检（`tools/build_motion_table.py`）**：
- 逐素材算逐帧运动量 → 落盘 `assets/avatar/<素材名>/motion.json`（运行时**零像素开销**）；
- 输出"处理前后速度突变比"报告；判定口径 `|x-1| < 0.35`。

**首轮批量结果（13 个素材）**：**11 个达标**；2 个留待人工看观感 ——
`talking_low`（0.41 → 0.56）、`idle_offline`（1.49 → 1.48，运动分布特殊）。

**结论**：SOP 有效且可复用 —— **新素材入库后只需重跑一次
`"<AURA>\.venv\Scripts\python.exe" -s tools\build_motion_table.py --write`** 即可。

⚠ **判据本身的三个坑（都踩过）**：① 不能用"帧索引差"当速度（恒为 1，什么都测不出）；
② 窗口不能用"前 3 个间隔"（单点取整抖动会污染结论，误报 6 个）；③ 脚本打印必须
`sys.stdout.reconfigure(encoding="utf-8", errors="replace")`（U+2212 在 GBK 下崩）。

## 9. 三段式（enter / loop / exit）：说话很久不再"反复抬手放下"

**用户实测指出的结构性问题**（2026-10-04）：素材是"起→高潮→收"**一整段**，说话 10 秒会变成
"抬手→放下→抬手→放下…"重复约 6 次，极不自然。正确结构应是：

```
[进入：抬手] 播一次 → [保持：手在空中 + 小幅自然动] 循环 N 次 → [退出：放下] 播一次
```

**已实现（引擎 + 自动切段 + 预计算）**：

| 组件 | 作用 |
|---|---|
| `avatar_timing.Segments` / `segment_time()` | 三段式时间映射（enter 一次 → loop×N → exit 一次） |
| `tools/split_avatar_segments.py` + `segments.json` | 自动推荐三段（在高潮附近找"小幅 + 首尾相近"的窗口） |
| `loop_slowdown`（默认 **3.0**） | **保持段单独放慢** → 每轮 ≥1 秒，避免"每 0.33 秒抖一下" |
| 保持段**来回（乒乓）**循环 | 用户实测要求（2026-10-04）：**单向**循环会"手刚抬起来就立刻缩回去、没有过渡"；**折返**才自然。⚠ 与"整段素材乒乓"（已否决）不同 —— 这里是**小幅保持段内的微晃**，不是"倒带" |
| `loops_for_duration()` | 按句长算循环次数（长句多循环、短应答只 1 次） |

**⚠ 关键结论：现有素材不支持"自然保持"**：
- 自动切段实测：**所有素材的 loop 段首尾姿态差 9~17 灰阶**（比素材平均帧间差还大）⇒
  **素材里根本没有"手停在空中小幅动"的段落**（i2v 生成的是一段连续动作）。
- 因此强行三段式只能做到"手在空中**带小跳地**循环"：`talking_normal` 切出
  `enter 0..12 ／ loop 12..19 ／ exit 19..38`，10 秒循环 10 次、每轮一次小跳 ——
  **比现状好，但不是根治**。

**根治（方案 A：写进生成侧口径）**：生成素材时**显式包含保持段**，例如 5 秒素材规划为
`抬手 1s → 保持 3s（手停在半空、仅手腕/手指轻微动、**不回起始姿态**）→ 放下 1s`；
这样 loop 段首尾天然衔接，三段式才完全自然。提示词要点：
> …动作结构：抬手打招呼 → **手停在半空保持 3 秒**（只做轻微自然晃动，**手不要放下、不要回到起点**）→ 再自然放下…

**样品**：`docs/demo_alive/talk_before.webp`（现状：整段往复）／`talk_after.webp`（三段式）；
素材 `talking_normal`，10 秒 @24fps。

### 9.1 打断衔接（真实交流不会按整数倍来）

**用户实测要求**（2026-10-04）：实际交流中"说话时长"**不可能是保持段时长的整数倍**，随时会被打断
（用户插话 / 回复结束 / 状态切换）⇒ **那几帧必须做好衔接**。

**实现**：

| 组件 | 作用 |
|---|---|
| `segment_at(t, seg, fps, stage="enter/loop/exit")` | **按阶段独立求值** —— 各段时长由调用方决定（不再依赖固定周期） |
| `stage_seconds(seg, fps, stage=...)` | 各阶段时长（`loop` = **一个来回**） |
| `SEGMENT_BLEND_MS = 150` / `segment_blend_seconds()` | 阶段切换的**交叉淡化**时长（与 `ui_tokens.transitions.state_ms` 同口径） |

**播放层状态机（S3 接入口径）**：

```
enter 播 stage_seconds(enter) 秒
  → loop 一直播（往返），直到"该走了"（被打断 / 回复结束）
  → 交叉淡化 segment_blend_seconds()（150ms）到 exit
  → exit 播完
```

**样品**：`docs/demo_alive/cut_hard.webp`（硬切：跳变可见）／`cut_blend.webp`（150 ms 淡化：过渡连续）；
场景 = 话说到 **3.7 秒**被打断（**刻意取非整数倍**时刻）。

## 18. 说话"变化感"：loop 段**多窗口轮换**（用户实测 2026-10-05）

**用户反馈**：说话不够自然 —— **"全程是嘴巴张开、手在那边晃"**（同一个动作反复）。

**根因**：`talking_neutral` 的 loop 段只有 **8 帧**，阶段机让它**往返** ⇒ 长时间说话 = 同一动作反复晃；
且原实现只有**单一**循环窗口。

**实现（三层）**

| 层 | 改动 |
|---|---|
| 数据 | `Segments` 加 **`windows`**（多个可循环窗口）；`split_avatar_segments.py` 取打分最高的**前 3 个互不重叠**窗口写入 `segments.json`；`segments_from_dict` 读回（缺失 = 旧行为，**向后兼容**） |
| 求值 | `segment_at(…, window_index)` / `Segments.loop_at(i)` / `loop_window_seconds()` |
| 阶段机 | `StageCore` 每个"来回"结束 → `_loop_round += 1` ⇒ **换下一个窗口**（`stage_reset` 归零） |

**踩坑（三次实测修正）**
1. 窗口搜索上界用 `peak + 6` ⇒ 峰值靠前的素材**只能落在开头**、凑不满 3 个（实测 `windows=((12,19),(1,8))`）
   ⇒ 放宽上界到 `n - wl - 2`；
2. 放宽后选出**起势段**窗口 `(1,8)`（手还没抬起来）⇒ 加"**前 20% 不作保持窗口**"+
   "**窗口均值 < 目标 50% 排除**"（否则会选到近乎静止段 ⇒ 变成"停住"）；
3. `split` 最初**没把 `windows` 写进 json**、`segments_from_dict` 也没读 ⇒ **链路断裂**（已补）。

**验证**
- `verify_segment_exit.py` **E9**：6 秒完成 3 个来回；loop 段 **21 个不同帧**（单窗口仅 8）⇒ **轮换生效**；
- 全量窗口：`talking_neutral windows=((28,35),(12,19),(20,27))`（3 个、均在运动段、**无起势**）；
- 证据图 `docs/demo_stage/stage_machine_proof.png` 前 4 格 = "第 1~4 来回"（可直接看到窗口切换）。

**仍做不到的（素材侧）**：**口型跟随语音**（viseme / 口型分层）—— 现素材嘴部是"整段同一种开合"，
要在播放层做出真口型需要**口型素材**或**嘴部分层**（生成侧工作）。
若不重制素材，次优方案是 **跨素材交替**（`talking_neutral` ↔ `talking_normal`，切换处用现成 150ms 淡化）
—— **未实现**，等确认。

## 19. 说话"变化感"进阶：**跨素材交替**（用户 2026-10-05："如果要交替的话就在多生成一些"）

**背景**：§18 的多窗口轮换把**单素材**的变化量从 8 帧提到 21 帧，但素材本身只有 **1.6 秒**（39 帧 @24fps），
长时间说话仍会看出重复。用户选择「**多生成一些素材做交替**」。

**设计（三层，本轮完成前两层）**

| 层 | 状态 | 内容 |
|---|---|---|
| 素材池 | ✅ 就绪 | `avatar_assets.POOLS` + **`pool_assets()`**：状态 → **语义等价**素材元组；只返回**目录真有帧**的候选 ⇒ **可先写池、后补素材**（未生成时返回旧值 = **零回归**） |
| 生成 | ✅ 就绪（待执行） | `tools/gen_talking_variants.py`：3 段变体（`SPEAKING_NEUTRAL_B/C`、`SPEAKING_B`） |
| 播放 | ⏳ 下一轮 | `StageCore` 按 `pool_assets()` 取素材 +"播满 N 秒换素材"+ 150ms 淡化转场 |

**为什么必须"语义等价"**：池内素材会在同一状态下**互换**。若把 `talking_low`（低落）混进
`SPEAKING_NEUTRAL` 池，就会出现"平静说话时突然垂头丧气" —— **情绪串味比单调更糟**。
故池内**只收同语义变体**（都属"中性播报"/"高涨播报"）。

**生成脚本的三条纪律**（已写进脚本注释，避免后来者踩坑）
1. **零侵入**：`ComfyUI\tools\run_doll_green.py` 是 12 态共享脚本，本脚本**不改它**，
   只通过 HTTP API 提交**新 tag**（该脚本本身也只走 API ⇒ 放在 aura 侧同样能跑）；
2. **同代一致**：模型 / 首帧 / `COMMON_TAIL` / 采样参数**逐字沿用**，只有"手/头的动作描述"不同；
   seed 用**独立段 `420400+`**（与 `SEED_MAP` 的 11~22 不重叠）⇒ 可复现且不撞；
