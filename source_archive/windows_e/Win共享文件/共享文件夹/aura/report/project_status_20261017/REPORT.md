# AURA / KV260 整体项目进度核查

核查日期：2026-10-17。主仓：`Win共享文件/共享文件夹/aura`。

## 总体结论

**项目已具备实板演示原型，当前处于整机集成阶段；完整的“看见人 → 选择并跟随 → 识别身份 → 真实问答 → 板端播报”尚未串成同一可验收版本。**

已经做出的核心成果包括 KV260/DPU 底座、真实人体检测、ByteTrack 跟踪选人、双层板端界面、MCP01 录音和缓存播放，以及 Windows 上已被用户接受的语音模型链。录音转文字的客户端和显示已上板，主机识别真实板卡录音也通过，但新录音跨网返回实屏文字仍待验收。

本报告对照 ZIP 原始方案、10 月 8 日现行框架、10 月 12 日扩展计划、最新日志、当前源码/配置及保存的板测工件。**“有代码”“主机测试通过”“历史有限板测”“当前整机验收”分别判断，不用目录数量或单模块成果计算总体百分比。**

## 仍然卡住整机的具体问题

### 1. 统一运行入口尚未收拢实板成果

当前 [runtime.kv260.json](../../config/runtime.kv260.json) 仍使用 `aura-framework-20261008`：

- `identity.backend`、`dialogue.backend`、`motion.backend` 均为 `disabled`，物理运动为 `false`。
- 总配置中的检测模型 SHA、DPU 指纹和入口为空，配置指向的 `person_detector.xmodel` 本地不存在。
- 时效与成本参数仍标明示例/未标定。

这些字段说明**统一框架没有回收实际版本**。板端独立 UI 相机服务已跑通 YOLO/ByteTrack 的证据仍然有效，不应因旧总配置再次判定它们没做。

### 2. 语音还差真实跨设备回路

最新已保存板测中，板卡为 `192.168.50.2`，ASR 目标已配置 `192.168.50.1:8791`，但健康接口超时。当前界面具备停止录音后自动请求和文字显示逻辑；实际成功用例仍缺“这次板端新录音 → 识别电脑 → 这块屏幕出现文字”的完整证据。

此前主机识别保存的板卡 5 秒录音成功，与上述实时回路是两项验证。Windows 已接受的文本语音聊天也不包含当前图 VLM；动态问答和 TTS 尚未回到板端输出。

### 3. FPGA 创新尚缺正式实现和对照证明

当前 [visual_servo.sv](../../hardware/rtl/visual_servo.sv) 在 COMMIT 时装入相对 `lease_left`，还不是按源观测绝对期限监督。当前 [SingleCuScheduler](../../board/fusion/scheduler.py) 在 PS 中管理 detection/identity 两类任务；不能称为全模型 PL 仲裁。

[校准集](../../data/calibration_manifest.json) 和 [独立测试集](../../data/test_manifest.json) 的 `items/annotations` 均为 0；[G0—G5](../../config/experiments.json) 仍为 `planned_not_board_verified`。因此现阶段不能宣称可变期限、PL 调度或完整方案已经取得某个性能提升。

### 4. 机构和最终验收没有完成

[机械标定配置](../../config/servo_calibration.json) 仍为 `verified=false`，状态为等待 3D 模型和机械测量。历史已经确认过有限测试方向及往返，但这些不等于最终机构的零点、限位、负载和准确指向标定。

最终还须在同一配置验证实际随动、停止/恢复、外设故障、并发、长稳和多次冷启动。旧完整方案提出两小时整机长测/三次冷启动，10 月 8 日框架提出先至少 60 分钟；团队需在最终测试前统一并冻结验收口径，不能将短测算作整机关卡通过。
