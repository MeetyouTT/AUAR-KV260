## 1. 背景与目标

v1_1 口径对照文档（`C岗首批工作包文档口径对照_v1_1.md`）§7 把"六份交付材料"列为下一步，
其中**材料① C01 事实与依赖表**要求：分**主机 / 板端 / 模型 / 外部程序 / 显示**五部分，
每条填 **实际版本或 unknown、路径、负责人、依据、第一失败层**。

难点：**本机无 MCP01、无 KV260、无网络、无大模型权重**，若靠"写文档"就会变成猜。
因此本轮把材料①做成**可复现的实测产物**：先写只读盘点脚本 → 落 JSON 证据 → 再由证据写表。

## 2. 做了什么

1. 新增只读脚本 `tools\collect_host_facts.py`：一次运行产出 JSON（结构化原文）＋ TXT（人读摘要）。
2. 运行脚本 2 次（v1 基础版、v2 增补版），最终证据时间戳 `2026-10-03 17:08`。
3. 依据证据撰写 `docs\C01_事实与依赖表_v1_0.md`，并用项目自带 `tools\render_docx.py` 渲染同名 docx。

## 3. 关键修复细节与技术决策

| # | 决策 / 坑 | 处理 | 理由 |
|---|---|---|---|
| 1 | **"unknown 不猜"** | 未实测项（板端全部、权重）一律写 `unknown` 并给"取证方式"列 | 事实表一旦含推测值，后续所有"第一失败层"判定都会失真 |
| 2 | **单列 `torch` 探针** | 脚本内嵌 `TORCH_PROBE` 子进程，取 `version / cuda_build / cuda_available / device_count / cudnn / get_num_threads()` | `pip list` 只显示 `torch==2.10.0`，**看不出是 CPU 构建**；本轮实测 `2.10.0+cpu`、`cuda_build=null`、`device_count=0` |
| 3 | **扫描有界** | 层深 5/5/3，命中上限 400/300/200，>50 MB 跳过哈希，只扫 3 个已知根 | 遵守成本控制：禁止递归整盘；同时保证"0 个权重"这个结论**有边界声明** |
| 4 | **修正复用仓路径** | 初版把复用仓猜成 `项目\aura`（实测 **不存在**），修正为**工作区根下 `aura\`** | 路径靠猜必翻车；实测发现 `aura\` 顶层是 `board/common/docs/scripts/tests/ui`，**未见 `runtime`/`interaction`/`assets`**，与复用清单口径需核对 |
| 5 | **意外收获：上游 commit** | 脚本记录 `git rev-parse HEAD`／`describe --dirty`／`remote -v`／`status --porcelain` | 上游 `wujing-lite` 是 git 仓且**工作区干净**、HEAD = `a46d9016cc50d318e5c6da9463ae691579c48a81`、**无 remote** ⇒ 材料② 的"固定 commit"可直接引用，且必须"本地目录＋哈希"而非"拉取"复现 |
| 6 | **前台长任务被终端杀掉** | 改为 `Start-Process ... -RedirectStandardOutput/-WorkingDirectory` **分离运行**，再用 PowerShell 循环**轮询产物 mtime** 判定完成 | 本轮实测：前台跑盘点脚本时命令被后续操作打断，`_tmp_hf.txt` 为空、证据文件未更新（脚本本身无错） |
| 7 | **`editor` 插入位置越界静默失败** | 追加段落改为**用 `old_text` 锚定最后一行再替换追加**，不再依赖 `insert_line` | 先按预计行号插 §2/§3 报"超出范围"；且**不能把被替换行本身弄丢**（本轮一次替换把 §5 尾句吞掉，已回补） |
| 8 | **cmd 不支持 `;` 与 `|` 混用** | 一次命令只做一件事，串联只用 `&&`；`|` 交给 PowerShell 内部时整串必须整体加引号 | 本轮 `powershell -NoProfile -Command "..."; Get-ChildItem ... | Select-Object ...` 被 cmd 按 `|` 切断，把 `Select-Object` 当外部命令执行 |
