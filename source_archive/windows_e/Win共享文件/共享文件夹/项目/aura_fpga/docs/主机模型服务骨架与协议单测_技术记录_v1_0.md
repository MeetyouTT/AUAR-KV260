## 3. 关键修复细节与技术决策（踩坑记录）

### 3.1 `SegmentLedger.pending_gap` 是**永不触发的死代码**（真缺陷）

原实现：

```python
return [i for i in range(self._next_index) if i not in self._accepted]
```

`offer()` 里 `_next_index` 只在"连续命中已收段"时才自增，因此
`range(_next_index)` 内的下标**天然全部已在 `_accepted` 中** —— 该属性恒为 `[]`，
"超时缺段"这条 §6.6 的拒绝语义永远拿不到证据。

修复（改为以**已收到的最大段号**为界，即前视窗口内的空洞）：

```python
if not self._accepted:
    return []
return [i for i in range(max(self._accepted)) if i not in self._accepted]
```

判据含义：越过（收到更大段号）却始终未到的段号，就是必须超时上报的缺段。
用例 `test_pending_gap_reports_missing`：先收 0 再收 2 → 上报 `[1]`。

### 3.2 fixture 的 `probe()` 会真的调用 `answer()`——探针污染了服务状态

表现为 `test_cancel_during_vlm_discards_audio` 拿到的响应
`timings == []` 且 error 文案是"世代已取消或**已被更新世代取代**"，
而非预期的"VLM 完成后世代已切换"。

定位：调试脚本打印显示 **`[vlm] cancelling generation 1` 出现在 `health:` 之前** ——
`FixtureVlm.probe()` 会走一次完整的 `answer()` 做功能探针，测试里的取消钩子
在那一次就触发了 `cancel(1)`，于是真正的 `handle()` 卡在**入口世代校验**直接返回，
根本没进流水线。

修复：测试侧引入显式 `armed` 开关 + 图像指纹匹配，只在**真实请求**那一次触发取消：

```python
if self.armed and kw.get("image_sha256") == self.sha:
    self.pipeline.cancel(self.generation)
```

**留下的工程约定**：探针可以调用后端功能，但**不得改变服务状态**
（世代／取消集合／统计）。真实后端实现同样必须遵守。

### 3.3 决策：重试幂等（同一请求不重复推理）

手册 §C04／§C07 要求"重试保持请求语义、同一 request 不重复执行播放"。
网络重传若被当作新请求，会造成重复推理与重复播放。因此在 `handle()` 的
世代校验之后、抢占在途信号量之前加入缓存：

```python
cached = self._cache.get((req.session_id, req.request_id, req.generation))
if cached is not None:
    self.stats.replayed += 1
    return copy.deepcopy(cached)     # 返回副本，防调用方改动缓存
```

- 键 = `(session_id, request_id, generation)`，容量 **16**（FIFO 淘汰）。
- **只缓存成功结果**（`_remember()` 在 TTS 之后、未失效时调用），失败允许重试重新执行。
