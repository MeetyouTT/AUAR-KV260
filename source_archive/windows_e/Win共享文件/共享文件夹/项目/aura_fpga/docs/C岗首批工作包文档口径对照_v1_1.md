### ② C04：字段样例 → 必须成为**可执行的协议包**

字段归属、二进制媒体、取消/目标换代/超期拒绝、重复请求幂等，v1_0 理解正确；但"列字段"只是协议设计的一部分。
按审查报告 §4.1，交付包至少覆盖这些**部位**（细节以正式 I05/I06/I07 冻结为准）：

| 部位 | 至少要明确的细节 |
|---|---|
| 协议与服务身份 | release、protocol_version、主机项目身份、支持能力、**服务重启代次** |
| 请求归属 | board_boot_id、session_id、request_id、generation、utterance_id 及**各字段作用域** |
| 目标与图像 | camera_epoch、frame_id、track_id/track_generation、尺寸、编码、hash、**源时间语义** |
| 音频 | 硬件与模型的**真实格式**、声道、sample_count、字节数、media hash、长度限制 |
| 字段类型 | 字符串/整数、必填/可空、枚举、单位、**宽整数的 JSON 表示** |
| 媒体载荷 | 小元数据与二进制的对应方式、大小上限、编码/校验、**缓冲所有权** |
| 期限与时间 | 板端 deadline、剩余预算、主机本机耗时、**板端回包后再检查** |
| 事件与音频段 | 阶段枚举、段号、顺序、结束、错误、重复丢弃、缺段超时 |
| 幂等 | 相同请求重复提交；**相同标识但不同载荷的冲突**处理 |
| 取消 | 本地 generation 先失效 → 清应用及设备队列 → **异步**通知主机 |
| 资源与重连 | 问答与 ASD 各自队列上限、并发、优先级、有限重试、断连恢复 |

**首批建议固化的异常样例（10 条）**：① 合法一轮全链；② 同 request 重复提交不重复播放；③ 同标识不同媒体 hash → 按冻结规则拒绝；
④ 旧 generation 回复迟到 → 全丢；⑤ 错 boot/session、错协议、track_generation 变化 → 分别拒绝；
⑥ 排队超时/执行超时/deadline 已过 → 分别记录失败阶段；⑦ 重复段/乱序/缺段/超大载荷 → 有上限；
⑧ 取消发生在上传/排队/推理/下载/应用队列/设备已缓存**各阶段**；⑨ 主机退出或断网后恢复 → 只允许新有效请求恢复；
⑩ 格式错/模型未 ready/设备丢失 → 原因可定位。

**交付目录**：schema ＋ 正常/异常元数据 ＋ **独立二进制媒体** ＋ 预期行为 ＋ 运行记录。
⚠️ 手册 §8.3 的请求/取消代码是**逻辑骨架**：我先前所说"骨架字段已就位"指的是
`项目\aura_fpga\host\model_service\` 的实际实现（35 项 unittest 全绿），**须附该实现版本与样例，不能用手册示例代替完成证据**。

### ③ C08：板端实屏

- 冻结对象＝**"界面框架＋平台/显示后端"组合**，并列明目标库、平台插件、字体资源、所需显示服务器/compositor；
  候选可含 Qt、SDL 或浏览器，**是否可用及实际版本以目标镜像验证为准**。
  〔"Qt/SDL/DRM 等择其一"把不同技术层次并列，原手册此句需修订：Qt 可通过平台插件与 KMS/DRM 组合。〕
- 顺序（成立）：**先实屏静态中文图**（核分辨率/方向/字体/缺字/资源路径）→ 真状态 → 动画/字幕 → 与相机/音频/DPU 并发。
- **静态图只放行显示基础**：显示基础（最终屏幕＋最终平台＋实际驱动/模式/权限＋中文出图）→ UI 功能 →
  故障与并发 → 最终验收（实屏事件时延、真实播放与口型、T25 等）。**不能由静态图签收完整 C08**。
- 需冻结依赖：目标 ARM64 应用、与目标 rootfs 匹配的 SDK/库、实际平台插件、字体与资源路径、所需 libdrm/EGL 等、设备权限与输入路径。
- 通路未过时：**C 可继续协议与原型，实屏签收保留具体阻塞原因**；最终必须用 **DPU 与 motion 共存**的有效平台配置复测。

### ④ HTTP 与主机服务

- 框架自由（无 FastAPI/Flask/WebSocket 强制），但 **API 功能、进程结构与并发行为不能留白**：
  完整问答须有可运行的 ASR→VLM→TTS 路径并能关联请求、返回阶段/结果、处理取消与错误；
  **VLM 可以是内流水线调用，不必为形式齐全另造 `/vlm`**；Light-ASD 也须有实际可调用的输入/结果通路。
  冻结的是**功能覆盖与语义**，不是三个 URL 的拼写。
- **READY 必须拆开**：端口存活 ≠ READY。每个必需模型分别具备工件、加载状态、固定输入探针结果与明确失败原因；
  问答整体可用＝其 ASR/VLM/TTS 均可运行且**实际串联通过**；ASD 未通过时问答可仍可用，但自动说话人建议须显示**未就绪**；
  **板端音频与实屏健康状态也要分别展示**；健康返回带服务身份/协议/模型能力/错误，**避免重启后沿用旧 ready**；
  探针**不应每次健康查询都完整加载或跑全部大模型**。
- **控制响应**：重模型不得堵住取消/健康/阶段事件/主机握手 → 建议接入控制与**有界模型工作队列**分离；
  并发与优先级按显存与实测延迟定；多进程各自加载模型须计入显存预算。
  〔若选 FastAPI，`async def` 不等于阻塞模型自动非阻塞；重模型调用仍要另排工作线程/进程或队列，并实测取消与健康响应。〕



### ⑤ CUDA、PyTorch 与模型工件

- **"是否换 CUDA torch"是有约束的决策**（不能仅凭手册未点名就无条件换，也不能只"记进 C01 表"就算过关）。判定顺序：
  1. 固定要复用的源码 commit、模型工件与后端；
  2. 盘点目标 Windows 主机的 GPU/显存/驱动与实际 Python 环境；
  3. 核对该后端**是否要求 CUDA**、是否有经验证的 CPU/其他设备路线；
  4. 若原样路线要求 CUDA → 核对实际 PyTorch 构建与 GPU 可用性，并跑**该模型的真实固定样例**（`import torch` 成功不算）；
  5. 若做 CPU/其他后端适配 → 记录改动、权重加载、预处理与结果一致性，以及热延迟与资源实测；
  6. 按冻结的功能与性能要求选定路线后再锁环境。
- **C01/C05 环境记录至少补齐 8 类**：执行路线（原生 Windows/WSL/容器及**每个模型的环境位置**）、Python 环境（版本/路径/标识/直接与传递依赖/锁文件，须为该入口实际使用的解释器）、
  GPU 环境（型号/显存/驱动/后端设备支持/实际运行位置）、PyTorch 路线（实际 torch 版本、**CPU/CUDA 构建信息**、相关音视频与 processor 依赖）、
  外部程序（ffmpeg 等**是否被代码调用**、路径/版本/必要功能）、模型（ASR/VLM/TTS/Light-ASD 各自 model_id、源码 commit、工件 manifest）、
  能力预算（冷加载/热推理/峰值 RAM 与显存/输入上限/并发与队列上限，冷热分列）、启动与复现（启动入口、配置位置、加载/失败/退出、功能探针、非作者复现）。
- **权重 hash ≠ 完整可运行模型**：权重、分片及索引、配置、tokenizer/processor、词典、预处理、模型代码/后端版本、许可证与样例**共同归档**。
- **模型状态分级**（C01 步骤 3）：候选／权重已取得／参考样例通过／服务化通过／阻塞；C05："SenseVoice、Qwen2.5-VL、中文 VITS 等是**候选名字，不等于已有通过工件**"。
- **手册 T/U/J 是内部验收目标与检查，不是已测成绩**；T18/T19/T25 等目标须按手册的冻结与修订规则执行，**不得结果出来后改标准包装通过**。
