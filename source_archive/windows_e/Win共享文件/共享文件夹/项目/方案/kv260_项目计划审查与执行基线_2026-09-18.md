## 2. 方案中需要现在统一的五件事

1. **只保留 KV260 作为当前硬件基线。** FMQL30TAI V3.4 是历史参考，原板引脚、内存、ICraft/NPU 工件不能移到 KV260。AMD 版完整工作要求第 1.2 节已明确这一点。正式工程说明和演示稿应只从 KV260 基线取事实。
2. **确认赛道。** 现有 AMD 计划按自主选题编写。竞赛指南第 3.3 节允许用 KV260 所属器件系列，要求上板、源码、仿真或验证、综合实现报告、构建脚本、协作记录和可复用 Skill；工具推荐 2026.1 或 2025.2，使用 2022.2 必须在报告说明并保证脚本可复现。若改报具身智能，第 3.2 节要求 AMD Ryzen AI PC 与规定软件栈，现有 Windows/NVIDIA 主机方案要重新设计，不能只改标题。
3. **先确定比赛主线，再安排增强项。** 20 天计划把 DPU、运动 IP、语音、VLM、身份、UI、整机机械与测试都压在前 15 天，还要在第 16 至 20 天长跑和交付；这是目标窗口，尚无工作量与已完成资产支撑。先以“KV260 感知→PS 目标选择→自研 PL 安全运动控制→实体转向→可复现实测”为首个不可替代闭环。语音问答、身份记忆和双麦方向依原工作要求保留为目标，但须分别过关，不让它们阻塞第一条实体闭环。
4. **冻结一份版本锁，不混搭工件。** 历史组合为 Vivado/Vitis/PetaLinux 2022.2、Vitis AI 3.0、DPUCZDX8G 4.1。KV260 有 Vitis AI 3.0 对应的预构建镜像，可先作板卡与 DPU 基线；后续要证明自研 IP 与 DPU 共存，必须取得匹配的参考硬件源码并重建。记录镜像、固件、DPU 配置、VART/XIR、模型和最终 XSA/位流的对应关系。Vitis AI 3.0 编译器使用与实际 DPU 配置一致的 `arch.json`。
5. **清理文档引用。** 完整工作要求第 23 章提及 D1—D4、`wujing-lite/`、`111.docx`、`docs/BASELINE_CONVERGENCE.md` 等，但本目录均不存在。W17 的 22 项不能按“已收敛”登记；先找回原件或将其标为外部参考，再决定是否继续执行这一批跨文档任务。不要为追求六份 Skill 或文档格式，挤掉实机验证时间。

## 3. 从今天开始的阶段关卡

相对开发日 D1 从**首次实际开工**计算，不自动套用旧稿的日历日期。每项关卡须由工件加原始证据判定；只有计划文字不是通过。

| 关卡 | 前置工作 | 通过证据 | 未通过时的处理 |
|---|---|---|---|
| G0：范围与实物盘点 | 确认赛道/组别、团队人数与可用工时；检查 KV260、电源、卡、线、相机、屏幕、舵机和仪器；收集其他仓库成果 | 一页场景卡、BOM、成果清单、工具版本记录、待决事项负责人 | 没有部件或原工程时先改排期；不把采购/安装算成功能完成 |
| G1：板卡和参考 AI 基线 | 使用与 Vitis AI 3.0 对应的 KV260 镜像；完成串口、SSH、相机、DPU 最小样例；锁定参考平台源码 | 首启日志、镜像哈希、`xdputil`/示例输出、模型与 DPU 配置信息、平台来源 | 先排查镜像/固件/电源/版本；自研联合构建暂不启动 |
| G2：自研 PL 最小闭环 | 先仿真 PWM、限位、租约、停止与复位；空载测波形；核实供电与真实机构 | RTL、仿真波形、综合/时序报告、空载波形、接线和标定记录 | 转轴保持禁用；软件可用模拟接口继续联调 |
| G3：同片共存与实物随动 | 在匹配平台中集成 DPU 和自研 IP；用同一相机帧驱动目标选择和转向 | 可重建脚本、XSA/位流、DPU 与运动 IP 同时工作日志、20 次左右移动试验 | CPU 检测仅作为故障定位或演示降级；报告 DPU 目标未完成 |
| G4：交互与扩展 | 在 G3 稳定后并入板端 UI/按键/音频和 Windows 本地问答；身份登记与双麦方向各有独立测试 | 端到端问答、断主机回退、身份错认/删除、双麦定位各自的原始测试 | 没通过的能力明确标为未完成，不用模板或跟踪 ID 冒充 |
| G5：竞赛交付 | 基于冻结硬件与模型做性能、资源、正确性、长跑、冷启动和复现 | 源码、构建脚本、报告、原始数据、视频、许可、Skill 与他人复现记录 | 报告真实完成状态、失败案例和未实现项 |

**首批最小行动（G0—G1）：**

1. 把安装成功、板卡到货和每个部件的真实状态填入成果清单；标注“已运行/只有文件/待验证”。
2. 核对赛道与组别；把自主选题指南第 3.3.3、3.3.5 节作为本版提交要求，不再引用 FMQL 旧评分表。
3. 冻结 2022.2/3.0/4.1 的下载来源及哈希。先用 KV260 预构建镜像做首启和 DPU 基线，PetaLinux 安装与自定义镜像放在需要重建平台时完成。
4. 确定自研 FPGA 贡献的最小演示：舵机 PWM、限位、超时和外部停止；先完成仿真、波形和空载测试，再接负载。
5. 每天在同一份状态表里记录负责人、实耗时间、工件路径、通过证据和阻塞。没有原始证据的状态统一写“待验证”。

## 4. 赛道与工具版本的说明口径

以当前文件夹中的《2026 FPGA 赛道选题指南（AMD）》为依据：自主选题赛道的核心评分是创新应用 30、性能资源 20、功能完整 20、大模型协作与 Skill 15、文档复现 15；需要上板运行及实测结果。指南推荐 Vivado/Vitis 2026.1 或 2025.2，并允许其他版本在报告说明且保证脚本复现。因此选择 2022.2 是为了维持 Vitis AI 3.0 / DPU IP 4.1 的已验证兼容组合，但必须把版本理由、安装包、脚本、构建环境和重建结果写入最终报告。赛事后续公告若有新要求，再更新这段说明。
