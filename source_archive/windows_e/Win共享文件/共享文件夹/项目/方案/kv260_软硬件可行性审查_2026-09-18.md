# 雾镜 Lite（KV260）软硬件可行性审查

日期：2026-09-18（按本地日期）  
审查对象：`amd_kv260_full_work_requirements_v3.md`、`amd_kv260_20day_3person_execution_plan_v2.md`、`amd_kv260_plan_v1_0.md`、竞赛选题指南与本次对话中确认的物料。  
性质：设计审查；尚未取得板端实测，不以文档或官方示例替代本队工程的验证。

## 结论

**项目在技术原理上可以做。当前没有足够证据保证按现有“20 个开发日、三人、全部功能与全部验收指标”完成。** 若优先完成“KV260 DPU 人体检测 → PS 目标选择 → 自研 PL 安全 PWM → 实体单轴随动”并逐关卡增加功能，这条比赛核心闭环有实际可行路径。完整版本还包括同片双麦方向、视听选人、语音和图像问答、持久身份、板端显示、全部异常保护与复现包；从现在的可核验成果和物料状态看，应按高风险研发目标管理，不适合承诺 20 天必成。

不同的“完成”必须分开：

| 交付层次 | 可行性判断 | 当前把握的依据 |
|---|---|---|
| KV260 用官方 3.0 镜像启动并运行 DPU 示例 | 高，但要实测新到板卡、卡与固件 | AMD 提供对应 KV260 的 `xilinx-kv260-dpu-v2022.2-v3.0.0.img.gz` |
| 相机检测、PS 跟踪、自研 PL 单轴控制、实体随动 | 技术可行；工程风险中高 | 板卡具备摄像头、Pmod、显示等接口；运动 IP 本身复杂度可控，难点在联合硬件、供电、安全和机械 |
| DPU、运动 IP、板端显示和音频在同一最终配置稳定共存 | 可做，但目前没有验证证据；这是主关键路径 | 官方提供 2022.2 KV260 平台/benchmark 工程；加载方式、设备树和 VART/XRT 组合必须一致 |
| Windows 主机本地 ASR/VLM/TTS 与身份记忆 | 原理可行；性能和可用性要在实际主机测 | 现有模型和 OpenCV 链有公开实现；现有目录无模型、依赖锁、延迟与正确率记录 |
| 双 I2S 麦克风由 PL 判粗方向并视听选人 | 条件可行，成功率不确定 | 麦克风未到；麦间距、引脚、时钟、机身噪声和声学结果均待核验 |
| 20 天完成现有完整清单和 T01—T30 全部目标 | 把握低 | 当前目录仅有方案和学习资料；平台重建、RTL、机械、模型、集成和测试均缺产物；音频物料下周才到 |

这不是成功率百分数。没有真实板卡、团队工时和性能数据时给出百分数会制造虚假精度。

## 已确认的实物与现状

- 用户确认：KV260、舵机、摄像头、屏幕已到；Vitis/Vivado Unified Installer 已安装。音频设备和麦克风预计下周到。转盘/轴承、电源、microSD、散热、接线、外部停止键和测量工具的实物状态还未提供。
- 用户认为示波器暂不需要。**不一定要购买示波器**；但若要报告 PWM 周期/脉宽、停止输入到数字输出的毫秒级响应、1000 周期抖动，至少要借到示波器或可导出原始时间戳的逻辑分析仪。电源与堵转电流另需合适的电测手段；视频只能说明机构动作，不能代替数字时序波形。
- 文件夹内没有工程源码、板端日志、测试数据、模型或合成报告。Unified Installer 已装和板卡已到是准备进展，仍需实际安装版本与首启证据。若其他仓库有成果，应并入成果盘点后重估。

## 技术审查：硬件

### 1. KV260 适配

KV260 确有 USB、Pmod、HDMI/DisplayPort 输出、相机接口；硬件平台适合视觉与 PL 控制。官方资料指出载板有 rev. 1.0 和 rev. 2.0，部分特性不同；旧 2022.2 镜像和参考工程能否覆盖手中这块板，必须通过载板丝印、首启和外设测试确认。官方套件标准包装不含电源、SD 卡和外设，不能因为“板卡到了”就默认可立即启动。[UG1089 接口](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Interfaces)、[包装清单](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/What-s-in-the-Box)。

### 2. 单轴舵机与安全

PL 产生 PWM、限制脉宽、处理命令超时是可实现的。但舵机型号、堵转电流、负载、转盘轴承和失去 PWM 后的实际行为尚未确定。KV260 的 Pmod 供电能力只有 **3.3 V、100 mA**，不能直接给舵机供电；执行器须按铭牌与实测使用独立合适电源、共地、电平核对、保险/限流及机械限位。[UG1089 电源预算](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Powering-the-Starter-Kit-and-Power-Budgets)。

板上 PL 逻辑在配置完成前不能保证执行停止逻辑；“断 PWM”也不一定等于机械即时停止。因此外部可触及停止键、默认禁能/断电门、负载轴承和恢复时人工确认位置是实物安全设计，不应只写进状态机。没有编码器时，只能证明指令角和视觉居中效果，不能声称测到了真实轴角或闭环位置精度。

### 3. 双麦与 I/O

计划用共 BCLK/WS、两条独立数据线接双 I2S 麦，需 4 根 PL 信号线；舵机 PWM、外部停止和确认输入还会占线。KV260 只有一处 2×6 Pmod，须做正式引脚表和电平/占用检查，不能按 KR260 多个 Pmod 的经验设计。若最终显示平台占用同一 Pmod 音频编解码器，这一接口方案还要重新核对。[UG1089 接口](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Interfaces)、[KV260 平台功能示例](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Vitis-Platforms)。

50 mm 麦距、48 kHz 的最大物理时差约为 7 个采样点，做前方左/中/右粗分辨有原理基础；近中间、背后声源、两人同时讲话、舵机噪声和设备自播音会降低可靠性。麦克风未到且型号未锁定，不能先承诺 85% 现场正确率。该项应在视觉随动稳定后独立验收，失败时按计划降为增强项。

### 4. 显示与整机负载

KV260 有 HDMI/DP 输出，不代表所选 **Vitis AI 3.0 镜像加最终自研位流**已经具备可用的桌面/显示栈。屏幕到货后先在目标镜像验证实际分辨率、DRM/显示、摄像头采集与 DPU 并发。若最终显示要另加 VMIX 等 PL 模块，资源、时钟和视频管线可能改变 DPU 联合设计；不能以 PC 浏览器界面代替板端显示通过。[UG1089 Vitis 平台说明](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Vitis-Platforms)。

## 技术审查：工具与软件

### 5. DPU 与自研 IP 的真正难点

2022.2、Vitis AI 3.0、DPUCZDX8G 4.1 是 AMD 核验的版本组合；Vitis AI 3.0 有 KV260 预构建镜像，2022.2 分支也有 KV260 benchmark overlay。它们证明了**存在起点**，没有证明本队在这个起点上加入运动/音频 IP 后可直接使用原镜像。新增 IP 涉及 PL 资源、地址、设备树、加载物、驱动与 Linux 软件的同步更新。DPU 配置改变时，模型需用对应 `arch.json` 重新编译。[版本兼容](https://xilinx.github.io/Vitis-AI/3.0/html/docs/reference/version_compatibility.html)、[Vitis AI 3.0 系统集成](https://xilinx.github.io/Vitis-AI/3.0/html/docs/workflow-system-integration.html)、[2022.2 KV260 benchmark 工程](https://github.com/Xilinx/kria-vitis-platforms/tree/xlnx_rel_v2022.2/kv260/overlays/examples/benchmark)。

**最重要的设计决定：先选定一个加载路线。** AMD 文档明确 Vitis 流使用 `xclbin` 和 XRT，而 Vivado 流的 MPSoC VART 应按 standalone 方式构建；两套运行时混配会在运行时出错。计划目前把 `.bit/.xsa/.hwh/.xclbin` 都列成可能产物是合理的，但实际项目必须在参考设计跑通后冻结其中一条路线。[Vitis AI 3.0 集成说明](https://xilinx.github.io/Vitis-AI/3.0/html/docs/workflow-system-integration.html)。

PetaLinux 2022.2 是自定义镜像和软件平台的重要工具；先用预构建镜像验证板卡与 DPU，再建立自定义构建环境，可缩短诊断链。最终不能只交预构建镜像加一个单独 PWM 测试位流，因为那不能证明 DPU 与自研 IP 同片共存。

### 6. 检测、跟踪和模型

预训练人体检测模型在 DPU 上推理可行。风险在模型/架构匹配、预后处理、现场小目标与背光、USB 相机采集到推理的实际吞吐；“只取 person 类”不会减少网络主体运算。现有 ≥10 Hz、precision/recall ≥90% 等为内部目标，没有数据支持保证。先用官方已编译模型和固定画面建立基线，再决定是否自量化 YOLOX-Nano。官方 Model Zoo 的模型随平台 DPU 配置使用，不能把其他板卡 `.xmodel` 任意拷来。[Vitis AI 3.0 Model Zoo](https://xilinx.github.io/Vitis-AI/3.0/html/docs/workflow-model-zoo)。

IoU 跟踪、单目标保持、画面死区和有限角度控制是合理的首版。多人交叉、ID 切换与摄像头自身转动会破坏身份连续性，因此“再次看到同一人”必须由独立人脸特征与保守拒识支持，不能由轨迹 ID 推断姓名。

### 7. 主机问答、语音与身份

当前设计把 ASR、VLM、TTS、YuNet/SFace 和身份库放在 Windows GPU 主机上，技术上可行，但**“能跑”与“能在 8 秒内完成语音看图回答”不同**。实际显存、模型后端、图片尺寸、网络、音频缓冲和并发均未测。Qwen2.5-VL-3B 官方模型卡提供图像文本输入示例；模型是否在当前 Windows 环境稳定调用、首次回答耗时和许可要逐项锁定。[Qwen 模型卡](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct)。

人脸识别链有 OpenCV 的检测与特征示例，受控展台演示可做；跨光照、侧脸、遮挡和陌生人“零错名”不应承诺。自愿登记、unknown、换人时取消、删除后清除缓存都是必要的真实工程工作，不是接入模型后自动获得。[OpenCV 人脸检测与识别教程](https://docs.opencv.org/4.x/d0/dd4/tutorial_dnn_face.html)。

USB 音频预计下周到，因此 ASR/TTS 现在只能做 Windows 单机样例和接口，最终板端录放音、串音、取消旧结果与动图同步要在实物到齐后重测。首版按键半双工可行；全双工/AEC/免按键唤醒不应并入当前必交付。

### 8. 竞赛适配

当前计划按**自主选题赛道**写是合理的。指南第 3.3 节重视创新、性能/资源、功能、协作 Skill 和复现；作品须上板验证。该赛道推荐 Vivado/Vitis 2026.1 或 2025.2；使用 2022.2 可以，但最终报告要说明旧版 DPU 兼容理由并给出可重建脚本。若改报具身智能赛道，其第 3.2 节另要求 AMD Ryzen AI PC 与指定软件栈，当前 Windows/NVIDIA 主机不能直接算作满足该要求。最终以实际报名组别和赛事后续公告核对。[本地《2026 FPGA 赛道选题指南（AMD）》PDF 第 8、14—20、22—25 页](../参赛资料/全国大学生嵌入式芯片与系统设计竞赛'2026FPGA赛道选题指南-AMD.pdf)。

## 工期审查与建议承诺

20 天表目前把参考平台重建放到 D3，把 DPU＋自研运动 IP 联合板级验证放到 D7，把双麦、身份、问答和整机首演放到 D10。这些顺序只有在**三人均有持续工时、关键器材齐全、有匹配参考源码且已有可运行工程**时才可能作为冲刺计划。现有文件夹不能证明这些前提；音频下周才到，旧稿第 23.1 节也承认“20 天/360 人时”与“35 天/630 人时”存在冲突。因此不建议以 D10 全功能首演或 D20 T01—T30 全通过对外承诺。

更稳妥的承诺是**按关卡而非日历**：

1. G1：这块 KV260 上官方 3.0 镜像、相机、屏幕与 DPU 最小例程同时可用，记录板卡版本、镜像和运行日志。
2. G2：运动 RTL 仿真通过，空载 PWM、限位、租约和停止有原始波形；舵机独立供电和外部禁能检查通过。
3. G3：DPU 与自研运动 IP 在**同一硬件配置**运行，人员进入后能真实安全转向；完成重复试验与断链/停帧/急停故障测试。
4. G4：增加按键语音、真实图像问答、板端 UI，再增加身份记忆；每项单独记运行位置、性能和失败场景。
5. G5：双麦 PL 粗方向和视听选人作为额外创新关卡，只有实测正确率、UNKNOWN 覆盖率、资源与延迟通过后纳入最终主线。

**判断是否继续当前完整方案的硬门槛：**若 G1 后无法取得并重建对应 2022.2 参考平台，优先解决平台而不是开始新的模型训练；若 G2 外部停止和供电无法验证，不接实体负载；若 G3 无法共存，只能如实提交降级版，不能宣称已经完成 FPGA/DPU 协同加速。

## 需进一步确认的五个事实

1. 手中 KV260 载板 rev. 1.0 或 2.0；12 V 3 A 电源、microSD、串口线和目标屏幕供电是否齐全。
2. 舵机确切型号、额定电压、堵转电流、轴承/转盘、外部停止键与独立供电方案。
3. Windows 主机实际 GPU/显存、Linux 构建机系统、三名成员可投入的真实工时与 RTL/Vivado/PetaLinux 熟练度。
4. 下周到货的 USB 音频与 I2S 麦克风确切型号、接口、电平、时序与返回/替换条件。
5. 是否已有其他代码仓库、板级工程、原始测试日志；若有，先盘点再重新评估工期。

只有这五项与 G1/G2 的原始结果齐备，才能把“技术可行”升级为“本队有把握按某日期交付”。
