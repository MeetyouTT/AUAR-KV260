## 3. 发现一：本批 `length=39` 远低于模型训练范围

`MiniMaxH3ImageToVideo.length` 官方 tooltip 原文（`generator_probe_dump.json` 实测抓取）：

```
Frame count at 24 fps, snapped up to the model's 17k+5 grid
(124 = ~5s; trained range is ~124-362, longer is untested)
```

- 参数约束：`min=5 / max=3600 / step=17 / default=124` ⇒ 合法帧数为 **5, 22, 39, 56, …, 124, …, 362**。
- 本批用 **39 帧（≈1.6 s@24fps）**，即**低于"已训练区间"下限 124 约 3 倍**。
- **待验证假设**：极短长度下模型缺少可用的时间结构，倾向在中段"自行编排"手臂/躯干动作 ⇒ 与接收端观察到的"中段手位上移、躯干变窄、头倾斜"症状一致。**这是假设，不是结论**，须用 §5 的 E1 单变量实验证实或否定。

> **v1 报告的三处命名错误（接收端 2026-10-06 独立审计指出，本机复核确认）**：
> ① 所谓“hand_l/hand_r”取相对高度 0.58–0.78，实测落在 y=892–1188，是**长发与腿**所在带，**并未覆盖手**（手在 y≈650–740）；

> 因此 v1 里“手位带降到 0.67”这一结论**作废**——它描述的是下部外缘，不是手位。

**可以下的结论（更正后，有限、不含“已修好”）：**

1. `length=39 → 124` 在本机 **15.9 GB 显存上跑得通**：124 帧、无 OOM、约 17 min（属**可用性事实**）；
2. **长度加长确实让“下部外缘（长发/腿）”与腰下、腿更稳**（0.56/0.51/0.33），外接框横向中点也略稳（0.80）；
3. **但在真正的手与躯干区域，124 帧并不更好、甚至更差**：手/前臂 ROI 位移 10.26 → 10.57 px（**1.03**，
   与接收端独立复核一致）、含手横带 78 → 112 px（**1.44**）、胸部 46 → 64 px（**1.39**）；
   124 帧的峰值集中在**前 1/3（frame 16–40）**；
4. **对假设的判定**：`length` 不是手位/躯干漂移的解法 ⇒ **E1 只能算“跑通性验证 + 假设未被单独证实”**，
   必须叠加**姿势约束**（E2 `MiniMaxH3AddGuide` 中间帧锚定 / E3 区域掩码）再做单变量小样（已按接收端 §4 执行 E2）；
5. **方法学限制**：`span*` 与 `low_edge*` 只看**轮廓外缘**，双手在身体前方移动时无感；肤色中心只是**外观代理**
   ⇒ 数值一律不得单独作为通过/失败判据，必须配合 `review\` 抽帧与接触表做视觉确认（按 `vision handoff` 留档）。
