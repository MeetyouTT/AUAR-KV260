## 本次实测结果

完整回归 **547 项通过，40.19 秒**。最终独立音频进程版本记录了最近 20,000 次桌面采样，提交间隔 P95 为 **21.99ms**，最长 **60.48ms**，超过 100ms 的次数为 **0**。说话期间记录到 157 次眨眼采样、1,839 次张嘴采样；这些是运行证据，不是自然度评分。记录见 `latest_verification.json` 和 `evidence/live_1791340823191374200.json`，运行源码指纹已逐项与记录核对。

实际设备连续三次暂停／恢复均成功：暂停时音频与视觉时钟保持不变，设备进入 StoppedState，恢复从保存的样本位置进入 ActiveState。语音播放中打断后设备停止、画面回待机；四种动作均先回应再说话，三档表情选择对应素材；12.24 秒说明长句完整结束并回待机。对应记录为 `browser_checks.json`、`action_checks.json`、`emotion_checks.json`。新语音的自动转写中，问候把“汐蓝”识别为同音“西兰”、开心句有“啦／了”差异，应由人耳确认，不能把自动识别当作精确发音验收。

## 启动与当前功能

双击共享目录中的 `aura/tools/run_demo_stage.bat`，或本交付目录的 `run_live_stage.bat`。桌面窗口名称为“汐蓝 · DeepSeek 鲸鱼娘 · 实时交互演示”；浏览器入口是 <http://127.0.0.1:8773/>。声音由桌面窗口在本机播放，浏览器同步展示这个窗口的实时渲染结果并提供控制。它依赖桌面程序运行。

- 可输入 1–240 字台词，并选择平静、开心或安慰表情；四段“快速体验”已预生成，可以无模型播放。
- 点头、摇头、惊讶先完整展示一次，再播放声音；疑惑原素材为循环，展示 0.9 秒后进入说话。
- 口型用音频输出设备处理的样本数推进，依据声音强度平滑开合；语音结束或打断后收口。当前不是具体音素对嘴。
- 独立眨眼贯穿待机、语音等待和说话；动作素材保持原眼部动画，避免套错眼部位置。暂停同时冻结音频、口型和眨眼，继续后保持同步。
- 打断停止音频并作废语音／对话代次；迟到结果不得重新开口。正在运行的非流式语音生成可能继续计算并写入缓存，但被取消的请求不会播放。

音频设备在独立本机子进程中操作，向画面进程报告已处理样本数和设备状态。这样语音启停、暂停／恢复不会占用画面进程的 Python 执行锁。窗口关闭时会一起关闭音频子进程。本机直接恢复音频后端曾出现 IOError，因此暂停保存已处理样本位置并停止设备，恢复时从该样本位置重新播放剩余 PCM；检查实际设备 ActiveState／StoppedState 和稳定的样本时钟，不只依赖按钮文字。

浏览器控制只监听本机 127.0.0.1，不承担另一台电脑的远程播放器角色。其画面传输约 30Hz；桌面按 16ms 计时刷新，实际流畅度以 `latest_verification.json` 和 evidence 内记录为准。

## 在另一台 Windows 电脑运行

保持共享目录的 `aura/` 和 `deliverables/` 相邻。可以使用本次提供的移机 ZIP，它包含播放器、相关素材、参考声线、四段音频缓存与本交接，排除了大型模型和本机虚拟环境。不要单独拷贝实时演示目录。

在解压后的共享目录中，用 Python 3.12 建立播放环境：

```powershell
py -3.12 -m venv .venv-live
.\.venv-live\Scripts\python.exe -m pip install -r aura\requirements-live.txt
```

然后双击 `aura/tools/run_demo_stage.bat`。启动器优先使用共享目录下的 `.venv-live`；也支持环境变量 `AURA_PYTHON` 指向已有 Python。只播放四段已缓存语音不需要显卡、语音模型或 Qwen 环境。先确认系统有可用扬声器。

可先运行 `.\.venv-live\Scripts\python.exe -B aura\tools\realtime_stage.py --check`，检查四段缓存、五套嘴部和六套眨眼姿势。这项检查不开窗口、不加载语音模型。包旁 `.migration.json` 记录本机解压到全新路径的同项检查；它证明目录依赖完整，不代表另一台实体电脑或板端已经实测。

新台词合成需要单独配置语音推理环境。修改本目录 `stage_config.json` 的 `voice.python` 和 `voice.model_path`，可写另一台电脑的绝对路径；相对路径以**共享目录的父目录**为根。本机默认位于父目录的 tmp 下。使用选定 Qwen3-TTS 1.7B Base 模型及 qwen_tts 0.1.1，模型固定版本见参考声线目录 `base_model_verification.json`；本机 CUDA/bfloat16/SDPA 配置与原语音交接一致。

模型和虚拟环境不在 ZIP 中，也不应复制本机虚拟环境作为跨机安装方法。未配合成环境时，缓存播放仍可用，新台词会明确报错；不会悄悄换成系统音色。本机这四段首次非流式生成约 11–27 秒，不能作为低延迟对话体验或板端性能结论。

## 对话主机接入

保留项目已有 WebSocket 合同 1.0。修改 `stage_config.json` 中 `dialogue.enabled` 为 true，再填写 host、port、path 和 timeout_seconds。默认目标是 127.0.0.1:8765/dialogue；host 应填写演示电脑实际可达的对话主机地址。

对话请求字段：protocol_version、request_id、audio_generation_id、transcript、scene_state、allowed_emotions、allowed_avatar_actions。当前 scene_state 为空，因为本演示没有真实视觉输入。

响应必须包含相同 request_id 和协议版本，reply_text 为 1–240 字；emotion 为 neutral/friendly/happy/excited/sad/low；avatar_action 为空或 ack_nod/deny_shake/emo_surprised/emo_puzzled；visual_claims 必须为空。既有 `tools/dialogue_host_ollama.py` 可作为主机适配实现参考，不应把其模拟兜底结果当成真实模型验收。

示例响应：

```json
{"protocol_version":"1.0","request_id":"回传请求中的编号","scene_seq_used":0,"reply_text":"你好呀，我是汐蓝。我们继续吧。","emotion":"friendly","avatar_action":"ack_nod","visual_claims":[]}
```

模型角色提示建议：你是汐蓝，DeepSeek 鲸鱼娘，声音柔亮俏皮，语气自然亲近；日常回复用一至三句中文，避免连续夸张感叹和幼儿化表达。按请求的允许名单选择表情和动作，动作适量使用；没有视觉输入时不要编造看见的人或物。角色提示由对话主机管理，不写入声音参考转写。

接入验收顺序：真实服务返回一句短回复 → 缓存／新生成声音 → 长句与停顿 → 三档表情与动作 → 生成等待期间打断 → 说话期间打断 → 新请求覆盖旧请求 → 服务超时和断线。失败必须可见；旧响应不得覆盖新轮次。

## 文件职责与后续移植

角色身份：`aura/board/runtime/character.py`。声音缓存和验证：`selected_voice.py`、`selected_voice_service.py`。播放编排：`realtime_controller.py`。本机音频设备：`realtime_audio.py`、`realtime_audio_worker.py`。嘴部和眼部：`realtime_facials.py`、`facial_layers.py`。桌面和网页同步：`realtime_stage.py`、`realtime_bridge.py`。可选真实对话：`realtime_dialogue.py`。

现有 FSM、动作白名单和共用 AvatarPlayer 继续复用。PC 为避免切换解码卡顿预加载八个非说话状态；这是桌面策略，不可直接搬到 KV260。板端仍需按实际内存／刷新率预算实现嘴部与眼部小图层、设备样本时钟、暂停和取消代次；语音模型先运行在主机，设备消费音频与时间线。麦克风、VAD、ASR 和正式板端 UI 尚未接入本实时窗口。

已接受的 47.27 秒旧剧本与参考音色保留历史对照，本次没有替换接受记录。新实时版需由用户观看和听音后确认主观自然度。移机包的 package_manifest.json 保存每个文件的大小和 SHA-256，包旁验证报告检查 ZIP 文件指纹与归档条目。
