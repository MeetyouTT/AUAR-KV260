# 音色辨识度提升：A/B/C 加特点候选与固化方案

交付目录：`deliverables/2026-10-07_voice_signature/`　试听入口：<http://127.0.0.1:8774/>（需先运行 `启动试听.cmd` 或 `python serve_preview.py --port 8774`）

## 1. 背景与目标

用户反馈：当前“柔亮俏皮”音色**符合需求**，但听起来**很像通用音色**，希望它有别于通用音色的辨识特点。本轮先产出**同台词四段对照**（1 段当前配方作基线 + 3 段不同“加特点”方向），供人耳盲选；选定方向后再做正式固化。

## 2. 根因（代码级证据，不是猜测）

| 环节 | 事实 | 结论 |
|---|---|---|
| 生产合成 | `aura/board/runtime/audio/selected_voice.py` 调 `generate_voice_clone(text, voice_clone_prompt, max_new_tokens=1200)`，**没有 `instruct` 参数** | 输出风格 100% 继承参考音频 |
| 参考来源 | `voice_design_young/design_generation.json` 的 `instruction` 为「纤细、柔亮、轻盈、音调中高、甜度适中、吐字清楚、停顿舒服」 | 这是**通用优质少女音配方**，无辨识特征 |
| 参考规格 | `reference/soft_young.wav` 仅 **9.52 s**，参考文本内容中性 | ICL 可学的“说话习惯”太少太平 |
| 生产参数 | `torch.manual_seed(8701)`、`x_vector_only_mode=False`、RMS 归一化到 0.1 | 一致性/音量无关，不产生“特点” |

⇒ **要加“特点”，唯一有效杠杆是参考音频**（源头 = VoiceDesign 的 `instruct`）。Base ICL 会连带复制参考里的韵律、气息与语速习惯，这正是“特点”的载体。

## 3. 本轮候选设计（同台词，控制变量）

- 台词（55 字，含语气词、停顿、疑问、长句）：
  `你好呀，我是汐蓝。今天想聊点什么？嗯……让我看看，动画已经更连贯啦，我们一起把说话时的停顿和口型调得更自然吧。`
- 候选（`signature_plan.json`）：

| id | 名称 | 方向要点 | seed |
|---|---|---|---|
| `baseline_generic` | 当前配方（对照） | 原“柔亮俏皮”提示词与种子，量出“通用感”基线 | 7331 |
| `signature_a_genki` | A 元气戏感 | 音区偏高、句尾上扬滑音、语速快而跳脱、抢气、笑音/气声笑 | 8101 |
| `signature_b_texture` | B 独特音质 | 气声比例偏高、中高频鼻音共鸣、尾音轻微颗粒毛边、情绪克制细腻 | 8102 |
| `signature_c_lazy` | C 慵懒冷感 | 音区略低、语速偏慢、句尾下沉收气、漫不经心与疏离感 | 8103 |

每段都保留“年轻少女底色”约束与“避免项”（捏嗓/尖叫/沙哑老化等），目标是**加辨识度而不是换一个人**。

## 4. 生成与试听步骤（在持有 VoiceDesign 模型的那台机执行）

该目录内脚本在本机只做过语法与试听页验证；**生成必须在有 Qwen3-TTS 的机器上跑**（本机 D 盘镜像无 `tmp/Qwen3-TTS-*` 与语音 venv）。

```powershell
cd "E:\项目\共享文件夹\deliverables\2026-10-07_voice_signature"
# ① 生成 4 段同台词候选（VoiceDesign，CUDA/bfloat16/SDPA，本地离线）
tmp\qwen-voice-audition-venv\Scripts\python.exe generate_signature_samples.py `
  --model-path "E:\项目\tmp\Qwen3-TTS-12Hz-1.7B-VoiceDesign" `
  --model-revision 5ecdb67327fd37bb2e042aab12ff7391903235d3
# ② 音量近似对齐 + 生成对照页数据与检查
tmp\qwen-voice-audition-venv\Scripts\python.exe build_comparison.py
# ③ 打开试听页（本机也可用 ComfyUI 便携版 python 只做静态试听）
python serve_preview.py --port 8774
```

产物：`raw/四段未处理 wav`、`audio/音量对齐 wav`、`signature_generation.json`（含 instruction/seed/sha/rtf）、`comparison.json`、`audio_verification.json`（格式/非静音/峰值/削波/哈希 PASS；**辨识度与“是否仍像同一角色”需人耳**）。

**三步听法**：① 遮住名字盲听，选最容易被记住的一段；② 确认它是否仍是同一个年轻少女（无沙哑/漏气/捏嗓/变老）；③ 听长句与停顿是否舒服。

## 5. 选定后的固化流程（正式接入，另开单元）

1. 用选中的 instruction **重做 15–25 秒多语气参考**（陈述/疑问/开心各一句，含自然呼吸与停顿，**不要过度降噪**），替换“9.52 秒两句样”。
2. Base ICL 重新固化：`create_voice_clone_prompt(ref_audio=新参考, ref_text=与录音逐字一致的转写, x_vector_only_mode=False)`。
3. 更新 `selection.json` 的 `reference_audio`／`reference_sha256`／`reference_text`。⚠ `identity()` 含 `reference_sha256` ⇒ **旧缓存全部自动失效**，四场景、`voice_manifest.json` 与 8771/8772/8773 的缓存都要重生成。
4. 回归与验证：`audio_verification` + ASR 复核 + 完整回归（当前 531 项 + 专项）。
5. 旧已接受版（8771，47.27 s）**保留原件对照**，不覆盖；新版本走新入口。

## 6. 风险与回滚

- 加特点过头会变成“另一个人”或听感做作 ⇒ 用基线对照判断；B（音质）与 C（冷感）风险高于 A（戏感）。
- 只改 instruction 不改参考音频文本，韵律特点会偏弱 ⇒ 建议同时把参考台词换成角色味句子。
- 任何一步失败都不影响现状：本轮只新增目录，未改 `selection.json`、未碰 `aura/assets`、未动已接受版。
