# 板端移植交接：2026-10-06 演示基线

本基线包含当前共享项目的源码、正式素材与既有 RGB565、模型、候选／原始素材、工作流、提示词、交接与验证证据。它保存 PC 侧现状，板端移植尚未执行。先阅读同目录的《流畅度复核与保留意见》。

## 一、当前两个播放层的关系

| 层级 | 当前状态 | 接手注意 |
|---|---|---|
| 正式共享播放器及正式 Qt UI | `aura/board/interaction/avatar_player.py`；正式状态及素材池 | 原有连续游标、余弦折返、邻帧插值、原动作收尾 |
| 最新临时剧本 | `aura/tools/demo_script.py` 默认 `--assets reuse` | 三档说话由交付目录 `preview_script.py` 的 `ReusePreviewPlayer` 提供 |
| 板端资源合同 | `aura/ui/avatar_board_manifest.json`，schema 1.2 | 15 态、16 套正式素材、573 张 PNG；不含五套新口型的资源与策略 |
| C 参考 | `aura/board/interaction/lvgl/avatar_playback.h` | 实现正式 1.2 播放算法；没有最新 180ms 局部收口算法 |

不能只运行现有 `board_export.py` 就认为最新演示效果已经导出。该工具读取正式素材池；三档复用仍在临时剧本适配层。也不能只修改全局素材表：新的口型前向循环与原有整身动画需要不同的播放策略。

最新桌面标题为「AURA · 临时剧本（全说话口型）」。浏览器 `127.0.0.1:8767` 是较早的中性素材并排对照，不能代替最新桌面验收。

## 二、五套口型的可重建来源

| 状态 | 运行时素材名 | 活动口型来源 | 数组帧数 / 循环可达帧数 |
|---|---|---|---:|
| SPEAKING_NEUTRAL | talking_calm_reuse_v1 | 已导出候选 A 的 4–30 帧 | 31 / 30 |
| SPEAKING_NEUTRAL | talking_calm_reuse_v1_b | 已导出候选 B 的 2–32 帧 | 35 / 34 |
| SPEAKING | talking_high_reuse_v1 | 正式 talking_normal 的 5–30 帧 | 30 / 29 |
| SPEAKING | talking_high_reuse_v1_b | 正式 talking_normal_b 的 8–30 帧 | 27 / 26 |
| SPEAKING_LOW | talking_low_reuse_v1 | 正式 talking_low 的 5–28 帧 | 28 / 27 |

帧号从 0 开始。两套中性候选各保存原始 39 帧；运行时才裁取活动段并补短开闭过渡。它们使用正式 `idle_normal/000000.png` 锚点。高涨两套共用 `talking_normal/000000.png` 锚点，低落使用 `talking_low/000000.png`；对齐及源图 SHA-256 在 `emotion_profile.json`。高涨／低落由已有 PNG 在 PC 初始化时组合，不存在可直接搬走的五套完整 PNG 目录。

组合、局部柔化及邻帧插值均以 `preview_script.py` 为可执行来源。保持该文件与 `candidates/`、`emotion_profile.json`、正式 `aura/assets/avatar/` 的相对目录关系。中性原始 E2 与浏览器测量资料也随完整共享项目保存，具体路由在 `serve_preview.py`。

播放策略：24fps 前向循环；最后重复锚点不单独占循环相位。停止／池轮换时冻结当前嘴部相位，以 smoothstep 在 180ms 内回到同情绪锚点，随后显示目标状态。池切换由既有 6 秒阈值触发，等待收口完成再从下一套首帧起播。取消、对话代次、业务 FSM 与非说话状态仍使用原有逻辑。

## 三、板端显示与格式：以当前文件为准

当前 `avatar_board_manifest.json` 和 `ui/ui_tokens.json` 一致：

- 屏幕画布 1024×600。
- 玩偶区域 x=593、y=32、w=423、h=516。
- 正式源帧 464×480，contain 缩放并底部对齐；资源表实际落位 423×438。
- 当前面板底色 **#FCFCF3**，RGB565 值 **0xFFFE**。早期技术记录中的 #16202B 是历史值，不应据此重打包当前资源。
- `frames.rgb565` 为 **大端 R5G6B5**、无 alpha、逐帧紧密排列；透明像素按当前面板底色合成。目标 LVGL／显示驱动的字节序与颜色交换设置需实机核对。
- 单帧 464×480×2 = 445,440 字节；两帧 890,880 字节。整屏 1024×600×2 = 1,228,800 字节。它们只是像素载荷，不包含框架、缓存、音频和其它任务开销。
- 16 套正式帧流的唯一资源总载荷为 255,237,120 字节（573 帧）。状态重复引用的合计值不能当成磁盘资源总大小。

新增口型全帧 RGB565：保留 151 张含重复末帧需 67,261,440 字节，去掉五张重复末帧的 146 个可达帧需 65,034,240 字节。若去掉末帧，末尾插值须明确连接索引 0。全部 151 张展开为 RGBA 的纯像素载荷约 128.29MiB；PNG 压缩体积不是运行内存。

## 四、建议的首轮移植工作流

1. 恢复归档并验证逐文件哈希；先在 PC 重放本剧本，确认五套口型、短句、长句、停止、取消、回待机和重播。使用 `--assets original` 对照。
2. 选定实际板端显示路径与存储预算。先将 `ReusePreviewPlayer.sequence()` 的五套结果离线展开为确定的 PNG／帧流，保留锚点、循环周期及源图指纹；运行时不必在板端执行 OpenCV 对齐或加载这些测量依赖。
3. 将“前向局部口型＋180ms 同锚点收口”纳入显式资源／播放配置并更新合同版本，分别保持正式整身播放策略和最新口型策略。正式 Qt 与板端应共享策略口径；不要将 1.2 的速度渐入误写为新嘴部收口。
4. 首版优先全帧 RGB565＋有限帧缓存／预取，核对颜色、落位与插值。收口需要当前嘴部到锚点的插值能力，或预先定义可对照的离线收口方案；直接跳锚点会丢失当前效果。后续再考虑 ROI 补丁节省带宽；ROI 需要新的透明／混合约定，目前无 alpha 合同不能直接支持。
5. 在实际硬件连续记录提交／显示帧间隔、存储读取耗时、缓存命中、内存峰值、丢帧和停止延迟。先检查稳定 24fps 及切换时不阻塞显示，再运行音频／摄像头等并发负载。验收截图、原始时间戳和设备／驱动版本一起保存。
6. 接真实音频，用静音与能量驱动开闭口，再评估音素映射。复用已有眼部动作做独立眨眼。素材生成只补明确缺口，本轮没有新增生成任务。

PC 实测约 20.69fps，11 次切换间隔超过 100ms，最长约 206.52ms；这应成为优化与对照项，不能直接继承为板端达标结论。桌面完整回归为 509 项通过，板端未连接、未验证。

## 五、恢复与启动

解压归档后，保持 `共享文件夹/aura` 与 `共享文件夹/deliverables` 平级。不要只复制 `aura`：当前默认复用模式会从相邻交付目录加载口型适配器。

归档有逐文件 `archive_manifest.json`、排除清单、说明和 `verify_archive.py`。在包含清单的归档根目录运行：

```powershell
python verify_archive.py .
```

机器相关的 `.venv`、Python 缓存和 VerySync 状态不打包。已记录本机实际验证环境（Python 3.12.14／Windows 11）及包版本在本目录 `runtime_environment.json`；轻量桌面演示可按 `requirements-demo-validated.txt` 重建环境：

```powershell
cd 共享文件夹\aura
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ..\deliverables\2026-10-06_avatar_reuse\requirements-demo-validated.txt
.\.venv\Scripts\python.exe -B tools\show_demo_script.py --assets reuse --qt-window
```

也可双击 `aura/tools/run_demo_script.bat`；原版用 `run_demo_script_original.bat`。使用本机 Python／Tk 的选择取决于实际环境；本轮窗口通过 Qt 备用路径运行。

轻量演示依赖清单不覆盖完整 ASR、TTS、音频设备和板端 SDK。正式仓的 `requirements*.txt`、本地模型和所有工程文件均保存，后续按实际目标重新适配，不携带本机绝对路径的虚拟环境。
