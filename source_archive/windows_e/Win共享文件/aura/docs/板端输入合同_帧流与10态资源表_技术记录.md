## 三、关键决策与踩坑

### 3.1 决策 A：帧流从"已入库 PNG"转，而不是重跑抠像

重跑 `--formats png,rgb565` 需要**再抠像一遍**（每状态 ≈55 s × 6 ≈ 5.5 min），而 RGB565 只是
PNG 的**确定性**函数。故新增导出器直接读已入库 PNG，并**复用入库工具的同一函数** `qimage_rgb565`：
- 口径一致靠**单测锁死**（`test_pack_frames_matches_tool_encoding` 逐字节比对 `paf.qimage_rgb565` 输出）；
- 幂等：已有 `frames.rgb565` 默认跳过，`--force` 才重打包；
- 素材更新后只需重跑导出（秒级/状态），无需触碰原始 mp4（始终只读）。

### 3.2 决策 B：把"专属 / 复用 / 兜底"分成三种口径（否则板端表会误导）

第一版把 `ready` 简单定义为"解析到的素材 == 该状态映射的素材"，结果 **`CANCELLED` 被判成"专属素材就绪"**
（因为 `STATE_ASSET["CANCELLED"] = "idle_normal"`，与 `IDLE` 同一个素材名），
计数显示"7/10 有专属素材"，与"**表达性 6 个全齐**"的口径直接冲突。

修正为**数据驱动**的判定（不硬编码状态名）：
```python
_primary_owner(asset)  # all_states() 顺序里第一个把该素材名作为专属素材引用的状态
reuse = _primary_owner(own) != state      # CANCELLED → True（复用 IDLE 的 idle_normal）
```
⇒ 表与预算给出 **专属 6 态 / 复用 CANCELLED / 兜底 CAMERA_LOST,NETWORK_LOST,ERROR**，
与 `--status` 的"6/9 素材名"、与"表达性 6 + 系统·故障 4"的口径**完全对齐**。

### 3.3 决策 C：几何一律**按合同算**，不在代码里写像素

`avatar_box()` 从 `right_panel(x0/x1/y0/y1/padding) + right_inner(label_h, avatar_box)` 推导，
得 **(593, 32, 423, 516)**；`contain_rect()` 与 `qt_widgets._draw_sprite_frame`（`Qt.KeepAspectRatio` + 底部对齐）
同约定。好处：合同改动（`ui_layout_spec.json`）→ 表与头文件自动跟随，单测会先红。

### 3.4 踩坑记录（本环境可复用）

1. **GBK 控制台无法编码 `✔`(U+2714)** → `print_status` 中途抛 `UnicodeEncodeError`（表/头文件其实已写出）。
   修法：输出只用 ASCII 安全标记（`[专属] / [复用] / [兜底]`），并在 `main()` 里
   `sys.stdout.reconfigure(encoding="utf-8", errors="replace")` 兜底。
2. **Python 重定向后 stdout 是块缓冲** → 长任务日志要等进程结束才成块落盘；
   轮询时"文件为空"不等于"没在跑"。
3. **`frames.rgb565` 必须 gitignore**：6 素材 ≈224 MiB，属"可由 PNG 再生"的派生产物（`.gitignore` 已排除）。
4. **C 头文件里"素材"列应是"实际加载目录"**：第一版只写了解析后的名字，测试断言"映射名 `talking_low`"失败 ——
   这提醒板端需要**两个名字**：`asset`（实际加载 = 帧流所在）+ `asset_mapped`（该状态映射名，未就绪时供诊断）。
   现已同时导出。
