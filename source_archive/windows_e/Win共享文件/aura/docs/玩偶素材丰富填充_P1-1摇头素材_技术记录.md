## 一、目标

方案 §3.3 / §4.2 指出：**"有'点头'没有'摇头'"** —— `ack_nod` 有素材、`deny_shake` 只有白名单没有素材，
否定时只能落到 `SPEAKING_*` 或语义不符的 `emo_puzzled`。P1-1 要求补 1 条与 `ack_nod` **同规格**的 burst 素材。

## 四、关键决策与踩坑

1. **P0-4 的"单一来源"红利兑现**：`deny_shake` 早在 P0-4 就写进了
   `avatar_actions.ALLOWED_AVATAR_ACTIONS` 与 `ACTION_TO_STATE`，而 `fsm._route_emotion` 用
   `RuntimeState.__members__.get(name)` **动态判存在** → 本轮**只加状态与素材**，**路由代码一行没改**就生效。
   同理 P0-1 的续播对 `DENY_SHAKE` 自动适用（转换表加一行成员即可）。
2. **提示词与 `ack_nod` 同构**：`ack_nod` 是"点头 12°×2 次"，摇头就写"左右各 15°、各两次"——
   幅度给"可读的量"、并明确"起于静止、终于静止"（burst 素材必须是这个语义，否则切回上一状态会跳）。
   实测 `amp_p90 32.48 / face_p90 69.52` 与 `ack_nod` 同量级，说明幅度承接成功。
3. **素材只在"生成端 + 入库端"两处登记**：生成端 `BURST_GEN`/`SEED_MAP`/`STATES`，入库端 `MAP`；
   漏一处就会出现"生成 39 帧 loop 而不是 22 帧 burst"或"素材名与状态不匹配"。
4. **验收脚本的 `BURST_ASSETS` 也要同步**（`verify_v2_amp.py`），否则 burst 帧数不被检查。
