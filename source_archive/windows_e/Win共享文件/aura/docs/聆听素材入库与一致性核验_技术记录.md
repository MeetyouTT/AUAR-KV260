### 2.3 判读一致性 FAIL：三联图法（本轮最有价值的复用点）

`--ref` 的数字**不能单独用**，必须打开 `*_ref_check.png`（首帧｜参考图｜差异热力×4）判读：

- 本轮三联图显示：**同一角色、同一绿幕 `#00FF00`、同一正面机位**，差异热力是**遍布全身的描边重影**

## 三、关键决策与踩坑

1. **单条素材也按定稿口径跑**（waist-up / 480 / 35 MiB），不"先将就 full 口径"——
   否则 6 条到齐后要全部重跑（每条 57.8 s 抠像 + 抽帧）。
2. **本轮只出 PNG**（与在库 `idle_normal` 一致、仓库精简）；RGB565 是**板端打包步骤**，届时一键再生且**不入库**。
   ⚠️ 注意：`--budget-mb` 把 PNG+RGB565 **合计**计入预算 → 两格式同开时预算要给 **≈70 MiB**，否则误报 `[超预算]` 并建议降帧率。
3. **`--ref` FAIL ≠ 素材不可用**：先用三联图区分"缩放/平移错位"（可消化）与"外观不一致"（需重生成），再决定是否入库。
4. **踩坑 · PowerShell 重定向把中文日志写花**：`python … > log.txt 2>&1` 在 PowerShell 5.1 下产出
   **UTF-16 + GBK 混编**字节流（中文全变 mojibake），排查极痛苦。改用：
   ```powershell
   cmd /c "set PYTHONIOENCODING=utf-8&& python <脚本> > %TEMP%\log.txt 2>&1"
   ```
   → 纯 UTF-8 日志，可直接阅读；控制台直连输出本身正常（只有重定向才坏）。
5. **踩坑 · "completion could not be observed" 不代表失败**：本机 shell 集成不稳定，长命令（抠像 57.8 s）常报此提示。
   **判定成功看产物**：`%TEMP%` 日志出现 `241/241` 与 `[video] idle_listening.mp4 → 完成（adaptive, 57.8 s）`、
   `assets/avatar/idle_listening/` 出现 `meta.json` / `manifest.json`。别急着 `--force` 重跑（会白等一轮抠像）。
6. **下载文件名不可用**：即梦导出名含空格、`@`、`9_16` 且**被截断带省略号**，
   必须重命名为 `<素材名>.mp4` —— 批量模式 `--src <目录>` 完全依赖文件名映射素材名。
