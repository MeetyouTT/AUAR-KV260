**逐帧背景估计**（每帧四角 40×40 块均值）：

逐帧 std：B 29.6 / G 36.4 / R 38.5      G 峰峰 88.8     与全片均值欧氏偏差 max 68.5

**后果**（逐帧自适应背景口径 `%TEMP%\aura_verify2.py`，56 帧）：

| 帧段 | 背景误留（源为背景却被保留 `a>128`） | 人物误抠（源为人物却被抠掉） |
|---|---|---|
| 1–15 | **0** | 16k–24k（=发丝间隙，正常） |

| 44–56 | 0–567 | 20k–100k（帧 53 达 100k） |

**口径说明**：上表 `std / 峰峰 / 欧氏偏差` 来自 `aura_bg_stab.py`（**固定四角 40×40 块**、绝对位置口径）；
`aura_verify2.py` 另给一套**自适应背景**口径（每帧自估背景）——**两套数字不可混用**。

**阈值经验（本轮两次试验给出）**：

| 四角块口径 | 数值 | 抠像后果 |
|---|---|---|
| **安全** | 逐帧 std ≤ ~8、G 峰峰 ≤ ~21、与全片均值偏差 ≤ ~18 | 背景误留 **0 px** |
| **失效** | 逐帧 std 29~38、G 峰峰 88.8、偏差 max 68.5 | 背景误留 **47,438 px**、人物误抠 **244,796 px** |

**性质**：模型把"亮纯绿"重画成**偏暗偏灰的渐变绿**，并且**逐帧抖动**。
关键区分：**全局性的轻微压暗并不致命**（39 帧版均值 G = 219.9 vs 源 247，同样偏暗，
但抠像零误留）；**致命的是逐帧抖动** —— 自适应背景估计一旦抓不住背景色，判据就整体翻转。
后者是**信息不可恢复**的（像素已判为背景），任何后处理都救不回来 → 本版 **56 帧素材不可用**。

## 六、根因（与历史教训同源，只是换了维度）

1. **fl2va 的"必须产生变化"压力**：首末帧硬锚定只保证两端，**中间帧是自由的**；
   prompt 越"抽象"（或场景越不自然），模型越会挑一个**最省力的维度**去摆动。
   上一轮是**摆色调**（LISTENING 84.0/25 帧），这一轮是**重画背景绿**。
2. **绿幕本身"不自然"**：亮纯绿在真实/动画场景里几乎不存在，模型倾向把它"合理化"
   （加阴影/渐变/压暗），而 `white` 背景则不会触发这种重画。
3. **`adaptive` 抠像依赖"背景可估计"**：背景一旦逐帧漂移且带渐变，阈值法/色度键都会在
   那几帧失效 —— 这与"抠像算法不好"无关，是**输入前提被破坏**。

## 九、对照实验：LEN=39 基础版 vs 39 帧强化背景词版

目的：判定漂移是**长度累积**导致，还是 **prompt 不够硬**导致。

- `DOLLG39B`：`--len 39`（1.625 s）+ 基础背景词；
- `DOLLG39S`：`--len 39` + **强化背景词**（`--strong`：背景是"绝对均匀的纯绿矩形"、
  无阴影/渐变/暗角/纹理、比人物更平、"绝不重画背景"）；
- 两版同首帧、同 seed、同提示词主体；跑完后逐版做入库 + `verify2` + `bg_stab`。

（下表由 `%TEMP%\aura_chain39.log`、两版 `verify2.txt` / `bg_stab.txt` 汇总。）

| 指标（39 帧，864×1536） | **DOLLG39B**（基础背景词） | **DOLLG39S**（`--strong` 强化词） | 对照：56 帧版 |
|---|---|---|---|
| 生成耗时 | 131 s | 135 s | 205 s |
| 四角块逐帧 std（B/G/R） | 7.75 / 7.07 / 0.84 | 7.58 / 7.06 / 0.88 | **29.6 / 36.4 / 38.5** |
| G 峰峰 | 20.7 | 21.4 | **88.8** |
| 与全片均值欧氏偏差 max | 17.41 | 18.09 | **68.5** |
| **背景误留** max / 均值 | **0 / 0** | **0 / 0** | 47,438 / — |
| 人物误抠 max / 均值 | 16,182 / 14,815 | 16,276 / 14,853 | **244,796 / —** |
| 不透明 px 峰峰 | 3,667 | 4,234 | （画幅级漂移） |
| `d≥3` / `q60` 合计 | 0 / 0 | 0 / 0 | 0 / 0 |
| 自适应口径背景 std / G 峰峰 | 0.24/0.35/0.18 / 1.6 | 0.25/0.34/0.19 / 1.5 | — |
| 入库体积（464×480 @24fps） | 12.18 MiB | 12.19 MiB | 20.54 MiB（56 帧） |
| 抠像耗时（39 帧） | 5.0 s | 4.9 s | 7.9 s（56 帧） |

**结论（本轮两次独立生成，证据一致）**：

1. **背景词不是主因**：`--strong` 与基础词**全指标差异 <1%**（背景误留同为 0、
   逐帧 std 7.58 vs 7.75、偏差 18.09 vs 17.41）→ 加强措辞**无额外收益**。
2. **长度是关键变量**：39 帧**两版都完全稳定**（背景误留 0、人物误抠 ~1.5 万 = 发丝间隙正常量），
   而 56 帧版在帧 16~43 崩坏 → 崩坏是**更长片段触发的整体失控**，不是"帧号超过某值"（39 帧版含帧 16~39 仍稳）。
3. 因此本轮**不采用 `--strong`**；**单态长度按 39 帧（1.625 s）定**，长态用"多段拼接"
   （每段首末帧都锚定同一首帧 → 段间天然无缝，见 §十）。
4. 体积：39 帧 @24fps = 12.18 MiB 仍超 10 MiB 预算 → 直接让脚本自动降档：
   `--fit-budget` 给出 **16 fps / 26 帧 ≈ 8.28 MiB**（摄取日志原话）。

## 十、结论与定型口径（本轮产出）

1. **（已定）绿幕路线保留**：39 帧长度下绿幕**可用**（§九），无需回退白底；
   背景固定用**基础背景词**（`--strong` 无收益）。
2. **（已定）单态长度口径**：i2v 一次生成 **39 帧 / 1.625 s**；
   需要更长的状态用**多段拼接**——每段 `first=last=同一首帧`，段末回到基准姿势，段间可直接串接（必要时叠 2~3 帧交叉）。
3. **（已定）体积**：批产时一律加 `--fit-budget`，让它按预算自动选帧率
   （39 帧 464×480 档 → **16 fps / 26 帧 ≈ 8.28 MiB**，落在 10 MiB 内）。
   若要求 24 fps 全帧率，则需走 397×410 档或把预算提到 12 MiB（见上表）。
4. **（待办）边界确认（可选）**：若某状态确需 >39 帧，先做 **45 / 51 帧**各一次的边界扫描，
   用 `aura_bg_stab.py` + `verify2` 判是否仍 ≤ 安全阈值（逐帧 std ~8 / G 峰峰 ~21 / 偏差 ~18）。
5. 无论走哪条，本轮的链路修复（Pillow 回退 / `--matte-src` / 默认路径）都要保留。
6. `aura_verify2.py` 的汇总行文案硬编码为「（56 帧）」，实为当前帧数 → 下次顺手改为动态文案（不影响数值）。
3. 体积决策：24 fps/56 帧 = 20.54 MiB 与 10 MiB 预算冲突 → 需在
   「尺寸档 480/410」「帧率 24/12」「预算 10/12 MiB」三者间定口径（分析文档 §8、handover §3）。
   实测口径换算（按本轮实测 **≈1.86 B/px**；代码里 `PNG_BYTES_PER_PIXEL = 1.5` **偏乐观约 24%**）：

   | 464×480 @24fps / 56 帧（本轮实测） | ≈376 KB | **20.54 MiB** | ≈185 MiB |
   | 464×480 @12fps / 28 帧 | ≈376 KB | ≈10.3 MiB | ≈92 MiB |
   | 397×410 @24fps / 56 帧 | ≈287 KB | ≈15.7 MiB | ≈141 MiB |
   | 397×410 @12fps / 28 帧 | ≈287 KB | ≈7.9 MiB | ≈71 MiB |

## 十一、帧间「白点闪」的定位与结论（决策：不去闪，维持 V1 羽化口径）

**现象**：39 帧试产序列回放时，深蓝裙子腰部有白点闪动（V1 羽化 / V2 / V3 三档边缘口径**都有**，
说明与边缘口径无关）。

**诊断脚本（均可复现）**：`%TEMP%\aura_flicker.py`（源/抠后/入库三层对照）、
`%TEMP%\aura_flick2.py`（去绿 A/B）、`%TEMP%\aura_hotspot.py`（8×8 网格热区定位）。
指标定义：帧 t 与 t-1 在「人物区域内（`g - max(r,b) < 30`）且 `alpha>=200` 且近白
（`min(R,G,B)>=238`）」像素上的翻转数，单位 px/帧。

| 组 | 白点闪 均值 |
|---|---|
| 源绿幕帧（生成侧，裁到 464×480 对齐） | **2,144 px/帧** |
| 入库帧（含 A 硬限绿 + D1 去青） | 3,117 px/帧 |
| 入库帧（`--post-despill off`，同源同帧） | 3,119 px/帧 |
| 纯抠像输出（864×1536，按像素量归一） | ≈2,160 px/帧 |

1. **去绿不是主因**：3117.5 vs 3118.9，**差 0.04%**（A/D1 与本问题无关）。
2. **链路只额外贡献缩放的 ~950 px/帧**：纯抠像输出 ≈ 源帧（2,160 vs 2,144）
   → **闪烁主体来自生成侧**（i2v 逐帧抖动）。
3. **热区定位**：39 帧累加后最密集格 `x 174..231 / y 300..359`（占 8.2%），Top5 格全在腰线一带
   → 即**深蓝裙腰的金色星饰与腰线高光**（生成时最不稳的细节），与肉眼观感一致。
4. 另测到：**背景有 327,105 px（39 帧合计）未抠净的残留**，可用「源绿幕硬掩码」清零（本轮未采用）。

**去闪实验（四档，同一批源帧，只改生成帧、不动抠像参数）**
