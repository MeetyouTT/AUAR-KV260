# 玩偶眼部阴影根因排查 · 技术记录

> 日期：2026-09-12　环境标签：**PC 侧排查**（未改板端 / 未改素材）
> 触发：用户在演示视频/素材截图里发现「**眼睛下方有块阴影**」，怀疑抠像或渲染引入缺陷。
> 结论先行：**该暗带来自原始 Seedance 绿幕视频的美术本体**（画上去的眼妆/眼睑·眼窝阴影，下边界偏硬），
> **抠像、取景裁切、缩放、GIF 量化、MP4 编码都没有引入它**；代码无需修改。

---

## 一、问题与目标

- 现象：玩偶脸部在「眼睑下方偏外侧」有一道**横向的暗色带**，边界较平、像一块色块，
  在缩小的演示画面里更明显。
- 目标：判定该暗带产生于哪一环 —— ① 原始美术 / ② 抠像（alpha 残留或去绿溢）/
  ③ 取景裁切与缩放 / ④ 交付格式（GIF 调色板、MP4 有损）/ ⑤ 渲染合成（暗背景透出）。

## 二、排查方法（6 组探针，全部可复跑）

所有探针均为**只读**，临时脚本位于 `evidence_shots/_*.py`（可删）。

### 2.1 抠像 alpha 探针 —— 排除「脸上留洞」

- `_band_probe.py`：`idle_normal/000050.png`（闭眼+腮红帧）眼区 `(130,170)-(340,310)`：
  `alpha min=0`、非 255 像素 1160（3.9%），但**逐行 alpha 剖面**显示缺口集中在发丝与背景轮廓方向。
- `_alpha_holes.py`：全帧低 alpha（<250）**连通域**排序（这才是判定"成块残留"的正确方法）：

| 连通域 | 面积(px) | bbox | alpha 均值 | 判读 |
|---|---|---|---|---|
| #1 | 100,252 | 全画幅 | 4.7 | 背景（含软边轮廓），非人脸 |
| #2 | 5,126 | (341,245)-(463,403) | 42.0 | 右侧发尾 |
| #3 | 1,632 | (405,396)-(465,479) | 52.8 | 右下衣摆 |
| #4 | 1,577 | (22,396)-(74,479) | 47.6 | 左下衣摆 |
| #5 | 1,043 | (0,380)-(49,479) | 60.2 | 左侧衣摆 |
| #6 | **11** | (141,193)-(143,197) | 227.0 | 左侧刘海小点 |
| #7 | **6** | (146,185)-(147,187) | 223.3 | 左侧刘海小点 |

**判读**：脸部皮肤区域 alpha **全为 255**；脸部内部仅 2 个 11/6 像素、alpha≈225 的小点（肉眼不可见）。
⇒ 抠像蒙版**没有在人脸上留下半透明块**。

### 2.2 白底 / 暗底合成对照 —— 排除「暗背景透出」

- `_band_probe.py` 输出 `_band_idle_normal_f000050_compare.png`：
  同一帧同一区分别合成到白底 `#FFFFFF` 与板端底色 `#16202B`，**观感一致**。
⇒ 若是半透明残留，暗底会明显发黑；实测不发黑 ⇒ 与背景透出无关。

### 2.3 全素材逐帧扫描 —— 排除「AI 糊帧 / 硬边色块帧」

- `_band_scan.py`：对 100 帧计算「行内最长连续暗像素（luma<130）」，若存在横跨脸的硬边暗带，该值会 >60。
- 实测：**全部 100 帧稳定在 40~43 px，所在行 y≈231~237** —— 那是**左侧头发宽度**（检测窗左边界 140 起）。
⇒ 素材里不存在异常色块帧，也没有 AI 视频常见的糊帧。

### 2.4 眨眼过程连续帧量化 —— 证明阴影「跟随眼形」

- `_blink_strip.py`（帧 38~72，步长 2，带区相对框 `0.32~0.72 × 0.38~0.52`）：

| 指标 | 实测范围 | 判读 |
|---|---|---|
| 带区暗像素占比 | 27.1% → 33.7%（连续） | 无跳变 |
| 最暗行 y | 189 → 210 → 189 | 随眼睑闭合下移 |
| 全脸均亮度 | 166.3 ~ 168.3 | 稳定 |

⇒ 阴影是**被眼睑带动的连续美术阴影**，不是抽帧/编码造成的静态色块。

### 2.5 原始绿幕帧对照（决定性证据）

- 对照组：`evidence_shots/_c_preview/idle_normal_t00.00_f000000.png`
  = **未抠像的原始视频首帧**：`720×1280`、`mode=RGB`、**alpha extrema=(255,255)**（无 alpha ⇒ 未抠像）。
- 坐标换算（waist-up = 先裁下部 42% 再长边 480）：`x_asset = x_raw × 0.6472`、`y_asset = y_raw × 0.6466`。
- `_align_check.py`：最佳对齐 **dx=0 / dy=-1**（换算准确，非错位造成的假差异），对齐后：

| 指标 | 入库抠像帧 | 原始绿幕帧 | 判读 |
|---|---|---|---|
| 剖面最暗行 | y=197（luma 152.9） | y=198（luma 134.6） | **位置一致** |
| 凹陷深度（相对邻近亮行） | ≈25 | ≈26 | **深度一致** |
| 同区平均亮度差 | +5 ~ +29（自上而下递减） | — | 整体亮度微调 |

- 并排图 `_raw_vs_asset.png`（左＝入库帧、右＝原始绿幕帧）**肉眼可见同一条眼周暗带**。

**两个结论**：
1. 阴影**在未抠像的原始视频里就存在**，位置与对比度都一致 ⇒ 来自美术本体；
2. 入库帧整体比原始帧亮 +5~+29（呈**自上而下递减的梯度**），与抠像工具的**去绿溢 / 色彩去污**一致
   （越靠上、靠外受绿幕环境光污染越重，回填越多）——这只是整体亮度微调，**不改变阴影结构**。

### 2.6 交付链同帧对照 —— 排除 GIF / MP4 引入

- `_deliver_compare.py --t 4.96`（IDLE 闭眼时刻）：
  - 模板匹配：素材 `f048` 在渲染帧 `1024×600` 中的位置 **(593,112,423,436)**、相关系数 **0.9679**
    —— 与 `ui_spec` 的 `dst_rel={x:0,y:80,w:423,h:436}` 合同一致；
  - 反查渲染帧实际使用的素材帧：`f047` / `f049`（平均像素差 ≈4.9~5.5 / 255）；
  - 四联图（素材原图 / demo 渲染 PNG / GIF 512×300 / MP4 512×300 fps=24）：
    **同一条阴影都在**，GIF / MP4 只是更小更糊，**没有新增硬边块**。

## 三、结论：为什么它看起来像"一块"

1. 原始美术里这条阴影**横向贯通到两侧脸颊**、**下边界较平且是硬边**（AI 生成图的常见特征），
   不符合常见二次元「柔和渐变」的观感；
2. 素材 `466×480` 里它只有约 **20~30 px 高**，与睫毛线相连；
3. 演示链路再经 **0.9077 缩放**（板端 contain）+ **GIF/MP4 半分辨率 512×300** + 256 色量化，
   阴影与睫毛线糊成一片，于是更像"方方正正的一块"。

⇒ **属素材美术特征，不是流水线缺陷**（抠像/取景/缩放/编码/合成五环均已排除）。

## 四、技术决策（本轮**不改任何代码 / 素材**）

1. **不动抠像参数**：alpha 探针与连通域分析证明人脸区域蒙版干净，调 `--matting` 参数无从改善；
2. **不动取景口径**：C 方案已定稿 `waist-up 466×480`，与阴影无关（见 `IDLE素材取景口径统一_技术记录.md`）；
3. **不做局部提亮后处理**：该阴影在 RGB 上与眼睑/睫毛相连，局部提亮会把睫毛线一起冲淡，
   且 6 态需保持一致（只修 IDLE 会破坏一致性）；
4. **若必须消除**：唯一根治手段是**重新生成 `idle_normal.mp4`**，在提示词中明确
   「闭眼/半闭眼时**不要画眼影或眼下阴影**；上眼睑阴影须为柔和渐变，不要硬边横带」；
   提示词基线见 `docs/玩偶素材Seedance提示词包_技术记录.md`。
5. **可顺手合并的遗留**：`idle_normal.mp4` 循环缝 FAIL（主体 mean 19.90 / 差异 47.3%，见
   `assets/avatar/README.md` §五）与本品同源，**同一批重新生成可一并解决**。

cd "D:\share\项目开发\FPGA语音助手开发\wujing-lite"

结果：
- 上述命令全部**只读**素材与产物，**未修改任何代码或素材**；
  因此**无需重跑 `pytest`**（无代码改动，回归基线仍是 217 passed / 0 failed）；
- 关键判据均通过：脸部 alpha 无洞 ✔ / 白底暗底观感一致 ✔ / 无硬边暗带帧 ✔ /
  阴影跟随眼形 ✔ / **原始绿幕帧同一位置同样深度** ✔ / GIF·MP4 未新增色块 ✔。

### 环境踩坑（可复用）

- 本机 shell 回显不稳定：长/中文输出用
  `Start-Process python -RedirectStandardOutput ... -NoNewWindow -Wait` 落到文件，再读文件；
- **Python 输出中文时的 GBK 限制**：`print` 遇到 `↔`、`→` 等字符会 `UnicodeEncodeError`，
  探针日志里的特殊符号请改成 ASCII（本次把 `↔` 改为 `<->`）；
- 证据 PNG 过大时先用 `_mkjpg.py` 降采样转 JPEG 再人工查看。
