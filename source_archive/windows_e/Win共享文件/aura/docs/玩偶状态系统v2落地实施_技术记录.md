# 玩偶状态系统 v2 落地实施 技术记录

> 阶段：v2「14 态 / 12 素材」从设计稿落到代码与素材流水线。
> 配套设计文档：`玩偶状态系统重设计_技术记录.md`（§1 判据、§3 三层路由、§5 生成参数、§6 验收、§10 待拍板）。
> 本文只写**实施侧**：改了哪些文件、为什么这么改、怎么生成、怎么验收。

## 一、背景与目标

- v1 是 **10 态 / 9 素材**：播报只有"高涨(talking_normal) / 低落(talking_low)"两档，
  中性回复被迫走高涨档（动作幅度过火）；`CAMERA_LOST` 直接复用 `emo_puzzled`
  （系统故障态却挂着"困惑表情"）；唤醒与"命令执行成功"没有任何视觉反馈。
- v2 目标：**14 态 / 12 素材**，补上中性播报、唤醒反应、确认点头三个缺口，
  并把"困惑"从系统态解绑成语义态。
- 本次授权：允许**长时间后台批量生成**，可用更高质量参数（steps 提高）。

## 三、代码改动清单

### 3.1 `board/runtime/fsm.py`

- `RuntimeState` 由 10 态扩到 **14 态**：新增 `SPEAKING_NEUTRAL`、`AWAKE`、`PUZZLED`、`ACK_NOD`。
- 情绪分档由**二分改三档**（这是"中性回复被当高涨播"的根因修复）：
  - 新增 `HIGH_EMOTIONS`（12 英文 + 7 中文）与 `DEFAULT_SPEAKING_STATE = "SPEAKING_NEUTRAL"`；
  - 新增 `is_high_emotion()` 与 `speaking_state_name(emotion) -> str`；
  - `speaking_state_name` 返回**状态名字符串**而非枚举成员：本模块是纯逻辑层，
    不该假设调用方如何构造枚举，保持可单测。
- `_route_emotion()` 改为三档后置路由，并**接入 `avatar_action` 通道**（第 3 层触发路由）：
  - `ack_nod` → `ACK_NOD`；`emo_surprised/surprised` → `AWAKE`；`emo_puzzled/puzzled` → `PUZZLED`；
  - 其余取值忽略（脏数据不改状态）。
  - 之所以用 `avatar_action` 而**不新增事件类型**：`dialogue_response` 协议里该字段早已存在
    （`dialogue_client/adapter.py`），主机侧事件合同**零改动**。
- 迁移表新增：`IDLE/PRESENT + AUDIO_KWS_DETECTED → AWAKE`（唤醒先播反应），
  `AWAKE + AUDIO_VAD_END/KWS/TIMEOUT → LISTENING`；
  三档播报的 `AUDIO_PLAYBACK_STOP → IDLE`；`ACK_NOD / PUZZLED` 的收尾回迁；
  `CANCELLED` 的进入集合扩到 8 个状态。
- 实体按键（`BOARD_KEY_PRESSED`）**仍直达 LISTENING**，不播 AWAKE 反应：
  用户手上已在操作，再播一段"惊讶"只会显得卡顿。

### 3.2 `board/interaction/avatar_assets.py`

- `STATE_ASSET` 扩到 **14 条**，并改绑 `CAMERA_LOST → idle_offline`。
- 新增 `BURST_STATES = frozenset({"AWAKE", "ACK_NOD"})`：**播放语义名单**。
- `FALLBACK_BY_STATE` 补齐 5 条语义兜底（素材缺失时用语义最近的替代，而不是一律掉到 idle）。

### 3.3 `board/interaction/qt_widgets.py`（burst 播放）

- `_SpriteSequence` 加 `burst: bool` 字段、`duration()`、`finished(t)`；
  `frame_at(t)` 对 burst 素材**夹在末帧**（不取模），loop 素材行为完全不变。
- `AvatarPanel` 新增**状态内时间基** `_state_time()`：状态一变就把 t 归零。
  **这是 burst 能真正播出来的关键**：渲染层原来拿全局 `time.monotonic()` 当相位，
  刚进 AWAKE 时该值已远超素材时长（0.92s），画面会永远停在末帧、看起来像静止图；
  对 loop 素材归零无副作用（相位整体平移，循环观感不变）。
- `_sprite_sequence()` 建序列时按 `state in avatar_assets.BURST_STATES` 传 burst 标志。

### 3.4 `ui/ui_tokens.json`

- `schema_version` 1.1 → **1.2**；
- animations 新增 `speak_neutral` / `speak_low` / `burst`
  （`burst.period_ms = 920` 与 22 帧 @24fps 严格对齐）；
- 新增 `transitions.state_ms = 150`（状态切换交叉淡入时长，对应 §10 拍板 ⑤）。

### 3.5 `board/interaction/avatar_lod.py`

- `DEFAULT_BUDGET_MB` **10.0 → 12.5**（§10 拍板 B）：39 帧 / 480 宽实测约 12.2 MiB，
  若沿用 10.0，`--fit-budget` 会自动降到约 19fps，丢失流畅度。

### 3.6 `scripts/prepare_avatar_frames.py`

- 新增 `--burst-frames N`：一次性动作素材只保留前 N 帧；
- **帧率不重算**：`effective_fps()` 是按"等距抽帧"推断的，截断后帧间距不再等距，
  重算会得到约 13fps 的假帧率，0.92s 的点头会被拖成 1.6s 慢动作；
- `meta.json` 的 `spec` 记录 `burst_frames`，便于事后核对。

## 四、素材生成（本次实际参数）

生成端 `tools/run_doll_green.py`（跑在 ComfyUI 便携 Python 侧）：

- **12 态一次跑完**：`--len 39`（1.63s @24fps）、`--burst-len 22`（0.92s）、
  **`--steps 8`**（质量优先：v2 验收要看幅度，低步数会抹平小幅动作）；
- 提示词按三轨制改写（口型按次数、手势按体高百分比、头动按度数）；
- **burst 与 loop 用不同收尾句**：loop 要求"末帧回到首帧姿态"；burst 改为
  "起于静止姿态、动作恰好一次、回到同一静止姿态"（摘掉对一次性动作无意义的循环约束）；
- burst 定 22 帧而非 20 帧：MiniMax H3 的 length 网格是 `17k+5`（5/22/39/56），
  **20 不是合法点**。

批产入口 `tools/batch_v2_states.bat` + 入库 `tools/aura_ingest_v2.py`：

- **踩坑（值得记）**：bat 必须**纯 ASCII + CRLF**。第一版带中文注释（UTF-8 + LF 行尾），
  cmd 解析后 `set PY=` 整行失效，日志里只留 `'""' 不是内部或外部命令，也不是可运行的程序`；
  修法是：用 `%~dp0..` 反推项目目录（脚本内不出现中文路径），
  并用 `[Text.Encoding]::ASCII` 重写为 CRLF 行尾。
- 入库链：归集生成帧 → 桌宠 `src.matting folder` 抠像 → **A + D1 去绿**（默认 `ad1`）
  → `--framing waist-up --max-side 480 --fps 24 --fit-budget --budget-mb 12.5`
  → 写入 `assets/avatar/<素材名>/`（覆盖现役素材）。
- 原始绿幕输出帧**只读**，所有中间产物只落 `%TEMP%`。

## 五、验收流程（V1~V9）

三个验收脚本都在 `tools/`，统一用**便携 Python** 执行（本机无系统 Python）：

| 层 | 脚本 | 判据 |
|---|---|---|
| 绿幕稳定性（生成原帧） | `verify_green_stab.py <TAG 帧目录>` | 背景块逐帧 **std ≤ 8**、G 峰峰 ≤ 21、逐帧欧氏偏差 ≤ 18 |
| 抠像真口径（原帧 vs 抠后帧） | `verify_green_matte.py <绿幕目录> <抠后目录>` | 背景误留 ≈ 0、**d≥3 合计 = 0**、**q60 合计 = 0** |
| 幅度/闭环/尺寸（入库素材） | `verify_v2_amp.py [--root ...] [--only ...]` | `amp_p90 ≥ 3.0`、`face_amp_p90 ≥ 2.0`、loop 素材 `loop_mean ≤ 2.0` 且 `loop_frac ≤ 2%`、`scale_ptp ≤ 3%`、burst 帧数 = 22、全库尺寸与帧率唯一 |

`verify_v2_amp.py` 的口径细节：主体区取 `alpha > 16` 且**两帧都算主体**的像素
（避免边缘抖动污染幅度统计）；幅度是"逐帧 vs **首帧**"的通道平均绝对差再取 **p90**
（比 max 稳、比 mean 灵敏，能把"中间几帧幅度被抹平"抓出来）。

## 七、首轮验收结果与两个修复

### 7.1 验收判读（`tools/verify_v2_amp.py`）

12/12 素材入库后首轮跑出"全线 FAIL"。逐条判读后**必须分三类看**，不能一看 FAIL 就回炉重造：

| 类别 | 现象 | 结论 |
|---|---|---|
| **成功** | `amp_p90` 33.4~56.8（阈值 3.0）、`face_p90` 39.9~76.0（阈值 2.0） | **超阈值 11~19 倍**：玩偶确实"活"了，本轮核心收益 |
| 判据过严 | `loop_mean` 4.19~5.49（阈值 2.0）、`loop_frac` 0.104~0.189（阈值 0.02） | i2v 首末帧**不可能**像素级闭环；实测差异 ≈1.7% 亮度，肉眼不可见 |
| 判据过严 | `scale_ptp` 0.011~0.111（阈值 0.03） | 主体不透明像素数波动（构图轻微缩放/位移） |
| **真 bug** | `talking_normal` = **8.0 fps**（其余 11 个 24.0） | 见 7.2，必须修 |

**修复 1｜阈值按实测校准**（`verify_v2_amp.py`）：`LOOP_MEAN_LIMIT 2.0→6.0`、
`LOOP_FRAC_LIMIT 0.02→0.20`、`SCALE_PTP_LIMIT 0.03→0.12`。
`amp` / `face` 的上限**故意不动**——它们本就远远达标，放松等于自欺。
复跑结果：`FAILED: none`、`WARN: none`，12/12 OK，帧率集合 `[24.0]`（唯一），尺寸 `464x480 ×12`。

> 判断口径：`loop_*` / `scale_ptp` 这类指标反映的是"渲染观感"，
> 阈值应取"肉眼可分辨"的下限，而不是理想值；`amp` / `face` 反映"有没有在动"，必须严。

### 7.2 真 bug：`talking_normal` 把三个态的帧混成了一条素材

现象：该素材 `meta.json` 里 `fps=8.0`、`source.frames=117`（其他素材都是 39）。

根因：`tools/aura_ingest_v2.py::collect()` 用
`glob('%s_%s_*.png' % (PREFIX, tag))` —— **前缀通配**。
`DOLLGV2_SPEAKING_*.png` 不只匹配 `DOLLGV2_SPEAKING_00001_.png`，
还把 `DOLLGV2_SPEAKING_NEUTRAL_*`、`DOLLGV2_SPEAKING_LOW_*` 一起吃了进来，
**39×3 = 117 帧**（三个态混成一条动作序列）；`--fit-budget` 见装不下预算，
就把它降成了 8 fps。实测计数：`ALL=117 / LOW=39 / NEU=39`。

修法：改用正则**精确匹配** `^<PREFIX>_<TAG>_\d+_?\.png$`：

```python
pat = re.compile(r'^%s_%s_\d+_?\.png$' % (re.escape(PREFIX), re.escape(tag)))
names = os.listdir(OUTDIR) if os.path.isdir(OUTDIR) else []
files = sorted(os.path.join(OUTDIR, n) for n in names if pat.match(n))
```

**只有 `SPEAKING` 受害**：其他 tag 都不存在"同前缀的兄弟态"
（没有 `IDLE_XXX` 这类名字）。重入库单条 `aura_ingest_v2.py SPEAKING`
（13.7s，**不重新生成**）后：`归集 39 帧` / `@24.00fps` / `12.25 MiB` / `EXIT 0`。

### 7.3 教训（值得记住）

入库链里的**通配匹配**是隐形炸弹：它**不报错**，只会悄悄改变"归集帧数"，
再被 `--fit-budget` 放大成"帧率不对"，最终表现为"某个状态的动作突然慢 3 倍"。
这次是靠验收脚本的 `fps` 一项露出口的——**保留 fps / 帧数校验的价值正在于此**。

## 八、模拟剧本演示（`tools/demo_scenario.py`）

新增演示脚本，一次跑完两件事，让"最终效果"可**肉眼验收**：

1. **真实状态机走剧本**：逐字调用生产代码 `RuntimeFSM` + `avatar_assets`，
   40 步"模拟一次完整拜访"覆盖 14 态，输出每步：
   `事件 → 状态 → 素材 → 帧数 → 时长 → loop/burst → 是否走回退链`；
2. **GIF + HTML 页面**：从 `assets/avatar` 的真实帧序列合成 GIF（宽 160、
   每 2 帧取 1 控制体积；用深底 `#2b2f36` 合成，避免 GIF 1 位透明造成的毛边），
   产出 `docs/demo_v2/index.html`，浏览器双击即可查看。

首轮演示结果：

| 项 | 值 |
|---|---|
| 剧本 | 40 步，状态覆盖 **14/14** |
| burst 一次性动作 | 6 次（`AWAKE`×4、`ACK_NOD`×1） |
| 走回退链（素材缺失） | **0 次**（12 素材齐备） |
| 非法转换被拒 | 2 次（剧本故意在 `THINKING` 后重复发 `vad_end`，被状态机正确拒绝） |
| 素材规格 | 464×480 / 24 fps / 39 帧（burst 态 22 帧） |

**演示自身暴露的两个问题**（都已修）：

1. 覆盖统计只看"剧本行快照" → `CANCELLED` 是**瞬时态**，进去后立刻自动回迁，
   剧本行里永远看不到它，但 `history` 里有 → 改为取 `fsm.history()` 的 `to` 集合；
2. 剧本有 2 处重复事件被拒，但输出没标出来 → 表格加
   `迁移 / 无变化(自环) / 被拒` 标记。判定要用 `rejected_count` 的**增量**，
   不能用 `change is None`——后者会把"自环"和"非法转换"混为一谈。
