## 一、背景与约束

- 玩偶现状：`board/ui/qt_widgets.py` 的 `AvatarPanel` 为 **B2V 矢量方案**（QPainterPath 主体 + 程序化表情），渲染接入点 `_render_avatar`。
- 板端目标是 **LVGL**，合同明确"不把 Web 前端 / Live2D 装进板端" → 桌面 AI 桌宠的实时 GPU 抠像（Qt ShaderEffect / WebGL）**不可移植**。
- 故采用：**PC 端预抠像成透明帧序列**（复用桌宠 `matting`），PC 原型与板端共用同一帧序列/贴图形态。

## 三、素材规范

```

```

### 5.3 ⚠️ 素材体积实测（重要：决定入库策略）

| 项 | 实测 |
|---|---|
| 单帧体积 | **≈1.23 MB/帧**（720×1280 RGBA PNG） |
| 单状态（10s@24fps = 241 帧） | **≈290 MB** |
| 9 态全量 | **≈2.5 GB** |
| 板端 RGB565（720×1280×2B/帧） | 241 帧 ≈ **590 MB** raw，直接存不可行 |

**结论**：帧序列 PNG **不可整体入库**（与 `assets/avatar/README.md` 第四节预留说明一致，需团队决策）：

1. 素材放**外部存储/网盘 + 校验清单（sha256）**，仓库只留 `meta.json` 与清单；
2. 或**降分辨率**（面板显示区仅 ≈550×420，720×1280 属过采样）后再入库；
3. 或改 **MJPEG / 专有帧流**（板端可直接解码，见桌宠 `--export mjpeg`）。

> 本次演示因此走 `--frames-root` 指向 `%TEMP%`：既验证了链路，又没往版本库塞 40 MB。

### 5.4 入库规格（降清晰度 + 降帧率）——决策与实现

**决策**：**原始素材保持原样不变**；**纳入本项目的素材统一降采样**（降分辨率 + 降帧率），

### 5.5 本轮踩坑
1. **中文 Windows 重定向输出崩溃**：`⚠️/✓` 不在 GBK 字符集内，`> log.txt` 时直接
   `UnicodeEncodeError` 挂在 `plan_spec`。→ 运行期输出改纯 ASCII 标记（`[OK]` / `[超预算]`），
   并给 stdout 加 `reconfigure(errors="replace")` 兜底。
2. **预算默认值要能容纳真实素材**：320 档 10fps = 100 帧 ≈**8.24 MiB**，初版预算 8 MiB 恰好卡住
   → 默认预算提到 **10 MiB**，并加 `--fit-budget` 按帧率阶梯自动降帧。
3. **帧率不是"源帧率/2"，而是"保留帧数 ÷ 原始时长"**：否则非整数分频（24.06→10）会让动作变速。

### 5.6 生成阶段关键帧核验（新工具 `tools/avatar_keyframes.py`）

**动机**：循环素材最怕两件事——① 单素材首尾帧不一致（循环到接缝处跳一下）；
② 各素材人物大小/机位不一致（切状态时"跳大小"）。这两件事都能量化，不必靠肉眼。

```bash
python tools/avatar_keyframes.py --src "<新素材>.mp4" --out-dir "evidence_shots\keyframes" ^
    --check-loop --ref "D:\share\项目开发\实体桌宠\桌宠动作素材生成提示词_20260901\refs\idle_normal_t00.00_f000000.png"
```

| 能力 | 说明 |
|---|---|
| `--check-loop` | 首帧 vs 末帧差异；判据 **主体区 mean ≤2.0 且 差异像素(>8) ≤2%** → PASS（2 倍内 WARN，超出 FAIL 且退出码 1） |
| `--ref <png>` | 新素材首帧 vs 参考图（跨素材一致性）；判据 mean ≤4.0、差异像素 ≤5% |
| `--find-loop` | 顺序扫描全片，找"与首帧最接近的帧"（**尾帧锚点 / 循环裁剪点**） |
| `--count N` | 抽 N 个等距关键帧（含首尾）；`--count 1` 只抽首帧当参考图 |
| 产物 | 关键帧原图（**绿幕原样**，可直接当 Seedance 首帧/尾帧/参考图）+ `*_loop_check.png`（首帧\|末帧\|差异热力）+ `*_ref_check.png` |

**实测结论（2026-09-11，现役素材）**：

| 素材 | 首帧 vs 末帧（主体区） | 判定 |
|---|---|---|
| `idle_normal.mp4` | mean=**19.90**、差异像素 **47.3%** | **FAIL** |
| 全片最佳循环点 | 最接近首帧的帧 = **f0 自己**（mean=0.00） | 该视频**不是闭环** |

→ 说明 Seedance 默认产出的是"一段动作"而非"一个闭环"。对策：**图生视频时首帧与尾帧给同一张参考图**，
生成后再用 `--check-loop` 复核。构图基准（实测首帧）：头顶距上边 **6.7%**、人物高占比 **93%**、
左右安全边距 0~2%、绿幕实测 ≈ `#0FE91B`。
