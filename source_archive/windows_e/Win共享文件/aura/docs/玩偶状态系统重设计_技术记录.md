## 1. 设计判据（先立规矩，再谈状态）

### 1.1 素材物理事实 → 状态类型的唯一判据

生成侧单段素材是 **39 帧 / 1.625 s 的循环片段**，这一条决定了全部取舍：

| 判据 | 规则 | 违反后果 |
|---|---|---|
| ① **持续性** | 持续语义（呼吸 / 聆听 / 说话）→ **loop**；一次性动作（点头 / 惊讶）→ **burst** | burst 做成 loop = "每 1.6 秒点一次头" |
| ② **闭环性** | 首帧 = 末帧（同姿、同尺度、同色） | 接缝跳变，素材不可用 |
| ③ **可触发** | 必须有 `emotion` 词 / 事件 / `avatar_action` 三者之一 | 素材做了也永远播不到 |

### 1.2 生成侧实测硬约束（本轮 + 上一轮跑数，非推测）

| # | 约束 | 实测依据 |
|---|---|---|
| G1 | **单段 39 帧，不可更长** | 56 帧版帧 16~43 背景误留 ≤47,438 px、人物误抠 ≤244,796 px（不可恢复）；39 帧版全链 `ALL_DONE` |
| G2 | 背景提示词用**基础词**，不用 `--strong` | 两版指标几乎相同（误抠 16,182 vs 16,276；四角 std 7.75 vs 7.58）⇒ 强化词零收益 |
| G3 | **不做时域去闪** | 白点闪来自生成侧（源帧 2,144 ≈ 纯抠像 2,160 px/帧；去绿开关差 0.04%）；去闪档仅压 31%~44% 且柔化腰饰 |
| G4 | 抠像安全阈值（四角块口径） | 逐帧 std ≤ ~8、G 峰峰 ≤ ~21、偏差 ≤ ~18 → 背景误留 0；超出（56 帧版 29~38 / 88.8 / 68.5）即整体失效 |
| G5 | 首帧 = 末帧 = `doll_green_9x16.png` | 段间天然无缝（未来多段拼接的前提） |
| G6 | 去绿固定 **A 硬限绿 + D1 蓝发去青** | 56 帧实测 `d≥3 = 0 / q60 = 0`；蓝发保留 97.0~97.7% |
| G7 | 边缘口径 = **V1 羽化**（用户拍板） | V2/V3 硬边对白点闪无改善；羽化观感最优 |
| G8 | 入库 **24 fps + `--fit-budget`** | 39 帧 464×480 @24fps = **12.18 MiB** > 10 MiB 预算 ⇒ 必须 fit |

### 1.3 播放侧现状约束（代码事实，改动点由此确定）

### 1.4 三条红线（v1 就成立，v2 继续守）

1. **不做 42 态笛卡尔积**（阶段 × 情绪全展开）——生成、存储、验收三重爆炸；
2. **不混档**——跨素材换分辨率会"跳大小"，要降就**全降**；
3. **系统态不做专属素材**（`CAMERA_LOST / NETWORK_LOST / CANCELLED / ERROR`）——复用 + 降级。

## 3. 触发路由（保证"新素材一定有路可走"）

### 3.1 情绪 → 素材矩阵（替换 `LOW_EMOTIONS` 二分）

```python
# board/runtime/fsm.py —— 新增；旧 LOW_EMOTIONS 保留（兼容既有测试），由矩阵统一驱动
EMOTION_ASSET: typing.Dict[str, str] = {
    # ── 低落档（原 LOW_EMOTIONS 的 14 词，语义全部保留）────────────────
    "sad": "talking_low", "low": "talking_low", "down": "talking_low",
    "depressed": "talking_low", "gloomy": "talking_low", "tired": "talking_low",
    "低落": "talking_low", "沮丧": "talking_low", "难过": "talking_low",
    "伤心": "talking_low", "疲惫": "talking_low",
    # ── 歉意档（语气偏低，先共用 talking_low；留独立命名位）──────────────
    "apologetic": "talking_low", "sorry": "talking_low", "抱歉": "talking_low",
    # ── 中性档（新增：补最大缺口）────────────────────────────────────
    "neutral": "talking_neutral", "calm": "talking_neutral",
    "平静": "talking_neutral", "普通": "talking_neutral",
    # ── 困惑档（播报中语调偏低；非播报时走 PUZZLED 状态，见 3.2）─────────
    "puzzled": "talking_low", "confused": "talking_low", "没听懂": "talking_low",
    # ── 高情绪档（保留旧默认行为）────────────────────────────────────
    "happy": "talking_normal", "surprised": "talking_normal",
    "高兴": "talking_normal", "开心": "talking_normal", "惊讶": "talking_normal",
}

def asset_for_emotion(emotion: typing.Any) -> str:
    """播报类情绪 → 素材名。未命中 / 缺省 → talking_normal（与旧行为一致，不回归）。"""
    if not isinstance(emotion, str):
        return "talking_normal"
    return EMOTION_ASSET.get(emotion.strip().lower(), "talking_normal")
```

- **口径**：矩阵**只管"播报时选哪条 talking_* 素材"**；`emo_*`（非播报表情态）由**事件/显式动作**触发，与情绪词解耦——这是"解绑"能被实现的前提。
- **配套**：`policy_validator` 的 `allowed_emotions`（主机下发白名单）应与本矩阵**同源**，避免"LLM 给了词、白名单拦掉"或反之。

### 3.2 事件 → 状态（新增两条触发）

| 事件 | 新状态 | burst？ | 备注 |
|---|---|---|---|
| KWS 唤醒词命中 | `AWAKE` → 播 `emo_surprised` | ✅ 单次 | 播放结束后转入 `LISTENING` |
| 命令类对话成功（`intent=command` 且 ok） | `ACK_NOD` → 播 `ack_nod` | ✅ 单次 | 播报前的 0.8~1.2 s；结束回 `SPEAKING`/原状态 |
| 未听懂 / ASR 低置信（非播报态） | `PUZZLED` → 播 `emo_puzzled` | ❌ loop | 超时或新事件到达即退出 |

### 3.3 `avatar_action` 通道（协议已有，补播放层绑定）

现状：`dialogue_client/adapter.py:66` 有 `avatar_action: str` 字段（mock 给的是 `"wave"`），
`policy_validator.py:75` 还按 `allowed_avatar_actions` 白名单校验，**但没有任何代码把它接到素材播放**。

建议：把合法值**收敛为素材名子集**并**限定为 burst 类**：

```
allowed_avatar_actions = ["ack_nod", "emo_surprised", "emo_puzzled"]
```

理由：① 给主机一条"显式指定动作"的直连通道（比让 LLM 猜情绪更准）；
② 只放 burst 类，避免复活 mock 里的 `wave`——挥手类是"一次性动作"，做成循环会被踩坑（§1.1 判据①）。

### 3.4 路由优先级（写进播放层，防"新素材播不到"）

1. **显式** `avatar_action`（最高优先；burst 播一次）
2. 运行时状态专属素材（`STATE_ASSET`）
3. 状态中间兜底（`FALLBACK_BY_STATE`，如 `SPEAKING_LOW → talking_normal`）
4. 全局兜底 `idle_normal`
5. B2V 矢量主体（无素材时）

> 收益：**新状态可以"先只改映射、不补素材"**——第 3/4 步保证它掉档不掉黑，素材随后补。

## 4. 播放层契约（接口级，实现依此改）

### 4.1 `_SpriteSequence.frame_at` 扩展（`qt_widgets.py:42-48`）

| 现状 | 目标 |
|---|---|
| `index = int(t*fps) % len(frames)`（纯取模） | 增加 burst 模式：`index = min(int(t*fps), len(frames)-1)`，并在 `t*fps ≥ len(frames)` 时**报告"已播完"** |

```python
def frame_at(self, t: float, loop: bool = True) -> typing.Optional[QImage]:
    """按时间取帧。loop=True 取模无限循环；loop=False 单次播到末帧后停在末帧。"""
    if not self.frames:
        return None
    fps = self.fps if self.fps > 0 else 24.0
    idx = int(max(0.0, float(t)) * fps)
    if loop:
        return self.frames[idx % len(self.frames)]
    return self.frames[min(idx, len(self.frames) - 1)]

def finished(self, t: float) -> bool:
    """burst 是否播完（供播放层决定退出该状态）。"""
    fps = self.fps if self.fps > 0 else 24.0
    return t * fps >= len(self.frames)
```

### 5.2 三轨制提示词模板（每态一段，中英混写可直接用）

> 骨架（分析文档 §3.3）：`[动作轨] + [表情轨] + [微动轨]`，**幅度给可读量**、**表情写成动作 + 回到起点**、
> **每轨都带"色调/曝光/白平衡一致"约束句**、**不写一次性动作**。

```
[动作轨] <持续动作 + 可读幅度：about X% of the body height / about N degrees>;
[表情轨] <眨眼/视线/口型的变化次数 + 明确"回到起点">;
[微动轨] <发梢/衣物仅极轻微移动，其它部位不动>;
[约束] the last frame returns exactly to the pose of the first frame; the character never changes
```

## 6. 体积与帧率预算（**这里有冲突，需拍板**）

### 6.1 实测基线（本轮真实数字）

| 口径 | 单素材 PNG | 说明 |
|---|---|---|
| 39 帧 464×480 **@24 fps** | **12.18 MiB** | 实测，**超 10 MiB 预算** |
| 26 帧 464×480 @16 fps（`--fit-budget` 自动结果） | **≈8.28 MiB** | 达标，但**帧率破了 24 fps 硬约束** |
| 旧口径对照：17 帧 336×480 @10.46 fps | ≈4.7 MiB | 现役 v1 素材 |

### 6.2 四个可选方案（都满足"不混档"）

| 方案 | 做法 | 单素材 | 12 素材磁盘 | 24 fps | 观感代价 |
|---|---|---|---|---|---|
| **A** | `--fps 24 --fit-budget`（现命令） | ≈8.28 MiB | **≈99 MiB** | ❌ 降到 16 fps | 丢帧感回来 |
| **B** | 全 39 帧 @24 fps + **预算 10 → 12.5 MiB**（改 `avatar_lod.DEFAULT_BUDGET_MB`） | 12.18 MiB | **≈146 MiB** | ✅ 保 | 无（磁盘换质量） |
| **C** | 全 39 帧 @24 fps，**全降尺寸**（464→410 宽） | ≈9.5 MiB | ≈114 MiB | ✅ 保 | 人物略小 |
| **D** | 39 帧里**抽 32 帧** @24 fps（时长 1.33 s） | ≈10.0 MiB | ≈120 MiB | ✅ 保 | 动作弧线略短 |

**推荐 B**（保 24 fps 硬约束；12 素材 146 MiB 对 SD/eMMC 无压力；且 PNG 系数 1.5→1.8 的修正已在分析文档 §3.5 记录）。
**次选 D**（不改预算、体积可控，代价是每段短 0.3 s）。

### 6.3 板端存储（估算，以 `scripts/board_export.py` 实算为准）

- RGB565 单帧：464×480×2 B = **445 KB**；26 帧 ⇒ **≈11.0 MiB/素材** ⇒ 12 素材 ≈ **132 MiB**；
- 旧口径对照：336×480×2×17 = **5.2 MiB/素材**、9 素材 **47 MiB**；
- **RAM 不随状态数增长**（单/双缓冲，`_sprite_cache` 上限 2 态）；涨的只有存储 ⇒ 状态数上限由 SD/eMMC 容量决定。

## 7. 验收判据（每态必过，把"够不够活"变成数字）

| # | 判据 | 阈值 | 工具 |
|---|---|---|---|
| V1 | **闭环**（首帧 vs 末帧，仅这两帧） | mean ≤ 2.0 且差异像素 ≤ 2% | `scripts/avatar_keyframes.py` |
| V2 | **动作幅度 `amp`**（下限，证明"真动了"） | `p90_frac ≥ 3%` | 需新增指标（§8.1-6） |
| V3 | **动作幅度上限**（防抖） | `amp_p90` 不超基准态 2 倍 | 同上 |
| V4 | **表情幅度 `face_amp`** | 脸部 ROI 差异峰值 ≥ 阈值 | 同上 |
| V5 | **缩放跳变**（防"偷偷推近"） | 人物高度占比变化 ≤ 3% | 同上 |
| V6 | **绿幕安全**（生成侧，抠像前） | 四角块逐帧 std ≤ 8、G 峰峰 ≤ 21、偏差 ≤ 18 | `aura_bg_stab`（本轮脚本） |
| V7 | **去绿干净** | `d≥3 = 0`、`blue_q60 = 0` | `scripts/despill_frames.py --check` |
| V8 | **背景误留** | 逐帧 = 0 | 本轮 `aura_verify2.py` 口径 |
| V9 | **跨素材一致**（防跳大小） | 12 素材 `size` 全等；相邻态人物高度差 ≤ 3% | 同上 |

> V1 与 V2 **不冲突**：V1 只管首末两帧闭环，V2 只管中间帧"动得够不够"——这正是旧判据"把有效动作判死"的原因（分析文档 §3.6）。

## 9. 与 v1（10 态）差异对照

| 维度 | v1 | v2 | 变化原因 |
|---|---|---|---|
| 状态数 / 素材数 | 10 / 9 | **14 / 12** | 补"中性播报 / 唤醒反应 / 确认 / 困惑解绑" |
| 情绪路由 | 二分（低落 vs 非低落） | **三档播报 + 独立表情态** | 消除"抱歉被演成兴奋"的语义失真 |
| `CAMERA_LOST` | `emo_puzzled` | `idle_offline` | 系统态不该有"情绪表情"，且 `emo_puzzled` 该归"困惑" |
| 播放语义 | 全 loop | **10 loop + 2 burst** | 一次性动作必须单发 |
| 触发通道 | 仅 `runtime_state` | `runtime_state` + `emotion` 矩阵 + **`avatar_action`** | 新素材必须有路可走 |
| 素材规格 | 336×480 / 10.46 fps / 硬边白底 | 464×480 / 24 fps / 透明 V1 羽化 | 24 fps 硬约束 + 绿幕管线 |
| 质检 | 闭环（会误杀大幅动作） | **闭环 + 幅度下限/上限 + 表情幅度 + 缩放跳变** | 让"够不够活"可验收 |
