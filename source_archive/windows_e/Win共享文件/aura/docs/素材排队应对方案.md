## 一、影响面：什么被阻塞、什么不阻塞

| 工作 | 是否被阻塞 | 说明 |
| --- | --- | --- |
| UI 三区布局 / 合同 1.1 / 单测 | ❌ **不阻塞** | 已用**真实素材**（含腰部以上占位帧）验收；**10 态**证据图 `--all-states` 已出齐 |
| 板端 LVGL 三区实现 | ❌ **不阻塞** | 只依赖 `ui_spec/` 数值（V2.0 核对表 L1~L14） |
| 帧序列播放链路 / 帧率 / 内存 | ⚠️ 半阻塞 | 单态（`idle_normal`）即可验证链路；**10 态总量**需 9 个素材名全到齐 |
| 10 态总量与预算核算 | ⚠️ 半阻塞 | 单帧字节数已实测（229 KB/帧 @466×480），可外推；精确总量待齐 |
| 10 态**观感**验收（表演/表情是否达预期） | ✅ **阻塞** | 只有真素材能定，无法绕过 |
| 提示词复核 / 一致性判据 | ❌ **不阻塞** | `--check-loop` / `--ref` 工具链已就绪 |

**结论**：被真正卡住的只有"观感验收"一项；其余都可现在推进。

## 二、四条路线（可并行，不必二选一）

### A. 加/换生成渠道（治本 · 人工）
- **国内同构替代**：可灵、即梦非 Seedance 通道、通义万相、海螺等 —— 提示词与产出要求**完全复用**
  （图生视频 + 首尾帧上传同一张锚点图 + 9:16 + 10s + 低动态 + 静态镜头），产出 mp4 走**同一入库流程**。
- **海外**：Runway / Pika / Luma —— 需确认能否 9:16 竖屏；若只能 16:9，
  **取景口径必须重算**（`crop_box` 只裁纵向的假设不再成立，要改为按比例裁边）。
- 判据不变：`--check-loop`（循环缝）+ `--ref`（跨素材一致性）+ 分辨率 ≥720×1280。

### B. 本地生成（治本 · 一次性投入）—— **用户已决定不采用，转为技术探讨**
> 2026-09-11 用户决定：**不落地本路线**，但希望了解其技术细节 →
> 见 `docs/技术探讨_I2V视频生成_提纲.md`（原理 / 显存账 / 模型对比 / 失败模式 / 实验菜单）。
> 本路线在此仅作**记录**，不再安排实施。
- 路线：ComfyUI + 开源 I2V 模型（Wan2.2-I2V / LTX-Video / CogVideoX 等），本机或租卡批量出 7 条。
- 优点：**无排队**、可 `seed` 复现、可批量重试；首帧统一用 `evidence_shots/avatar_ref_idle_normal_f000000.png`。
- 代价：一次性环境搭建（权重数十 GB + 依赖）；画风与 Seedance 存在差距 → 需重跑一致性判据。
- 产出要求与 A 相同 → **入库流程零改动**（工具只记录 `source.sha256`）。

### C. 现役素材派生「占位序列」（治标 · 零等待）
- 用 `idle_normal` 的抠像帧做**几何/色调派生**（呼吸缩放、轻微旋转/平移、亮度-饱和度调整、口型区纵向缩放），
  以 `placeholder: true` 入库 7 态，用于**板端联调与体积核算**；真素材到达后 `--force` 覆盖。
- 优点：当天可用、脚本可复现、不改提示词；
- **红线**：不是真表演，**只能用于工程联调，不能用于观感验收**。
- **当前状态：尚未实现**（本方案仅给出路线）。如需落地，可新增
  `tools/derive_placeholder_states.py`（对 `idle_normal` 抠像帧做几何/色调派生 + 直接入库，
  `meta.json.spec` 标 `placeholder: true`），真素材到达后 `--force` 覆盖即可 —— 预计半天工作量。

### D. 矢量回退兜底（已在库，随时可用）
- `board/ui/avatar_assets.py` 在"无素材"时自动回退 **B2V 矢量主体 + 程序化表情**（**10 态**齐备，
  证据 `evidence_shots/b2v_*.png`）→ 即便素材为空，板端 UI 的 **10 态**都有东西可看，不会开天窗
  （另有**状态专属中间兜底**：`SPEAKING_LOW` → 先退 `talking_normal`）。

## 三、推荐执行顺序

1. **立即**：D 兜底（已可用）→ 板端 LVGL / 联调**不等人**；确有需要再叠 C 的占位序列；
2. **同时**：A 与 B 各起一条并行出片，**谁先出片谁先入库**；
3. **逐条到达逐条入库**：`--status` 看进度 → 单条用 `--state <STATE> --src <该片>.mp4`
   （整批到齐再用 `--src <目录>` 批量；已有帧自动跳过）；
4. 9 个素材名齐 → `--verify` → `python examples/run_ui.py --all-states` → **10 态**观感验收。

## 四、增量入库 SOP（排队期每次只跑这几条）

```powershell
    --out-dir evidence_shots\keyframes --name idle_thinking --count 3 --check-loop --find-loop `
    --ref evidence_shots\avatar_ref_idle_normal_f000000.png
# ③ 单态入库（PNG 先行；已有帧目录自动跳过，不会重复劳动）
python tools/prepare_avatar_frames.py --state THINKING `
    --src "D:\share\项目开发\桌面AI桌宠\assets\videos\idle_thinking.mp4" `
    --framing waist-up --max-side 480 --budget-mb 35

```

- **整批到齐时**可合并为一条：`--src "<绿幕素材目录>" --framing waist-up --max-side 480 --budget-mb 35`
  （批量模式按 `<素材名>.mp4` 映射素材名）。
- **RGB565 到板端打包时再出**（`--formats png,rgb565 --rgb565-bg 16202B`，≈43.7 MiB/状态，`frames.rgb565` **不入库**）：
  `--budget-mb` 会把两种格式**合计**计入，届时预算要给到 **≈70 MiB**，否则会误报 [超预算] 并建议降帧率。

- **批量命名**：`idle_present.mp4` / `idle_listening.mp4` / `idle_thinking.mp4` / `talking_normal.mp4` /
  **`talking_low.mp4`** / `emo_puzzled.mp4` / `idle_offline.mp4` / `emo_sad.mp4` 放同一目录即可
  （`--src <目录>` 批量模式按文件名映射素材名）。
- **增量安全性**：`prepare_one` 对"目标目录已有帧且无 `--force`"直接 `[跳过]` → 不会误覆盖已完成状态。
- **口径一致性**：`--status` 会把取景不是 `waist-up` 的行标出来，避免"帧齐了但要重跑"。

## 五、风险与判据（换渠道/换模型必看）

1. **一致性必须重验**：新渠道产出后重跑
   `python tools/avatar_keyframes.py --src <mp4> --check-loop --ref evidence_shots/avatar_ref_idle_normal_f000000.png`；
2. **比例必须 9:16**：否则取景裁切逻辑（只裁纵向）失效，需先改 `avatar_lod.crop_box` 与本文档口径；
3. **可复现性**：本地模型须把 `seed` 与模型版本写入 `meta.json.spec`（工具已支持 `spec` 扩展）；
4. **观感验收不可省**：占位/矢量素材不得用于"9 态观感通过"的结论。
5. **`--ref` 基准有「代次」概念（2026-09-12 实测）**：同一张提示词 + 同一张锚点图，
   **不同代次/不同渠道**产出的素材可能与**旧锚点图**系统性差一档取景（`idle_listening` / `idle_present`
   主体 mean 均 ≈16.6，几乎同值），但**同代素材彼此 mean≈2.0**。
   ⇒ 判 FAIL 前先跑一次「**新素材 vs 同代已入库素材首帧**」互比：
   互比 PASS + 三联图呈**等宽描边**（非块状换装）→ 是**代次口径差**，可入库；
   **建议把 `--ref` 基准换成新代首帧**（见上述 PRESENT 技术记录 §3.2），避免"每条新素材都报 FAIL"的噪声。
6. **同代互比也可能 FAIL（2026-09-12 实测 `idle_thinking`）**：thinking 首帧 vs `idle_listening` 首帧
   主体 mean=**16.73 / 40.51%**（≈一个完整代差），但**并非素材缺陷**，而是
   ① thinking 的**首帧是"起手站姿"**（素材结构 = 站姿 → 托腮 → 回站姿），与 listening 的"正视站姿"本就不同姿态；
   ② 该素材是**又一代**锚点图产物（张嘴笑 + 呆毛 + 发丝更蓬）。
   此时改用**剪影度量**判读（`idle_thinking` 实测）：左右均触边（x0=0 / x1=719）、质心 cx=359.5 正中、
   底部同触底，仅头顶高 **12 px（72→60，+1.0%）**、非绿幕占比 65.9%→67.9% ⇒ **近同取景、轻微尺度差**，
   不是换装/换机位。**结论：可入库**；1% 尺度跳变待「alpha 包围盒归一化」根治（§待确认项③）。

---

7. **循环缝「临界 FAIL」的判读（2026-09-12 实测 `talking_normal`）**：末帧比对 f0 vs f240 得
   主体 mean=**2.90** / 差异像素 **4.21%**。判据是「mean≤2.0 且 frac≤2% → PASS；2 倍阈值内 → WARN；
   超出 → FAIL」（`avatar_keyframes.verdict`），本例 mean 2.90 仍落在 WARN 区间（≤4.0），
   但 frac **4.21% > 4.0%** 而判 FAIL ——**只超 0.21pp**，属**临界 FAIL**，不等于缺陷。
   判读要点：
   - **先看幅度再看比例**：mean 2.90 与前三条真素材（2.60 / 2.75 / 2.64）**同档**，量级上没有质变；
   - **再看剪影有没有变**：f0 与 f240 剪影**逐项相同**（y0=60 / h=1220 / boxcx=359.5 / 非绿幕 68.0%）
     ⇒ 无姿态跳变、无尺度跳变；
   - **最后看差异分布**：差异 bbox 覆盖全图、热力为**沿轮廓的细描边**（发丝/袖口/腰带/裙摆），
     无块状换区 ⇒ 是**整体轻微微动**（说话时重心/衣摆动），不是结构差异；
   - 与 `--find-loop` 联动：本例最佳循环帧就是 **f0** ⇒ **没有更优裁剪点**，裁帧无法改善；
   - 结论：**可入库**；若日后要压到 WARN，需在提示词里降低「说话时衣摆/重心微动」幅度（成本高，本轮不做）。

8. **播报两档的 `--ref` 基准选择（2026-09-12 新增 `talking_low`）**：`talking_low` 与 `talking_normal`
   **同源**（同一锚点图、同一构图段、同一机位），故核验时**优先「`talking_low` 首帧 vs `talking_normal` 首帧」互比**
   （同代同姿态，判据 mean ≤4.0 / 差异像素 ≤5%）；拿**旧锚点图**当基准会读出 ≈26 的"代差"数字，
   那是代次口径差而非素材缺陷（判读方法同第 5/6 条）。
   另需**显式压掉微笑**：锚点图嘴角带笑，若 §4.8 提示词漏写"嘴角下垂"，产出会与 `talking_normal` 观感趋同
   （见提示词包 §2.6 第 1 条）。
   **实测（2026-09-12，`talking_low` 回收）**：vs `talking_normal` 首帧 = 主体 mean **2.13** / 差异 **1.16%** → **PASS**；
   剪影逐项相同（y0=60 / h=1220 / boxcx=359.5 / 前景 67.9% vs 68.0%）⇒ 同代同取景同姿态，**差异只在表情与口型**；
   循环缝 f0 vs f240 = 主体 mean **2.63** / 差异 **2.77%** → **WARN**（优于 `talking_normal` 的 2.90 / 4.21%）。
