## 一、背景与目标

目标 G1「长句播报不露循环节」。说话 10 秒的句子，玩偶会把 1.625s 的同一段动作原样重复 6 遍。
两个根因（**都已用代码核实**，见 `.cline-handover.md` 第 28 条复核）：

1. **入场一致**：`qt_widgets._state_time`（状态内时间基）**状态一变就归零** → 每次进 SPEAKING 都从第 0 帧起播；
2. **循环节一致**：素材 1.625s，长句必然反复回到同一帧。

手段（方案原文）：**相位随机化**（`frame_at(t + phase)`）+ **轻度变速**（`frame_at(t * speed)`，
`speed ∈ [0.85, 1.15]` 按回复字数估句长）。**关键认知：不必加长素材，只改播放层**。

## 三、关键决策与踩坑

1. **为什么把时序抽成独立模块**：`qt_widgets` 依赖 PySide6，而**本机没有 PySide6** → 验收脚本与 pytest
   都拿不到取帧口径，"验收测的不是播放层"这个坑无法回避。抽到 `avatar_timing.py` 后，播放层与
   验收脚本**共用同一份口径**（`qt_widgets._SpriteSequence.frame_at` 直接调用 `frame_index`）。
2. **只对 loop 生效**：`frame_time(burst=True)` 原样返回（不加相位、不变速）—— 一次性动作必须从第 0 帧
   起播，否则永远停在末帧（`_state_time` 原注释已说明）；`speed_for_state` 也只在播报三档返回非 1.0。
3. **双向限幅**：`clamp_speed` 把速度夹在 `[0.85, 1.15]`（方案 §8 风险表），并让 `frame_time` 内部也走它 ——
   即"从外部传进来的越界速度同样被夹紧"。
4. **踩坑·`int(t*fps)` 的浮点下溢**：`(23/24)*24 = 22.999999999999996` → 取到第 22 帧，导致"精确周期"
   这类度量失真（首轮 T6 实测 `None`）。修法：`int(t*fps + 1e-9)`（远小于半帧的 epsilon，观感无差异，
   但让整数帧边界稳定、**验收可复现**）。
5. **踩坑·原 demo 出片测不到 P0-2**（复核阶段发现）：`make_gif` 是 `list_frames(dir)[::GIF_STRIDE]` **逐帧直出**，
   与时间基无关 → 改前改后 GIF 完全一样。故本次先补"按播放层时间基渲染"通道再出片。
6. **出片降冗余**：「改前」对三档是**同一段**（相位 0 / 速度 1.0），只出一份 `before.gif`（避免 3 份 1.5MB 重复）；
   演示用 `out_fps = 素材 fps = 24`，这样"改前精确周期"恰好 = 素材时长 1.625s，与 G1 的说法对齐。

## 四、验证方式与结果

**1) 数值验收** `tools/verify_v2_timing.py`（素材 `talking_neutral` · 39 帧 @24fps · 1.625s · loop）

| 项 | 结果 |
|---|---|
| T1 限幅 / 非法输入 | `speed ∈ [0.85, 1.15]`，非法 → 1.0（3 档实测 1.150 / 0.978 / 0.850） |
| T2 单调 | 字越多越慢（5/15/30/45/80 → 1.150/1.133/0.967/0.850/0.850） |
| T3 仅播报档 | 6 个非播报态恒 1.0；3 个播报态按句长变速 |
| T4 burst | `frame_time(1.5, burst=True, phase=5, speed=0.5) = 1.5`（不被拉长/偏移） |
| T5 相位 | `phase ∈ [0, 1.625)`；64 次抽样 64 个不同值 |
| **T6 改前基线** | 精确周期 = **39 采样点 = 1.625s**（= 素材时长，肉眼可辨的循环节） |
| **T7 改后** | 三档句长（speed 1.150 / 0.978 / 0.850）精确周期**全部消失**（"无（已打散）"） |
| **T8 入场一致性** | 改前 32 次入场首帧恒为同一帧 `[7]`；改后 **21 种**首帧 |
