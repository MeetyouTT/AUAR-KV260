## 9. 强化去绿：A 硬限绿 + D1 蓝发去青（批产定稿口径）

### 9.1 问题与根因

§8 的"零残留绿"是按 `d = g - max(r,b) >= 20` 判的；用户目视仍见绿。放大定位后归因为两项：

- **淡绿残留**：`d ∈ [3,10]` 有 **11,449 px**（占内容 0.44%），**91% 落在距实心区 < 3 px 的边缘带**（<1 px 带内 911 px）。
- **根因（桌宠 `src/matting/backends.py:291-301`）**：兜底去绿权重 `weight = clip(s/0.15, 0, 1) * despill`，
  其中 `s = 绿度 / 背景绿度` 是**线性斜坡** —— 绿度低的边缘像素只被削 30%~40%（spill=10 只减 ~3.7）；
  且 `interior` 掩膜**直接跳过内部像素**。实测源图前景里 `d>=11` 有 56,266 px（2.17%，最大 182），现役去绿削掉了强绿、只剩淡绿。
- **青染盲区（观感主因）**：该去绿把 `g` 压到 `max(r,b)`，对蓝发等价于 `g = b` → 蓝发呈**青蓝**，而 `d = 0` **判不出青**。
  改用青染比 `q = (g - r) / (b - r)`（`q≈0` 真蓝、`q→1` 全青）实测：源蓝发 1,477,253 px 中
  **37.8%（558,550 px）`q >= 0.35`**，其中 **84,600 px `q >= 0.6`**（重青染）。

### 9.2 定稿方案（两步）

| 档 | 规则 | 作用范围 | 实测效果 |
|---|---|---|---|
| **A 硬限绿** | `g = min(g, max(r,b))` | 所有 `α>0` 像素 | `d>=3` 11,449 → **0 px**；不透明像素数一字不变 |
| **D1 蓝发去青** | 蓝发（`b-r>30 且 b>80`）且 `q>=0.35` → `g = min(g, r + 0.5·(b-r))` | 蓝发像素 | `q>=0.6` 85,546 → **0**；改动 228,166 px（占内容 8.79%）、平均降绿 21.6 |

守恒项（A+D1 后）：**内容 2,596,529 px、不透明 2,549,745 px、蓝发保留率 98.18%、蓝发 `(b-r)` 均值 168.3 —— 全部与抠像产物一致**
（只改色相：不减面积、不吃发丝、不动 alpha）。

> 备选档（本次**未采用**，需要更彻底时才用）：**D2**（`q-max=0.25`，蓝发 g 均值 86.4→64.6）、**D3**（`q-max=0`，g 均值→32.5，青色高光基本消失）；
> **C2**（去掉最外 1px 圈里 `α<128` 的淡晕，减 28,095 px = 内容 1.1%）—— 已作 `--trim-edge soft` 预留，默认关。
