## 三、关键实现细节与技术决策

### 3.1 复用 `run_ui.build_app()`，而非重写装配

`run_demo_scenario.py` 直接 `from run_ui import build_app, sample_scene`，保证
「事件总线 → FSM → UiState → PySide6 板端三区 1024×600」这条链路与 `run_ui.py` **完全一致**，
避免演示环境与真实入口出现双份实现漂移。

### 3.2 虚拟时钟：让定格动画可复现

玩偶取帧走 `qt_widgets` 模块内的 `time.monotonic()`，因此把**该模块的 `time` 对象整体替换**为可控时钟即可定格：

```python
class _VirtualClock:
    def __init__(self, t: float = 0.0) -> None:
        self.t = float(t)
    def monotonic(self) -> float:
        return self.t
    def time(self) -> float:
        return self.t

clock = _VirtualClock(0.0)
qt_widgets.time = clock          # 只影响玩偶动画取帧
```

要点与坑：

- 必须替换 **`qt_widgets.time`**（该模块内 `import time`），**不能**只改 `time.monotonic`，
  否则会污染全局。
- `qt_app.py` 里的 `time` 是**另一个模块级名字**，`MainWindow._refresh()` 的 fps 统计走的是它，
  因此**不受**本替换影响（这是想要的：动画可控、fps 统计照旧）。
- 同一手法在 `examples/preview_avatar_frames.py` 已有先例，本次额外补 `time()` 兜底。

### 3.3 开场复位：`build_app()` 后必须主动拉回「真·待机」

`run_ui.build_app()` 初始化时按设计做了两件「有人在场」的事（源码注释：*避免"有人但待机"*）：

```python
ui.set_scene(sample_scene())                                # people_count=1
bus.publish(EventEnvelope(event_type=EventType.SCENE_PERSON_ENTER, ...))   # → PRESENT
```

因此演示脚本在拿到 `build_app()` 后立刻复位，否则**开不了「空场待机 5 秒」**：

```python
fsm.reset(RuntimeState.IDLE)
ui.set_runtime_state("IDLE")
ui.set_scene(_empty_scene())     # people_count=0 / current_target=None / recent_events=[]
ui.set_dialogue(reply="")
ui.clear_events()
ui.set_fps(30.0)
```

**新增 `UiState.clear_events()` 的原因**：上述 `SCENE_PERSON_ENTER` 会在事件流里留下
`状态 -> PRESENT` / `场景事件: scene.person_enter` / `状态 -> IDLE` 三行，与「开场待机」叙事冲突
（首版截图已复现该问题）。`UiState` 原有 `_recent_text` 为私有且无公开清空入口，故补一个纯增量方法：

```python
def clear_events(self) -> None:
    """清空事件文本缓冲（仅 _recent_text，不动 _s 中任何状态）。"""
    with self._lock:
        self._recent_text = []
```

**不做的事**：不修改 `snapshot()/recent_text()/push_text()` 任何既有语义 → 对既有调用方与本项目
`test_recent_text_bounded` 等单测零影响（已全量回归验证）。

### 3.4 剧本时间轴与事件契约

| 时刻 | 动作 | 事件 / 调用 | FSM 迁移 |
|---|---|---|---|
| 0.0s | 复位空场 | `fsm.reset(IDLE)` + `set_scene(空场)` | → IDLE |
| 0.0–4.5s | 待机 5 秒 | 无 | IDLE |
| 5.0s | 摄像头看到人 | `set_scene(sample_scene())` + `SCENE_PERSON_ENTER` | IDLE → PRESENT |
| 6.5s | 麦克风唤醒 | `AUDIO_KWS_DETECTED` | PRESENT → LISTENING |
| 8.0s | 说完 | `AUDIO_VAD_END` | LISTENING → THINKING |
| 9.5s | 给出回复 | `DIALOGUE_RESPONSE_RECEIVED{reply_text}` | THINKING → SPEAKING |
| 12.0s | 播放结束 | `AUDIO_PLAYBACK_STOP` | SPEAKING → IDLE |
| 13.0s | 结束 | — | IDLE |

要点：

- `SCENE_PERSON_ENTER` **只驱动 FSM**，`UiState.update_from_event()` 对它仅追加一行文本；
  摄像头画面（检测框 / `people_count`）必须**另行 `ui.set_scene(...)`**，否则会出现「状态 PRESENT 但画面空场」。
- 回复文案沿用现成口径：`我看到画面左侧有一位来访者。`（与 `run_ui.py --all-states` 的 SPEAKING 文案一致）。
- 采样间隔默认 0.5s，`0 ~ 13.0s` 共 **27 帧**；可用 `--fps 24` 提高采样率（见 §3.8）。

### 3.5 冻结 fps 统计，保持证据图干净

`MainWindow` 内有 20Hz 的 `QTimer` 做 fps 统计，批处理渲染时会算出 `2.6 / 1.4` 之类的抖动值（`run_ui.py --all-states` 的旧图即如此）。
本脚本取窗口后 `win._timer.stop()` 并固定 `ui.set_fps(30.0)`，让 27 张证据图的 `fps=30.0` 一致。

### 3.6 GIF 拼装

用 Pillow（项目既有依赖，`tools/make_asset_gallery.py` 已在用）把逐帧 PNG 等比缩到 0.5×（512×300）后合并：

```python
images = _load_scaled(saved, scale)                 # 读图 + 等比缩放（GIF / MP4 共用）
durations = _gif_durations_ms(len(images), fps)     # 逐帧延时（GIF 只能存 10ms 整数倍，见 §3.8）
images[0].save(gif_path, save_all=True, append_images=images[1:],
               duration=durations, loop=0, optimize=True, disposal=2)
```

`disposal=2`（每帧还原背景）配合 `optimize=True` 可显著压体积并避免残影。
实测 27 帧 @ 1024×600 → 1.23 MiB，便于随文档流转。

`--mp4` 时另用 `cv2.VideoWriter`（`mp4v`）写**真帧率** MP4，取舍见 §3.8。

### 3.7 无头渲染两处既有约束（沿用，不新造）

- 入口统一 `os.environ.setdefault("QT_QPA_PLATFORM", "offscreen")`；中文字体依赖
  `qt_style.ensure_cjk_font()`（`MainWindow.__init__` 内已调用），否则中文变方框。
- 截图走 `MainWindow.render_to_file()`，其内部已强制归一化到**窗口逻辑尺寸 1024×600**，
  规避高 DPI 屏 `QWidget.grab()` 被 devicePixelRatio 放大（实测 200% 缩放屏会拿到 2048×1200）的问题。

### 3.8 帧率提升：`--fps` / `--mp4`（2026-09-12 增补）

**问题**：默认 `--sample-ms 500`（2 fps）意味着每帧跨 **5 个素材帧**（素材本体 9.983 fps）→ 目视顿挫。

**做法一：`--fps` + 精确时间点采样**

```python
if args.fps and args.fps > 0:
    fps_out = float(args.fps)
    count = int(args.duration_ms * fps_out / 1000.0) + 1
    times = [int(round(i * 1000.0 / fps_out)) for i in range(count)]
```

> ⚠️ **不要**写成「`step = round(1000/fps)` + `range(0, dur+1, step)`」：
> 24fps → 41.67ms 取整成 42ms，恒定步长实际只有 **23.81 fps**（13s 会从 313 帧掉到 310 帧，尾帧 12978ms 而非 13000ms）。
> 精确时间点则始终是 **24.00 fps**（0 / 41.67 / 83.33 … ms）。

**做法二：GIF 用「累积误差扩散」延时**

GIF 帧延时以 **10ms 为步长**，物理上存不下 41.67ms。故逐帧延时由累计时长取整后取差值：

```python
def _gif_durations_ms(count: int, fps: float) -> typing.List[int]:
    period_ms = 1000.0 / float(fps)
    cum = [int(round((i + 1) * period_ms / 10.0)) * 10 for i in range(count)]
    durations = [cum[0]] + [b - a for a, b in zip(cum, cum[1:])]
    return [max(10, int(d)) for d in durations]   # 最小 10ms
```

→ 24fps 得到 `40/40/40/50…` 交替，**均值 41.67ms ≈ 24 fps**（单个延时只能是 40 或 50ms）。

**做法三：真 24fps 走 MP4**

新增 `--mp4`，用 `cv2.VideoWriter`（`mp4v`）写视频，fps 直接给 `24.0`，无 10ms 量化。
cv2 缺失或编码器打不开时**只打印跳过、不报错**（`_make_mp4` 返回 False）。

**做法四：帧号补零宽度自适应（顺带修掉的隐患）**

原 `"demo_%02d_t%05.2f_%s.png"` 固定 2 位补零，≥100 帧时**字典序 ≠ 时间序**
（`demo_100…` < `demo_10…`），会打乱任何 `sorted(glob.glob(...))` 的合图/合视频流程
（本文档 §4.1 与交接文档里的"手拼 GIF"命令正是这种写法，实测 313 帧时末帧被排成 `demo_99`）。

```python
idx_width = max(2, len(str(max(0, len(times) - 1))))   # 27 帧 → 2 位；313 帧 → 3 位
"demo_%0*d_t%05.2f_%s.png" % (idx_width, idx, t_ms / 1000.0, state)
```

取 `max(2, …)` 是为了**默认 27 帧的旧文件名保持不变**（`demo_00…demo_26`），
避免打断已引用它们的 `evidence_shots/demo_viewer.html` 与既有文档。

**已知边界（重要）**：玩偶素材本体 **9.983 fps**，24fps 下每个素材帧显示约 **2.4 次** ——
观感连续，但**不会超过素材本身的运动分辨率**。想要真正 24fps 的动作，需重新生成 24fps 素材。
另一个可观测后果：**Pillow 写 GIF 时会把与前一帧完全相同的帧合并**（延时并入前帧），
故 313 帧 PNG 写出的 GIF 只有 ~135 帧、延时 40~130ms 交替 —— **总时长不变、视觉无损**，
GIF 的"有效变化帧率"上限就是素材的 9.983 fps。要逐帧保真的 24fps 请用 `--mp4`。

## 附：运行环境踩坑备忘（供后续长任务参考）

- 本会话终端环境下，**前台长命令会被后续新命令的新 shell 关闭而中断**（Python 进程被连带杀掉），
  典型表现为「产物文件已建但为 0 字节」。应对：
  - 演示脚本 + GIF 分离执行（帧先出、GIF 单独短命令拼装）；
  - 或 `Start-Process -WindowStyle Hidden -RedirectStandardOutput ... -PassThru` **脱离启动**，
    再用 `read_files` 轮询产物文件（读文件不会打断进程）。
- Python 重定向 stdout 为**块缓冲**：日志文件暂时为空 **≠** 进程没在跑。
- `pytest -q` 重定向会丢末行汇总，改用 `--junitxml=<file>` 读 `<testsuite>` 属性更可靠。
- 含空格 / 中文的路径一律用 `-LiteralPath`；本环境 `git` 不在 PATH（无法用 `git status` 检查改动）。
- 无头渲染的 PySide6 字体告警
  （`QFontDatabase: Cannot find font directory ... PySide6/lib/fonts`）为**已知噪声**，
  中文字体由 `ensure_cjk_font()` 兜底，不影响证据图。
