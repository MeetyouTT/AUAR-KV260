调研日期：2026-10-21。用户要求优先使用成熟组件，尽可能避免自行实现算法。本轮仅查询官方文档和本地源码，未安装依赖、下载模型、读取私人录音、开麦、播放或改变服务。动画任务的板端测试窗口保持。

结论：可以复用现成组件完成大部分能力。环境噪声、人声干扰、声纹身份和镜头内发声者归属是不同任务，没有查到一个已证实适配当前桌面远场条件、无需标定就能全部解决的组件。优先保留现有声纹模型；普通噪声使用成熟降噪/VAD；旁人和电视人声另外评估现成主说话人隔离SDK。以下优先级是根据项目现状作出的工程判断，不是本项目效果实测排名。

## 当前实际基础

| 项目 | 已有证据 | 尚缺什么 |
| --- | --- | --- |
| 自身播放与打断 | SpeexDSP AEC及取消前ASR核验；用户已确认安静时正常播放、真人插话后回答新问题 | 不能据此推导旁人/电视拒绝通过 |
| 声音入口 | `aura/board/runtime/audio/capture.py`实际申请16kHz、PCM16、单通道；普通与插话路径共用设备独占约束 | 软件收到单通道，不等于已确认硬件只有一个麦；现有资料没有证明可取得同步多麦原始信号或DoA |
| 语音切分 | 正式入口是`automatic_capture.py`的SpeechEndpoint，插话路径复用；不是已接入神经VAD | 需要用真实噪声和短语音比较成熟VAD，而不是继续堆能量门限 |
| 视觉 | 新鲜正脸、单目标与轨迹归属门槛 | 正对镜头不能证明音频由该脸发出，尚无已验收音视频ASD |
| 声纹 | SpeechBrain ECAPA已有独立CPU环境和固定模型，四段本人录音前三段登记、第四段同会话匹配0.8571；模型在D盘 | 未正式接入聊天；没有跨天/陌生人误认率标定。现有录音入口要求3–20秒，不能直接拿来挡住“停一下”等短句 |

声纹依据：[原型验收汇总](../语音共享文件/deliverables/2026-10-19_speaker_identity/verification_summary.json)、[原型说明](../语音共享文件/deliverables/2026-10-19_speaker_identity/README.md)。CPU短公开片段预热特征中位53.5ms只是当时离线计算耗时，不包含收集足够语音的等待，也不是正式对话新增延迟。

## 候选与适用边界

| 能力 | 优先考察组件 | 可复用内容 | 对本项目的判断 |
| --- | --- | --- | --- |
| 风扇、空调等非人声噪声 | WebRTC Audio Processing / RNNoise | 成熟音频处理库、噪声抑制 | 可做免费离线基线；先选一种，不叠加多层强降噪 |
| 判断是否有人说话 | Silero VAD，经现有sherpa-onnx生态接入 | 预训练VAD、流式状态、官方API | 优先替代单靠能量判断；不能识别是谁，也不能把电视人声当噪声消除 |
| 判断声音是否属于登记者 | 已有SpeechBrain ECAPA | 预训练声纹模型、现有模板/标定工具 | 第一选择是复用，补现场负样本和异日验收 |
| 更封装的流式声纹SDK | Picovoice Eagle | 登记进度、声纹Profile、逐帧相似度 | 少写推理适配的商业备选，仍需标定和未知人拒绝 |
| 保留主说话人、压制其他人声 | ai-coustics Quail Voice Focus | 本地CPU SDK、Python/C等接口、主说话人隔离 | 最值得先列入软件试用候选，但不能承诺远场和目标选择效果 |
| 商业人声隔离的对照 | Krisp VIVA / RTC BVC | 已有SDK与集成文档 | 官方近场限制不适合直接当玩偶远场默认方案 |
| 阵列前端 | XMOS XVF3800 / ReSpeaker | 阵列波束、DoA、AEC、噪声抑制 | 如果现有拾音硬件能力不足，优先评估成品前端，避免自研阵列算法 |
| 镜头中的人是否正在发声 | Light-ASD | 论文作者公开模型、推理代码 | 可复用研究模型，但音视频同步/跟踪集成工作较多，第二阶段 |
| GPU主说话人隔离 | NVIDIA Maxine Speaker Focus | 16/48kHz单通道Speaker Focus | 官方仍标Early Access，不能列作现在最省事的稳定默认项 |

### 1. 免费离线前端：WebRTC、RNNoise与Silero

[WebRTC官方APM接口](https://webrtc.googlesource.com/src/+/refs/heads/main/api/audio/audio_processing.h)提供AEC、噪声抑制与增益控制，约10ms音频帧；它是处理库，不是本项目可以不经适配直接启用的Python成品服务。可先只评估NS，保留现有已验收AEC与回声保护；完整换AEC应另做受控回归。

[RNNoise官方仓库](https://github.com/xiph/rnnoise)是BSD-3-Clause语音降噪库，官方示例输入为48kHz单通道PCM。本项目16kHz链路需要格式适配，不能默认没有额外开销。它主要解决噪声，不能用作“只保留已登记用户”的身份过滤器。

[Silero VAD](https://github.com/snakers4/silero-vad)采用MIT许可、支持8/16kHz与ONNX。[sherpa-onnx官方VAD文档](https://k2-fsa.github.io/sherpa/onnx/vad/index.html)已经提供Silero接入，也支持TEN-VAD；后者采用修改版Apache许可，本轮不作为最省许可核对工作的首选。Silero只给语音活动证据，不给发声者身份。板端运行耗时和CPU占用尚未实测，不能把上游桌面CPU数字当KV260成绩。

### 2. 声纹：保留已有ECAPA，Eagle作为封装备选

[SpeechBrain官方模型卡](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb)提供预训练ECAPA及余弦验证，输入16kHz单通道，模型卡标Apache-2.0；官方明确不保证其他数据集成绩。已有原型应继续作为本地基线，优先补登记一致性、陌生人负样本、跨天和距离标定；不从一个人的一次匹配分数推出通用阈值。声纹核验和完整混说分离不是同一能力。

[Picovoice Eagle官方文档](https://picovoice.ai/docs/eagle/)提供本地流式说话人识别，包含Windows支持；[逐帧API](https://picovoice.ai/docs/api/eagle-web/)明确语音不足时可能返回null。[官方仓库](https://github.com/Picovoice/eagle)说明需要AccessKey联网验证，不能把“推理本地”写成完全断网可运行。采用它可以减少特征推理适配，但不能取消现场标定，也不自动证明嘴声属于同一人。

若已有ECAPA在中文现场标定不理想，再比较[WeSpeaker预训练模型](https://github.com/wenet-e2e/wespeaker/blob/master/docs/pretrained.md)的CNCeleb ResNet34/ONNX，或[3D-Speaker](https://github.com/modelscope/3D-Speaker)的CAM++。WeSpeaker明确预训练模型许可随数据集，3D-Speaker代码Apache-2.0也不能自动代表所有权重许可。不同模型的向量不能混用旧模板，换模型意味着重新登记/建模板，而不是改一下名称。

### 3. 旁人、电视人声：优先试现成隔离SDK，先核实距离

[Quail Voice Focus官方说明](https://docs.ai-coustics.com/models/voice-focus/quail-voice-focus)定位主说话人隔离：依赖近期音频上下文，启动时较弱，另一个人变得更突出时可能换目标，明确不是固定身份锁。官方当前列出16kHz模型。这个任务与用户的问题相符，但仍需验证能否保住低声、短句和第一句话；“电视更响”必须单列测试。

[官方Python封装](https://github.com/ai-coustics/aic-sdk-py)发布Windows/Linux等平台包；[认证说明](https://docs.ai-coustics.com/models/get-started/authenticate-apps)和[网络说明](https://docs.ai-coustics.com/reference/concepts/sdk-telemetry)表明自助密钥需要在线授权/用量上报，断网授权需另行确认。官方称这些SDK上报不包含音频和转写；这不等于应用其他部分也不会传音频。接口可开源不代表引擎和模型免费。价格、可用试用配额和离线授权本轮未确认，不据此建议购买。

[Krisp VIVA官方说明](https://sdk-docs.krisp.ai/docs/voice-isolation)非常关键：可去其他人声的Telephony/WebRTC模型要求主说话人约30cm内；远场Smart-speaker模型只降噪，保留可听背景人声。[RTC BVC说明](https://sdk-docs.krisp.ai/docs/krisp-rtc-bvc-nc)也主要面向耳机。桌面玩偶若通常超过30cm，不直接套用近场BVC；不能把厂商通话演示外推为本项目效果。

[LiveKit官方降噪文档](https://docs.livekit.io/home/cloud/noise-cancellation)把普通降噪和Voice isolation分开，并说明其增强Agent方案依赖LiveKit Cloud。现有ASR/LLM/TTS为本地链路，没有必要仅为过滤器迁移整个通信栈；优先直接SDK。不同增强器不能无脑串联，声纹识别也要比较处理前后分数与目标词保留情况。

### 4. 空间与视觉归属：有现成模型/硬件，但需要实机验证

[ReSpeaker XVF3800官方资料](https://wiki.seeedstudio.com/respeaker_xvf3800_introduction/)列有四麦、AEC、DoA、波束及降噪，可把DSP负担移到专用前端。厂商最远拾音距离不等于本项目稳定距离。先确认现有MCP01暴露的通道、是否已有DSP和参考输入，再判断是否需要硬件替换；不能由单通道音频凭空补出可靠空间方向。阵列DoA也不能单独认定具体身份。

[Light-ASD作者仓库](https://github.com/Junhua-Liao/Light-ASD)公开代码和权重、MIT许可，可用于判断画面目标是否在发声。但从视频研究流程变成实时服务仍需时间对齐、面部轨迹和推理预算；不将其称为直接安装即用的产品SDK。可以后置，但不以自写嘴部运动阈值替代已经存在的ASD模型。

[NVIDIA Speaker Focus官方页面](https://docs.nvidia.com/maxine/afx/latest/AboutTheEffects/AboutSpeakerFocusEffect.html)仍标Early Access，支持16/48kHz单通道。[Windows要求](https://docs.nvidia.com/maxine/afx/latest/WindowsAFXSDK/GetStartedOnWindows.html)限定支持的Tensor Core GPU和驱动。现有显卡还承担模型推理，独立测很快也不能证明并发不会拉长回答等待；不作为首轮默认候选。

## 建议执行顺序：只做集成和标定，复用上游算法

1. **先建立成熟组件基线。** 优先评估Silero VAD及一条NS路径，复用已有ECAPA；用公开允许使用的测试素材验证安装、格式和推理预算，再安排现场测试。只写有界适配、取消/代次隔离、状态与指标，不重新训练降噪、VAD或声纹网络。
2. **旁人人声单独比较。** 将Quail Voice Focus列为首个商业软件候选，以当前未增强链路为对照。若不采用商业授权，则保留开源前端+声纹路径，并明确混说、电视拒绝尚有边界，不能用提高音量门槛冒充解决。Krisp只有在实际距离满足其官方条件时进入同场比较。
3. **根据结果决定阵列/ASD。** 如果单通道条件下主说话人选择不稳，优先现成阵列硬件；确需“看见谁就只听谁”再复用ASD。声纹负责已登记身份，隔离模型负责声音增强，视觉/DoA提供归属证据，职责分开。

现有PC转写入口主要收完整语段。把VAD放到该接口后面无法修复前端误触发：必须让VAD参与流式入口。若PC运行，需要有界流式PCM适配；若板端运行，需要测对UI帧率/声卡队列的影响。不能把“项目已有sherpa-onnx”当“所有新能力已经可直接开启”。

短句身份证据不足时保留明确的“不确定”状态；不能沿用旧请求身份，不把游客聊天强制改成声纹登记，也不能为满足现有3秒声纹入口让每句短话等3秒。普通匿名对话和个人记忆权限分开，个人资料绑定等待可靠归属。声纹相似也不证明真人现场发声：同一人的电视/手机回放仍需单独覆盖，不能把此次选型写成防回放已实现。

## 验证应看什么

| 场景 | 主要指标 |
| --- | --- |
| 只有风扇、敲键、碰撞，没有人说话 | 错误开听/提交/打断次数与实际观察时长 |
| 有电视，镜头前的人保持安静 | 电视错误开轮、错误转写插入词数 |
| 目标说话，同时有旁人/电视 | 目标词丢失、背景词混入、ASR错误、短句/低声保留 |
| 已登记人、陌生人、异日与远近变化 | 误认、拒认、不确定比例，独立标定与验收集 |
| 刚开听、切话题、两人轮换、同时说话 | 首音丢失、目标选择漂移、过期身份误绑定 |
| 汐蓝播放中用户真插话或保持安静 | 误打断、漏打断，从人开口到停播的完整延迟 |
| 长时间与模型/动画并发 | CPU/队列/音频延迟、回答首音P50/P95、UI长帧及资源泄漏 |

这些是后续验收项目，不是本轮已通过的测试。上游宣传准确率、处理耗时不能换成本项目结果。公开混音能比较算法，不能替代真实房间、距离、扬声器和麦克风验收。本轮不额外采集或外传现场声音。

分析和来源保存在共享目录；本轮没有新增任何权重。大语言模型继续遵守项目外D盘存储约定；后续ASR/TTS及其他语音模型按已明确的运行配置另行落实，不借调研移动或删除历史资源。
