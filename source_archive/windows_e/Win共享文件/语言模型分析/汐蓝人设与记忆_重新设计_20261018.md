# 汐蓝人设与记忆：重新设计

日期：2026-10-18。状态：重构方案，尚未接入持久记忆、修改活动部署或重启服务。取代本轮临时提出的“固定常用用户/手动切访客”方案；旧规划保留历史参考。

## 设计目标

汐蓝应能接住长对话、记住相处中明确的重要信息，在可靠识别同一个人后接回其个人记忆。用户无需每轮选择档案；系统无法确认归属时仍可自然聊天，但不猜测、混用或写入他人的档案。

角色身份、看见的人、当前说话者和记忆归属是四件事，不能只凭一句“我叫小林”或相机当前选中对象就把它们合并。

## 本轮查证到的真实基线

- 现场只读结果：电脑8792为原27B/IQ4_XS和OmniVoice16，五项延迟开关仍开启，服务空闲；板端对话STOPPED，无录音任务。本轮没有开启麦克风。
- 相机8790的实际健康结果为DPU YOLOX人体检测/ByteTrack跟踪，`identity_recognition=false`；当前画面人数为0。这是本次观测，不代表相机以后一直无人。
- 身份源码已经有SQLite身份库、稳定UUID、显式登记/删除、模型隔离、目标代次和结果有效期检查；未启用不等于没有实现。
- 说话人模块已有窗口、时钟域、目标代次、分数和歧义校验，但现有文档明确Light-ASD真实推理尚未接入。它不能直接作为已就绪的说话者识别服务。
- 正式语音请求只有boot/session/request/generation/capture等字段，校验器拒绝额外字段，没有person_id或说话者证据。
- 当前颜色锚点仅限同boot/session，完整播放ACK后保存，最多32个会话，服务/UI重建会清空。它不是通用个人记忆。

现场原始证据：`../语音共享文件/deliverables/2026-10-18_persona_memory/design_live_state.json`。相机PID/boot仅作为该时点记录，后续动态读取。

## 一、统一人设，允许关系自然发展

核心人设固定为“汐蓝、鲸鱼娘陪伴角色、温柔自然、有一点俏皮、有自己的判断”。将角色设定和实际模型配置分开，问真实模型时按当前后端回答，不把DeepSeek旧文案当真实身份。

表达层根据场景决定：日常闲聊简短接话，解释时说完整，用户要求详细时才展开。用户明确选择的称呼、玩笑尺度和追问偏好属于个人相处偏好，不能混进所有人的公共人设。

不因单次情绪永久修改性格，也不自动增加恋爱关系、共同经历或没有传感器依据的观察。人设改动需在现有2048上下文和输出限制下实测，不能靠增加长提示挤掉聊天记忆。

## 二、把“谁在说话”作为独立模块

每一轮创建板端拥有的身份绑定快照，至少包含：board_boot_id、camera/service epoch、录音capture_id和时间窗、target_key及代次、person_id、身份库修订号、证据时间与有效期、归属方式和歧义原因。

person_id使用身份库的稳定UUID；名字只是可修改的显示属性。新报姓名不会自动开放已有同名档案，也不自动登记人脸。

| 场景 | 交互与记忆行为 |
| --- | --- |
| 已登记、当前身份与本轮说话者归属均已验证 | 自动取得该人的有限相关记忆；允许确认后更新其档案 |
| 画面只有一名已登记对象，尚无说话者模型 | 可以作为身份候选，不能把人数=1当成已证实发声；首次关联需明确确认，范围限本次交谈和连续有效目标 |
| 初次见面、未登记、相机不可用 | 继续本次聊天和临时记忆；通过已有身份管理入口一次性登记和确认记忆归属后，才建立个人长期档案 |
| 多人、目标变化、人物离开、证据过期 | 暂停个人记忆读写；清除旧绑定，不沿用上一人的上下文。若有必要，简短确认正在和谁交谈 |
| 身份删除或身份库版本变化 | 立即撤销绑定和缓存；迟到结果不得恢复已删身份，关联个人记忆的处理单独列明 |

视觉身份与说话者关联属于陪伴交互能力，不能据此宣称完成了安全认证、防照片冒认或敏感信息访问认证。首版不引入未经验证的声纹模型。

绑定在录音窗口内建立；不能等ASR结束后取一张可能已经换人的当前画面。生成后、记忆提交时再次检查修订和归属。回复包含个人信息时，目标换人应取消旧轮，避免继续向新对象播放。

这些是拟议合同，尚未传入正式语音通道；必须与旧协议兼容或显式版本升级，不允许直接给严格校验器增加未知字段。

## 三、记忆分层，不靠无限追加历史

| 层 | 内容 | 生命周期与更新 |
| --- | --- | --- |
| 当前交谈 | 最近若干轮、当前主题、未结束的问题 | 窗口有界；按预算裁剪；身份变化时隔离；模型生成与实际播完分别记录 |
| 会话摘要 | 较早话题的要点和未完成事项 | 每条带来源和对应身份；后台空闲维护，不把猜测写成事实；遗忘时同步失效 |
| 个人事实 | 明确确认的称呼、稳定喜好、用户要求长期记住的事情 | 以person_id关联的本地SQLite；支持查看、纠正、逐条遗忘和清空 |
| 临时情景 | 今天累、正在调试、当下心情 | 明确失效时间，不自动升级为长期标签；来源不明时仅限当前交谈 |
| 系统知识 | 已验证设备能力、汐蓝设定、运行配置 | 全局配置管理，不能由普通闲聊覆盖 |

每个事实至少有fact_id、person_id、类别/槽位、值、来源轮次、确认状态、修订号、更新时间、可选到期时间。更正会替换当前有效值；不把所有“我喜欢……”当作永久喜好，不根据模型猜测或引用他人的话自动写档案。

第一版不增加向量模型。优先用明确类别和关键词检索少量相关事实；验证确有需要后再加检索方案。摘要维护复用原27B，在空闲时串行执行，前台请求优先；未完成的摘要不能阻塞下一句聊天。

## 四、按事件分别提交，不把所有记忆都绑在播放ACK上

1. 语音识别后先验证本轮归属与输入来源。姓名、数字、日期等拿不准的信息进入候选，通过简短复述和用户下一轮确认后生效；不偷偷更改原始ASR。
2. **个人事实在有效的用户确认事件上事务提交。** 用户明确要求记住的内容，不应仅因后续TTS失败就当作从未说过。取消需区分“取消播放”和“撤回尚未提交的记忆操作”。
3. **助手说过的话继续以匹配完整播放ACK为准。** 生成、传输完成和实际听到分开，未播完的承诺/回答不能伪装成已经交付。
4. **明确遗忘在归属和指令验证后立即执行，不等待播报。** 播放失败不能让“忘记”失效；操作结果用事务状态返回，模型不能先声称删除成功。
5. request_id和操作ID去重；匹配的重复确认返回原结果，不重复插入。版本过期、归属变化、迟到结果拒绝写入。

为避免已忘记的事实被恢复，遗忘需同时清理当前事实、候选、摘要、检索副本和可重提取的活动历史；保留不含被删值的删除版本标记。历史测试/归档不自动删除，也不作为线上记忆输入。涉及主动保存的原始录音或其他归档，需独立说明范围，不能把清理活动记忆说成磁盘取证级抹除。

## 五、上下文与性能

维持原27B、量化、2048上下文、OmniVoice16与现有流式主线。预算顺序为核心人设、当前问题、相关事实、近期对话、必要摘要和输出预留；先裁掉较旧且不相关的对话，而不是随意丢弃当前纠正或遗忘状态。

记录实际提示长度/token数、事实召回数量、台词准备、首PCM、失败和额外推理次数。不能因为新提示更长却省略历史而宣称记忆变强或速度未受影响。

身份和记忆存储、召回、操作结果都应是可测试的独立模块；模型只负责自然表达与产生待验证候选，不能直接操作数据库、任意选择用户或执行删除。

## 六、实施顺序和验收门槛

1. **先核实身份闭环。** 在隔离候选中复用现有登记/识别/删除能力，做真实登记、离场返回、陌生人、两人和目标变化测试；确认可用范围后再决定是否启用。没有实际说话者推理时明确拒判，不能填入虚构person_id。
2. **实现归属合同与独立记忆核心。** 先用合成身份测试持久化、重启恢复、候选确认、跨用户隔离、并发修订、更正、遗忘和重复提交。数据库测试数据与实际用户数据分离。
3. **统一人设并接入对话。** 在相同预算下增加相关记忆召回与短期摘要；保留旧通道和可回退开关，空闲部署。
4. **最后做真实交谈验收。** 同一人至少20轮干扰话题后召回；服务及UI重启后重新确认身份仍能召回；换人不串档；姓名误听可纠正；遗忘后新会话及摘要均不恢复；网络/播放失败和取消不制造虚假“已说过”。最后由用户实际听音确认自然度。

上面是待执行门槛，不是已通过的测试。本次只读检查没有验证真人身份准确率，没有自动登记任何人，也没有改视觉DPU/FPGA或部署新语音模型。
