# 玩偶的时间轴记忆与视觉融合

日期：2026-10-28。本文保留最初实施设计；[时间轴第一版现已部署](../语音共享文件/deliverables/2026-10-28_timeline_memory/README.md)。已接通来源/时间检索、跨开机视觉历史及派生回复遗忘，配置新事件最多30天/10000条；后台日摘要、事实变化时间和权威库移交PS仍待后续。

用户方向：长期记忆按时间轴记录，结合视觉信息；语音保持独立于视觉，不要求人入镜才能对话。

## 当前已经有什么

| 模块 | 已有能力 | 本次要补的能力 |
| --- | --- | --- |
| 对话档案 | SQLite 持久保存用户输入、生成/中断/完整播放状态；按会话读取近期轮次和相关原话 | 跨模态事件索引、明确的时间范围检索、情节摘要 |
| 个人长期事实 | 明确选择个人档案后，可记住、更正、遗忘；当前每档案最多 12 项 | 有来源和生效时间的事实变化历史，与事件时间轴关联 |
| 视觉观察 | 开启监听时约每 15 秒生成一条短描述，不保存原图；最多 1000 条、24 小时 | 去重后的事件记录、跨开机的授权历史、与相关对话关联 |
| 视觉回忆 | 按同一 boot 查询最近 3 条历史；20 秒以内可标为当前观察 | “昨天下午”“上次谈到某物”等时间与内容组合检索 |

视觉记录目前是短期观察缓存，三类记忆尚未统一。个人明确事实已具备跨会话能力，不能把现状描述为完全没有长期记忆。

## 核心结构：事件、情节、事实

时间轴是统一索引，内容仍保留来源与访问范围。模型每次按问题获取少量相关资料，不把完整历史塞入提示词。

1. **事件层**：记录某个时间发生的对话、可见场景、明确记忆修改。语音事件即使没有图像也能独立存在。每个事件有不可复用的 ID 和原始来源引用。
2. **情节层**：把一段连续交谈和附近相关观察整理成一个片段，如“下午讨论玩偶比赛，桌面有板卡”。按会话或场景变化分段，再形成日摘要；摘要必须引用仍有效的源事件。
3. **事实层**：存储用户明确告知或确认的姓名、偏好、项目等。保留生效时间、被哪条更正替代和来源；视觉描述或模型推测不能直接升级为个人事实。

摘要只做检索索引和压缩依据，不能覆盖来源。源事件过期或被遗忘时，要同步处理派生摘要、索引、事实与缓存，避免摘要把被删除的信息重新带回来。

## 一条记录的必要信息

| 字段组 | 内容 |
| --- | --- |
| 时间 | 事件发生时间/时间范围、服务接收时间、入库时间、时区、时间可信度；发生时间不明确时允许为空 |
| 来源 | 用户原话、已播放回复、相机观察、用户确认、模型归纳；来源轮次或帧引用 |
| 内容 | 简短原话或可见事实、主题/物体标签、状态；模型归纳与观察原文分开 |
| 归属 | 会话 ID、授权个人档案或设备范围；无法确认人物时保持未知 |
| 关联 | 请求 ID、boot、相机 epoch、帧 ID、相关事件 ID、关联依据和时间间隔 |
| 生命周期 | 记忆版本、保留级别、到期时间、被更正/撤销状态、派生来源 ID |

boot 和 epoch 继续用于拒绝过期帧、旧请求和错误设备来源；长期历史检索改用稳定设备身份及授权范围。重启不会把旧观察变成新画面，也不能仅取消 boot 过滤来开放所有历史。

## 时间轴必须先处理时钟

最近重连证据中，板卡 systemd 时间仍显示 2021 年，而接收端检查时间是 2026 年。不能直接拿板卡墙钟作为长期记忆日期。

- 第一版以经检查的 Windows UTC 接收时间为可靠锚点，保留板端单调时间、boot、源序号与帧年龄。
- 获取双端时间锚点时记录往返延迟和误差；能可靠换算才生成估计发生时间，不能精确换算则显示“约某时收到的观察”。
- 日期查询按用户配置的时区解释；“昨天”先换成明确起止时间，存储统一 UTC。设备间同一时刻关系还需结合请求与来源，不能只比墙钟。
- 时钟回拨、断网补传和设备重启保留为时间边界。离线阶段没有可靠日期时，只保证该 boot 内顺序，不补造绝对时间。

## 视觉如何写入时间轴

保留现有单相机所有者与低频观察通道，先接收描述再做有界的重复合并。相似场景记录起止、最近一次观察和观察次数；物体/人物位置明显变化、用户询问或确认时，形成独立事件。

15 秒采样可能错过中间动作。因此，只看见杯子在桌上时记录“桌上可见杯子”，不能补写“某人把杯子放上桌”。没有观察到变化也不证明期间完全没变化。

相近时间可把视觉事件与对话放入同一情节，但关联含义是“当时附近的观察”。不能据此认定画中人就是发言者。已校准身份结果、明确授权的档案以及声画归属须各有证据；现有未现场标定的声纹不自动解锁个人记忆。

第一版延续只存文字描述和来源引用的方式。长期保存关键图片、录像和原始录音另作为明确设置；本设计不自动开启。早期未保存的画面无法事后恢复。

## 检索与回答

检索顺序为：访问范围 → 时间范围 → 主题/物体/明确人物 → 相关事件 → 上下文预算。先复用现有中文词片段检索和 SQLite 索引；有证据表明语义召回不足时再增加独立语义索引，不要求新模型才能开始。

- “刚才看到了什么”：当前设备的近期视觉事件，注明观察时间。
- “昨天下午我们聊到哪里”：授权对话范围内的时间段、情节摘要和最后几个有效轮次。
- “我上次把杯子放哪了”：找与杯子相关的最近观察和用户原话；没有放置动作证据就回答最后看到的位置，不把历史位置说成当前位置。
- “现在杯子还在吗”：请求新鲜画面；旧时间轴只能补充历史。
- “你怎么知道的”：返回可读的来源和时间，例如“你昨天告诉我的”或“我在刚才的画面里看到的”。

检索结果应带 observed / user_said / confirmed / derived 等来源标记及是否历史，作为资料传入模型。画面文字和历史指令不能取得当前指令的权限。相关资料缺失时明确说没记录或不确定。

近期对话、检索片段、系统提示和输出预算统一计量。索引/归纳在后台完成，检索设有界超时，失败仍可普通聊天；不能为写长期记忆阻塞开口、音频采集或显示线程。

## 一个示意情节

以下内容是设计示例，不是现场记录。

| 时间 | 来源 | 记录 |
| --- | --- | --- |
| 14:02:00 | 用户原话 | “我把杯子放桌子左边了。” |
| 14:02:03 | 相机观察 | “桌面左侧可见一个红色杯子。” |
| 14:07:00 | 用户提问 | “我刚才把杯子放哪里了？” |
| 14:07:01 | 检索依据 | 同一授权情节中的原话与最近杯子观察 |

回答可以是“你刚才说放在桌子左边，14:02 左右的画面也看到了那里有一个杯子；我还没确认它现在是否仍在那里。”两种来源互相补充，不合并成无来源的确定结论。

## 长期保存、修正与遗忘

- 保留等级建议区分短期细节、长期情节摘要、明确个人事实；每层同时设时间和容量上限。长期摘要的具体保留期限作为可配置策略，不能直接将现有 24 小时记录全部改成永久保存。
- 不同档案保持隔离，访客记录不自动归入后来识别到的个人。摄像头背景信息也不因用户在场就全部成为其个人记忆。
- 事实更正产生新版本，旧值标为被替代；检索“现在的偏好”和“以前的偏好”须区分，已要求遗忘的值不再可召回。
- 遗忘支持事件、时间段、主题和档案范围；级联失效所有派生摘要、语义索引及在途结果，保留现有 memory_revision 与旧 ACK 拒绝机制。
- 现有“遗忘”主要是排除召回，原始对话归档可能仍在。新功能须明确区分“不要再用于回答”和“删除保存记录”，物理删除还要覆盖索引、副本与备份保留策略；不能把逻辑屏蔽说成已擦除。
- 模型回复仍须完整播放 ACK 后才作为已经说给用户的内容。中断回复保留状态，但不被摘要为用户已经听到的完整答案。

## 分工与实施顺序

目标仍是让板卡 PS 管理时间轴、权限、入库与查询，Windows 执行现有对话、视觉理解和必要的摘要推理。推理资源与记忆管理可以分开迁移。

1. 先增加共用事件结构、时间锚点和增量索引，复用现有会话/视觉来源；用合成库验证跨开机查询、重复写入、错时钟与关联依据，不接管真实库。
2. 接入时间范围检索、来源标记与有界上下文；保留现有播放 ACK、个人授权、更正/遗忘屏障。视觉失败或关闭不阻塞语音。
3. 增加后台情节/日摘要、重复场景合并、容量管理及派生记录失效；以有答案的测试情节评估检索和事实误归属。
4. 按既有迁移方案把权威数据库和写入者移交 PS，验证 ARM 实际延迟、磁盘写入和 UI/音频共存。Windows 保留推理服务；不能让两端各自拥有可独立更改的记忆库。
5. 一次集中验收“当天→次日→重启后”的跨模态回忆、更正/删除、陌生人隔离及普通聊天延迟。通过之前不称长期时间轴已上线。

第一版验收至少包含：无视觉仍记得对话；新 boot 可查授权历史但拒绝旧帧充当实时；相似画面不无限重复；未知人物不自动命名；中断回答不算说完；删除源事件后派生摘要不再泄漏；时间错误不生成虚假的“昨天”；记忆检索故障不影响普通聊天。
