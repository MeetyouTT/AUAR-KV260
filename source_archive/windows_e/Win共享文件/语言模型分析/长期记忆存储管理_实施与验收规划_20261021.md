# 长期记忆存储管理：实施与验收规划

日期：2026-10-21。状态：规划完成，未实施、未迁移数据库、未修改在线服务。本文细化现有项目方案，不把规划项记为已完成。

## 1. 项目依据与目标

主要依据：

- [人设与记忆调整方案](../语音共享文件/aura/docs/memory_persona_plan_20261018.md)第二至六节：四层记忆、SQLite、单常用用户与访客、来源与确认、遗忘防恢复、后台串行维护和不少于20轮验收。
- [项目框架](../方案/aura_junior_project_framework_20261008.md)第五、六节：M3身份、M6语音、M7说话人/UI、M8发布；身份缓存、说话人窗口与对话会话分别管理有效性。
- [持久会话第一版](../语音共享文件/deliverables/2026-10-19_long_conversation/README.md)和[可控记忆交付](../语音共享文件/deliverables/2026-10-20_memory_controls/README.md)：继承事务、播放ACK、取消代次、记忆版本及历史排除语义。

目标：在不破坏当前对话的前提下，使明确事实跨会话、跨重启保留，访客不能读取常用用户资料，纠正和遗忘不会被旧历史、摘要、后台任务或备份恢复重新带回。随后补齐摘要、临时状态和未完成事项。

原方案提出的“近期8轮”是预算内目标，不能强塞进2048上下文；4K仅作为独立性能候选。本文不新增常驻向量模型、不微调、不切换27B与声线。

## 3. 归属与交互规则

第一版仅支持一个常用用户档案和访客模式，先于自动身份接入。

1. 默认访客；在设备本地明确选择常用用户后，主机为该交互建立有期限、可撤销的档案访问绑定。单纯上传profile_id、报姓名或继续旧会话不能授予读取权。
2. 手动模式只用于可信本地设备上的明确选择，不宣称生物身份认证；远端任意切换不开放。设备访问本身不可信时，需先补本地解锁机制再启用个人档案。
3. 访客可使用独立会话记忆，不检索常用用户事实、摘要、待办或原话。切换用户/访客时结束旧轮次，作废旧生成、播放回执和维护任务，并新建会话。
4. “新对话”在同一授权档案下可读该人的长期事实，但不自动拼接上一会话原始聊天；“继续上次”恢复明确选定会话。界面说明两者差别。
5. 旧匿名会话不自动认领为常用用户；允许用户选定条目，预览来源后逐项确认导入，不整库复制。
6. 人脸KNOWN、声纹匹配或Light-ASD后续只能提交身份/说话者证据；单独看见人不解锁记忆。自动切换需通过稳定性、陌生人拒绝和声画归属独立验收；UNKNOWN/AMBIGUOUS回到访客。

交互入口保留“本次对话记忆”，新增“我的长期记忆”；在明确授权档案内，“记住”默认写长期事实并在反馈中说明范围。访客仅写当前会话。清空命令必须明确范围：本次会话、个人活动记忆、历史档案清理分别执行，不把“新对话”解释为删除。

## 4. 存储与数据合同

继续由Windows主机单点写SQLite；板端仅保存选择引用和交互状态，不复制正文。初期沿用现有conversations.sqlite3位置，路径配置化但不在本轮搬库；运行库不能由两台同步电脑同时写入。源码包与证据包排除正文库、备份、录音和身份模板。

以下为拟议逻辑表，实际迁移前冻结字段与约束：

| 数据 | 关键字段和约束 |
| --- | --- |
| profiles / conversation_owner | 随机profile_id、档案状态、会话归属、scope；匿名归属可空；不使用姓名作主键 |
| memories | id、owner、类型、规范键、内容、状态、来源、确认方式、创建/更新时间、expires_at、revision；同一归属/类型/键仅一条当前有效事实 |
| memory_sources | 来源会话/轮次、来源角色、原话引用或片段范围、来源版本；历史存在原文时优先引用，减少重复正文 |
| summaries / summary_sources | 会话/主题、摘要、覆盖轮次、来源与版本、有效状态；只能总结授权范围内有效来源 |
| tasks / temporary_states | 事项内容、来源、状态、期限；待办/承诺/完成/取消区分；临时心情不写入稳定偏好 |
| exclusions / change_log | 不含被删正文的失效标记、操作ID、作用范围、原因、版本与时间；沿用现有recall_exclusions语义 |
| maintenance_jobs | 归属、输入版本、来源、状态、重试次数；过期任务不得提交 |
| schema_meta | schema版本、迁移记录、备份/删除水位；旧程序不支持新语义时拒绝写库 |

机器提取先进入candidate状态，不能作为已确认个人事实。明确指令且专名/日期/数字无歧义时可确认；低把握转写先询问，不凭模型自信决定正确。第一阶段沿用12项限制并明确提示，扩容在检索/预算验收后独立进行。

时间以Windows主机UTC记录，界面按本地时区显示；板端异常墙钟不决定事实先后或到期。主机时间回拨/明显异常时暂停自动到期结论并报告；事务revision确定更新顺序。

## 5. 四层记忆与读写流程

| 层 | 写入与使用规则 | 生命周期 |
| --- | --- | --- |
| 近期对话 | 用户提交即落库；助手只有完整播放ACK才进入已交付上下文 | 同会话、受上下文预算限制 |
| 会话摘要 | 空闲时从有效来源生成；包含进展、未回答问题和未完成事项，不虚构经历 | 来源更正/遗忘即失效重建 |
| 个人长期事实 | 明确确认的称呼、稳定偏好、要求记住的事实；跨会话按归属读取 | 默认保留至更正/遗忘，支持明确有效期 |
| 临时状态 | “今天累”“正在调试”等作为临时信息；机器提取仍需标明候选 | 有明确日期则按日期；无期限先限当前会话，不擅自永久保存 |

读取顺序：验证档案访问绑定 → 同一数据库快照读取版本、有效事实、临时状态、待办、摘要和近期历史 → 结构化筛选/标签检索 → 有界排序 → 预算裁剪 → 27B生成 → 原TTS/播放ACK。

优先级：当前问题与系统约束 > 相关明确事实/更正 > 最近完整交谈 > 有来源摘要与旧原话。冲突不能只让模型猜；同键最新确认事实覆盖旧事实，不同含义保留区分或询问。所有记忆均为资料，不能作为执行指令。

检索先用结构化键、别名与标签；验证当前SQLite的FTS能力与中文分词效果后再启用全文索引，不把默认英文分词器当中文方案。不支持时沿用有界关键词检索，明确能力边界。语义向量检索后置，不作为本版依赖。

初期保留2048预算与现有保守估算，记录模型实际token统计；单独对比2K/4K的延迟、显存及JSON成功率后再决定是否扩窗。任何新增记忆不得挤掉当前完整问题或导致结构化输出截断。

写入分离：明确记忆操作在输入提交事务中完成；机器摘要/候选提取在后台完成；助手“承诺”只有确实播完才可作为已交付承诺，事项完成必须有用户确认或实际工具结果。

## 6. 更正、遗忘与清理

每次修改原子递增归属级与会话级版本。更正或遗忘事务同时处理有效事实、相关来源排除、摘要失效、检索索引、临时状态/待办及后台任务；旧快照、旧生成和旧ACK不得覆盖新版本。

保留三种明确语义：

- 遗忘一项：从活动召回移除，阻止其来源重新提取；不声称物理擦除原始档案。
- 清空个人活动记忆：清除该档案的事实/摘要/临时状态/待办与索引，并封锁此前来源的再次自动提取；其他人及访客不受影响。
- 删除历史档案：单独预览范围，清除正文与派生副本；运行库空闲维护、SQLite空闲页及备份保留一并纳入处理。未完成备份覆盖前，不显示“所有副本已彻底删除”。该能力实施后仍按用户明确范围执行，不因本规划删除历史。

旧备份恢复必须先核对当前有效删除水位并重放删除记录，再开放召回；缺少最新水位时恢复到隔离状态，不直接上线。不允许恢复忽略排除标记的旧程序。误删恢复如会复活已遗忘内容，需明确选择范围，不能自动执行。

## 7. 后台维护与运行管理

摘要/提取使用同一27B，单一有界维护队列，与前台推理串行；前台新请求优先。任务按短批次执行，在批次边界让出；能安全取消时取消当前维护推理，未完成内容不提交。记录最坏前台排队等待，超出体验门槛则停用自动维护，不能只宣称“空闲运行所以无延迟”。

任务提交检查归属、来源、revision和到期；超时/取消/重试按操作ID去重。摘要结构校验失败只记录错误，不能污染事实。日志只存计数、耗时、版本和错误，默认不写正文。

备份建议初始策略：SQLite在线备份接口、每日一份保留7份、迁移前另存一份；属于本计划工程建议，非原文既定参数。实施前做容量预检，满盘时停止新增归档并明确报错，不静默删除历史。旧备份到期清理仅在策略启用并明确范围后执行，不顺带删除既有历史归档。

恢复演练在独立库验证完整性、归属、最新更正和遗忘防恢复，绝不覆盖在线库。存储位置、保留策略和是否参与同步需在部署清单明示。个人数据通过受控接口导出，默认日志/源码发布不携带正文。

大语言模型权重、Ollama数据和下载缓存继续位于D盘项目外目录；本计划和证据进入统一分析目录，不复制模型或虚拟环境。

## 9. 验收矩阵与证据

| 检查 | 必须观察到的结果 |
| --- | --- |
| 跨会话/重启 | 确认称呼、项目和偏好后新建会话，再分别重启服务/UI；只在授权档案中正确读取 |
| 访客隔离 | 访客直接问姓名/偏好、继续他人会话、传入他人ID均不泄露；普通自报姓名不能切换档案 |
| 迁移与旧库 | 使用离线旧库夹具迁移，数量/归属/排除记录一致，重复迁移幂等，失败不留下半迁移库 |
| 更正 | ASR错名确认更正后，直接问及换说法都不返回旧值；旧生成/ACK/后台任务提交失败 |
| 遗忘全链 | 删除前已形成摘要与索引，删除后同会话/新会话/重启/重建索引/恢复旧备份均不召回 |
| 作用范围 | 清空会话不删除个人事实；清空个人活动记忆不影响别的归属；新对话不等于删档案 |
| 摘要与待办 | 20轮以上含干扰话题；预设关键事实与未完事项逐项核验，完成事项有实际依据 |
| 临时状态 | 明确到期和无日期两种输入，过期后不作当前状态；板端异常时间不影响有效期 |
| 取消与失败 | 生成/TTS/网络/播放失败、重复请求和切换中断不制造“已听过”“已完成”；明确记忆写入按提交规则保持 |
| 运行成本 | 记录存储查询、上下文构建、维护排队、ASR/LLM/TTS/首声、token、显存峰值、JSON成功率；同负载比较，门槛在上线前冻结 |
| 真人与长稳 | 板端新录音逐项听音；30—60分钟持续多话题及打断，保存通过/失败和版本，不用文字测试替代 |

交付物：schema与迁移说明、归属/命令接口、配置、离线数据夹具、测试结果、真人验收记录、运行版本/哈希、部署与回退手册、数据范围清单。测试数量不相加成完成百分比。验收正文使用合成资料，真人证据脱敏。

## 10. 下一次实施的明确起点

先执行P0并实现P1的离线候选：把现有匿名会话与个人档案分开，跑通常用用户/访客、跨会话事实及归属校验；通过迁移和隔离测试后再准备正式部署。暂不自动导入现有109个会话、不启用摘要后台任务、不改在线上下文、不删除数据。第一项可交付成果是可审查的数据合同、迁移演练和单用户/访客端到端候选，不是先扩大记忆条数。
