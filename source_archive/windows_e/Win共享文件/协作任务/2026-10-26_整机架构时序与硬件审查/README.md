# AURA 整机架构时序与硬件审查

2026-10-26。范围为现役系统架构、感知到执行的时序合同、最终 FPGA 检查点、隔离与动力链、USB 和语音并发，以及部署与数据归属。用户现场确认：**舵机接 J2.3，经过 ADuM1201**，基本按项目文件接线。

**主要问题集中在层与层的衔接：运动源绝对截止没有硬件保证，机械标定与控制参数不匹配，隔离器之后的掉电停止链未完成验收，USB 复发与软件尾延迟仍影响整机稳定。当前 FPGA 已布通、setup/hold 通过，但跨时钟解释、资源余量和约束签核还需补齐。** 这些结论不否定三模型 DPU、真实语音和有限实体转动的已有成果。

本轮只做本机源码/资料审查、模拟反例和 Vivado 报告。未连接板卡或 Windows、切换服务/固件、运行模型、开麦播放、操作舵机或读取私人数据库。实板状态引用最新封存交付，不代表本轮实时测量。

ADuM1201 的 B 通道是 VIB→VOB。ADI 真值表明确：VDD1 未供电、VDD2 仍供电时，VOB 默认高。这个高电平本身不证明舵机会转，但它不能充当“失效即低”的停止证据。器件自身的正常传播延迟远小于当前毫秒级控制等待，不应把随动迟缓直接归因于数字隔离延迟。[ADI 数据手册，表16/18及应用说明](https://www.analog.com/media/en/technical-documentation/data-sheets/adum1200_1201.pdf)

若停止合同要求在处理器/FPGA掉电后仍强制安全状态，应由默认关闭的负载开关、经验证的接收侧门控/看门狗或合适失效电平的隔离方案承担。**不能指望一个下拉电阻压过隔离器主动输出的高电平。** ADuM1201 两通道方向相反，也不能当两个同向输出分别传 PWM 和使能。上述是方案修正方向，本轮未改线或换器件。

项目原件已要求“PWM停止、动力切断、机械停止分别测”。当前数字 STOP 读回与有限肉眼观察没有覆盖隔离后断电波形、独立动力停止、负载失保持及线束拉力。舵机端的储能电容还可能延后实际失电，不能直接用开关逻辑沿代替机械停止时间。

MCP01、相机、触摸实测处于同一个 USB2 Hub 上行：`1-1.2`、`1-1.3`、`1-1.1`，不是三个独立主控。相机当前640×480 YUYV/30fps的纯图像载荷约18.432MB/s，MCP01播放约0.192MB/s；简单相加不能证明等时调度、TT、DMA或供电均有余量。板卡官方预算是每口900mA、四口总2.1A，Pmod3.3V/100mA；实际电流、启动压降和线损没有本轮测量。[AMD UG1089 供电预算](https://docs.amd.com/r/en-US/ug1089-kv260-starter-kit/Powering-the-Starter-Kit-and-Power-Budgets)

## 3 感知到实体的时序问题

现链路为：UVC采集 → PS转换/检测跟踪 → 单DPU原生调度 → 当前脸图与检测锚 → PS控制/轨迹 → AXI提交 → PL 50Hz帧 → ADuM1201 → 舵机内部位置闭环与机构。每个阶段都需要自己的输入归属、时间与终态；模型返回、命令ACK、PWM更新和轴移动是四种不同证据。

### 源有效期和首帧预算

当前控制期限是 `min(当前图时刻+250ms, 检测锚时刻+500ms)`。r14要求首次预算至少覆盖20ms提交余量、23ms首PWM租约和3ms预检余量，合计需大于约46ms。它已修复原6/11ms短租约只输出旧角度的问题。

前一r12/v16真人窗口的滚动256源统计：图龄P95 129ms、锚龄P95 439ms、源间隔最大798ms。因此，锚龄到439ms时只剩61ms期限，首帧准备仅余约15ms额外空间；798ms断档也无法靠滤波填平。这里是按两个合同做的算术示例，**不是把不同P95相加得到最坏延迟**。v17已显著减少预处理，但新版本目前主要是无人窗口，仍需有人同负载验证连续有效源。

v17对齐24轮NoFace记录里，原生lease中位约2.241ms，整个检测process墙钟中位约39.704ms。输入等待、CPU预后处理、GIL/调度和消费仍需单独记录，不能把它们全算作DPU执行。20ms控制循环运行在通用Linux上，还依赖HTTP读流、寄存器访问和报告输出；目前没有整机压力下的确定上界。

### 绝对截止仍存在最后提交窗口

本轮用当前r14同SHA的 `DeadlineDriver` 加模拟寄存器复现：源10.000s、截止10.250s，在最终检查之后、模拟MMIO写内部暂停300ms，COMMIT于10.300s被接受，相对租约可到10.530s。新软件随后检测并STOP，最终返回REJECTED；它没有预防此前已发生的迟到提交。这是本地故障注入，不是实物多转了280ms的测量。[反例数字](evidence/software_probes.json)

若目标是独立硬件源截止，PL必须能识别可信的源期限或与源时钟有界转换后的期限。仅把Python检查移到C或提交后再查仍会缩窄而非彻底消除暂停窗口。不要把Windows单调时间直接写成PL绝对时间；要定义时钟域、启动代次、转换误差、计数回绕和过期优先级，再验证PS停顿/重启/重复旧源。

另外，现相机源码使用 `appsink_dequeue_monotonic`，在pull-sample/数据提取后打应用时标，没有将驱动采集时间或曝光时间直接带入控制合同。因此“250ms”目前只约束这一起点之后的年龄；上游USB/驱动/转换等待仍需测量或保守计入。`max-buffers=1/drop=true`是正确的限队措施，不能自动证明传感器到应用无积压。

### 机械量与控制量没有完成对应

当前软件最大20µs/s、浅越线最低6µs/s，而命令输出取整数µs。即使忽略加速，积累1µs分别需50/167ms；按商家3µs死区简单做量级比较则为150/500ms。这不是机械首动保证，实际死区/回差可能不同。按附件180°/2000µs线性标称估算，20µs/s也仅约1.8°/s；必须通过实机角度/PWM标定判断是否符合桌面随动要求。

Ruckig只约束持续轨迹的相应段。当前按用户规则回安全区立即保持、失跟/过期STOP、每源4µs硬额度均可能重置速度/加速度；不能把“用了Ruckig”写成整条实体轨迹始终满足jerk限制。先保留停止和时效要求，再区分正常减速、失效停止与量化响应，不通过续用旧源换平滑。

新增模型是复用同一DPU时分执行，主要增加PS、DDR与排队压力，不会按模型个数直接复制DPU逻辑。若新增PL仲裁/监督逻辑，则需另做资源估算与联合实现。本次不建议用扩大DPU或放宽时序约束代替感知输入与CPU准备优化。

## 5 整机架构和交付衔接

三端划分本身可行：KV260负责真实传感、板端视觉/播放/运动；Windows承载较重的语音模型和个人记忆；Ubuntu负责构建与部署。当前真正缺的是最终组合下统一的任务归属、依赖、就绪、取消、恢复和发布证据，而不是再把已有模块从头开发。

- **采集/音频实时性。** 当前远端GTCRN/VAD每20ms帧做一次同步往返，默认事务超时180ms；长期平均服务时间必须跟得上20ms生产率，且需测捕获积压/xrun。历史600帧短窗P95 7.091ms、最大21.377ms，不能证明持续超载，也不足以验收网络长尾。可先异步限队/保留原始PCM时标，或按已验证余量评估本地VAD，不能简单丢音频帧破坏ASR/声画归属。
- **音频逻辑停止与实际尾音。** 本轮受控堵塞下游中，stop后Python队列清空，但已提交的3840B/80ms输入PCM仍留在模拟原生队列。该数字不是实板尾音测量；它证明当前接口不承诺清空原生播放缓冲。新队列上限已经改善异常态，后续应验收插话/切档/错误后的真实停止上界。
- **运行时健康。** GUI、相机、DPU owner、声音设备、USB端点、Windows依赖和实体输出各有不同健康层。`active`、`identity_ready`、`IDLE_READY`不能统一缩成一个“整机正常”。本轮还复现多字寄存器读回跨越lease到期时，ACK不变却混合读到active=true和lease=0；这是现有尽力采样的边界，未证明它能绕过PL停止。需要原子状态快照或显式一致性/重试规则改善诊断。
- **模型与身份搭配。** 三视觉模型已有DPU业务，语音ASR/27B/TTS已有真实链路；真实当前图问答和Light-ASD没有整链完成证据。人脸、声纹、说话人选择和档案授权各有用途，当前默认访客、显式授权的个人记忆机制是正确方向；个人后端已加载，正式板端选档仍是候选，不把空旧回执当“Windows没做”。
- **版本与持久数据。** 共享源码树、板端冻结根和覆盖层都存在。需要记录“实际启动入口＋基础版本＋补丁闭包”，不是只打包某一个aura目录。SQLite运行库在同步树的现状需有可靠排除或迁出安排；本轮未读库正文，也没有证明已发生同步损坏。一致备份应走SQLite备份机制。[SQLite对活动事务复制的说明](https://www.sqlite.org/howtocorrupt.html#_backup_or_restore_while_a_transaction_is_active)
- **时钟与冷启。** 板端墙钟仍为2021，当前运动期限和主机授权TTL使用各自单调时钟，这不自动构成TTL失效。但跨机日志、证据排序和重放不能直接相减；需UTC/boot/单调跨度与转换误差分开记录。HDMI冷启花屏仍按用户决定暂停，已有业务自动恢复不能扩为实体显示和整机冷启通过。
