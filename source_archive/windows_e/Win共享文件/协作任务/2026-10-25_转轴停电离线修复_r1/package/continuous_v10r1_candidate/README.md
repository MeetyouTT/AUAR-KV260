# v10r1 停电期间离线候选

**仅主机验证，未部署、未上板、未做实体随动验收。** 板端最后已知版本仍为v9；本目录不会自动改变板端配置。

本轮集中修复三类可复现的软件问题：

1. 单帧回区不再重开3µs纠偏额度。回区仍立即停止角度变化，稳定回区250ms且至少三张不同新图才允许下一轮；未确认、跳变、断流会中断稳定确认。
2. 有效新图在旧许可将到期时到达，直接用该新图续交**当前角度**，避免等待下一20ms tick导致无谓丢ARM。重复帧、无图或失效刷新不能走该续交路径。
3. 每次轨迹及驱动许可同时受`source_mono_ms+250ms`和`face_detection_mono_ms+500ms`限制，取更早者，再扣除既有20ms提交余量。真实检测锚不全、过期或被同源包改写均拒绝；短暂EXPIRED刷新最多沿用原图的原批准窗口，不能扩展任何截止。

原速度10µs/s、单轮3µs、全行程1400..1600µs、每真实新图最多4µs及PL保护不扩大。3µs仍是小幅诊断模式，修复不等于完整持续跟随已完成。Ruckig状态是命令状态，不是实测轴角；整数脉宽、回区freeze和STOP不享有数学连续jerk保证。

## 离线结果

48项软件检查及Python编译通过；13组成对合成回放使用同一份真实Ruckig主机数学库和FakeDevice：

| 合成场景 | 原v9 | 本候选 |
|---|---:|---:|
| 单帧回区穿插六轮越界，左右分别测试 | 累计18µs | 累计3µs |
| 四轮稳定回区再越界 | 4次ARM，累计12µs | 1次ARM，累计12µs |
| 短暂EXPIRED刷新后及时获得新图 | 会话已停 | 保留原合法会话 |
| 检测锚只剩50ms而图像较新 | 合成许可可越过锚界120ms | 不越过锚截止 |
| 真丢脸、多脸、冻结、错boot、身体输入 | 停止或拒绝 | 停止或拒绝 |

这是已知输入的软件反例与对照，不是新实板测量、帧率收益、实体延迟或电气波形证明。较早v10候选未同时钳制检测锚截止，保留其历史封存；来电后应审查本候选而非将旧v10直接部署。

## 复验

独立验证包按原相对目录保存`continuous_v9/`、本目录、`common/`、`offline_host_driver/`及`ps_trajectory_v1/`的主机数学依赖。在Linux x86_64运行：

```sh
python3 continuous_v10r1_candidate/verify_offline.py --output /tmp/aura-pan-offline-result.json
```

输出路径必须不存在，防止覆盖旧证据。该入口只读取本地文件、加载主机数学库并使用FakeDevice，不连接串口、网络、相机或MMIO。它不是Windows原生运行包，也不是整机最终发布包。

`recovery/read_only_resume_after_outage.py`另供来电后由唯一板卡终端运行：只收集新boot、服务和停止状态，不改配置、不启运动。它在x86主机上明确拒绝执行；目标板加载与检查仍待来电验证。

来电时先断开转轴动力，检查新boot/固件/FDT/VART和持久故障记录，再确认位置与有限动作许可。不能只改旧boot字段、清预算或自动恢复跟随。
