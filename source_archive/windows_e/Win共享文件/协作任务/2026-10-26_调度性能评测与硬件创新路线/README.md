# AURA 调度性能评测与硬件创新路线

2026-10-26。建议以“信息有效期、任务服务机会与FPGA执行截止协同”为研究主线，先得到正确的逐请求性能记录和同负载软件基线，再实现独立的PL源截止监督。模型分块、总线预算、音频特征流水线可作为后续分支，按实测瓶颈选择。

当前是单B4096上的三模型时分执行。已有INT8量化、原生唯一owner、主任务保留及可选任务30ms预算/5ms余量。本轮只做源码/历史数值审查和论文调研；没有接板、运行模型、修改生产或恢复用户暂停的机构改造。最新断电交接仍适用。[前轮状态与论文对照](../2026-10-26_项目优势与多模型调度论文对照/README.md)

## 适合现有平台的加速方法

| 方法 | 加速或保障什么 | 对本项目的选择 |
| --- | --- | --- |
| INT8与结构化通道剪枝 | 降低网络计算、模型存储和数据流量 | INT8已完成。剪枝须真正删通道、重新训练/量化/编译；固定DPU不会因权重变稀疏就自动减少LUT或获得零值跳过收益 |
| HLS流式流水线、算子融合、双缓冲 | 减少中间拷贝、DDR往返及CPU准备 | 针对已测热点选择；当前输入LUT软件优化已经存在，必须与优化后的CPU路径比较。图像resize/颜色转换/量化有官方KV260先例，但需按USB输入与现役B4096重新集成 |
| 音频分帧、加窗、FFT、功率谱、Mel滤波流水线 | 为声纹/ASR提供声学特征 | 使用PL FFT/HLS库作为积木，Mel/log等需自建并对齐既有前处理。它不等于将Paraformer或OmniVoice整网搬到DPU；16kHz音频下DMA和调度成本可能超过计算收益，先画像 |
| 网络分块与块边界调度 | 缩短长任务对紧急任务的阻塞 | 需要分块xmodel、边界张量、重新编译与等价测试；当前整次VART执行不能任意中断。仅在完整任务阻塞确实有害时考虑 |
| AXI带宽预算与突发拆分 | 降低共享内存干扰，改善尾延迟可预测性 | 先证明DDR/互连争用是瓶颈，再改总线拓扑。当前USB告警/GIL等待不能直接作为带宽根因证据 |
| PL任务准入、时间比较和源截止监督 | 降低决策抖动、独立拒绝过期输出 | 最贴近自研硬件贡献。先实现小而明确的源截止监督，再比较同策略PS/PL仲裁成本；不能预设几次比较器运算会明显缩短秒级语音等待 |

预处理依据：[AMD KV260硬件架构](https://xilinx.github.io/kria-apps-docs/kv260/2021.1/build/html/docs/smartcamera/docs/hw_arch_accel.html)。该示例为另一版本和B3136，不是本项目位流。音频FFT积木依据：[Vitis DSP PL库](https://xilinx.github.io/Vitis_Libraries/dsp/2021.1/index.html)。K26路径选择PL/HLS，不套用AI Engine专用实现。

现役全设计LUT约57.18%、使用过的CLB约95.41%、URAM87.5%，最紧WNS0.001ns。CLB占用不是LUT占用，但新增核仍须独立综合和联合布线，不能直接按空闲百分比承诺能放入。INT4、通用Winograd或新的稀疏执行引擎也不是现有DPU运行时开关。[硬件审查](../2026-10-26_整机架构时序与硬件审查/README.md)

## 当前测量存在的具体缺口

1. 原生版`NativeDpuSchedule.primary()`只宣布下一主任务期限并保存线程局部状态。`ui_camera_service.py`在进入此上下文后、调用`detect_bgr`之前就记录`yolo.schedule_wait`；真实执行权等待发生在后续原生调用。因此该字段不能作为真正DPU排队延迟。修正时应新增语义清楚的字段/版本，不直接把历史值改名追认。
2. `PipelineMetrics`默认每阶段保留256个样本，只导出recent P50/P95。不能从P95推出P99，也不能平均不同窗口P95得到全程P95。
3. 阶段聚合没有逐作业的源时间、到达、准入、完成和消费关联。不同阶段分位数不能直接相加为端到端P95。
4. 被拒绝、过期、被更新帧覆盖和测试结束仍未完成的任务必须计数；只看成功任务会产生选择偏差。当前数据不足以计算完整服务成功率与最长请求等待。

代码依据为[原生r4源码](../../语音共享文件/deliverables/2026-10-24_native_critical_live/source/aura/board/vision/pipeline_metrics.py)、[实际插桩位置](../../语音共享文件/deliverables/2026-10-24_native_critical_live/source/aura/board/vision/ui_camera_service.py)。未修改这些文件。

## 应怎样测调度性能

每个逻辑请求记录job_id、模型/输入版本、boot与时间域、源时间及语义、原始到达、依赖就绪、进入队列、获得执行权、VART提交、确认完成、发布、实际消费、源截止、请求截止及终态原因。重试保留原始到达，另记attempt_id；不靠重试重置等待时长。SFace依赖同源合格脸，依赖等待与DPU排队分别统计。多端单调时钟不直接相减。

| 指标 | 定义或口径 | 用途 |
| --- | --- | --- |
| 执行权排队 | t_acquire - t_enqueue | 判断调度等待；包括未获准作业的等待/终态，不能只取成功 |
| 请求端到端 | t_consume - t_arrival | 包含准备、依赖、排队、执行和消费；未完成明确保留 |
| 消费时图龄/音频龄 | t_consume - t_source | 判断结果对业务还是否及时；注明源时间不是曝光的限制 |
| 有效完成率 | 截止前被当前业务接受的逻辑请求数 / 全部合格到达请求数 | 与拒绝、取消、过期、覆盖、失败及未完成分别核账 |
| 有效吞吐 | 有效完成请求数 / 窗口秒数 | 避免用无用计算填高吞吐 |
| 持续有效覆盖 | 观察时间内满足误差/时效条件的时长比例 | 避免只有成功发布瞬间好看；源中断也计入 |
| 服务公平性 | 各类等待分布、服务间隔、最大等待与未完成数量 | 检查人脸/声纹被饿死；过载时不能承诺全部请求有界完成 |
| CPU与资源 | 核秒/有效任务、RSS、经测量的搬运字节、DPU驱动忙时；功耗有仪器再报 | 解释成本与收益，不用CPU墙钟差冒充DPU时间 |

不能从现有快照补造逐作业日志。新增观测先测开销，使用有界缓冲/异步批量写入，结束时记录丢日志数；不要把每帧磁盘写入重新放到实时路径。

## 建议的算法与硬件分工

第一版保留当前10Hz主任务底线、30ms可选预算、5ms余量和所有期限检查，在同一个原生owner内增加可选任务的显式元数据队列，先比较FIFO、轮询和EDF。EDF指按绝对截止选择，不能把按period排序称为EDF。

候选策略按三层推进，分别消融：

1. **有效性和成本准入。** 先检查源/目标/请求代次、依赖和结果截止；既有完整任务预算不足时拒绝或延后。估算成本应包括CPU/DPU边界与必要后处理。P99加余量属于经验估计，不是WCET；第一轮不据短窗均值降低30ms保护。
2. **期限和等待次序。** 已满足准入的任务按剩余期限排序，为长期等待任务增加服务机会；业务等待目标无法满足时显式拒绝，不能通过放宽源期限继续处理旧数据。等待补偿不能压过主任务保留和失效规则。
3. **信息价值。** 在单独校准后，估计一次更新能减少多少位置误差或身份歧义，并结合计算成本调整任务选择/触发频率。价值模型不可靠时退回期限策略；不能使用测试集真值作为在线可见输入。

概念准入式为：

```text
预计排队/计算/必要后处理 + 保护余量
    <= min(请求截止, 源有效截止, 下一主任务保留边界) - 当前时刻
```

各项必须在同一时间域，不能重复计入已包含的开销；该概念式不是当前生产实现，也不构成硬实时证明。

PL先负责可信源截止比较、同观测不可续期、代次/序号校验和原子提交/拒绝；PS保留复杂的误差估计、模型业务和VART执行。后续若继续原定PL全模型仲裁目标，可把有限任务表、期限比较和授权令牌下沉，但须与同策略PS实现比较。取消结果不能提前释放尚在计算的DPU/GPU资源，网络授权也不等于PL可直接执行CUDA。

这一研究组合的候选贡献是：**把推理优化目标从“完成多少次计算”扩展为“在误差和时效约束内完成多少次可用服务”，并用独立硬件约束最终消费。** 目前尚未证明它比已知策略更优，也不主张全球首创。

## 可验证的实验与交付

先做软件阶段：保留共同的主任务保留、预算和结果有效性规则，只比较可准入任务的排队策略。这样得到的是“准入后FIFO/轮询/EDF”对照，不能写成未经限制的全局FIFO。当前基线按冻结源码原样运行；新增显式队列的开销先单独测量。实验矩阵见[experiment_matrix.csv](experiment_matrix.csv)，全部为计划，不覆盖原G0—G5。

固定公开输入、同请求到达序列、模型/阈值、CPU配置、热身和窗口长度；场景至少覆盖持续合法人脸输入、身份突发、并发音频/UI负载及可控CPU干扰。纯合成任务只能验证调度逻辑，模型收益必须有真实推理。跨次重复、交换A/B顺序，报告全部失败和未完成任务。

最终至少形成四张图：负载与有效吞吐/拒绝率；帧龄和请求等待CDF；各身份任务最长等待/有效完成率；故障注入下过期提交接受数。资源、观测开销和独立精度同时报告。PL试验先仿真和无动力数字输出，机械结果另验。

当源绝对期限硬件及可变有效期真实实现后，再执行既有G0—G5消融。若论文贡献是新策略，必须在公平基线下展示收益与失败边界；若贡献是硬件截止执行，应提供明确属性、实现及故障验证。将EDF搬到PL或新增一个模型，本身不足以证明新的算法贡献。

本轮提取的真实旧快照、字段语义核对及来源指纹见[evidence/audit.json](evidence/audit.json)。建议下一步交付逐请求测量合同与离线回放基线；不自动发起上板、硬件重构或生产调度更换。
