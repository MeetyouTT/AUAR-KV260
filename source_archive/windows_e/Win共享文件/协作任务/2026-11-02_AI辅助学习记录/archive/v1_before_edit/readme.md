## 这份材料写什么

建议标题：AURA项目AI辅助学习与工程实践记录。

每个案例围绕一个真实问题，保留“原有疑问—真实提问—AI可见回答—人工判断/采纳或否决—实施/查证—结果/纠错—本人学习总结”的过程。

按本项目本地AMD指南第3.3.3.1、3.3.5.3，AI协作应包含真实提示词、可见回答和纠错，并关联设计与验证。若学校或老师另有固定表格、页数、签字或附件要求，优先映射到实际模板；本项目目前未取得该额外模板。

## 推荐材料组合

1. 一份主报告：基本信息、使用范围、代表案例、个人学习总结和限制。
2. 对应原始问答附件：实际工具的导出件或可辨认的上下文截图；主报告可摘录关键轮次，注明删节与附件位置。
3. 工程证据索引：源码/配置、测试输入输出、报告、版本/时间和平台。

可以先从9个素材主题中选5–8个代表案例。这是整理建议，不是官方规定的数量或页数。

## 最容易写错的地方

- 工程日志可以证明操作和结果，但不能冒充逐字AI对话。
- 不清楚模型/工具版本就填“未记录”，不推测名称。
- 保留AI给错、条件不成立、自己否决和仍未解决的部分。
- 截图/摘录应保留必要上下文和时间，能看清问题与修改，不要求提交无关聊天。
- 旧机器的速度、缓存命中、模拟/板测和真实播放分别标注；新桌面5090不能套旧5060 Ti或Laptop研究结果。
- “自己实际做了什么”和“AI建议了什么”分别写，学习总结由本人确认。
- 无原始问答时标为工程复盘/原文待补，不从最终代码反向编写一段历史对话。
