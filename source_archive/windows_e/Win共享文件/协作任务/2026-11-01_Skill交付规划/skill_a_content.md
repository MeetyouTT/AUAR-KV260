# A包内容：FPGA执行监督与失效验证

拟用目录：command-guard-validation。
状态：文档稿。已有自研RTL、仿真及有限板测来源；独立Skill交付未验收。
负责人：A；B复核来源时间、代次与时效。

## 1. 使用目的

面向软件提出动作、FPGA按合同允许/拒绝/到期/停止的系统，提供从合同到性质、用例、参考、RTL和板测证据的复用方法。换板或换执行器时，替换寄存器、时钟和输出适配。

本包当前围绕已实现wide监督合同。输出脉宽是数字控制读回，不是机械角度。PL源绝对期限等新能力不混入已实现范围。

## 2. 输入材料

| 输入 | 必须说明的内容 |
| --- | --- |
| 工程身份 | RTL/bit/XSA/设备树/驱动的版本、配对与SHA |
| 寄存器合同 | 真实ABI、字段、位宽、单位、提交和确认顺序 |
| 平台 | 时钟/复位、地址映射、引脚与输出路径的依据 |
| 状态 | boot、会话、恢复代次、序号、当前许可/故障 |
| 限制 | 脉宽范围、更新步进、租约、STOP和到期语义 |
| 事件与结果 | 输入序列、软件/RTL预期、回读/波形和采集时刻 |

当前冻结RTL的参数有500..2500µs范围、20000µs帧、4µs步进、build 0x10282601；租约条件在该源码中为4..500ms。以上是特定源码值，不直接推定某次当前上板配置，也不凭DIVIDER参数猜真实集成时钟。

## 3. 执行流程

### 步骤A1 固定合同与工件

回收实际工程及驱动，核对配对与哈希；记录当前合同具备什么、缺什么。不同版本ABI不能混用。不从历史方案中的地址直接发MMIO命令。

### 步骤A2 从合同提取可验证性质

至少列正常提交、范围/租约、重放/乱序、会话/代次、半写提交、STOP、到期、复位和恢复。将性质与具体源码/字段关联。

源期限与相对租约分开：软件最终检查通过，不代表延迟到达PL的提交仍在源期限内；PL是否独立检查绝对源时间需另有实现与证据。

### 步骤A3 做参考和RTL事件对照

先用公开序列或软件参考验证，再给对应RTL相同语义输入。保留正常许可的正例和失败拒绝的反例。工具路径、工程根和报告位置应可配置，不能依赖作者的home目录。

### 步骤A4 按层级补板端证据

后续由原设备窗口核对新鲜平台与操作权，再进行所需数字读回/无动力波形。真实机构响应另验，不把寄存器清零等同机械立即停止。本轮文档不执行此步骤。

### 步骤A5 失败、修正与复用

保存原失败、最小触发、源码变化、同输入复测。另一使用者在新目录或另一明确配置下复用，记录依赖和问题。

## 4. 用例内容表

| 用例 | 预期检查 | 证据层级 |
| --- | --- | --- |
| 合法目标与租约 | 正常接受，不能以全部拒绝代替正确功能 | 软件、RTL、必要板测 |
| 目标恰在范围边界/越界 | 边界按合同，越界不获得许可 | 软件、RTL |
| 租约上下限与非法值 | 按真实合同接受/拒绝 | 软件、RTL |
| 重复/倒序序号 | 不重放或续发旧命令 | 软件、RTL |
| 旧会话/旧boot/旧恢复代次 | 不继承新上下文许可 | 软件、RTL/板端 |
| 半写状态后提交 | 未满足原子合同的目标不能成为有效输出 | RTL/驱动 |
| 到期 | 按合同完成禁能；脉冲结束与故障位如实记录 | RTL/波形 |
| STOP已确认 | 当前合同的flags/lease/active/armed等状态符合停止语义 | RTL/读回 |
| 复位/恢复 | 不让旧许可重新有效 | RTL/读回 |
| 最终软件检查后延迟 | 检查相对lease与源绝对截止的差别 | 参考/RTL/后续设计 |

本表是计划覆盖要求，不能一律标PASS。归一化日志检查只能验证日志中明确提供的行为，不证明原始采集完整、MMIO原子性或真实引脚波形。

## 5. 输出报告内容

每例记录case_id、合同/源SHA、输入、预期、实际、判定、拒绝原因、时间/时钟域、波形/回读索引、工具与环境。缺少源时间或输出测量时标UNKNOWN。

报告将软件参考、RTL、数字读回、外部PWM与机械结果分列。新包装器和已有RTL也分开：当前草稿包装器未确认通过，不据此宣布原RTL通过或失败。

另一使用者先替换合同与工具配置，从最小正常/停止序列开始，再补范围和重放等边界。只做日志适配时说明仅为日志层复用；换板、改ABI或机构后须重验对应层级。

正式内容应包括README、合同/配置示例、独立入口、正反例、冻结RTL/测试来源或取得方法、结果/波形索引、案例、manifest和复用记录。
