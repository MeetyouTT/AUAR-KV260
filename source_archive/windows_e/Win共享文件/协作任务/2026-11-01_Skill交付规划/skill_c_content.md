# C包内容：本地大模型语音交互优化与记忆一致性验证

拟用目录：llm-voice-runtime-optimization。
状态：文档稿。已有Windows及后续板端优化的多阶段来源；新桌面5090和独立Skill尚未验收。
负责人：C；B复核模型/数据与性能条件，A复核板端时钟/设备边界。

## 1. 目标与定位

固定明确的模型、质量、音色和业务条件，优化有效回复等待、GPU/CPU资源共存、上下文/记忆和播放交付。将成功与未采用方案整理为他人可执行的方法。

近期工作主要是推理流程和交互系统优化；不命名为自主训练/微调新LLM，也不承诺所有回答固定提速。旧async-result-validation保留为本包子模块。

当前已核对方案是板端负责业务、记忆、ASR/前端、播放与显示，Windows负责原27B/OmniVoice推理。旧Windows权威数据库和旧启动入口只用于各自历史版本，新机具体分工以迁移回执为准。

## 2. 输入规范

| 输入 | 应记录的内容 |
| --- | --- |
| 环境 | platform_id、实际GPU/显存/驱动、Python、后端和依赖 |
| 模型 | LLM/TTS/ASR版本、SHA、量化、上下文/输出预算、音色/精度/步数 |
| 请求 | 公共输入/SHA、任务类别、会话/请求/代次、期限、提示/配置版本 |
| 资源 | 所属模型/worker、冷暖状态、共存模型、线程、显存与队列 |
| 测量 | ASR、首原始token、首有效正文、台词就绪、首PCM、入队/ACK、声学首声的起点与时钟 |
| 质量 | 预期语义、实际内容/正确性、缓存命中、误识/截断/复述/取消和失败 |
| 记忆 | 授权范围、来源ID/版本、是否已完整播放、摘要校验和撤销事件 |

公开样例可使用合成语句、匿名会话和临时SQLite，不读取生产私人数据。没有正确性依据时不能把短错误回答计成优化成功。

## 3. 模块一：计时与优化决策

流程：固定版本/输入/条件→预热和冷启动分层→采样→质量检查→阶段统计→保留无效测量/失败→解释采用或撤回。

首token、正文、首音频、音频入队和扬声器首声分别报告。并行LLM与TTS阶段不能简单相加；网络到达不等于真实播放。没有声学测量就不报告声学首声。

统计按机器、后端、模型、输入/任务组、冷暖与缓存分组，记录样本数和失败。旧5060 Ti与新5090不合并统计；自由回复小样本和共享负载对照只作描述性结果。

## 4. 模块二：LLM路由、结构化输出与历史表示

已有主题包括正文优先、内部短字段映射、Unicode/分包解析、聊天/思考分流、防复述和历史表示复用。

验证重点：

- 普通闲聊、程度副词和否定请求不误触长思考；真正推理请求保留对应路径。
- 改内部字段不丢正文/情绪/动作语义；截断、重复键、格式错误按合同处理。
- 回复复述、错误答案和内容变化保留质量记录；开启thinking不保证算术正确。
- 历史表示复用按完整ACK、代次、正文一致性和预算生效；没有KV命中数据就不将全部收益归因KV缓存。
- 依赖内部runner/build的优化注明版本和回退条件；compact_grammar等旧方案不自动恢复到当前新机。

## 5. 模块三：有界记忆、摘要和来源一致性

用户输入提交、助手已播历史、事实和摘要是不同记录。助手只有匹配完整播放ACK才进入已交付可召回历史；部分播放不猜已播文本。

公开用例应覆盖：

1. 同会话近期信息与有界上下文，超预算明确处理。
2. 当前事实、旧值、更正、遗忘与删除，默认作用域和授权。
3. 来源依赖失效后，旧生成、摘要和迟到ACK不得复活被撤销信息。
4. 摘要先校验并提交，再按策略清正文；失败保留原文、任务和原因。
5. 新对话/另一档案不继承未授权历史；视觉/声音候选不自动授予个人记忆。
6. 自然五分钟存储检查、真实同会话召回、跨天体验分开验收。

已有自然五分钟存储结果为STORAGE_PASS_RECALL_PENDING；不能据此称新版本召回全部正确。公开语义对照、人工审核和当前运行状态分别记录。

## 6. 模块四：GPU余量与模型生命周期

记录实际驻留而非仅有模型文件；冷加载、暖解码、TTS预热/合成增量和已分配/保留的空闲缓存区分。

既有方法包括有限准入/排队、请求原总时限、取消、流水线背压、独立owner和保持模型暖态。取消消费不等于原生计算已经停止，不能提前归还仍在使用的资源。

新5090需要重新校准余量和峰值。旧16GB机器的reserve/暖TTS/冷TTS/LLM预算及CPU/GPU分配仅作历史案例，不按新卡名称直接放大，也不自动卸载其他模型。

常驻、Stop和释放所属模型分别定义；进程/模型归属需实际核对。复制文件、进程启动或health显示模型存在都不单独证明真实任务成功。

## 7. 模块五：语音前端、供音与异步保护

包括降噪/VAD选择、结束判定、ASR线程、句段/整句TTS取舍、非阻塞IPC、缓冲背压，以及请求/代次/段序/PCM哈希/样本数/完整ACK。

应测正常交付、取消后迟到、错会话/代次、重复/缺段、错误ACK、资源交接、来源撤销和重连。公开回放只说明所测逻辑，不代替麦克风、扬声器、回声或完整双工。

当前半双工与历史受控插话是不同阶段。GUI/业务/模型若未READY，不借用旧听音记录宣称新版本通过。

## 8. 必须保留的真实优化案例

| 案例 | 保存的结果 | 必须注明的边界 |
| --- | --- | --- |
| 短字段 | 台词就绪约2763→2288ms | 少量配对模型阶段，非声学首声 |
| 历史表示 | 既有四轮固定seed对照有改善 | 无底层KV命中计数，包含输出变化 |
| 事实直答/缓存 | 重复首PCM约2.656→0.110s | 含TTS缓存，不是普通聊天或模型本体加速 |
| r9历史分流 | 各8次未缓存首PCM约4.052→3.801s | 自由回复/共享负载，普通聊天长尾仍未验收 |
| 空闲缓存 | 某次归还约2.71GiB reserved | 显存结果，不能直接换算延迟收益 |
| GPU共存 | adaptive小样本最低空闲1656MiB | 旧机器，非任意负载不OOM保证 |
| 音频IPC | 反压测试最大供音间隔约200→24.6ms | fakesink/自有管道，同PCM，非声学A/B |
| 逐句TTS | 首段可交付约2037→676ms | 软件时刻，非扬声器首声 |
| DFlash/Graph/串行TTS | 有未采用或收益不足结果 | 保留失败与恢复；新5090需重新验证 |

早期empty_cache无可靠时延收益未采用，后来为释放空闲显存采用，评价目标不同。原生流式TTS有低首包但内容错误的方案，不能用最快值代表可用语音。

## 9. 提示词工作流正文

第一轮：请根据带版本的阶段日志定位等待，区分推理、序列化、排队、TTS和播放；列尚不能归因的差异，不用外部硬件成绩代替本机结果。

第二轮：在保持模型/音色/质量条件的前提下提出最小改动与对照；明确冷暖、缓存、并行重叠、共存负载与内容正确性检查。

第三轮：根据实际输出判断采用/撤回，保存错误、无效测量和恢复结果；小样本改善不能写成稳定承诺。

第四轮：针对公开记忆与交付用例核对来源、范围、摘要、完整ACK和撤销；测试逻辑、真实模型语义与设备效果分层报告。

## 10. 新机迁移和正式交付标准

桌面RTX5090由用户确认，当前在复制文件。实际GPU、显存、驱动/Python/后端、模型路径与服务状态尚无本机可见的新回执；旧Laptop研究和旧5060 Ti数据均不当新机实测。

正式包应包含说明/流程、指标规范、路由/输出公共用例、SQLite或来源验证案例、异步回放、资源与模型适配说明、公开预期报告、真实采用/撤回案例、环境/源清单和独立复用记录。

首版可先限定离线方法与公开小样；真实LLM/TTS/GPU、同会话召回、声学首声及稳定性另验。内容完整不等于当前所有功能已闭环。
