## 3. 一条贯穿三包的主线

有限资源下，怎样让视觉与身份任务及时产生有效结果，并让过期、取消或归属错误的结果不再影响交互或执行：

- B负责模型、任务和结果的计算/时效。
- A负责按当前真实合同监督最终数字输出。
- C负责LLM/语音流程、资源与可追溯记忆，并保持结果消费正确。
- 公共附录固定版本、时间、输入/输出与证据关系。

当前最有证据的是软硬件集成和分阶段优化。可变有效期、四模型共享、PL绝对源期限和新5090收益仍需对应实验，不把研究建议写成完成成果。

## 4. 所有包统一写清的字段

| 项目 | 内容 |
| --- | --- |
| 使用条件 | 操作系统、工具/依赖、后端、硬件/模型版本、需要的权限或设备窗口 |
| 输入 | 文件格式、字段含义、单位、时钟域、来源和预期结果 |
| 操作流程 | 正常路径、错误处理、复测和产物位置 |
| 输出 | 逐例判断、统计口径、缺项、原始证据索引 |
| 真实案例 | 原问题、可核验失败、修改点、同条件复测与未解决项 |
| 复用 | 另一使用者换目录、配置、模型接口或日志字段后的实际记录 |
| 限制 | 不支持的输入、缺少的验证层级、失败时的明确状态 |
| 版本 | 源/工具/配置/数据的标识和SHA，以及报告生成时间 |

判定至少分PASS、FAIL、UNKNOWN、NOT_APPLICABLE。正例和反例一起验；反例按预期被拒绝可算该用例通过，不能把“所有任务被拒绝”当业务成功。缺项不填0。

## 5. 验证层级必须分开

| 层级 | 能说明什么 | 不能据此说明什么 |
| --- | --- | --- |
| 文档/静态检查 | 资料、路径和格式存在 | 功能正确、环境可用 |
| 合成离线用例 | 指定工具/逻辑对公开样例的行为 | 实际硬件、真实模型或现场效果 |
| 软件参考/RTL仿真 | 指定版本的逻辑/波形满足已测合同 | 引脚、机械、长期可靠性 |
| 模型固定输入/板端验证 | 对应模型、输入、后端执行与输出 | 所有真实场景的精度或最坏时延 |
| 真实交互 | 对应版本与条件下的听音、显示、控制和恢复 | 新平台或更长负载下自动成立 |
| 独立复用 | 明确环境/适配范围内可复现 | 所有板卡、协议或模型通用 |

历史业务测试只用于其原范围。新Skill的测试、新电脑复测和原项目旧测试分别记录，不叠加成一个“全部通过”数字。

## 6. 5090换机后哪些沿用、哪些重验

可以沿用：真实问题与取舍、方法说明、源代码、公开样例、指标定义及带平台标识的旧证据。

需要重验：Python/DLL/依赖环境、GPU驱动与实际CUDA计算、模型外部路径/完整性、后端版本、服务READY/唯一owner、板端通信、内容/记忆正确性、冷暖/缓存分层性能、停止恢复。

不能直接套用旧5060 Ti 16GB的显存准入阈值、延迟或DFlash否决结论，也不能把早期“5090 Laptop 24GB研究”当成这台桌面卡的实测。新机实际参数未知时写UNKNOWN，不按显卡名称猜测迁移完成。

目前本机共享入口仍主要是11月1日及更早的运行记录；未看到新桌面5090环境/模型/服务/性能的验收回执。这与用户“文件正在移植”的描述分别记录，不据此诊断同步故障。

## 7. 当前缺口与任务优先级

1. 先审阅本套内容，明确各包边界和新机迁移字段。
2. 文件迁移完成后，Windows负责人记录实际环境、路径和模型清单。
3. 按选定版本形成各包最小独立实现，补公开正反例与复用。
4. 在新机验证C的真实模型/GPU/协议；在原平台窗口验证A/B需要的板端部分。
5. 声纹先做同模型基线与DPU兼容/量化质量，成功后再加入共享调度。
6. 同一冻结版本下补整机、长稳、设计报告、AI协作记录及最终提交。

上述为后续顺序，本轮不执行工具实现或功能实验。原一日安排仅能作为限定范围初版估算，不保证本套所有能力、新声纹DPU及新机迁移同日闭环。
