# 固定轨迹隔离：仅离线计划

本目录没有板卡连接、MMIO适配器或伪造人脸帧。使用现役 Ruckig 的主机数学库生成完整数值表，并提供只接受外部注入适配器的有限执行核心。1420µs 是历史用户参考；旧末值1426µs不是本次来电后的实际位置。**未实测、未部署、CLI不能直接运行实体转轴。**

查到原 `bench_finite_step.py` 的“2秒小步”实际是保持初值1秒、一次跳到目标（最多5µs）、保持1秒，每40ms提交100ms租约。它可验证有限动作和停止，但不是平滑轨迹，不能直接拿其手感与视觉模式作同条件对比。

新固定数值方案每20ms算一次：期望速度依次为 `+10、0、−10、0 µs/s`，每段0.5秒；两秒内从参考到+5µs再返回。反方向也计算。速度上限20、加速度100、jerk800，现役PL1400..1600不变。每条101个完整样本，无丢失；端点速度/加速度为零，最大整数目标变化1µs。**历史manual窗口仅1402..1420，因此1420→1425只是数值对称验证，不能沿用为现场许可；确认1420参考后可优先选择负向1415往返。**

离线结果还有一个有用结论：即使没有视觉等待，当前约束下首个整数目标变化仍在160ms；到1/2/3/4/5µs分别160/280/380/480/580ms。整数目标常隔100ms才变化一次，往返中间最大580ms包含减速和停稳等待。连续轨迹平滑不代表整数脉宽或实体轴已经平滑；这些数值不能当机械响应时间或死区测量。

`OFFLINE_FIXED_PLAN.json` 包含两条完整轨迹、源指纹与限制。原r14实测只有220/234条命令可重建、范围1402..1449，不能伪称与本次5µs方案配对比较。其10段首变化目标提交197～338ms保留为历史证据。

返场只需做一次有判别力的对照：

1. 主终端核对新boot、固件、唯一owner、输出停止、现场参考和当前有限范围；不拿旧1426或寄存器默认值当当前角度。
2. 在已确认参考附近执行一条有限±5µs平滑往返，复用原bench的上下文/ACK/超时/QUIESCE/STOP框架，替换旧阶跃调度；不要直接重跑旧boot执行文件。
3. 同一初始位置、负载和幅度下做r15短时脸随动；保留原图250ms、检测锚500ms及每源4µs约束，固定bench许可不得伪装成人脸源。保存完整ACK、实际提交时刻、原源时刻和所有STOP原因，必要时扩大仅该有限窗口的内存记录，结束再写盘。
4. 固定轨迹也顿挫：继续查PWM实际连续性/脉宽量化、舵机最小可见步长、机构负载和供电；固定顺而视觉顿：按源空档/反复停止/输入到提交延迟定位。两者是下一步实验分支，尚不是本轮结论。

`run_fixed_motion.py` 已实现可评审的有限执行核心，测试仅注入 FakeDriver：

- 要求适配器已独占并验证本boot硬件、现场参考与窄范围许可；`BenchPermit`只是这些约束的记录，不是授权证明。当前STOP读回必须等于现场参考，默认1500不能冒充历史1420。
- 同一2秒截止传给每次 `submit_bench`，不使用人脸源接口。共98次完整提交到1.94秒，最后40ms预留QUIESCE/STOP；第101点是离线终点校核，不在截止处重新发租约。轨迹在约1.724秒已回参考静止。
- 绝对20ms时刻调度；迟到超20ms或实际提交间隔少于10ms立即停止，不补发积压命令。记录每次实际提交、ACK采样时间及独立标量快照，适配器复用字典不会改写历史。
- ACK序号/session/epoch、目标、可解释的PWM帧锁存宽度和租约逐次核对。拒绝、异常、QUIESCE失败均执行finally STOP；STOP失败附加记录，不能覆盖原始控制错误。STOP不明确或返回超过截止均不得给出PASS。
- **真实硬件适配器尚未实现。** CLI默认`PLAN_ONLY`；`--execute`明确拒绝，不能通过填入几个布尔值就开启实板。未来适配器还须接现有同boot身份/独占锁/实测参考/许可核查、真实寄存器期限与ACK采样时刻。Python期限检查和FakeDriver独立时钟测试不解决现役native最终写阻塞的Q09问题，报告明确硬件绝对截止未保证。

不能完整复用原bench函数，因为它写死台阶目标；本核心复用了有限时长、ACK、QUIESCE/STOP的执行结构，实际身份/唯一owner适配还待接入。也不应向生产跟随接口注入周期生成的“新脸帧”来完成固定轨迹。
