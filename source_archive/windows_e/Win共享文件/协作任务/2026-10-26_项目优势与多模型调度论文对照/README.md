# AURA 项目优势与多模型调度论文对照

日期：2026-10-26。用于判断项目优势、研究贡献和答辩表述。当前最有证据支撑的优势是：在一套真实交互终端中，完成单DPU多模型推理、带时效约束的PS调度、自研PL运动监督，以及Windows语音服务协作。最有研究潜力的方向是把信息有效期、推理服务机会和最终动作许可统一起来；其优于基线的效果仍需公平实验。

本次是本地源码、历史实测和论文对照，没有连接KV260或Windows、重跑模型、改业务代码或部署。最新交接为r15/source-v17已配置、真人随动未验收即断电；用户已暂停宽范围和中点改动，本报告不恢复这些工作。见[最新停电交接](../2026-10-26_抽动延迟全链路复核_r15/README.md)。

## 共享调度实际做了什么

已核对[NativeDpuSchedule](/home/ghmd/aura-native-live-20261024/r4/candidate/aura/board/vision/native_schedule.py)及其[原生调度器](/home/ghmd/aura-native-critical-20261024/integrated/native-v2-560d824588eb8f8a/native/native_lease_v2.hpp)。这是已上板r4对应的冻结来源；后续运行状态需结合最新交接，不能用旧进程号代替当前实读。

原生调度器只有yolo、yunet、sface三种任务。主任务等待时不再准入新的可选任务；可选任务要求距离下一主任务截止至少35ms，即30ms占用预算加5ms余量。实际提交前再次核对期限与主任务等待状态。模型在执行时不因另一个任务到达而任意抢占；等待依赖条件变量通知，Python锁不跨整个推理调用。

返回后还要检查原始结果期限、执行状态和占用超限。已提交但未确认完成的作业会使owner进入保护，不能为了继续服务而直接当成资源已空闲。已确认的可选任务异常采用有次数与冷却的恢复，旧故障和恢复历史保留。

**30ms是准入及事后检测预算，不是30ms时硬件强制中止。** 源码在callback返回后计算hardcap和guard；因此该实现尚不能提供经过证明的最坏响应时间。身份最长等待及持续服务公平性也需要测量，不能仅由主任务优先推出所有任务都满足期限。

这套设计解决的是多个业务怎样共享资源、过期结果怎样拒用、异常后怎样可信地恢复。DPU忙时低也不代表整机有相同比例余量：CPU准备、USB、内存、Python/C++边界和业务消费都可能限制及时性。

## 与相关论文的关系

| 论文 | 论文处理的问题 | AURA可借鉴及当前差异 |
| --- | --- | --- |
| [Time-Predictable Acceleration of Deep Neural Networks on FPGA SoCs with Multi-Core DPUs，RTAS 2026](https://retis.santannapisa.it/~giorgio/paps/2026/Aromolo-RTAS26.pdf) | 多核DPU干扰、分块执行、优先级调度及响应时间分析 | 作者实验为ZCU102上三核B512、90MHz，采用总线流量预算。AURA为单B4096，尚无相同分块、ABU及分析保证，不能直接套用性能结论 |
| [Age-of-Information vs. Value-of-Information Scheduling，ICCPS 2019](https://arxiv.org/abs/1903.05356) | 信息年龄相同，不同系统动态下的控制价值仍不同 | 为按运动速度和不确定性选择有效期提供思路；当前固定250/500ms合同不能称为已验证的可变有效期方法 |
| [Computation and Communication Co-scheduling for Multi-Task Remote Inference，2025](https://arxiv.org/abs/2501.04231) | 联合分配计算与通信，降低时效相关推理误差 | 可用于设计板卡和Windows间的队列、依赖及资源合同。当前并未实现论文的MDP/MGF策略，也没有相应最优性结论 |
| [FPGA Stream-Monitoring of Real-time Properties，EMSOFT 2019](https://arxiv.org/abs/2003.12477) | 将RTLola规格编译为独立FPGA流监控器 | 支持把时间约束交给独立硬件监督的方向。AURA使用手写VSRV RTL，未复现该编译器；源绝对期限尚未落到现役PL |
| [Run Time Assurance教程](https://arxiv.org/abs/2110.03506) | 将复杂控制器与独立约束执行机制分离 | 可用来解释运动建议与输出许可分工；当前租约/限速/STOP不能被扩大为完整动力学安全证明 |

RTAS论文的关键价值是降低阻塞、约束干扰和改善可调度性，分块并不意味着单个网络总推理时间必然变短。对AURA，优先证明现有完整任务调度的收益；只有实际阻塞不能接受时，再评估模型分块与编译、搬运和精度成本。当前联合平台资源和时序余量也不支持未经评估就承诺新增DPU核。

本地[作者实验包](https://zenodo.org/records/19366892)已有109个条目，包含调度、模型切分和分析代码；本次复查没有RTL文件。README说明部分硬件实验通过预配置ZCU102远程提供，公开包不等于完整可直接部署的FPGA工程。已读调度源码使用period排序并调用VART，不能称为本项目的PL仲裁器或EDF实现。本次没有执行或复现作者实验。

## 最有潜力的项目贡献

可以围绕一个具体问题组织研究：**有限推理资源下，如何保持交互所需的信息及时可用，让身份任务获得服务，并阻止过期观测继续授权动作？**

人快速移动时，旧位置容易失效，应优先更新；人静止时，可在误差允许范围内给身份任务更多机会。若声纹后续上DPU，它能提供另一种到达模式和截止要求，适合检验策略能否扩展到音频身份，而不是预先把未编译模型计入成果。语音回答应使用自己的交互期限，不能套用运动证据的短期限。

原方案候选误差模型为：

```text
U(dt) = u0 + (abs(v_hat) + delta_v) * dt + 0.5 * a_b * dt^2
T_valid = 满足 U(dt) <= e_allow 且 dt <= T_cap 的最大时长
deadline_source = t_source + T_valid
```

这是项目工程假设，参数需要独立标定与测试；还要计入相机运动、跟踪歧义、滤波滞后和源时间语义。不能把它写成引用论文已经证明的公式或机械安全边界。当前实际仍采用固定图像250ms、检测锚500ms限制。

最终输出层是关键缺口：现役RTL在COMMIT时重装相对lease。10月26日审查已用模拟MMIO复现最终软件检查后暂停、迟到提交仍被接受的窗口；后续STOP不能撤销此前已被接受的提交。若要声称硬件拒绝过期源，需定义PS/PL时钟转换误差、启动代次和回绕，再由PL比较源绝对截止。[现有反例及硬件分析](../2026-10-26_整机架构时序与硬件审查/README.md)

把有效期、准入和输出许可连接起来，可以形成有特色的应用研究；这些概念各有先行工作，当前检索不足以支持“首创”或“领先论文”的声明。

## 最值得补的实验

第一轮先只测现有PS调度，在无动力、固定公开输入下比较FIFO、轮询、简单检测优先和当前准入策略。各组统一模型、输入、请求到达、时钟定义、队列上限、过期处理、CPU线程及预热；若某策略同时改变多项，必须追加消融解释。不要通过取消基础保护让基线承担额外风险。

| 实验问题 | 最少记录 | 判定方式 |
| --- | --- | --- |
| 调度能否保护及时性 | 源帧龄、更新间隔、P50/P95/P99、有效完成数/全部到达数、拒绝和过期数 | 尾延迟及有效服务改善，且不靠大量丢任务掩盖 |
| 身份是否被饿死 | 人脸/声纹请求等待、完成率、最大等待、超出测试窗口仍未完成的请求 | 主任务改善时，身份获得可解释的服务机会 |
| 可变有效期是否值得 | 独立真值误差、误差越限率、有效控制覆盖、计算与拒绝开销 | 相同误差标准下改善覆盖或资源使用 |
| PL监督是否关闭最后窗口 | 软件检查后暂停、旧源重复、新序号重放、复位、时钟回绕及停止边界 | 先仿真和无动力数字输出，再分开验机械结果 |
| 跨机编排是否有价值 | 首声、取消到实际静音、CPU/GPU等待、断网后的资源归还、过期PCM | 对照原语音流水线，证明新增握手成本值得 |

现有[experiments.json](../../语音共享文件/aura/config/experiments.json)仍是planned_not_board_verified，G0—G5的原定义保持。PS阶段比较应另建标识，不把它改名追认为含PL绝对截止的G组。测试要重复多个窗口并保留失败，硬实时证明与观测最大值分开。

## 答辩定位与工作优先级

当前可以说：

> AURA在KV260上实现了三模型共享DPU、带准入和故障恢复的软件调度，并将推理业务与自研FPGA运动监督、Windows语音服务接入同一交互终端。

研究方向可以说：

> 面向有限算力的交互系统，研究信息有效期、推理调度与执行监督的协同，在约束感知误差的同时提高有效服务覆盖。

当前不宜声称多核DPU并行、全部模型由PL统一调度、原生硬抢占、确定最坏时延、源绝对期限已经由硬件保证，或已优于上述论文。

优先补现有调度的同负载对照，其次关闭源绝对截止并做消融，再用ECAPA检验跨模态扩展。若目标仅为短期演示，先守住已接受功能和版本；不为增加论文名词自动扩充硬件或恢复用户暂停的机构改造。

本次静态核验摘要、来源指纹和阅读范围见[evidence/audit.json](evidence/audit.json)。项目结论依赖所列版本和记录；后续新实测应更新相关状态。
