# AUAR 雪妃技术报告

基于 AMD KV260 的多模型视觉感知与语音交互终端

全国大学生嵌入式芯片与系统设计竞赛 2026 FPGA 赛道

AMD 自主选题  技术报告 V6  2026年11月04日 北京时间

## 摘要

桌面交互终端需要持续感知用户、组织多模型计算，并使回答、画面和执行动作保持一致。AUAR 雪妃采用 AMD Kria KV260 与局域网 Windows 主机协同的结构：KV260 的 PS 负责采集、视觉预后处理、任务调度、音频前端、语音识别及业务状态，PL 集成单核 B4096 DPU 和自研运动监督逻辑，Windows 主机承担现有 27B 语言模型与 OmniVoice 语音合成，Ubuntu 用于构建、模型适配及验证。系统通过同源帧标识、可选模型准入、带租约的执行事务、播放确认和记忆来源管理，处理资源争用与迟到结果。

历史固定输入路径对照中，YuNet 由 ARM FP32 的 124.02 ms 降至 DPU INT8 的 61.41 ms，约加速 2.02 倍；SFace 由 520.86 ms 降至 13.56 ms，约加速 38.41 倍，样本分别为 40 次与 8 次。公开独立 1000 对人脸测试中，FP32 与 INT8 模拟总体准确率均为 98.8%，错误类型在正文分列。约 1 分钟板端自然负载观察中，主检测约 9.89 Hz，YuNet 591 次、SFace 8 次原生完成，二者失败计数均无新增。历史两轮真人交互均保存完整播放回执。上述数据各自保留模型版本、输入及计时范围。

最新已交付源码 RAR 共 1687 个文件，1686 条文件校验通过；该包从源码完成综合、实现及解包复跑，使用 66,887 个 LUT、123,100 个 FF 和 710 个 DSP，WNS（建立时序最差余量）为 0.002 ns、WHS（保持时序最差余量）为 0.010 ns，路由错误及 DRC Error 为 0。本报告将历史实板测量、报告采样、独立 RTL 重跑及源码重建结果分别关联到工件指纹；新固件、原生库及新编译模型的实板验收另列。

KV260 上的单 DPU 组织 YOLOX-Nano、YuNet 和 SFace，与主机 27B 语言模型、板端音频和受监督执行形成协同结构。主检测约 9.89 Hz 来自已注明版本的 1 分钟窗口；语音交付有两轮历史完整回执，最新源码包具备独立构建与解包复验记录。整机同版长稳、机械响应和声学首声另行测量。

关键词：KV260；软硬件协同；多模型推理；执行监督；语音交互；可复现验证

## 1 选题背景 需求与创新点

### 1.1 应用场景与实际问题

当用户在桌面终端前移动并发起交谈时，系统需要同时回答三个问题：当前关注谁、当前回答是否仍然有效、动作是否仍有执行条件。视觉网络输出目标框，不能直接保证目标仍在画面中；语言模型完成回答，不能直接保证当前会话仍等待这一回答；上层发出运动命令，也不能保证软件之后还能按时续约。模块各自正确，只解决了系统问题的一部分。

AUAR 雪妃将真实输入输出和业务状态集中在 KV260，以减少多个设备对会话、身份和播放记录的重复管理。较大的语言模型和语音合成沿用 Windows 主机已有环境，经局域网向板端提供推理服务。Ubuntu 是独立的工程开发节点，承担 FPGA 工程、模型转换、测试和文档图表生成，不参与正常交互的在线决策。

### 1.2 相关工作与现有方案分析

目标检测与跟踪为连续感知提供基础。YOLOX 将图像转为类别、置信度和位置，ByteTrack 在相邻检测之间关联轨迹；轨迹编号用于维持时序关联，不代表已经确认的真实身份。本项目复用这些公开算法，将采集、预后处理与目标状态接入板端业务。[R1][R2]

人脸检测和特征提取以 OpenCV Zoo 的 YuNet 与 SFace 公开模型为基础，团队针对 KV260 B4096 的算子与接口约束，完成了部署计算图的重构和等价改写。YuNet 按固定版本提取卷积、激活与池化子图，将形状整理和 Softmax 留在 PS，并将输入缩放的逆变换折入首层权重；SFace 则对 27 处 PReLU、全连接头和输出归一化层作等价表示转换，使计算主体能够进入目标 DPU 编译链。[R3][E15][E29]

在计算图改造之外，团队建立了公开数据校准、INT8 量化、目标编译、端口顺序核对和实板整数向量比对流程，并将特征模型与模板库按版本配套。这样，公开模型的网络能力转化为可在本项目单 DPU 与四核 ARM 环境中运行、可检查数值及任务质量的板端模块。固定输入实测中，YuNet 和 SFace 的迁移路径分别获得约 2.02 倍与 38.41 倍加速；该结果对应硬件与精度共同变化的路径对照，测试范围见第 5 章。[E04–E07][E19]

### 1.4 主要设计特点与工程贡献

第一项贡献是将多模型感知组织为有状态的板端业务。项目在同一个 B4096 上分时运行 YOLOX-Nano、YuNet 和 SFace，将图像转换、排队、推理、结果接受分开检查。历史固定输入数据支持两条人脸模型迁移路径的耗时结论，约 1 分钟观察记录了当前负载下三模型计数持续推进；它们分别回答路径性能和业务共存问题。

第二项贡献是将运动请求设计为可拒绝、可确认、会到期的事务。PS 检查目标与源帧时效，PL 检查绑定、参考、使能、连续序号、范围和租约，再输出受限 PWM。其价值在于对软件停顿和迟到命令建立明确边界；它没有取代机械限位、角度传感或独立急停装置。

第三项贡献是建立大语言模型与 FPGA 感知及执行系统的联合协同框架。团队将 Windows 上的 27B 大语言模型和语音合成服务，与 KV260 的 PS 业务管理、PL DPU 视觉推理和自研运动监督逻辑接入同一交互系统。板端负责真实输入、当前目标和会话状态，主机承担语义回答及语音生成，回答返回后再由板端校验并交付。该分工将大模型的语义能力与 FPGA 的视觉计算、定时输出能力衔接，使终端能在维持用户感知的同时组织语音交互。[E15][S02]

协同的关键在于把不同计算过程的有效条件写入接口。语言生成和网络返回的耗时会变化，PS 通过请求代次、取消和结果接受管理回答生命周期；运动请求经过目标与帧龄检查，再由 PL 独立验证序号、范围和租约。这样，语义交互、持续感知与受限动作能够在统一状态下配合，主机生成等待也不会成为 PL 输出许可的时间基准。当前跟随依据视觉目标形成，语言模型返回文本与音频，动作仍通过既定监督接口执行。[E20][E21]

有效回答进入播放、字幕与角色显示，完整播放确认后才提交已交付历史，摘要校验并落库后才回收原文。团队由此将主机推理结果落实到设备可见、可听和可追溯的交互过程。接口和测试中的反复问题进一步整理为 PYNQ Skill，以两个独立任务和超时反例验证方法复用，形成后续扩展模型与硬件模块的工程基础。

## 2 系统设计原理与总体架构

### 2.1 系统输入 输出与功能组成

系统输入包括相机图像、MCP01 音频和触控操作，输出包括显示、语音与单轴 PWM。板端处理输入的生命周期，而非把设备数据全部转发给 Windows。主机接收经板端组织的模型请求，返回回答和音频；最终结果是否接受仍由板端当前请求状态决定。

图 2-1 将运行链与开发链分开标明。PS 与 PL 位于同一 KV260，DPU 负责网络计算，自研监督 IP 负责输出许可和 PWM 时序。Windows 负责 LLM 与 TTS，Ubuntu 提供构建、适配和证据整理。开发机断开并不意味着模型主机也可以断开，当前对话仍依赖 Windows 推理服务。

![图 2-1 系统总体结构 蓝色为 PS 橙色为 PL 绿色为 Windows 虚线表示开发链](../figures/system_architecture.png)

### 2.2 感知 交互与执行流程

一次正常交互从同源采集开始。目标检测更新人数与轨迹，人脸链按条件提供候选身份；当前有效目标可形成受限跟随请求。用户发言后，板端音频前端及 ASR 产生转写，再结合会话上下文向主机请求回答。主机返回的文本与 PCM 经当前代次检查后交付，播放、字幕和角色状态随真实事件推进。

感知交互链和运动链具有不同的完成条件。文本生成成功并不表示扬声器已经发声，PWM 指令脉宽读回也不表示机构已到达相应角度。报告对模型阶段、软件起播、数字输出及机械响应分别命名，避免用一个“响应延迟”覆盖不同起止点。

### 2.3 系统状态与取消原则

交互状态包含空闲、采集、识别、生成、播放与收尾。会话切换或取消使旧任务失去接受资格，即使网络稍后返回结果，也要在业务入口检查代次。播放结束与任务结束同样分开：只有符合完整播放确认条件的内容，才可作为已交付回答进入相应历史。

运动采用另一套许可状态。复位后输出关闭；绑定、参考和 ARM 只建立命令接受前提；有效 COMMIT 才启动或续期输出。STOP、到期或完成 QUIESCE 会使绑定失效，恢复需要重新建立上下文。这样，上层恢复运行不会自动重新获得旧许可。

### 2.4 当前功能范围与验证范围

当前系统保留板端 ASR、独立人脸与声纹处理、记忆、主机 LLM/TTS、显示和单轴跟随。声纹继续运行于 ARM CPU 的 ONNX Runtime 后端；人脸与声纹的自动关联不属于当前保留功能。VLM 和视觉说话人方案没有列入本报告的已验收链路。[S02]

本次观察 boot ID 为 a6d4a069-e9b0-4065-8df7-dc23556b168e。MCP01 已枚举，GUI 状态为 IDLE、音频输出为 IDLE_READY，视觉页可见，转轴控制面板为 READY。观察期间聆听和人脸跟随关闭，未发起新推理或运动任务。该状态更新了早期稿件的设备故障描述，但不构成完整对话或机械验收。[L01][L02]

## 3 软硬件划分依据与接口设计

### 3.1 平台选型与版本依据

KV260 的 K26 器件为 xck26-sfvc784-2LV-c，联合 PL 包含单核 B4096 DPU 与自研运动 IP。项目沿用 Vivado、Vitis、PetaLinux 2022.2 和 Vitis AI 3.0，因为参考平台、运行系统和模型编译链已经围绕这一组合建立。AMD 官方兼容表列出了 2022.2、DPUCZDX8G 4.1 与 Vitis AI 3.0 的对应关系。[R4] 最新源码包已在 Ubuntu 20.04.4 LTS 与该版本组合下完成 Tcl、综合实现和解包复跑；2025.2、2026.1 未列为本工程已验证环境。[E30]

工具版本说明只解释选择依据，不能保证任意同名产物可互换。部署必须同时核对源码、器件、DPU fingerprint、模型目标、运行库和固件工件。不同运行根的同名文件按各自清单保存，尤其不能用主业务的文件覆盖独立相机命名空间。

### 3.2 任务划分与权衡

表 3-1 软硬件任务划分

| 网络卷积等子图 | PL B4096 DPU | 利用已有 INT8 计算硬件 | 算子 形状 目标指纹必须兼容 |
| 采集 预后处理 身份匹配 | PS Linux | 与设备及动态业务关联 | CPU 与内存压力影响长尾 |
| 多模型准入和等待 | PS 原生运行层 | 统一单 DPU 使用权 | 预算估计不构成硬实时保证 |
| 租约 限速 PWM | 自研 PL | 时间基准独立于上层线程 | 仍需电气和机械确认 |

划分的核心是把确定的时间规则留给 PL，把需要动态上下文判断的工作留给 PS。模型推理加速后，预后处理和业务仍在 CPU 上执行，因此 DPU 忙时低不能推出整板有同等余量。主机侧也并非单纯增加算力：服务需要限制请求来源、接受取消，并明确何时可以交付回答。

### 3.3 硬件连接 供电与外设

相机与 MCP01 通过 USB 接入 KV260，触控屏使用现有显示转换链和 USB 触控，板卡网口连接 Windows 推理主机。部署记录的 Windows 服务端点为 192.168.50.1:8797，板端为 192.168.50.2。当前 Ubuntu 通过已有热点 SSH 通道进行开发管理，网络地址属于现场配置，不应硬编码为通用复现条件。

### 3.4 PS 与 PL 的寄存器事务

运动 IP 的 AXI4-Lite 数据宽度为 32 bit，地址窗口为 0x80080000 起的 4 KiB。软件先写 session、epoch、seq、width 和 lease 等影子字段，再向 command 写 COMMIT。AXI 写应答只表示总线事务结束，软件还要读 reason 与 ack_seq 才能判断命令是否接受。[E20][E21]

表 3-2 关键寄存器及业务语义

| 关键字段 | 相对偏移 | 单位与业务语义 |
| --- | --- | --- |
| ID ABI BUILD_ID | 0x000 0x004 0x008 | 只读身份 ABI=2 BUILD=0x10282601 |
| flags 与 reason | 0x00c | 状态低 4 bit 原因高 4 bit |
| shadow session epoch seq | 0x010 0x014 0x018 | 当前上下文与连续命令序号 |
| shadow width lease | 0x01c 0x020 | µs 与 ms 分别计量 |
| command | 0x024 | BIND REFERENCE ARM COMMIT STOP QUIESCE |
| ack_seq width lease_left | 0x028 0x02c 0x030 | 已接受序号 当前脉宽 剩余许可 |
| reference 与 target | 0x040 0x044 | 控制参考及目标脉宽 不等于实测角度 |

有效 COMMIT 要求已经绑定、参考和 ARM，当前未在 QUIESCE，会话及代次一致，seq 恰为 ack_seq+1，目标为 500–2500 µs，租约为 4–500 ms。拒绝不会更新接受序号。接受后租约从 PL 接受时刻开始计时；源帧是否过期由 PS 检查，当前 PL 不验证源图像的绝对截止时刻。

### 3.5 模型运行接口与数据格式

部署模型使用 NHWC 输入，YOLOX-Nano 为 1×416×416×3，YuNet 为 1×320×320×3，SFace 为 1×112×112×3。预处理必须与量化及编译时一致，包括通道顺序、缩放、布局和整数类型。输出按 VART 返回的端口顺序组织，不能把 XIR 集合的迭代顺序当作运行器端口顺序。[E04][E05][E19]

模型输出之后还有 PS 解码、筛选、对齐和匹配。因此报告同时保留 submit/wait 与完整路径耗时，前者反映调用区段，后者覆盖相应前后处理。图像时间标识跟随业务结果传播，旧结果不能覆盖较新的目标状态。

### 3.6 大语言模型与 FPGA 的协同接口

板端组织转写、会话标识、请求代次和必要上下文，经主机模型接口得到回答与音频。Windows 端口 8797 提供专用推理服务；正式运行不应另启旧完整业务服务来争夺板端状态。主机权重存放于项目共享目录之外，板端仍为会话与记忆的业务权威。

该接口把大模型能力连接到 FPGA 终端的实际交互流程。PS 维护输入、会话和请求标识，PL DPU 持续承担视觉计算，主机围绕板端组织的请求生成回答。模型端和硬件端通过数据格式及生命周期衔接，各自可以在保持接口的条件下升级；视觉推理、语言生成和运动监督的故障也能按边界定位。运动许可仍由 PS 与 PL 的专用事务链维护，语言模型输出不直接绕过监督逻辑写 PWM。

请求返回时，板端检查任务是否取消、代次是否变化以及回答是否可用，再向播放和字幕交付。网络响应完成、PCM 入队、软件 SPEAKING 和扬声器首声分别是不同事件。只读健康接口与模型推理请求也分开：本次采集没有增加 LLM/TTS 生成任务。

### 3.7 时钟 复位 超时与恢复

运动逻辑使用约 100 MHz AXI 时钟，以时钟使能获得约 1 µs 时间基准，再形成 20,000 µs PWM 帧，不另造低频门控时钟。复位、STOP 与租约到期关闭输出，并收回上下文许可。QUIESCE 为等待当前脉冲自然完成的停止语义，显式 STOP 则可以立即拉低输出。

实现时钟报告包含约 99.999 MHz 的寄存器时钟和约 299.997/599.994 MHz 的 DPU 时钟。布局布线后已约束 setup 与 hold 失败端点为 0，但仍保留 DRC warning 和外部延迟约束缺项。时序摘要必须与完整约束范围一起解释，不能把软件截图中的通过文字等同于整个外部系统已验证。[E03][E23][E25]

## 4 关键模块的设计与实现

### 4.1 同源视觉检测 跟踪与身份

多个视觉模块如果各自打开摄像头，就难以确认检测框、人脸和动作来自同一帧。系统采用唯一采集源，为图像和业务结果保留源序号与时间信息。YOLOX-Nano 提供目标框，轨迹管理维持短时关联；YuNet 提供人脸框和关键点，PS 完成解码、NMS 与对齐；SFace 提取特征，再由 PS 归一化和模板匹配。

![图 4-1 视觉与身份链 DPU 执行网络 PS 完成解码 对齐 匹配及业务接受](../figures/old_vision_pipeline.png)

身份判定同时依赖图像质量、特征模型、模板和阈值。模板按模型版本隔离；证据不足或分数歧义时保留 UNKNOWN，目标轨迹与真实身份不混用。界面中的轨迹编号和身份标签用于显示业务状态，不能据此计算识别准确率。现场任务质量需要带真值的数据集与独立测试。

### 4.2 DPU 模型适配 量化与部署

模型迁移依次处理算子兼容、数值等价、代表性校准、INT8 量化、目标编译和板端向量比对。团队为 YuNet 和 SFace 编写了目标平台适配代码，将公开权重转换为适合 B4096 执行的计算图，并保留模型外 PS 处理。编译后检查 DPU 子图的输入输出形状、目标 fingerprint、端口顺序和缩放因子，使模型工件与运行接口配套。[E15][E19][E29]

YuNet 的重构脚本按原始 ONNX 的 SHA256 固定版本，复建 43 个卷积、18 个 ReLU 和 5 个池化节点，保留四路网络输出。由于板端采用 BGR/256 输入，脚本把对应逆缩放折入首层卷积权重；输出的形状整理与 Softmax 由 CPU 完成。该处理明确了 DPU 计算主体与 PS 后处理的边界，避免将不匹配的输出布局直接接入人脸解码。[E29]

SFace 的改写针对目标工具链的表示约束。27 处 PReLU 按原斜率改写为残差、ReLU 与逐通道卷积的组合；全连接头改写为分组空间卷积和通道求和，保留原权重与偏置，移除中间 Flatten，并把输出 BatchNorm1d 转换为空间形式。脚本包含激活与全连接头的浮点等价检查，随后再做公开数据校准、INT8 量化、编译及板端向量核对。这里的成果是面向 FPGA 部署的模型计算图改造与验证，基础网络及预训练权重仍来自公开模型。[E15][E29]

YuNet 保存了 4 组输入、399,500 个 INT8 输出整数的实板与主机参考一致记录；SFace 也有 4 组向量逐整数一致记录。这些结果验证运行接口和特定向量，不替代公开测试集或现场身份质量。特征模型升级后需要重新检查模板兼容性，不能只替换 xmodel 文件。[E04–E07]

### 4.3 单 DPU 上的多模型调度

交互负载中的身份任务会变化，固定轮流执行容易让主视觉等待，简单统计模型调用次数又会掩盖过期结果。PS 调度器因此将主检测和可选任务分开：主任务维持优先级，可选任务在预算和状态允许时准入，进入原生运行层后统一持有 DPU 使用权，完成后再检查结果时效。

![图 4-2 多模型准入与结果接受 主任务优先 可选任务退让 过期结果不更新业务](../figures/scheduler_flow.png)

设计采用通知等待、独立取消、预算准入与超限恢复，减少无效等待和旧结果传播。准入预算是软件估计，DPU 驱动、CPU 调度和内存访问仍可能引入长尾。本次约 60 秒观察中主任务超周期计数没有新增，不能据此证明硬实时截止期永不违反。可选任务频率随目标条件变化，SFace 低频也不能单独解释为性能不足。

### 4.4 自研 PL 执行监督与 PWM

上层运动请求先经 PS 的目标和时效检查，再进入 PL 事务接口。BIND 将非零会话和代次写入当前绑定；REFERENCE 设置外部确认的控制参考；ARM 开放 COMMIT；有效提交更新目标和租约。REFERENCE 只建立命令参考，没有角度传感器反馈，不能称为机械归零。

PL 的 width、target 和 reference_width 使用 12 bit 保存 2500 µs。旧 11 bit 截断会把 2500 变为 452，这一问题通过同时修改 RTL、原生接口与配置解决。每个 20 ms 帧边界最多改变 4 µs，使数字指令以有限速率接近目标；这一约束是脉宽变化率，不是已经标定的角速度。

![图 4-3 Ubuntu XSim 原生波形局部 截图为历史仿真 数字脉宽依次为 1450 1454 1458 1460 µs](../figures/native_02b_xsim_wave_detail.png)

四套测试分别覆盖正常序列、宽范围、协议与总线、脉冲保护。本次在 Ubuntu 新输出目录重新执行 xvlog、xelab 和 xsim，12 个阶段均通过，源码前后保持一致。停止优先级、边界租约和总线背压的仿真结果与物理电平测量分开保存。[L03]

### 4.5 语音交付与记忆管理

语音链路在板端完成音频采集、前端和 ASR，Windows 运行既有 27B 模型与 OmniVoice16。该分工保留现有模型和声音质量，避免把板端可用内存当作足以迁移整套模型的依据。声纹继续在 ARM CPU 上执行，未写成 DPU 已部署功能。

![图 4-4 回答与记忆生命周期 代次检查在交付入口 完整播放确认决定已交付历史](../figures/dialogue_lifecycle.png)

回答产生后先校验有效性，再进入音频、字幕和角色显示。取消或过期回答不能重新激活已结束会话。完整播放回执与历史提交相连，使系统可以区分“模型生成过”和“用户已经听到”。摘要任务在事务外调用模型，摘要通过校验并落库后再回收对应原文，失败保留可重试状态。[E10][E15]

自然到期的历史存储检查已经证明部分原文回收与摘要保留；用户较新反馈认为当前记忆基本正常。两类证据分别属于存储测试和功能使用反馈，不能提升为新 boot 的任意语义召回准确率。需要逐项检查身份绑定、撤回、更正和相同会话召回，而不是用数据库条目增长代替语义正确性。[S02]

### 4.6 界面 字幕与业务状态同步

界面从真实业务状态取得人数、目标、识别状态、播放及错误信息。当前板端使用 KV260 GLES2 原生角色渲染，健康状态中的目标帧率为 16，但视觉页面时角色不可见；这一配置值不作为实际显示帧率。字幕和角色状态应跟随当前任务与音频时间推进，迟到状态在接受处被拒绝。

切页时还需要处理视觉边界浮层，避免旧轮询回调在新页面重新显示。已有页面同步记录通过显式隐藏和 ACK 管理切换。本次取得的视觉截图证明当前页面像素，不能证明所有页面、触控和冷启动均已验收。后续整机测试应同时记录页面、音频和业务请求标识，以检查用户可见的一致性。

### 5.1 实验平台 基线与测量方法

本章使用三组独立证据。第一组为已保存的固定输入、公开模型质量及 FPGA 实现报告；第二组为本次当前板卡的自然负载观察和网络探测；第三组为本次 Ubuntu 独立目录的 RTL 重跑。每组保留输入、统计口径、版本与原始回执，不跨窗口拼接整机性能。[E01–E09][L01–L03]

本报告日期和时刻统一采用北京时间（UTC+8）。本次资源采样的主机记录时间为 2026年11月3日 21:52:23 至 21:53:24。板卡系统日期偏离实际时间，观察时长使用板端单调时钟，跨设备定位使用主机时间与 boot ID，不用两端墙钟相减计算单向延迟。61 个状态样本形成 60 个 CPU 差分区间，实际首末间隔为 59.988313 s。原始证据中的时间戳保持采集格式，正文展示已换算为北京时间；耗时、周期、租约和相对观察时间继续使用原单位。

CPU 取 /proc/stat 前八个计数字段，busy 排除 idle 与 iowait，四核总容量归一为 100%。内存采用 MemTotal-MemAvailable，统计系统可见内存；GPU、XRT 和 CMA 子分配不重复相加。分位数按排序后位置 (n-1)p 线性插值，完整计算脚本和逐点 CSV 随报告保存。

### 5.5 语音阶段拆解与回答交付

结构化回答需要等到有效台词字段可消费才能合成。早期优化将有效台词置于较早位置，同时保留业务字段与校验。旧、新格式各 4 次的模型阶段台词就绪中位数为 2762.88 ms 与 2287.70 ms，首正文为 1754.07 ms 与 1344.27 ms。两组回复措辞和长度发生变化，该数据用于定位阶段开销，不作为严格同文本收益。[E08]

这组 n=4 的结果作为阶段拆解示例，说明输出字段顺序会影响有效台词何时可消费。正式优化收益应采用同模型、同输入和配对文本检验，当前材料未给出这种因果对照。

较新的 Windows RTX 5090 Laptop GPU 上，两条公开短句的暖态未缓存 OmniVoice16 合成耗时为 0.547 s、0.750 s，对应音频 2.16 s、2.88 s，RTF 为 0.253、0.260。另有两轮真人交互，从采集结束至观察到 SPEAKING 约为 5.04 s、5.29 s，两轮均保存完整播放回执。它们分别属于合成短测与软件事件计时，未测扬声器真实首声。

## 6 大模型协作记录与自我纠错

### 6.1 AI 工具与人工职责

AI 编程助手参与需求拆解、接口草拟、脚本和测试生成、失败分析以及文档整理。人工确定功能范围、模型与声音要求、实物观察条件和方案取舍；工具实际执行的日志、输出与源码差异提供验证依据。没有对应执行记录的回答只作为候选建议。

现有工程资料保存五类案例、38 项来源索引及精选对话摘录。历史逐轮提示词、回答和模型 ID 没有统一覆盖全部案例，因此下面区分真实摘录与工程复盘。复盘按目标、首次方案、失败、人工判断、修改和验证组织，未将说明性段落写成虚构问答。[E15][E16][E28]

### 6.2 FPGA 联合工程案例

工程目标是在同一平台保留 DPU 与自研运动监督 IP，并形成可配套部署的工件。协作产物涉及 visual_servo.sv、prepare.tcl、implement.tcl 和导出脚本。早期导出失败后，采用同一已路由 DCP 恢复导出，再检查 BIT、XSA 及固件载荷的对应关系，而非把任意旧位流视作新工程输出。

人工判断集中在版本配套与证据层级：仿真证明协议断言，实现报告证明约束下的布局布线，目标板读回再证明运行对象。较新的源码工程把四套 bench 的执行结果作为后续流程输入，并增加缺项、非零退出码和篡改回执的拒绝测试。本次独立目录重跑四套 bench，再次取得 12 阶段通过与源码不变记录，未重新完成整套综合实现。[L03][S03]

### 6.3 DPU 模型适配案例

模型迁移的目标是降低人脸链路径开销。AI 协作用于模型重建、算子适配、量化与向量脚本，但每一步都需要不同证据。编译通过只说明工具接受图，整数输出一致检查运行接口，公开配对或检测评估检查任务质量，固定输入耗时检查路径开销。

一项实际错误来自输出顺序：XIR 集合迭代顺序与 VART 返回端口顺序不一致，导致结果解释错误。修正使用实际运行器顺序，并保留顺序互换回归。最终采用的依据包括向量一致、公开质量和实板短测，而不是 AI 对“网络应当等价”的判断。[E04–E07][E15]

### 6.4 语音与记忆协作案例

语音优化先拆解首正文、台词可交付、首 PCM 和板端播放事件，再讨论可减少的等待。AI 形成结构化输出、流式交付和 GPU 共存候选，人工要求保留既有模型、音色与质量。回复长度改变的测试只保留阶段观察，不作为严格收益。

记忆优化将摘要生成放在事务外，校验完成后提交，再回收对应原文。存储通过与语义召回分别验收，防止把摘要数量增长当作记忆正确。较新用户对记忆可用性的反馈保留为功能反馈，不改写自然到期测试的原始范围。[E10][E15][S02]

### 6.5 实际超时错误与修正

PYNQ 测试生成工具首轮 15 项单元测试中出现一个失败。合同要求软件在 100 ms 内观察完成，反例使完成标志到 200 ms 才被观察到。旧逻辑先判断完成，再检查超时，因此错误接受了迟到结果。[E13]

修改将“读回后检查当前观察时间是否超过期限”放到完成判断之前。修正后 15 项测试通过，同时保留迟到完成反例和正常完成用例。该纠错保证软件判定顺序，不会中断已经阻塞的 MMIO 读写，也不提供硬件最坏响应时间证明。

## 7 技能包的提炼 验证与边界

### 7.1 从接口失败到可复用规则

项目调试发现，HWH 中存在 IP 地址窗口，不保证包含完整寄存器定义；本机 wide 工程的 aura_m3_regs_0 曾有地址信息而 REGISTER 数为 0。直接按元数据生成任意 register_map 字段会造成错误接口假设。因此 Skill 将地址、寄存器元数据、用户合同和实际硬件分开处理，缺项与冲突使用不同结果。[E13]

另一个来源是第 6 章的迟到完成失败。工具把观察期限写入合同，将超时顺序固化为可复现反例，而不是只修改一次业务代码。提炼后的规则可以用于另一种寄存器布局，原 AURA 工程不作为 Skill 示例运行依赖。

### 7.4 正例 反例与跨任务验证

加法例使用 math_accel_0、0x10/0x14 输入和 bit0 完成标志，数据按 uint32 模 2^32 处理。CRC 例使用 checksum_unit_0、0x80 输入、0xa0 输出、bit7 完成和读清除状态；对输入字的四个小端字节计算 CRC-32/ISO-HDLC，模拟为逐位实现，黄金参考为 zlib。[E13]

保存的验证包括 15 项单元测试、36 个加法用例、37 个 CRC 用例，合计 73 个模拟向量。两个任务使用同一生成器，算法实现位于独立模拟和参考模块，说明工具可跨布局和算法换例；因为没有切换实际器件，不能称为跨板验证。

### 7.5 适用范围与失效条件

当前 Skill 适用于可由合同描述的寄存器调用和轮询完成任务。涉及 DMA、一致性、中断或复杂流接口时，需要增加对应合同与验证，不能自动外推。元数据缺失、地址不匹配、权限冲突和不完整完成语义都会影响生成结果。软件超时不能控制阻塞 MMIO 的持续时间，真实设备运行必须另设适合平台的恢复机制。

## 9 结论与后续工作

### 9.1 有证据支持的成果

AUAR 雪妃形成了大语言模型与 FPGA 联合协同的桌面交互结构，以 KV260 为感知、设备状态与执行中心，以 Windows 为 27B LLM/TTS 推理节点。团队完成 YuNet 卷积子图重构、SFace 激活及全连接头等价改写、INT8 校准和三模型共享运行，将公开模型能力接入目标 FPGA 平台；通过 PS 的会话和任务管理、自研 PL 执行事务及播放确认，将主机语义推理与终端实时感知、受限动作和交付历史衔接。相关接口问题进一步提炼为离线测试生成 Skill。

历史固定输入对照支持 YuNet 和 SFace 对应迁移路径的耗时结论，公开测试支持指定版本的量化质量结论，布局布线报告支持指定约束下的资源和时序结论。本次短窗补充了当前三模型、CPU、内存和 ICMP 记录，四套 RTL 在新目录通过。不同证据共同描述实现，但各自保持统计与验证边界。

### 9.2 当前限制与后续工作

后续工作应优先收拢同版整机验收：固定固件、模型、业务清单和外设配置，补充真实机械零点、有限行程、电气波形、声学首声及完整任务成功率。调度优化使用固定回放和同输入配对，报告等待、帧龄、P99 和丢弃代价；网络补应用 RPC、有效吞吐与超时恢复。

工程复现还需要在新环境中检查外置模型、角色授权、目标系统输入和部署映射。Skill 继续以明确合同和反例扩大适用范围，再通过真实 PYNQ、跨板及非作者使用验证迁移能力。所有新增结果都应能回到具体版本、输入和原始证据。

资源扩展还受布局和时序限制。历史宽版已用 CLB 站点 95.41%，最新源码重建为 98.63%，URAM 均为 87.50%；站点被占用不等于其中所有 LUT/FF 都已用满，但分布拥挤会增加新增逻辑的布局与时序压力。后续先按实际布局、布线和时序重新评估 DPU/IP 组合，再决定裁减逻辑或调整器件，当前 WNS 0.002 ns 仅说明指定约束通过。

## 附录 A 寄存器与状态定义

以下定义对应已核对的 VSRV/2 宽版 RTL，基址为 0x80080000。RW 字段要求 32 bit 全字节写入，表中位宽表示有效数据位；非法读取返回 SLVERR，命令业务拒绝由 reason/ack 表达。复位后影子与绑定为 0，width、target、reference_width 为 1500，输出关闭。[E20]

表 A-1 VSRV2 完整寄存器表

| 偏移 | 字段 | 访问及有效位 | 复位与说明 |
| --- | --- | --- | --- |
| 0x000 | ID | R 32 | 0x56535256 |
| 0x004 | ABI | R 32 | 2 |
| 0x008 | BUILD_ID | R 32 | 0x10282601 |
| 0x00c | flags_reason | R 8 | bit0 active bit1 armed bit2 referenced bit3 bound bit7:4 reason |
| 0x010 | shadow_session | RW 32 | 0 非零会话 |
| 0x014 | shadow_epoch | RW 32 | 0 非零代次 |
| 0x018 | shadow_seq | RW 32 | 0 下一连续序号 |
| 0x01c | shadow_width | RW 32 | 0 以 µs 为单位 接受时检查范围 |
| 0x020 | shadow_lease | RW 32 | 0 以 ms 为单位 接受时检查 4–500 |
| 0x024 | command | W 32 | 命令魔数 不提供读回 |
| 0x028 | ack_seq | R 32 | 0 接受序号 |
| 0x02c | width | R 12 | 1500 当前数字脉宽 |
| 0x030 | lease_left | R 9 | 0 剩余许可 ms |
| 0x034 | session | R 32 | 0 当前会话 |
| 0x038 | epoch | R 32 | 0 当前代次 |
| 0x03c | shadow_reference | RW 32 | 0 控制参考 µs |
| 0x040 | reference_width | R 12 | 1500 已接受参考 µs |
| 0x044 | target | R 12 | 1500 已接受目标 µs |

reason=0 表示接受或正常状态，1 表示命令前提不满足，2 表示 COMMIT 无效，3 表示未知命令或地址，4 表示许可到期。具体读取要结合 flags、ack_seq 与当前事务，不能只看 reason=0 就断言机构达到目标。

命令魔数为 BIND 0x42494e44，REFERENCE 0x52454621，ARM 0x41524d21，COMMIT 0x434d5421，STOP 0x53544f50，QUIESCE 0x51554945。STOP 与到期清除 active、armed、referenced、bound，恢复需重新绑定与参考。
