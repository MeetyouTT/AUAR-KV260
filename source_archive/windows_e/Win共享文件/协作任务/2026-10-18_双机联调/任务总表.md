### W1：使用 Windows 磁盘上的实际文件核验

在 PowerShell 中把下面两个路径换成实际值：

```powershell
$SyncRoot = 'D:\实际路径\Win共享文件'
$AuraRoot = Join-Path $SyncRoot '共享文件夹\aura'
$AsrDelivery = Join-Path $SyncRoot '共享文件夹\deliverables\2026-10-17_board_asr_host_files'
$VoicePython = 'C:\实际语音环境\Scripts\python.exe'
Set-Location -LiteralPath $AuraRoot
& $VoicePython -B (Join-Path $AsrDelivery 'check_asr_files.py') --aura-root $AuraRoot
```

该工具检查 8 份源码/说明和 3 份模型数据的长度、SHA256，以及包元数据。预期 11 项 MATCH，`sherpa-onnx` / `sherpa-onnx-core` 为 1.13.8；Windows 已接受环境曾为 Python 3.10 / numpy 2.2.6，先记录本机实况。仅核验文件可加 `--files-only`，但不能因此认定环境可运行。

把输出和退出码保存到 `evidence/windows/` 并写回执。遇到 DIFFERENT 先查看本机修改和同步冲突；保留现有语音环境及已接受音色基线，按差异补齐文件。完整代码包与说明见 [既有交接清单](../../共享文件夹/deliverables/2026-10-17_board_asr_host_files/FULL_ASR_CHECKLIST.md)。

### W2：核对网口、启动模型和健康接口

先读取网络，区分连接板卡的以太网适配器与 Wi-Fi / 虚拟网卡：

```powershell
Get-NetAdapter | Select-Object Name, InterfaceDescription, Status, LinkSpeed
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias, IPAddress, PrefixLength
Get-NetConnectionProfile | Select-Object InterfaceAlias, NetworkCategory
Test-NetConnection -ComputerName 192.168.50.2 -Port 22
```

板卡最近地址为 `192.168.50.2/24`。若已确认 Windows 与它单根网线直连、该适配器不承担其他网络且地址无冲突，可把该以太网 IPv4 配为 `192.168.50.1/24`，保留原配置以便恢复，直连口无需默认网关和 DNS。若实际采用其他拓扑/地址，先把实际地址与路由写进回执，由 Ubuntu 侧据此核对；避免盲目改动其他网卡。

接着在 W1 的同一个 PowerShell 环境启动：

```powershell
Set-Location -LiteralPath $AuraRoot
.\scripts\start_board_asr.ps1 -VoicePython $VoicePython
```

等待真实模型探针通过并输出 `READY`，保持该窗口。另开窗口检查：

```powershell
Get-NetTCPConnection -LocalPort 8791 -State Listen
Invoke-RestMethod -Uri 'http://127.0.0.1:8791/health' -TimeoutSec 5
```

记录监听地址、本机健康 JSON、实际网口地址和启动输出。板卡仍访问失败时，再分层检查路由、邻居、监听和防火墙；如确需放行，限定已确认的板卡网段和 TCP 8791，保留规则记录。不要关闭整个防火墙。

Windows 启动成功后将 W2 标为“待对端复核”；由 U1 从板卡确认可达。SSH 端口结果只是辅助诊断；本轮核心是 ASR 的 8791。

### U0—U1：Ubuntu 经板卡完成网络复核

Ubuntu 本机只有 Wi-Fi，连接 Windows 网线的端点是 KV260；Ubuntu 经既有 USB UART 检查板卡。先核对串口持有者、板卡身份、当前 boot 和实际服务，不沿用历史 PID。

收到 Windows 回执后，在板卡读取 `ip -brief address`、`ip route`、到 Windows 实际地址的路由及邻居状态，再访问 `http://<Windows实际IPv4>:8791/health`。以真实健康结果作为下一步前提；ARP/邻居失败时先处理地址或二层链路，不能直接判定是 ASR 模型错误。

确认服务成功后，在**板卡实际运行的 aura 目录**执行：

```bash
python3 -B tools/configure_board_asr.py --host <Windows实际IPv4> --port 8791
```

该命令通过 GUI 本机接口保存地址并等待确认，无需重启界面。保存配置回执和板端健康响应；共享仓副本上的配置不等于运行中板卡配置。
