# AURA·汐蓝：整个项目现在在做什么

复核日期：2026-10-18；本次本地工件核验时点：UTC 12:34。本文综合原始 ZIP、当前方案、Ubuntu 日志，以及刚同步到 Ubuntu 的 Windows 语音源码和验收资料。没有重新连接 Windows/KV260、启动模型、录放音、操作机构或修改业务配置。

## 项目目标与当前阶段

项目要做一台基于 KV260 的桌面单轴交互终端：看到并选择面前的人，小范围转向，按授权记住身份，通过 MCP01 录放音，用汐蓝界面反馈，并由 Windows 本地模型完成中文语音和当前图像问答。Ubuntu 负责 FPGA/系统构建、部署和证据整理。

当前处于整机集成阶段。真实检测跟踪、板端界面和单轮语音交互均已有实板成果；身份、视觉说话人、当前视觉到机构的正式随动、FPGA 创新对照和最终发布仍需补齐。范围仍为一个水平轴、USB MCP01，不包含已删除的双 I2S 麦克风声学定位。

## 最新工作集中在哪里

### 语音已从分端验证推进到真实单轮交互

新同步的 Windows 证据更新了旧共享总表：此前旧模型基线下，用户亲自操作新录音，Paraformer 识别、模型回答、OmniVoice 16 步合成、板端实际播放和口型均已通过单轮验证，并有用户听音确认。不能继续把这一整条链写成尚未接通。

随后修复了板端开头丢字：每次播放前增加 1 秒启动静音，内容时钟扣除这一秒，启动期间口型保持关闭。保存的修复后验收有 33 个播放采样、26 个非零口型采样，capture 归属一致，用户确认开头完整清楚。本机和板端分别有 14 项播放器测试通过的历史记录。本次重新核对了对应 WAV 的 SHA256。

最新对话配置已换成 `aura-qwen3.8-27b-abliterated:iq4_xs`，交接文档称为 Qwen3.8-27B Huihui 版；本次只核对本地模型标签和工件，不对上游模型命名作外部认证。该配置与保存的真实 HTTP 返回一致，历史板卡录音经过 ASR→27B→OmniVoice 的完整 HTTP 测试通过，单次 7.187 秒，输出 WAV 的长度和 SHA256 本次重新核对通过。

**27B 升级后尚无新板端录音听音验收。** 旧模型的实录通过、起音修复通过、27B 历史音频 HTTP 通过是不同验证范围；不能合并成最新组合已经实录验收。早期 1.609 秒、起音修复后约 2.48/2.57 秒和 27B 的 7.187 秒也不是同一版本、同一测量终点，不能直接作为统一的当前端到端延迟。

证据入口：[最新语音交接](../../语音共享文件/deliverables/2026-10-18_board_dialogue/README.md)、[单轮实录验收](../../语音共享文件/deliverables/2026-10-18_board_dialogue/live_acceptance.json)、[起音修复验收](../../语音共享文件/deliverables/2026-10-18_voice_clarity/acceptance.json)、[27B 验证](../../语音共享文件/deliverables/2026-10-18_board_dialogue/model_27b_verification.json)。

### 最新下一项是人设、对话连续性和长期记忆

Windows 新增了[人设与记忆调整方案](../../语音共享文件/aura/docs/memory_persona_plan_20261018.md)。文件明确标为规划稿，尚未修改在线人设、记忆和推理参数。

当前服务源码只在进程内保存最近 8 条消息，约 4 轮；会话由 boot/session 分隔，服务或界面重启后不具备长期记忆。新计划拟增加统一人设、按预算管理近期历史、SQLite 长期事实、摘要和查看/纠正/遗忘入口，之后与身份系统连接。这些仍是待实现内容。

## FPGA 主线目前在什么位置

现行主线是根据视觉证据还能有效多久安排推理，并让 PL 监督运动许可。10 月 12 日又增加了全模型 PL 调度扩展：PL 决定任务准入和次序，PS/Windows 执行各模型；不能把 Windows 语音串联起来等同于完成 PL 调度。

当前可见 RTL 在 COMMIT 时装入相对 `lease_left`，正式源绝对期限监督尚未完成。PS 调度仍处理 detection/identity 两类任务。校准集、独立测试集的 items/annotations 仍为空，G0—G5 仍标记 `planned_not_board_verified`；目前没有可据以宣称创新性能提升的正式对照数据。

机构配置仍为 `verified=false`、等待 3D 模型和机械测量。历史有限动作通过与最终机构零点、范围、负载、跟随误差和停止恢复验收分开。机构未齐期间，合同、RTL、无动力数字波形和软件接入仍可推进。

整体关卡继续判断为 L1 未完整验收、L2 部分完成、L3/L4 未达到放行条件；新语音成果补上了 L2 的一个重要环节。

## 目录与交接需要收口

全项目原共享主仓仍为 `共享文件夹/aura`；新 Windows 语音工作已迁到 `语音共享文件/aura`，以该目录的 README、AGENTS、配置及较新验收为语音进展依据。本次没有迁移目录、覆盖源码或改变主仓约定。

两处 11 份关键文件的 SHA 比较中，8 份相同，3 份不同：`tools/board_model_host.py`、`tools/dialogue_host_ollama.py`、`tools/gstreamer_audio_engine.py`。后者两份目录都存在；语音侧包含较新成果。因此不能直接把旧共享包重新部署到板端，后续应先核对并回收实际版本。

新语音项目配置把 LLM 权重和 Ollama 模型库放在 Windows 本地 `D:/AIModels`，ASR/TTS 沿现有配置保留。语音项目有 `start_voice.ps1` 启动入口，Windows 开机自启仍未设置。同步文件齐全也不代表换主机已有这些本地权重、环境或服务。

本次读取的 Windows 统一回执仍是初始模板；这表示总交接记录未回填，不能据此否定已同步的 Windows 验收工件。UTC 12:28 的最后保存同步快照显示 zhenghang/Ubuntu 零待同步，JoneNike 仍有约 6.94GB 独立队列；本次未重新查询微力，不宣称此刻所有设备同步完成。

## 接下来应按什么顺序做

1. 先回收并冻结当前 27B、起音修复和板端客户端版本，完成 27B 的新实录、字幕、真实声音/口型，以及取消、重录、断连恢复；统一记录延迟起止点。
2. 语音侧按已写方案实施稳定人设和可管理记忆，先解决短期连续性和失败轮次，再做长期事实、遗忘和身份隔离。
3. FPGA/运动侧继续正式源期限监督、停止恢复、联合实现和数字波形；把当前视觉轨迹接入唯一运动服务，机构到位后再标定验收。
4. 完成板端身份、真实说话人和当前图问答，补真实负载数据和调度对照。
5. 最后收口长稳/冷启、技能、干净构建、非作者复现、报告视频和匹配发布包。
