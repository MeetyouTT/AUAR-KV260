# AMD 自主选题初级组：源码修复与参赛要求核对

## 结论

**按用户 ZIP 中的《全国大学生嵌入式芯片与系统设计竞赛'2026 FPGA 赛道选题指南（AMD）》第 3.3 节，现有 DFX manager 和 ZOCL 源码修复未发现与该赛道条款冲突，可以保留。**

指南允许 PS 侧软件、RTL、HLS 等组合实现，没有要求官方软件必须原样运行，也没有禁止对开源运行时修复。它要求完整、可复现、可演示的 FPGA 作品。因此，需交代原始来源、修改范围、工具版本、验证结果和大模型协作过程；这两处修复的有限板测通过不等于整件作品已经满足全部参赛要求。

本结论依据用户提供的指南，不代表组委会对作品的最终审核。包中仅发现一份官方参赛 PDF，没有独立《评分细则》；在线检索及官网打开未取得最新细则的可读原文。指南第六部分明确最终评分公式、阈值和提交条件以相应评分细则为准，最新细则仍待核对。

### 2022.2 的说明应怎么写

指南 3.3.3.1 允许使用其他版本，附带报告说明和脚本可复现条件。可据实际证据写明：

- 固定 2022.2 是为了匹配已有 KV260 PetaLinux 2022.2、原 XRT/ZOCL 和 DPU 运行时对照，以及固定版本参考工程。
- 列出实际 Vivado/Vitis/PetaLinux、交叉编译器、平台源码、DPU IP 与模型版本；不能用“装了 2022.2”代替核验。
- 提供源码获取、补丁应用、构建、打包、运行与恢复的入口，标明外部工具、许可证和下载依赖；完整保存失败和成功证据。
- 说明哪些是主机验证、哪些是目标板验证、哪些尚未完成。

无需仅因本指南的推荐版本而重选源码或迁移当前基线。最终提交仍应核对后续评分细则是否新增复现环境要求。

## 3. 两项修改到底是什么

### DFX manager

- 上游固定 commit：`bc06691eb35d7f0acb7c2508b6d050d77b0264a0`。
- 实际只改 `src/daemon_helper.c`：按 wd/path 去重、检查参数边界、保护登记和删除写操作，内部容量仍为 500。
- 原版在主机 130 次扫描后内部占满 500 项，而内核只有 5 项；修复版 10,000 次扫描保持 5 项。
- 联合有限板测已通过 1,000 次列表查询、50 次目录增删、3 轮官方应用重载、官方/M3 同模型同图推理；完整候选日志没有 ERROR。
- 原源码许可证为 MIT；本次补丁没有删除原文件版权或 SPDX 声明。

### ZOCL

- 上游固定 XRT commit：`43926231f7183688add2dccfd391b36a1f000bea`。
- 实际改 `include/zocl_drv.h`、`cu.c` 和 `zocl_drv.c` 三个文件，补齐相关临时查询引用释放及所有权说明。
- 修复的是已复现的 overlay 退出引用问题；未把原内核诊断改成警告，未 force 加载，也未宣称所有并发卸载场景均已解决。
- 原三个文件的 SPDX 均为 `GPL-2.0 OR Apache-2.0`，驱动目录 LICENSE 也说明双许可；本次修改保留原声明。

## 4. 现在确实需要补的材料

1. **可提交的独立工程导出。** 原 ZIP 有中文目录、旧方案和 tmp 文件；运行时测试包主要是二进制、补丁和检查信息，尚不是完整参赛源码工程包。导出时整理英文路径、当前有效方案、完整自研源码、固定依赖、许可、补丁及构建脚本，不修改原 ZIP 或封存目录。
2. **工具版本与复现说明。** 将 2022.2 的选择理由和环境锁定写成正式材料。现有阶段构建脚本和日志已经存在，但本次没有完成陌生环境从零复现，不能提前声明通过。
3. **大模型协作记录及 skill/。** 保存真实提示词、可见回答、工具执行、失败与修正记录。例如 SOCK_STREAM 就绪误判及改为 SOCK_SEQPACKET 的过程，可以沉淀可复用排查方法；不虚构交互、隐藏推理或验证效果。
4. **自研贡献与最终功能。** 清楚交代 DPU 来自 AMD，运行时来源于上游，本队有哪些补丁、RTL、接口和系统集成设计。M3 最小寄存器已经有限板测；PWM、运动控制、完整 AURA 功能和长期验收仍需完成。应以真实资源、时序和性能报告呈现初级组考察的设计能力。
5. **后续规则。** 核对组委会最新评分细则和上传要求。进入决赛后还需按模板准备一页英文海报；本次不判断是否已经入围。

原包 README 仍记载新平台上板和自研 IP 共存待验证，属于较早状态。最终材料应引用后续已封存的实际结果，同时保留其“有限验证、未永久启用、长期待验收”的边界。

## 5. 工程方向如何继续

建议保留这两项经过验证的最小软件修复，把它们列为运行环境稳定性改进，并提交明确的上游与补丁证据。

随后继续备用卡受控启用与长期复验，并推进与实际应用有关的自研 PWM/状态机/接口。初级组考察逻辑设计、状态机、时序约束和接口协议，但指南没有规定必须自研整个 DPU，也没有给出必须达到的 RTL 行数或 FPGA 功能占比。本次不增造这些限制或预估得分。

已有修复案例可贡献可复现性及技能包材料；作品创新性与应用价值仍需由完整作品和真实应用证明。指南权重为创新与应用 30、性能与资源 20、正确性与完整性 20、大模型协作与技能包 15、文档与复现 15；这不意味着仅修驱动就能获得这些分数。
