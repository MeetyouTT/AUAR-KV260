2. 原理：两只麦凭什么能分辨左右
2.1 唯一用到的物理量：到达时间差（ITD / TDOA）
声音在同一时刻发出，到达两只麦的时间不一样。离声源近的那只先收到，就先收到这么多时间：
τ(θ) = d · sinθ / c

d：两麦间距（米）
θ：声源方向偏离阵列中轴线的角度（0° = 正前方，+90° = 正左，−90° = 正右）
c：声速，常温下取 343 m/s
把这个时间差换成「多少个采样点」，就是 FPGA 里真正要算的东西：
Δn(θ) = d · sinθ · fs / c

本次代入（d = 0.05 m，fs = 48000 Hz，c = 343 m/s）：
最大时间差 = d / c = 0.05 / 343 ≈ 145.8 µs
最大样本差 = 145.8e-6 × 48000 ≈ ±7.00 样本
即 Δn(θ) ≈ 7.0 · sinθ   （单位：采样点）

所以 FPGA 要做的核心运算只有一句话：在这两路音频里，找出让它们的互相关最大的那个整数位移（lag），范围 −8 … +8 就够。

2.3 为什么取 d = 50 mm 且 fs = 48 kHz（一对绑定的选择）
分辨率的关键结论：「一个采样点」能代表的角分辨率 = c / (d · fs)。
d = 0.05 m, fs = 48000 Hz  →  1 样本 = 343 / (0.05 × 48000) = 0.1430 rad ≈ 8.2°

也就是说，只用整数 lag 时，正前方附近每 8.2° 才算一个格子。这对「三分档」完全够用吗？我们验算一下门限：
门限 ±3.0 样本，对应真实角度 ±25.4°；
相邻整数 lag 之间跳变幅度：正前方约 8.2°，±60° 附近约 16.4°（角分辨率 = c / (d · fs · cosθ)，随 θ 增大而变粗，在接近 ±90° 时趋于饱和）；
结论：±3.0 样本的门限是一个「宽裕」的判据（±25° 与 0° 相差 3.0 个样本，远大于 1 个样本的量化步长），三档判断稳；但量化步长 8°—16° 意味着"精确指向"是无法宣称的——这就是连续方位角不做的第二个技术原因。

3.3 为什么最终选"2 只 I2S 数字麦"
唯一能满足 3.1 硬约束的形态（数据真的进 PL）；
接线最省：两麦共用 BCLK / LRCLK 两根时钟线，但各自使用独立 SD 数据线（SD_L / SD_R）→ 共占 4 个 PL IO（W17-06 裁定：便于分支排查与逐通道取证）。Pmod 的 8 根信号里：双麦 4 根 + 舵机 3 根（PWM / 使能 / 停止）= 7 根，余 1 根备用；
同步免费：同一 BCLK/LRCLK 下，两只麦的采样时刻由同一个时钟边沿决定，不存在两路 USB 麦那种漂移与重采样问题（这是选数字麦而不是"两个 USB 麦"的最重要理由）；
数字直出、无需模拟前端：没有运放偏置、没有 ADC 噪声、没有增益失配（只有在数字域做一次一阶增益校正）；
功耗与供电可控：毫安级电流，可直接吃 Pmod 的 3.3 V，不必引入 5 V 或电池。

4.2 采样时刻与时序裕量（源同步输入的经典处理）
麦在 BCLK 的某个沿输出数据；接收侧在相反的那个沿采样，天然留出半个 BCLK 周期（3.072 MHz 下约 162 ns）的建立裕量；
相对器件 Tco（数 ns 量级）与短线传输延迟，162 ns 余量非常充裕 → 先用"反相沿采样"实现，再用 ILA 验证数据眼；
若上板后发现数据不稳：把 BCLK 输出用 ODDR/相移时钟微调（推荐错开采样点至数据眼中心），并在 XDC 中补 set_input_delay（max/min）约束后复核 WNS；
纪律： 该路径属"PL 自己产生时钟再采回来"的源同步路径，不要用"默认没约束"的方式交付——必须在报告里说明约束与余量（这正是初级组"时序约束"考察点）。

5.3 多麦同步为什么"免费"（写进报告的关键论据）
两麦由同一根 BCLK/WS 驱动，采样发生在同一个时钟边沿，因此：
不存在采样时刻漂移 → lag 零点稳定，标定一次可长期使用；
不需要重采样、不需要时间戳对齐、不需要软件侧的时钟漂移估计；
对比：两台独立 USB 麦各有自己的时钟，几十秒内就会漂移到 lag 不可用；多通道 USB 阵列虽然同步，但数据被 PS 侧 ALSA 取走（3.1）——这正是"为什么必须自研 I2S 前端的 FPGA 方案"的实证理由。

7. 算法分级（v0 / v1 / v2）
7.1 v0：能量差（只用来打通链路，不作为最终方案）
项目
内容
做法
比较左右通道帧能量，能量大的那一侧即为声源方向（门限三档）
用途
D1 的"链路自检"：只要 v0 能正确区分"对左麦说话/对右麦说话"，就证明采集→时隙→通道映射→寄存器→PS 读取整条链路是通的
优点
逻辑极简（几个累加器），能在没有算法的日子里先排除硬件与接线问题
缺点
近场/偏轴时不可靠：声源在正前方时两侧能量接近但会有偏差；混响下误差大
结论
只做自检，12 h 内完成，不进答辩的算法叙事

7.2 v1：时域归一化互相关（本轮目标算法）
项目
内容
输入
480 样本一帧 × 2 通道（Q1.15，已去 DC、已低通到约 4 kHz）
搜索范围
lag ∈ [−8, +8]，共 17 个 lag
相关定义
R(k) = Σ x_L[n] · x_R[n+k]，k 为 lag；再做归一化（用能量归一，避免"哪路能量大哪路相关大"的假峰）
归一化实现
不做实时除法：用"比较 R(k)/sqrt(E_L·E_R)"的等价变形，或把分母固定（同一帧内 E_L、E_R 相同，不影响 argmax），只在计算置信度时才做一次近似除法
峰值选择
取最大 k*；再取左右邻居 R(k*−1)、R(k*+1) 求次峰用于置信度
插值
抛物线插值：δ = 0.5·(R(k*−1) − R(k*+1)) / (R(k*−1) − 2R(k*) + R(k*+1))，输出 lag = k* + δ（Q8）
计算量
17 × 472 ≈ 8.0 k MAC/帧 → 0.8 MMAC/s
判档
lag ≥ +3.0 → 左；−3.0 < lag < +3.0 → 中；lag ≤ −3.0 → 右

为什么"不去 DC 就能错得离谱"的提醒： MEMS 麦有直流偏置，若不去 DC，互相关会被这个巨大的常数项主导，R(0) 永远最大 → 永远判"中"。去 DC 是 v1 能否工作的前提，不是可选项。

8.2 标定六步（按顺序做，每步留数据）
第 1 步：零偏标定（对称性检查）
声源放 0°，播放白噪声 30 s，采集 LAG_Q8 序列求均值 lag0；
期望 lag0 ≈ 0（|lag0| < 0.3 样本）；
若明显非零：先查安装与接线是否对称（两麦朝向是否一致、连线长度是否差异过大、声孔是否被遮挡），不要一上来就用 `CALIB_OFFSET_Q8` 把问题补偿掉；
确认对称后，把残余零偏写入 CALIB_OFFSET_Q8 = −lag0。
第 2 步：增益一致性标定
仍在 0°（对称位置），比较 ENERGY_L 与 ENERGY_R 的均值；
写入 GAIN_TRIM_R = 256 × E_L / E_R（Q8）；
期望两只麦的差异 < 1 dB（约 ±12%）；若差异远大于此，优先怀疑焊接/连线的焊点质量或模块个体差异。
第 3 步：角度表采集（核心数据集）
在 0°、±30°、±60°、±90° 各播放白噪声 30 s（每个角度至少 3 轮，打乱顺序，避免漂移污染）；
每点记录：lag 均值、lag 标准差、DIR_CODE 正确率、CONFIDENCE 均值、峰值/次峰比；
与 2.2 的理论 lag 表逐项对比，偏差应 ≤ 0.5 样本。
第 4 步：判档门限复核
检查 lag(±30°) 是否落在 2.4—3.5 样本之间；
若明显偏离 → 用游标卡尺复测实际间距 d（间距差 10% 会让 lag 差 10%，直接表现为门限失准）；
门限最终写入 THRESH_DIR_Q8（默认 0x0300 = 3.0）。
第 5 步：VAD 门限标定
无人说话时采集 60 s 的帧能量分布，取 P99 的 3—5 倍作为 THRESH_VAD_Q 初值；
再让一人在 1 m 处正常说话，确认其帧能量显著高于该门限（建议留 ≥ 10 dB 余量）；
门限过低会让环境噪声被判成语音（导致乱转），过高会让轻声说话被忽略。
第 6 步：泛化验证（不可省）
换成人声朗读、拍手、音乐各测一轮（0° 与 ±45°、±90°），记录正确率；
目的：证明结果不是"对白噪声过拟合"，这是答辩时最容易被问的点。
8.3 温度 / 距离 / 增益 / 混响的量化说明（答辩必答）
因素
量化影响
本方案结论
温度
声速温度系数约 +0.6 m/s·℃⁻¹ → 相对变化约 0.17%/℃；lag 与声速成反比，属乘性误差。15—35 ℃ 范围内总漂移 ≤ 3.5%，折算到 ±25° 的判档边界约 0.9°
不做温度补偿（0.9° 远小于档位宽度）；若将来要 1° 级精度才必须补偿
距离
0.3 m 以内球面波使平面波 ITD 模型偏差增大；0.5—1.5 m 内模型成立
标定与使用都落在 0.5—1.5 m
增益差异
对能量法（v0）是致命的；对互相关的 argmax 影响很小，只影响置信度
这正是选 v1 而不是 v0 的技术理由之一
混响
把相关峰拉平、抬高次峰 → 置信度自然下降

麦克风一致性

第 1、2 步标定处理；差异过大则换同批次模块
