# KV260 只读审查摘要

**目前没有证据要求重装 Ubuntu。** 系统包状态和选定核心文件校验正常，现存日志未见磁盘 I/O、ext4 错误或 OOM。主机空间仅剩约 22 GB，低于 PetaLinux 2022.2 文档给出的 100 GB 空闲要求；这是后续重建风险，不是已发生的文件损坏。

Vivado/Vitis/PetaLinux 均有 2022.2 安装证据。Vivado 可运行、K26 器件和 KV260 板卡文件存在；历史安装时两个设备列表后置任务因当时缺 `libtinfo.so.5` 失败，但相关输出文件现已存在，不能据此判定整套工具损坏。当前缺 `flex`、`bison`、`socat` 等宿主包，正式重建前应按该版本要求核对并补齐。`petalinux-build` 当前不在 PATH，只是没有加载环境脚本。

**自定义系统尚未跟上最新硬件产物。** 当前 PetaLinux XSA 内嵌 bit、`images/linux/system.bit` 与 SD 候选 bit 的 SHA256 均为 `6a75e223…`；9 月 26 日新重建 bit 为 `d316ee9c…`。当前 FIT 内核、设备树、ramdisk 与同目录独立文件哈希相符；`BOOT.BIN` 的各成员字节仍未与 BIF 输入逐一证明相同。新 bit 完成实现和时序收敛，但尚无配套系统重建与板端功能验收。两路 DPU reset 的网表断连现象仍无法判定功能安全。

现有 FPGA 工程的 BD、IP 和主要引用文件可找到；但 Vitis AI 源码 zip 为 0 字节，解压源码无 Git commit 证据，Docker 镜像无法在不触发服务的条件下实时核验，模型与板端实际 DPU 的一致性也未证明。因此它们可作为历史资料和重建候选，尚不能作为完整、可验收的正式重建输入包。

下载的官方镜像大小 3,503,938,277 字节，本次 SHA256 与提供值一致，`gzip -t` 通过；AMD 文档列出了该文件名。**尚未取得官方发布哈希，官方校验未完成。** 已静态读到 MBR、FAT 启动分区目录和 ext 超级块；这不能替代完整镜像与板端启动验证。官方镜像文件的哈希/解压验证不依赖主机 Vivado/PetaLinux；自定义镜像构建才受工程来源、空间、依赖和 reset 问题影响。

建议先查证官方哈希，并为官方镜像另行安排受控板端验证；自定义路线先确定唯一 XSA/bit/IP/arch/模型基线和 reset 验收方法，准备空间、核对依赖，再在新目录重建并记录 BOOT/FIT 成员哈希。本次没有修复、安装、构建、烧录或板端操作。详细证据见 [REPORT.md](REPORT.md)。
