AUAR 雪妃

基于 KV260 的多模型交互与执行监督系统

AMD 自主选题设计报告 V2 2026年11月2日

摘要

AUAR·雪妃以AMD KV260组织视觉感知、独立身份服务、语音交互、记忆和单轴执行。PS承担采集、预后处理、业务与显示，PL集成单个B4096 DPU和自研运动监督逻辑，Windows主机提供27B语言模型与OmniVoice语音合成。设计重点是多模型共享、结果时效、命令许可和完整回答交付。

历史固定输入对照中，YuNet与SFace路径中位耗时分别由124.02ms、520.86ms降为61.41ms、13.56ms；宽版平台使用66,960个LUT、710个DSP。后续记录已确认转轴随动、人脸KNOWN和声纹本人识别的阶段成果；新版联合演示、冷启动及长时召回仍待对应验收。接口合同Skill在本次Windows独立目录通过15项单元测试和73个模拟用例。各结果按其版本、输入与验证层级分别报告。

关键词：KV260；软硬件协同；多模型；执行监督；语音交互；可复现验证

1 选题背景与创新点

1.1 应用问题与设计目标

桌面交互终端需要同时处理“用户在哪里、面对谁交互、当前说什么、何时执行动作”等问题。单独运行视觉或语音演示时，模块容易各自成立；合入同一嵌入式平台后，相机与音频争用 CPU、模型任务相互等待、旧帧与旧回答迟到、显示与播放状态不同步等问题会直接影响使用体验。

本作品选择将较重的语言模型与语音合成留在局域网主机，把真实采集、视觉推理、业务状态、记忆和受监督执行放在 KV260。设计目标是形成可解释、可验证的交互链，并明确每个动作和每项性能数据所依赖的版本与条件。应用定位是桌面交互原型及教学研究平台。

需求设计响应验证关注点
连续感知交互对象唯一相机源、目标轨迹与人脸身份链有效输出频率、帧龄、未知人拒识
多个视觉任务共存单 DPU 共享、主任务优先、可选任务准入等待、超限、恢复与业务覆盖
交互与动作保持一致PS 校验目标及时效，PL 独立管理执行许可旧会话、乱序、超时及停止
自然语音与可追溯记忆流式交付、完整播放确认、摘要校验与回收内容正确性、取消、存储与召回
可交接与复用配套工件、证据索引、Skill 与复现说明新目录复现、依赖闭包及第三方执行

1.2 前人工作与本项目定位

YOLOX 提供目标检测的公开模型基础，ByteTrack 提供通过检测框关联维持目标轨迹的方法；OpenCV Zoo 提供 YuNet 人脸检测和 SFace 特征模型。本项目使用这些已有算法与模型，工作重点是目标平台适配、任务组织、接口与系统验证。[1-4]

AMD Vitis AI 提供 DPU 模型量化、编译和运行基础；官方 3.0 兼容说明列出与 2022.2 工具链的配套关系。PYNQ 提供 Overlay、DefaultIP 和寄存器访问机制，可作为接口合同生成工具的目标环境。[5-6]

既有基础本项目实际工作应用边界
YOLOX / ByteTrack复用模型与关联方法，接入板端采集及目标状态轨迹编号不等于真实身份
YuNet / SFace等价改写、校准、DPU 编译、模板版本隔离与质量评估公开配对结果不代替现场识别率
Vitis AI / DPU同一 B4096 上组织三模型及 CPU 预后处理调度逻辑位于 PS，未实现多 DPU 核仲裁
PYNQ 接口机制从合同与 HWH 生成访问及测试骨架当前只完成离线生成和模拟验证

1.3 主要设计特点与创新价值

第一，围绕交互任务组织计算资源。视觉主任务与按需人脸任务共享同一 DPU；数据准备、推理和业务接受分别检查，关注有效结果与等待，而不只统计模型调用次数。当前已有混合运行及恢复记录，调度策略的严格同输入收益仍需单独实验。

第二，把运动接口设计为带独立许可的事务。上层提供目标脉宽和有限租约，PL 检查会话、代次与连续序号，并在帧边界限速推进。停止和许可失效优先关闭输出。设计将感知和策略计算的波动与底层 PWM 时序分开约束。

第三，将回答交付与记忆提交相衔接。回答文本、播放确认、摘要校验和原文回收使用可追溯状态，便于检查迟到、取消与更正。已有自然到期存储证据，真实同会话摘要召回仍待完成验收。

第四，把实际失败转化为复用方法。PYNQ Skill 将“有地址窗口但缺寄存器元数据”“完成标志迟于超时”等问题固化为检查、反例和独立示例，形成可交给其他工程使用的离线工具。

2 设计原理与功能框图

2.1 系统总体结构

相机与 MCP01 接入 KV260。PS 负责唯一采集、预后处理、视觉业务、音频前端和语音识别，通过局域网请求 Windows 的语言模型与 TTS，再在板端完成字幕、角色状态和播放。PL 中的 DPU 计算视觉网络子图，自研监督 IP 接受经 PS 检查的运动事务。

系统具有两条相互配合的路径：感知交互路径将图像、语音和身份状态转为有效回答；执行路径将当前目标转为有边界的运动请求。开发链使用 Ubuntu 完成 RTL/平台构建、模型编译与文件校验，不参与日常交互推理。

2.2 视觉、跟踪与身份原理

相机采集后保留源帧序号和时间信息。YOLOX-Nano 提供目标检测结果，跟踪过程维持目标轨迹；YuNet 提供人脸框及关键点，PS 完成解码、NMS 和对齐，SFace 输出身份特征，再由 PS 归一化、匹配并更新业务状态。身份模板按特征模型版本隔离，匹配不足或歧义时保留 UNKNOWN。

部署记录中的三个网络均为 INT8 DPU 工件，每个网络包含一个 DPU 计算分区；板上共享的是单个 B4096。图像编码、后处理、对齐和身份匹配仍消耗 CPU。模型与预处理、输出端口顺序及缩放因子需要配套。[V04-V07、V19]

2.3 语音交互与记忆原理

较新的板端业务记录采用板端音频前端与 ASR，Windows 保持现有 27B 语言模型和 OmniVoice 推理。板端将转写、身份及会话上下文组织为请求，主机返回有效回答和音频；板端负责播放、字幕及角色状态。较早 Windows ASR 结果只用于对应历史链路比较。

一次请求应关联会话及请求标识。取消、会话切换和迟到返回需要在结果接受处检查；被取消或未完整交付的回答不直接作为完整已播历史提交。记忆处理将原文保存、摘要任务、有效摘要与回收状态分开，便于追溯来源与失败重试。[V10、V29、V31]

人脸与声纹按独立服务工作。保存进度已记录人脸KNOWN和声纹本人三次独立录音识别的现场确认；普通聊天首句自动识别接入仍在推进。人脸与声纹跨模态关联已取消，不列入本版交付和联合演示的前提。[V29]

2.4 单轴执行监督原理

PS 根据当前目标及帧龄计算请求；PL 侧使用影子字段接收会话、代次、序号、目标脉宽和租约，再在 COMMIT 时进行一致性判断。BIND 建立上下文，REFERENCE 写入经外部确认的控制参考，ARM 开放命令接受，COMMIT 更新目标与租约，STOP 关闭输出许可。REFERENCE 是控制参考，不提供实际角度测量。

宽版 RTL 使用 100 MHz 控制时钟和共享约 1 µs 时钟使能，PWM 帧周期为 20,000 µs，目标范围为 500-2500 µs，12 位字段保存脉宽，帧边界每次最多推进 4 µs。上述值来自对应实现，实际机构零点、角度、负载及允许行程另行标定。[V20-V23]

3 软硬件划分依据与接口设计

3.1 平台选择与工具版本

目标平台为 KV260，宽版实现报告声明器件为 xck26-sfvc784-2LV-c。项目沿用已有 Vivado/Vitis/PetaLinux 2022.2 与 Vitis AI 3.0 环境，原因是已有参考平台、系统和模型编译链围绕这一组合验证，官方兼容说明也给出该组合。依据 AMD 指南，采用其他工具版本应说明原因并提供可复现脚本。[5、7、V01-V03]

该选择不表示任意同名镜像或 DPU 文件均可互换。最终 release 需要固定源码、实际 DPU fingerprint、模型目标、运行时、BIT/XSA/DTBO/XCLBIN 及设备树映射。

3.3 硬件与外设接口

相机和 MCP01 通过板端外设接口接入；显示通过现有显示转换链连接屏幕；网口连接 Windows 主机。运动信号在宽版 XDC 中约束为封装脚 E10、LVCMOS33；B03参考资料将E10映射为J2.3。封装脚、连接器针号和模块端子是三类编号，实物载板版本与针1方向需要另行确认。现有方案记录使用 ADuM1201 和独立舵机供电，最终接线、两侧电源/地及实际隔离关系仍须用实物原理图核对。[V20-V22]

控制器读回的 PWM 脉宽表示指令状态。它不能代替角度传感器、示波器测量或机构行程验证。附件wiring已给出资料核对版电气接线图、整机外设连接图及W01-W11逐线表，保留供电方案值和现场待核项。实物照片、实际供电值、模块端子和机械装配图需随最终实物记录补齐。

有效 COMMIT 要求已绑定、已参考、已 ARM，影子会话/代次匹配，序号恰为 ack_seq+1，脉宽在允许范围内，租约满足 4-500 ms。命令写入得到 AXI 应答后，软件还须检查业务 reason 和 ack_seq；AXI 总线成功不等于命令已生效。

STOP、租约失效及完成 QUIESCE 会关闭许可并使原绑定失效。QUIESCE 允许正在输出的脉冲自然结束；显式 STOP 具有直接关闭语义。源帧时效由 PS 检查，当前 PL 租约从接受命令起计时，PL 并未验证源帧的绝对截止时间。

3.6 时钟、复位与异常处理

监督逻辑在对应 AXI 时钟域运行，采用时钟使能生成时间基准，避免另造低频门控时钟。复位时输出与许可关闭。平台还有 DPU、视频及显示时钟，应随最终 clocks、timing、CDC 和 DRC 报告一并提交。

独立审查已记录 setup/hold 失败端点为0、路由错误为0，同时保留六类 DRC warning 和 6 个 no_input_delay、2 个 no_output_delay 端点。WNS 接近0，当前结果只覆盖已声明约束；板外 PWM、电源及机械测试仍需相应证据。[V03]

4 优化过程与性能、资源对比

4.1 测量口径

本章将固定输入模型对照、模型任务质量、静态实现资源和正常业务观察分开。每张表注明输入、样本量或版本；正文的中位数与 P95 使用历史原始结果中的定义，本轮未重新采样。已有结果不混合成“最终整机平均性能”。

对完整视觉路径，可把耗时分解为采集/排队、预处理、DPU 等待与执行、后处理和业务接受。对语音路径，可分别记录发言结束、ASR 完成、首正文、台词就绪、首 PCM 和板端播放开始。软件事件与扬声器真实首声属于不同测量量。

4.2 模型迁移：从 ARM FP32 到 DPU INT8

迁移先检查算子与数值，再完成代表性校准、目标编译和固定输入板测。模型外处理保留 PS，运行器以 VART 返回的端口顺序组织缓冲区。早期曾因 XIR 集合顺序与 VART 端口顺序不一致发生错误，修正后增加了顺序互换回归。[V04-V07]

路径与样本ARM FP32 中位 / P95DPU INT8 中位 / P95中位加速比
YuNet，40 次固定输入，含预后处理124.02 / 147.60 ms61.41 / 64.75 ms约2.02倍
SFace，8 次已对齐固定人脸，含输入输出转换520.86 / 627.78 ms13.56 / 26.60 ms约38.41倍

该对照同时改变执行硬件与数值精度，收益不能全部归因于量化。迁移复用同一 DPU 位流，不新增 DPU 核；软件模型切换本身没有新增静态 LUT/DSP/BRAM。两项短测不能表示 Windows 主机或整机问答的加速比。[V04-V05]

6.2 从失败到规则

第一次观察是元数据不完整。真实工程HWH中自研模块的REGISTER元素数为0，表明地址窗口与完整寄存器描述不是同一种信息。工具因此区分MATCHED、INCOMPLETE和冲突；缺少定义时不能凭空生成register_map字段，已知冲突不能绕过。

第二次观察是完成判定顺序。软件需要先判断观察时刻是否超时，再接受完成标志，防止“最终完成”覆盖“已错过期限”。对应反例和修正保留在包中。

第三次观察是单个示例不足以证明复用。加法例与CRC例更换实例、寄存器偏移、完成位和读清除语义；算法分别放在独立模拟和黄金参考中，生成器核心不按算法分支。

7.5 FPGA构建步骤

1. 在Ubuntu新工作区准备完整平台工程与已核对参考DCP，固定工具版本、IP仓库、RTL/BD/XDC和输入SHA。

2. 将原构建入口中的VIVADO、REFERENCE、平台输出和IP路径映射到该工作区，保存修改差异和新的输入清单。V14为历史入口证据，其绝对路径不能直接在其他机器上使用。

3. 先执行tb_wide、tb_servo、tb_pulse_guard和tb_nominal四套RTL验证，再按prepare、implement顺序完成平台构建。

4. 归档utilization、clocks、timing、check_timing、route、DRC，按需要检查CDC；记录警告、外部时序缺项与失败，不以单个WNS代替全部约束完整性。

5. 从同次路由结果导出配套工件，核对XSA嵌入载荷、位流、DTBO/XCLBIN、IP ID/ABI/build与模型目标。独立验证成功后再安排目标板部署。

7.6 模型和软件准备步骤

1. 按V19模型清单取得固定版本YOLOX-Nano、YuNet和SFace，保留来源、许可与SHA。公开仓库会更新，复现应选择经过本项目验证的工件，而不是仅按同名最新文件替换。[3-4、V19]

2. 固定B4096目标fingerprint 0x101000056010407及真实arch.json，使用项目保留的等价改写、量化与编译脚本；校准、选阈值、独立测试身份保持分离。

3. 依次验证浮点等价、INT8任务质量、编译接口和实板固定向量。VART端口顺序、输入形状、缩放因子与预后处理应配套。

4. 按最终应用、相机、控制器和原生库清单准备板端文件与服务。Windows准备相应LLM/TTS环境；大语言模型权重位于项目共享目录之外，使用明确的外部路径配置。

5. 在各自设备维护流程下验证服务就绪和LAN请求。新启动需要建立新的上下文与实际配套关系，不沿用旧进程和旧启动的绑定凭据。
