# 转轴跟随

2026-10-19分工：Ubuntu负责跟随，Windows负责身份。第一版软件已完成；当前实板仍为官方DPU位流，无VSRV，尚未启用真实运动或常驻跟随。

## 数据与控制

同一个相机服务完成YOLO/ByteTrack和身份处理；可选启动入口 `tools/board_camera_motion.py` 为它增加只读的 `GET /v1/motion/observation`。扩展保留原HTTP路由，不另开摄像头、模型或DPU，不修改身份/相机源码。接口只含选中轨迹的框、置信度、源帧编号、相机/服务/轨迹代次及源时间，不含照片、姓名、特征或身份库。

`source_mono_ms`沿用原帧appsink出队的板端monotonic时间，不使用UI刷新时间。有效期固定为源时间+250ms；预览继续更新不能刷新旧检测的期限。相机错误、检测错误、选择未完成、目标丢失或证据不一致时不输出可用目标。

`board/motion/follow.py`使用五个不同的新鲜源帧确认目标，然后计算人体框中心相对画面中心的横向误差。默认低通时间常数100ms，死区进入阈值0.05、退出0.025，40µs/s、每次最多4µs、参考位置±40µs，并受已有1400～1600µs台架范围约束。这些是脉宽限制，不是实测角度/机械限位。

镜像方向历史确认值为polarity=-1：画面左侧对应脉宽增大，右侧减小。新机构的安装与标定仍需现场核对。相机装在轴上时使用居中反馈；相机固定不随轴转时必须提供实测左/中/右指向锚点，不能持续积分同一偏差。画面已居中时保持当前指令位置，不无条件回机械零点。

重复帧不产生新提交或延长期限。失联、过期、换人、相机/服务重启、帧倒序、同源数据被修改、ACK拒绝/未知或时钟异常均停止并锁定，恢复需要新建显式会话。停止PWM不等同测得机构立即刹停。

## 运行方式

当前工具只提供旁路模式，不打开寄存器或ARM：

```bash
python3 -B tools/board_pan_follow.py --live --duration 10 --output /tmp/pan-shadow-new.jsonl
```

实况模式须在板上运行，且相机已通过可选入口提供新接口。现有运行相机尚未加载该入口；直接执行会提示接口未就绪，不会悄悄改用旧UI时间或另跑模型。

合成坐标可独立回放：

```bash
python3 -B tools/board_pan_follow.py --replay replay.jsonl --boot-id boot --output /tmp/pan-replay-new.jsonl
```

输出文件必须是新文件，避免覆盖旧证据。默认1500µs和相机随轴的假设仅供旁路计算；`config/pan_follow.shadow.json`明确标记未标定、physical_actuation_enabled=false。

物理控制器接受已经显式确认参考并ARM的 `VSRVDriver`，要求当前boot、参考脉宽、方向、相机安装声明和固定视角标定一致；自身不会加载FPGA、打开MMIO或自动ARM。现有VSRV/1为相对租约加源年龄补偿，不应称为新版绝对源期限硬件。
