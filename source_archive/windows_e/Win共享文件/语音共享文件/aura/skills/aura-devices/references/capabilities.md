# 设备能力及实际入口

当前Windows语音服务为voice-turn-handoff-20261029-r6，保留r4记忆功能，记忆权威库继续在Windows，用户已明确迁移后置。“我喜欢什么颜色”等明确事实问题直接读取当前有效值，不经过27B，不猜未记住的值；白名单覆盖颜色、称呼和项目的明确问法，既有人脸身份查询优先级保持。未指定范围时当前会话同项事实优先，然后是当前明确授权的个人档案；也可说“本次对话里，我喜欢什么颜色”或“个人记忆里，我喜欢什么颜色”，访客不能越权读取。

“查看颜色记忆历史”“我以前喜欢什么颜色”只读仍有效的录入/更正版本，默认最近两条摘录；“查看颜色第1条记忆历史”或“查看颜色第一条记忆历史”按从新到旧1—32编号读取完整存储值。“查看记忆历史”会提示指定项目。忘记某项同时移除其历史版本；日期仍是录入/更正日期，不代表事实实际生效时间。

普通持久回复记录memory_source_coverage完整来源标记，包括明确无历史来源。删除时对缺标记且无来源边的旧/导入/回退程序回复，自动保守停止相关范围后续召回，并将影响数量纳入预览；不再只依赖初次升级序号截止，不能给未知旧行伪造完整来源。当前交付及测量见项目deliverables/2026-10-29_dialogue_memory_polish/README.md。

“删除昨天关于比赛的对话记录”先给范围/数量预览；60秒内说“确认删除这些对话记录”才删除，也可“取消删除对话记录”。默认本次会话，个人范围仍需授权；新删除请求撤销旧预览。删除整轮数据库原文和来源事实，关联摘要失效、关联旧回复停止召回，不删除视觉记录或备份，不保证介质擦除。主题采用字面匹配而非模型猜测；范围/来源发生变化必须重新预览。实际验证见项目deliverables/2026-10-29_memory_controls/README.md。

| 能力 | 调度入口 | 执行和数据 |
| --- | --- | --- |
| 语音唤醒、接话、插话 | VoiceFirstRecordingController → ChannelConversationJobs → 8792 | 板端单一采集者，Windows ASR/LLM/TTS；PCM 在 RAM，结果按 request/generation 绑定 |
| 即时视觉问答 | X-Aura-Visual: frame-question-v1 | 主机 transcript 请求 token；板端从 8790 的现有预览获取同一 frame/epoch/boot JPEG，回传 /v1/voice/visual/frame；8810 CPU VLM回答 |
| 定时观察 | DeviceObserver → 192.168.50.1:8812/v1/observations | 默认 15 秒，最大一项推理，图像不落盘；摘要有 boot/epoch/frame/接收时间；关闭监听同时停止观察 |
| 摘要回忆/清除 | 主机 device_client → 127.0.0.1:8812/v1/memory/recall 或 /forget | 模型上下文注入带来源的摘要；“清除画面记忆”清除本次开机记录，同时拒绝在途旧结果重新写入 |
| 时间轴检索 | memory_timeline_host → 已授权 ConversationStore + 本地 8812/v1/memory/timeline | 时间/主题过滤后按统一预算注入；对话取权威档案，视觉事件按配置设备跨 boot；来源、接收时间、有限检索范围明确 |
| 时间轴删除 | 本地 8812/v1/memory/timeline/forget | “删除昨天的画面记录”或“清除所有视觉记忆”；日期范围内短期缓存及事件一起删除，持久版本屏障拒绝旧任务写回；关联对话回复在下轮检索时取消召回资格 |
| 人脸登记/识别 | 8792 identity exchange → 板端 VoiceEnrollment → 8790 identity 命令 | 现有注册流程、目标/帧绑定、模板/库版本、UNKNOWN/AMBIGUOUS 保护保持；不调用 VLM 猜人名 |
| 声纹登记/查询/删除 | 8792 device_client → 8812/v1/speaker/turn | 精确 ASR context+PCM摘要；ECAPA CPU 单线程池；三样本、一致性检查、最终保存确认；独立模板库，未标定不自动认人 |
| 入镜招呼 | VisualSocial → 缓存选定音色 → 原播放器 | 稳定入镜 0.6 秒“嗯？”，4 秒无发言后一次邀请，30 秒冷却；语音忙碌则让路，播放可由原回声核验插话路径打断 |

`8812/health` 明确报告声纹是否 ready/calibrated、最近视觉错误和保留时间。普通语音不会等待声纹/视觉推理；声纹指令才发送同一次已完成采集的 PCM。LLM 与新增视觉、声纹模型位于 D 盘，ASR/TTS 保持既有授权路径；摘要及声纹数据库在 Windows 用户私有 `AppData/Local/Aura/device-memory`，不打包到共享目录。时间轴参数在 `aura/config/timeline_memory.json`；当前默认时区 America/Los_Angeles，事件时间是接收时间，不是板卡墙钟。

“刚才看到了什么”“昨天下午杯子在哪里”等历史问题读取时间轴，不自动重拍当前画面。当前支持单日、上午/下午/晚上、上周/本周、最近若干天；不支持的日期组合要求澄清，不能换成不限日期的检索。新增事件不保存原图；旧版短期观察不自动延长到 30 天。当前合成录音实测“汐蓝”独立唤醒通过；短促“哎/欸”仍有转写失败，专用 KWS 候选尚未接入正式服务。时间轴部署及验收见项目 `deliverables/2026-10-28_timeline_memory/README.md`，其他交互限制见 `deliverables/2026-10-28_device_skills/README.md`。

示例：“汐蓝，你好”“这是什么颜色”“刚才看到了什么”“清除画面记忆”“登记我的声纹，我叫小林”“确认保存声纹”“你认识我的声音吗”“删除声纹小林”“确认删除声纹”。人脸登记沿用“帮我登记身份，我叫小林”及板端引导。

限制：VAD+ASR 不是专用流式 KWS；即时唤醒、自然噪声、多说话者、声画归属和现场声纹准确率须单独验收。视觉观察是配置设备的环境记忆，不属于任意个人；不据此写入个人档案。相近时间只能建立环境上下文，不能自动认定画中人是发言者。记忆数据库当前仍由 Windows 管理；ARM 测试通过不表示权威数据已迁到板卡。


语音请求交接最多等待5秒，始终受原请求总时限约束；客户端断开时，已开始的OmniVoice合成在原时限内完成后丢弃旧结果，保留暖态模型，不发旧PCM或提示音。服务健康含最多16条RAM请求结果码/字数/等待元数据，不保存原话。单独“汐蓝”返回唤醒聆听，不代表完整问题已作答；实际修复见deliverables/2026-10-29_listening_bounce/README.md。
