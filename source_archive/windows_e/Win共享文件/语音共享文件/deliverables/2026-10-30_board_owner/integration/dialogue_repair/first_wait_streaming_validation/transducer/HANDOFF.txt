Recommended four-file set totals 60,142,871 bytes, excluding runtime working memory. Large ONNX hashes are official LFS metadata; root verifies downloaded bytes. No model was downloaded or executed by this agent.
- Public upstream test_wavs/0.wav was read into RAM only: 321744 bytes, 160850 frames at 16k mono PCM16, SHA7d93384c..., 10.053125s. It is not the existing Paraformer/CTC 0.wav; no gold transcript claimed. Worker intentionally uses the same already-pinned 8 synthetic WAVs instead.
- Version-fixed from_transducer API exists in sherpa-onnx v1.13.8. It takes encoder, decoder, joiner, tokens, not a chunk_size argument. The chosen upstream exp/32/export-for-onnx.sh explicitly sets --decode-chunk-len 32. Do not swap exp/64 or exp/96 and still describe it as this candidate.
- Model type is read from model metadata by the recognizer. Start with 1 CPU thread and greedy_search, endpoint detection disabled. No hotword, LM, spelling replacement, or test-text-specific correction.

For realtime public pacing, use --mode realtime --feed-ms 160 (or 20). Each invocation loads one constant recognizer and makes one fresh stream per case; all eight cases must validate before model load. First decode is explicitly labelled; no hidden warmup. Use the existing reviewed Python/sherpa/numpy environment, not a package install.
The wrapper must enforce a root-owned external deadline and verify the current exclusive hardware window. Soft checks cannot interrupt a single stuck native call. This worker does not inspect/control production services, signal processes, open microphones, play audio, access Store/network, or persist anything. Native logs go to /dev/null; only public synthetic references/hypotheses and fixed numeric diagnostics go to stdout JSON. Exceptions use fixed enums. Bytecode writes are disabled.

Tail/measurement
- Both modes append 0.66 s / 10560 float32 zeros, call stream.input_finished(), drain while is_ready(), then get_result(), following the pinned official example. No extra 0.66s wall-clock sleep. These zeros are model context, not recorded speech.
- quality feeds the whole WAV before tail/drain. Its timing is offline_quality_not_realtime_latency. Do not call it speech-end latency.
- realtime offers 20/160ms chunks when their last sample becomes available, preserves final short blocks, and never discards overdue blocks. final_after_scheduled_input_end_ms includes accumulated input lag, last-block decode, and flush. Do not replace it with flush_wall_ms alone. No live capture or Silero endpoint evaluation is implied; endpoint_source=PUBLIC_WAV_END.
- Sample rate and actual PCM bytes remain those in the frozen manifest; no resampling in this worker. CER is against intended synthetic text, not human-verified spoken content. Critical spans are literal diagnostics; semantic_acceptance_passed remains null.
