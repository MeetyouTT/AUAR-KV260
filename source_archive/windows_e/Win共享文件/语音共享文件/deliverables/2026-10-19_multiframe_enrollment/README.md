# 多帧人脸登记与独立验证

用户2026-10-19同意实施：4份正脸、3份轻微左转、3份轻微右转用于选样，再用5份新正脸验证。匹配门槛0.85、身份间隔0.1保持，已有身份不自动删除或更新。生效状态以`deployment.json`及`verification_summary.json`为准。

## 实际流程

语音入口仍是“帮我登记身份”→“我叫某某”。随后板端启动一次有独立会话编号的内存采样，电脑原OmniVoice16分阶段提示正脸、左转、右转和回正验证。采样期间无需额外录音或调用27B；普通对话仍走原链路。

样本必须来自同一人脸轨迹和身份库修订，帧号严格递增、源时间晚于采样开始，至少间隔500ms。人脸较小、眼间距不足、模糊或明显歪头不计数。五关键点的眼轴与鼻部位置只提供几何姿态引导，使用首4份正脸建立基准，不是精确3D头部角度模型。尺寸至少72像素、眼间距至少18像素、清晰度方差至少40、歪斜不超过12度。

前10份中选择与这批样本整体最相近的一份真实特征模板，不合成或平均特征。选样完成后才开始接收5份新正脸验证；每份均须对候选达到0.85，并超过其他保留身份至少0.1。只要有一份失败，就清除候选并报告未保存。后5份不参与选样。

验证通过后仍需明确口头或屏幕确认。相同称呼会指向原身份；语音明确提示更新，必须说“确认更新登记”，普通“确认登记”不能替换旧模板。更新原ID和称呼并增加库修订，身份数量与其他身份保持。新称呼创建新身份。最终保存前再次核对当前人脸、结果新鲜度、库修订以及当前帧对候选的匹配。

采样最长90秒，通过后确认窗口60秒。换人、失脸、多脸、库修改、取消、网络请求结束或超时都会禁止保存；语音取消后的摄像头采样通过带会话编号的取消命令清除。屏幕仅显示112×112实时人脸裁剪、阶段与计数；失败后可点“重新采样”。所有选样图片和特征仅存RAM，完成/失败/取消后释放，不新增现场照片文件。

## 部署、证据和回退

最终候选为`candidate-c4f2aaebaf87`，完整板端路径见`candidate.json`。电脑仅空闲重载8792以接入阶段语音协议，原Paraformer、27B/IQ4_XS、OmniVoice16、语音生成参数和延迟开关保持。板端UI/相机仅在录放音和自动对话停止时切换，启动失败自动恢复旧单元。部署校验身份库文件保持。

`verify_and_archive.py`核对活动代码指纹、原人体DPU/ByteTrack及音频播放源码和生效配置；`verified_source.zip`只包含代码和小型配置。`rollback.py`恢复前一版板端UI/相机单元，不恢复或删除身份库。新的电脑语音协议向后兼容旧版单次登记回复。

真人新采样、用户听音及离场返回识别仍需现场验收。此流程能阻止未经独立验证的模板写入，尚不证明在所有姿态、光线或离场返回情况下达到0.85。也未实现活体检测、声纹归属或个人长期聊天记忆。

加载后的45秒元数据观察`live_sampling_observation.json`中，采样一直为`idle`，没有观察到用户启动新会话。人脸模型持续处理且无相机/模型错误；此时`identity_enroll=false`是等待独立验证的正常门控，不能将其当作新采样失败。用户已收到语音实测步骤，反馈仍待补入`listening.json`。

大语言模型权重与Ollama数据仍在D:/AIModels；本轮没有下载模型，不把权重、虚拟环境、身份模板或现场人脸照片复制到共享目录。
