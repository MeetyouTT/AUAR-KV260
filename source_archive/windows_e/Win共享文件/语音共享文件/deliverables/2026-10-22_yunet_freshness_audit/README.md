# YuNet 结果时效独立审查

2026-10-22。本任务只读取本机冻结源和数字证据，没有连接板卡、UART、相机、音频或网络服务，没有修改生产、共享入口、回执或主线候选。这里的 6 项虚拟时间路径检查通过属于本机软件证据，不能称为板端故障复现。主任务正在进行的亲和性实测不在本报告范围内。

**结论：1ms 双模型长测证明了当次吞吐和 30ms/5ms 保护通过，但还不能放行持续有效的人脸结果。最小后续应先补齐“拒绝→下一次尝试→发布”的数字关联，再单独验证仅对 YuNet `SlotUnavailable` 的有界短退让。** 保持原保护、身份库、模型和模板语义，不把提高 CPU 占用本身作为收益。

## 能从源直接解释的路径

1. [`FaceTargetService.offer()`](../2026-10-21_dpu_vision_start/candidate/aura/board/identity/face_targets.py) 第 31～34 行只有一个 latest pending 槽；不会累积帧队列。`process()` 第 56、77 行分别拒绝入场已过期、检测后过期的输入。`stamp` 只在第 119 行有效发布时更新，保存的是采集出队时间，**不是发布时刻**。
2. 同文件第 60～67 行捕获 `SlotUnavailable` 后只增加 `discarded`，保留旧观察的 `stamp`。这是为了避免把“没拿到 DPU”误作“没有人脸”；旧结果仍必须遵守原 1000ms TTL。
3. `work()` 第 145 行对成功和 `SlotUnavailable` 返回都设置 `next_at = 本次处理结束 + 200ms`。DPU 准入前已有输入转换、量化和输出分配等 CPU 路径；拒绝也会花费这部分时间。连续拒绝时旧 `stamp` 不动，每次还会等待 200ms，因此平均 2Hz 不保证每次结果间隔都小于 1 秒。
4. `current_target()` / `view()` 在年龄达到 TTL 时隐藏旧目标和脸数；`health()['ready']` 只表示初始化完成且没有 error，**不表示结果新鲜**。所以“健康但年龄超限”在当前接口语义下是允许出现的状态，不等于健康接口错误，更不是模型算错的证明。年龄也可能属于一次 0 脸负观察。
5. [`DpuVisionSchedule.optional()`](../2026-10-22_thread_wait_diagnostics/candidate/aura/board/vision/dpu_vision_schedule.py) 要求无 active、无等待的主任务，且距主期限至少 `estimate + 5ms`。首次 26.6063ms 的估计偏差后，估计升为 28.6063ms 并在后续快照保持，准入需约 33.6063ms 余量；当前没有衰减。10Hz 主任务与 200ms＋处理耗时的尝试周期可能形成不利相位，这是值得验证的假设，不能从稀疏计数直接认定。不要为消除拒绝降低估计或放宽保护。
6. 准入后的 native 执行、解量化、CPU 后处理、state.lock、回调，以及工作线程调度等待都可能扩大源帧年龄。当前数字没有覆盖每个阶段，不能在“拒绝、CPU、锁、GIL、native”之间确立唯一因果。已有一条末快照差值也不足以证明 CPU 后处理是主要根因。

[reproduce_service_paths.py](reproduce_service_paths.py) 直接加载上述固定 SHA 的真实服务源，使用依赖替身和虚拟时钟，验证 latest 覆盖、拒绝保留 stamp、过期隐藏、过期输入不进入 detector，以及拒绝处理 40ms 后仍等待 200ms 的真实 `work()` 路径。4 次拒绝使旧结果过期的演示仅是可行路径，40ms 为合成输入，不是实板拒绝耗时测量。结果见 [local-path-checks.json](local-path-checks.json)。

## 阶段和最长 trace 的限制

长测同 PID 首末差值的阶段平均：YuNet native+观察 `execute_wait` 4.4346ms、解量化 2.1396ms；YOLO 完整 path 20.6851ms、发布时间源年龄 64.9004ms；预览渲染/编码/发布 21.1791ms、capture callback 5.6706ms。它们是墙钟耗时，可能重叠执行，不能相加为整板 CPU 或 DPU 忙时。完整 YuNet CPU 预/后处理、condition/state 锁等待和回调仍未分段；`face_targets.last_inference_ms` 是最后一次成功 detect/解析的值，25/121 次稀疏读取也不能代替每次调用分布。

最长正常 trace 在诊断起点后 468.4431s：scheduler 占用 27.2545ms，execute 11.6185ms、wait 0.1046ms；`execute_return → wait_start` 间隙为 **15.2005ms 墙钟 / 0.4644ms 调用线程 CPU**。该间隙位于 Python/诊断读取和锁操作路径，包含可能的调度/GIL等待；两次读取本身墙钟合计仅 0.1347ms，不能把其余全部归给读取、纯 native 或硬件。此 trace 的位置与三个过期快照不重合，不能当它们的精确根因。

正常成功计时累计平均 optional=4.6594ms、execute=3.6114ms、wait=0.1332ms；平均值不能排除间歇长尾。1ms 长测整板 CPU=69.1032%、同窗口新匹配 USB=0、原保护 fault=0，有效证明范围如实保留。没有同输入 CPU 收益对照、XRT 忙时或严格 GIL 因果证据。

## 最小下一候选和记录要求

先等待主任务亲和性单变量测量结束，保持其结论独立。最小代码候选限定为默认关闭的 FaceTargetService 数字观测与 YuNet 拒绝短退让，分开验：

- **先观测，不改调度。** 计数 offer/latest 替换、attempt/成功发布/不同丢弃原因、当前/最大连续拒绝、源帧入场及发布年龄、成功发布时间间隔；以 monotonic 数字关联 attempt、DPU 请求和发布。补 detection 前/后、取得 state.lock 前/后、on_face 前/后墙钟和调用线程 CPU。纯数字有界缓冲与聚合，在锁外输出；先检查开销，所有开销仍计入原 30ms。
- **再单独试短退让。** 仅当 `process()` 明确返回 `SlotUnavailable` 状态时，在正常 200ms 周期前多一次/两次最新帧尝试。可先评审 25ms backoff、最多 2 次重试的保守参数：一轮从第一次准入拒绝开始，绝对准入截止为 `首拒绝 monotonic + 200ms`，第一次调用加两次重试最多 **3 次 CPU 准备**；预处理时间必须算入截止，不能只相乘 backoff 次数。每次从同一 latest pending 槽取当时最新帧，不保留旧图反复执行；无新 pending 就等新帧或到截止，不复制图像、不另建队列。
- 一轮内在等待前、CPU 准备前，以及 CPU 准备后且取得原可选准入后、真正 VART 调用前，再核对绝对截止和该帧 TTL。到截止后不再发 native，也不开始新准备；过期/取消/关闭立即结束这轮。这个边界需要给 `DpuYuNet` 的 native 前路径传一个仅本轮有效的截止，**只改 worker 的 sleep 不足以实现它**。已开始的 CPU/native 调用不可被 Python 强行打断，所以 200ms 应准确称为“开始/准入截止”，不是严格返回总墙钟上限；记录实际轮次结束和超出部分，不能掩盖该限制。原非抢占 native 仍受 30ms/5ms 收尾保护。
- 每次保持原完整调度 gate，成功、无脸、其他错误和退出保留原语义。只有纯准入拒绝且仍新鲜时 retryable，disabled/native failure/真实超限/截止过期均不重试；截止过期也不伪装成负人脸观察。任何 backoff 或等新帧都在 DPU 槽外进行，不持 state.lock/condition 锁睡眠（`condition.wait()` 应释放锁），不忙等，不预占 DPU 等下一帧。默认关闭时不得新增额外 CPU 准备或改变 200ms 周期。
- 这个候选可能减少拒绝后空等，也可能增加 CPU 负载或仍遇到不利相位，当前没有收益证明。加入本机虚拟时间验证：默认行为不变、次数/总时间边界、latest 优先、TTL、取消/关闭、真实超限仍走原降级。主任务审核后才独立板验，不与 1ms 或核分配混改。

真正要统计的时效是“上一有效源帧的 `stamp + TTL` 到下一有效发布之间的空窗”，可在每次发布记录前一个 stamp、上一发布与本次发布计算，并裁剪观察窗口首尾；另单独统计 fresh 0 脸、未确认、多脸、目标改变。这样才能区分“结果过期”与“有人但检测/确认没给出目标”，也能得到每次发布的真实间隔分布。五秒健康快照只用于低成本监督和故障恢复。

## 回到 SFace 三模型之前

1. 原有 GIL 双模型没有真人覆盖门槛。三模型前重新核验原后端、30ms/5ms、同一个 PID/boot 和自动回退，再做有界预检：持续单人脸、确认目标存在、YuNet 结果年龄小于 1000ms、采集新鲜。无脸要同时记录“新鲜负观察/TTL 过期/未确认”，不能把 0 脸直接解释为用户离开。只有稀疏 13/13 样本为 1 仍不能称连续覆盖。
2. 10 分钟之前先 60～120 秒真人三模型，逐发布统计时效和 fresh 单脸有效供给、producer 提交/拒绝/替换/过期、SFace 请求/准入/拒绝原因/重试/耗尽、native attempt/completed、fresh accepted、source age 在执行前/后。SFace 的 freshness 与 target 校验沿用现有 producer/shadow 的前后复核，保持正式 Windows 身份、旧库和 shadow-only，不开始登记。
3. 固定计数窗口内按同 PID 差值验收 SFace **fresh accepted ≥0.5Hz**（600 秒至少 300 次、1800 秒至少 900 次，实际用测得窗口向上取整），native 成功数至少覆盖 accepted，不能用启动累计数或 requests 代替。控制真人稳定覆盖下若观测到目标 TTL 空窗，单列时效失败；即使总吞吐通过，也不放行为正式身份。最大有效完成间隔应在测试前冻结并记录，不能仅看总次数。
4. YOLO≥9Hz、YuNet 有效结果/采集/预览时效、原保护 0 真超限、无新增设备告警、无异常重启、源和配置保护、结束恢复均需同时成立，再从 10 分钟到 30 分钟。先核分配或 GIL 单变量结果再选配置，不同时追加多个未经验证的变化。
5. 三模型计算通过之后，正式 INT8 身份仍需独立 INT8 登记库、现场阈值、已登记者/未登记者验证。固定图和 shadow 吞吐不能替代身份准确率；本轮没有采集新图、保存向量或修改任何模板。

该报告中的短退让和更细观测是精确建议，**未实现、未部署、未声称修复**；根因、连续真人覆盖、整板收益和正式身份均保留未验证。
