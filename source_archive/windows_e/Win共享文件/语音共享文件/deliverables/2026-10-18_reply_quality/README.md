# 普通聊天防复述保护及延迟分段核查（2026-10-18）

本轮针对已记录的“汐蓝今天过得怎么样”原样复述，保留原27B/IQ4_XS、2048上下文、采样参数、人设、称呼容错、四轮记忆和OmniVoice16。新增保护在电脑流式回复层；没有改KV260、摄像头、YOLO/DPU/FPGA或模型权重。

## 定位与方案选择

此前3次无历史完整语音HTTP探针出现2次问句复述。新旧无历史请求体相同。此次原提示8次原生模型探针（2次随机、固定种子0至5）全部正常，说明不能靠少量正常回复认定缺陷消失。

候选“明确区分聊天和改写”提示8次出现1次复述，固定seed3可复现；`guidance.json`同时保留原始模型JSON和解码台词。因此确认这类复制可以直接发生在模型生成阶段，不能归因于板端播放。候选提示未部署；尚未确定权重、采样及后端状态各自的影响，不能宣称完整根因已解决。

实际采用有边界的输出保护：

1. 仅普通聊天中，当回复仍逐字匹配输入问句（允许省略开头问候）时，暂存这一小段文字；一旦出现不同内容就立即放行，普通回答仍为一次模型请求。
2. 完整台词字段闭合后若确认只是复制问句，不发送该段文字、音频或完整回复；用同一27B、同一历史和采样参数，附加一次直接回答的纠正指令重新生成。
3. 每轮最多纠正一次，沿用剩余总超时与取消事件。第二次仍复制则返回“这次没能接住问题，请换个说法再试。”，不播放错误答案，也不写入记忆。
4. 明确要求复述/转写/改写的表达按用户意图处理。短确认、只共享开头但继续作答的回复保持原文字。

保护只覆盖至少8个规范化字符、完整或省略问候后的问句复制，不判断泛泛回答、改述后的复读、事实真假或所有中文意图。显式任务判断也是启发式。原生长思考和旧完整WAV接口保留原路径，不宣称所有回复质量问题已解决。

`timing.llm`新增实际输入/系统提示SHA256、疑似复制标记、纠正次数、首次实际放行和总处理时间。纠正发生时保留两次尝试的指标。原始ASR仍在transcript，避免诊断时重复存放整段输入。下游播放ACK、音频哈希、样本校验和记忆提交规则保持。

## 验证

- 138项回归、26个子用例通过（`tests.log`）。覆盖错误台词不进入TTS/待提交历史、纠正成功、两次失败、取消、正常共用前缀、合法复述和原有播放/记忆/路由。
- 初次非提权测试130项通过、2项本机HTTP测试因WinError10013被沙箱阻断；记录保留在`tests_sandbox_blocked.log`。获得本机网络执行权限后完整回归通过，没有把权限失败当成代码修复。
- `task_validation.json`：真实原27B连续四轮后，正确回答“小林、绿色、十五”；主动要求复述和错字改写均正常且无纠正重试。
- 同一报告的固定seed3压力样本使用被拒绝的候选提示构造可重复的真实错误；保护拦住第一次问句，第二次正常接话。台词就绪约7.325秒、完整JSON约9.168秒，未实际播放。这说明保护有效，同时明确失败纠正会增加该轮等待，不能称作提速或稳定低延迟。
- `normal_gate_profile.json`是两个种子、ABBA顺序的真实原27B对照。相同种子台词相同，正常回答纠正次数0；台词就绪时间约2.09–2.89秒（保护）与2.21–2.97秒（直接流）。样本很少且包含运行波动，仅证明未引入正常的第二次推理，不是固定提速承诺。
- 重启仅加载电脑8792服务。`quality_host.json`为原录音经过实际ASR→27B→TTS的HTTP探针，不发送播放ACK，不冒充现场录音听音。正式界面新录音以`live_playback.json`和`listening.json`为准。

## 本轮现场验收

用户确认“正常接话，清楚自然”。`live_playback.json`记录本轮新capture、完整播放及匹配ACK，`listening.json`绑定同一request（cb6615cb8a9a4a8d9c89bcffcef2e4be）。无等待插播、一次整段TTS、纠正次数0、复制标记false，相机PID987及原boot保持。本轮正常播放与听音已通过，不再标为待完成；它不等于板端实际触发纠正路径的听音验收。

本次软件请求到正式开口约5.726秒，台词准备2.813秒、TTS请求2.406秒（缓存未命中）、ASR0.141秒。回复较此前HTTP探针更长，不把不同台词的3.62/3.93秒与本次5.726秒做提速A/B，也不是外部声学测量。

本轮原始ASR为“你好啊西来今天过得怎么样”，保留原样；“西来”未被现有称呼规则改写，模型回复包含“我是汐蓝哦”。用户本轮确认的是正常接话与听感，不能把它扩展为所有姓名误听已解决或完全不再自我介绍。没有未经确认新增同音别名。

## 延迟解读及下一步

分别查看ASR的`recognition_ms`、台词就绪的`first_clause_ready_ms`、TTS请求的`first_tts_request_ms`、主机首PCM与板端`request_to_answer_seconds`。LLM元数据生成与TTS存在重叠，不能把完整LLM耗时和TTS简单相加。不同台词、TTS缓存命中和诊断并发也不能混成提速A/B。

本轮优先避免错误问句被说出口，不声称降低了27B计算量或达到1秒开口。后续优先压缩纠正路径的无效等待，并用固定问题集评估推理后端和语音启动；保留用户选择的27B及接近现有声线。
