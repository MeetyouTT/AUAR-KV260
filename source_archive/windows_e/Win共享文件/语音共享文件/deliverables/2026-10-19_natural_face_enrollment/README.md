# 自然转头、从视频自动选取人脸

用户反馈固定左右角度采样困难，要求在一段视频里自动筛选人脸。此版取消正脸4、左3、右3的姿势配额，改为至少15秒的连续选样窗口。实际部署状态见 `deployment.json` 和 `verification_summary.json`；没有这两个成功记录前，不代表已经载入正式界面。

首版自然选样现场日志已到“确认更新登记”，随后因当前帧提交条件不满足而丢弃流程；另一次采到3份后因连续失脸被取消。用户确认第一轮最后仍出错，并已结束对话。这两处现已修复为保留窗口、严格核对恢复人脸和重新确认，原始现场反馈见 `field_feedback_iteration1.json`，首版部署证据在 `iteration1/`。最终修复后的真人结果仍单独验收。

## 用户操作

开始对话 → 说“帮我登记身份” → 说“我叫……” → 听到自动选样提示后，在镜头前慢慢自然转头，不用按左右步骤摆姿势 → 听到验证提示后自然看向镜头稍停 → 按提示说“确认登记”；更新已有称呼需说“确认更新登记”。也可通过视觉追踪里的登记人脸窗口使用同一选样流程。

## 选样和保存

- 沿用板卡共享摄像头、CPU YuNet找人脸、SFace提取112×112对齐人脸特征。没有新开摄像头，也没有调用27B挑图。Windows继续负责原语音模型和语音提示。
- 选样至少持续15秒，至少收集10份合格且时间不重复的画面。每两份至少相隔500ms；模糊、过小、过侧、歪斜等不合格画面跳过，已经收集的进度保留。
- 最多在RAM保留24份对齐人脸裁剪及其特征。窗口内候选超过24份时丢弃质量较低的一份；从实际采集的候选中选择整体相似度最高的一份代表模板，清晰度作为相同时的选择条件。不合成、平均或增强身份模板。
- 选择窗口结束后，用后续独立的5份合格新画面逐份验证：与候选余弦相似度至少0.85，与其他身份的差距至少0.1。一个分数不合格就将验证计数归零、重新累计5份，保留之前的候选；不从失败画面之间拼凑5次通过，也不降低门槛。采样和验证总计最多90秒，通过后60秒内明确确认。
- 没检测到脸时立即隐藏当前身份结果和预览，暂停取样、保留窗口。原人脸IoU轨迹在其原1秒有效期内恢复可继续；恢复为新轨迹时，必须有新的合格SFace画面与登记开始时固定的原始特征匹配至少0.85，且比其他身份至少高0.1，才更新会话绑定。锚点不会随新帧滚动，不能利用逐次相似进行漂移。检测不到脸或核对未通过期间不计数、不能提交。多人脸、服务/摄像头生命周期变化、库修订变化、超时会停止本次登记。
- 最后确认时，若当前帧暂不满足严格提交条件，会保留已经验证的窗口并再次请求确认；明确拒绝的提交也可在同一有效窗口重试。每次保存仍须新的明确确认、当前合格人脸、相同有效会话和全部匹配条件，不自动保存或降低0.85。
- 修复脸框越过图像边界时，原始框与跟踪器裁剪框不一致而丢失选中人脸的问题；限制仅人脸IoU跟踪中的速度预测位移，减少转头后停下时过度预测导致的轨迹变化。人体DPU和ByteTrack源码/配置保持。
- 明确确认前身份库不会写入。保留同名原ID更新和明确更新确认，身份照片只在RAM；不保存视频、全身照或默认导出人脸照片。采样失败原因在身份健康状态RAM中保留，方便下一次只读诊断；不包含称呼、照片或模板。

## 验证边界

`tests_pc.log` 为电脑端回归；`tests_board.log` 为板端Linux回归；`preflight.json` 和 `real_models.log` 为公开人脸图片的真实模型顺序驱动验证，使用逻辑采集时钟。新预检不注入姿态/质量标签，不打开现场摄像头或用户身份库，但它仍是单张公开素材测试，不能证明真人不同转头角度都能识别。`sampling_progress_synthetic.png` 是隐藏GTK窗口与合成像素的排版检查。

`voice_host_probe.json` 使用历史录音、真实ASR和OmniVoice16验证三段自然采样提示和原27B普通聊天；没有板端播放或真人听音。身份库部署前后哈希/修订与实际载入的源码指纹见部署及源码核对文件。真人自然转头、语音听感和离场重返识别仍需现场验证，不能把软件预检当作已通过。

当前仍是单模板SFace识别。自然选样解决固定姿势流程困难，不能保证所有角度的实时分数都高于0.85；没有实现活体检测或说话者与人脸绑定。

## 回退

结束对话后，用本目录 `rollback.py` 恢复部署前UI/相机服务单元；不删除或恢复身份库。新的PC语音协议仍兼容旧固定姿势阶段提示。源码修改前的副本在 `before/`，新候选基于实际当前板端运行目录，旧候选、模型和档案保留。LLM权重及Ollama数据仍在D盘。
