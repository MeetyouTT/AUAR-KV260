## 执行顺序

1. `aura/tools/prepare_speaker_model.py --directory D:/AIModels/speaker-identity/ecapa`：固定官方提交，核对上游blob/LFS哈希，生成模型ID。
2. 独立Python3.12环境下运行 `aura/tools/prepare_speaker_environment.py --root D:/AIModels/speaker-identity`。固定CPU torch/torchaudio 2.5.1、SpeechBrain1.0.3、Hub0.36.0、WebRTC VAD2.0.14；安装包核对PyTorch官方SHA256。完整实际依赖以requirements.lock.txt为准。
3. `aura/tools/verify_speaker_model.py`：公开SpeechBrain v1.0.3两人四录音，断网加载和特征推理、同人/异人分数、CPU时延；临时库验证决策。录音短于正式门槛，所以这一步不冒充真实登记或真人验收。
4. 实际麦克风数据准备后，`score_speaker_dataset.py` 从WAV生成分数，`calibrate_speaker_scores.py` 只用calibration选候选阈值，再报告held_out结果，不改生产配置。

## 数据采集协议

- 每人明确同意后，用随机人员ID标注；一份录音仅一个人说话，单段建议6–10秒不同自然内容，16kHz单声道PCM16。
- 至少三条不同的登记录音；第二个独立会话用于标定；第三个独立会话用于验收。换一天的录音优先用于验收。不得把同一音频裁成多份冒充跨会话样本。
- 起步建议3名登记者、至少3名未登记者；每个标定/验收会话各人录5条，覆盖通常距离及稍远距离、安静及正常背景声。样本规模只是起步，不代表足以证明低误认率。
- “我是谁”过短时应返回声音不足，不能自动拿上轮身份作答。先测6–10秒，之后再测短句通过率。
- 未登记人的identity_id必须与库中任何ID不同。声纹身份不能根据姓名字符串自动绑定人脸或匿名历史。
- 先验证一次性明确采集；不自动开麦、不默认从历史私人录音生成声纹。保存样本的范围与清理方式在实际采集前告知用户。

输入JSON示例（实际应列出所有登记、标定和验收条目；下列仅展示格式）：

```json
{
  "thresholds": [0.4, 0.5, 0.6, 0.7, 0.8],
  "margins": [0.05, 0.1, 0.15],
  "recordings": [
    {"wav": "enroll/u1-01.wav", "identity_id": "u1", "session_id": "recording-day1", "role": "enrollment"},
    {"wav": "cal/u1-01.wav", "identity_id": "u1", "session_id": "recording-day2", "role": "calibration"},
    {"wav": "test/unknown1-01.wav", "identity_id": "unknown1", "session_id": "recording-day3", "role": "held_out"}
  ]
}
```

示例阈值是搜索候选，不是批准的运行值。session_id表示全局实际录音会话，禁止用换字符串掩盖同一会话。程序检查完全相同PCM及会话ID交叉，无法自动证明标签真实或识别裁剪重叠。
