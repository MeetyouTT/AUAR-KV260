# 移除 Qwen 视觉模型与 Ubuntu 接续

2026 年 10 月 30 日。用户要求移除 Qwen 视觉模型，并改用板端 YOLO、ByteTrack 和人脸链路梳理视觉采集、记录与处理。Windows 侧已更新并就绪；板端关闭图片上传器的两次发布均自动回退，随后用户要求交由 Ubuntu 接续。当前没有发布事务继续运行。

最新硬边界为板端拥有全部业务处理与存储，Windows 仅接收网线模型请求、运行原 27B 和 OmniVoice 并返回结果。ASR、语音前端、声纹、权限/上下文、记忆与摘要管理、播放和动画合成都归板端，旧“近期保留 Windows 权威库、迁库后置”安排已被替代。五分钟详细记忆、空闲请求模型压缩、校验保存后删原文及长期摘要检索均由板端管理。详见 [板端五分钟记忆与 Windows 模型接口方案](../../../语言模型分析/统一时间轴记忆与稳定性优先_20261030.md)。这只是目标与交接修订，现役仍有 Windows 业务模块；迁移、原文清理和新记忆机制均未完成，以下运行证据仍是上次交接快照。

- 当前源码 160 项回归通过。真实上游公开 WAV 通过 ASR、原 27B 和 OmniVoice TTS，首 PCM 单次约 3.969 秒；仅内存收包，无开麦、实体播放或成功播放确认。
- 原对话、视觉历史、声纹来源表经独立 WMI 私有视图比较通过；备份留 AppData。相机进程与配置、机械 FAULT/null 保护及其他服务监听归属保持。
- [板端视觉采集记录与处理说明](../../../语言模型分析/板端视觉信息采集记录与处理_20261030.md)已整理，明确实时状态与下一阶段结构化事件时间轴的区别。

## 板端发布失败

首次候选为 `/home/root/aura-board-vision-20261030/06391079cfddb734/runtime`，第二次为同名 `-r2/runtime`。两次均在启动器路径校验处失败：`stage.log` 指向原 r11 运行根的 `managed-runs`，不属于候选根。第二次排除 `managed-runs` 和 `__pycache__` 后仍失败，因此不能把单纯排除目录当成已经解决，也不应删除路径保护。

SSH 读写、远端候选准备及 ARM 模块检查均成功，不是已确认的网线传输故障。两次均自动移除本次 systemd 覆盖并恢复原入口。最终只读确认 `board_restored_and_safe=true`，相机未重启，原组件、机械与设置保持。

Ubuntu 接续见 [提示词](Ubuntu接续提示词.md)。应检查实际 `/proc` 入口、systemd 实际和下次入口、启动配置中的绝对路径、缓存状态和运行日志路径，不按旧 PID 或候选路径直接操作。
