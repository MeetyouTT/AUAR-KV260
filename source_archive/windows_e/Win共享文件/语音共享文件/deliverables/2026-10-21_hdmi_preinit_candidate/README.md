# HDMI首次AUX通信前等待候选

当前阶段：候选已停止选用，启动配置已回退到原Image；原内核是否重新运行仍待人工重新接电确认。候选的软件重启检查曾通过，但用户随后自行断电再上电后报告黑屏，新boot中USB集线器及下游设备掉线、相机/界面启动失败，冷启动验收未通过。不能使用此前软件重启成功来声称已修复。

## 为什么进入这一轮

[单次DRM重新检测](../2026-10-21_hdmi_redetect_once/README.md)执行成功但EDID仍0，用户反馈仍黑闪。一次通过DP AUX适配器直接读取EDID亦返回Remote I/O error。因此不安装重新检测循环，转到首次通信时序候选。

旧参数power_on_delay_ms=5000已在板端实读生效，仍未解决故障。它在D0请求后等待，而首次DPCD/EDID读取可能已经发生。本候选新增initial_aux_delay_ms，将准备窗口放在DP probe完成PHY初始化之后、drm_dp_aux_register之前；此时AUX I2C适配器和IRQ处理器尚未注册，避免这些消费者提前开始事务。随后沿用原bind/检测/模式启用路径。

这约束的是PS驱动端AUX首次可用时机，并不能阻止分配器独立进行下游动作，也不是物理HPD开关。延时只是待验证假设；即使EDID恢复，也仍需实屏反馈。

## 候选实现

- 新参数 `zynqmp_dpsub.initial_aux_delay_ms`，默认0、权限0444，允许0～10000毫秒；本次拟用5000。
- 在probe的可睡眠上下文执行一次等待，前后输出AURA日志，便于从单调时间核对实际5秒间隔。不会在每次模式切换重复等待；若重新probe设备，会再次等待。
- 试验选择新内核时移除旧power_on_delay_ms=5000参数，使D0后等待恢复默认4毫秒，区分两个阶段的作用。
- 不修改分辨率、Xorg、GUI、相机或模型，不发送分配器寄存器写入、硬件运动或CPU优化命令。

共享src保存准确补丁、候选DP源文件、构建/传输/安装/回退/启动检查工具。完整第三方源码和工作构建位于本机隔离目录，不修改历史源码树或历史构建目录。

## 实板验证顺序

受控软件重启仅用于确认候选可启动、参数5000/默认4以及AURA日志间隔符合设计，检查三服务、GUI和实际相机/DPU推理恢复。串口观察启动过程中不发送回车，避免打断U-Boot。软件重启的正常画面不能替代断电验收。
