AURA 模型运行观测台

启动：双击项目根目录“打开模型运行看板.cmd”。
或运行 start_model_dashboard.ps1。重复启动会显示已有窗口。

界面可查看：
1. 27B 项目实例、OmniVoice、模型请求调度、当前画面服务、其他 Ollama 实例。
2. 每项任务动态进程组的 CPU、工作集内存、WDDM GPU 与专用显存。
3. 整机 CPU / 内存、NVIDIA 整卡 GPU / 显存、最近 60 秒真实趋势。
4. 实际模型驻留、LLM 推理 / TTS 合成阶段、服务待机、排队及完成计数。
   阶段来自健康口提供的 GPU 资源租约，未提供时保留未知。
5. 点击任务显示进程 PID、端口、驻留模型或运行时长和健康检查往返耗时。
6. F11 全屏，Esc 退出全屏；“暂停显示”冻结画面但继续只读观测。

指标口径：
CPU 100% 为全部逻辑处理器总容量；不是单核 100%。
任务组先划分模型工作进程，再划分调度进程，组间不重复计数。
内存为工作集之和，共享页面可能重复计入。
任务 GPU 为该进程组最忙物理引擎占用，任务显存为 WDDM 专用显存。
整卡 GPU 和显存由 nvidia-smi 提供，不能直接与任务统计相加。
— 表示当前接口或计数器未提供；首次 CPU 要等第二次采样。
HTTP 403 时显示遥测受限。只看到监听/进程不会冒充“正在推理”。
Ollama 服务运行但 /api/ps 为空时显示“在线 · 模型未驻留”。
模型请求处理中但没有活动模型租约时显示“处理 / 等待资源”。
健康接口提供的空计数字典表示 0；接口缺失或被拒绝时保留未知。
GPU 资源排队及上次等待来自资源协调器。上次等待不是模型推理耗时。
健康检查耗时只是 GET 元数据的往返耗时，不是推理耗时。

运行方式：
采用本机现有 Codex primary Python 的 Tkinter 和 Windows 原生计数器。
没有安装新依赖，不启停模型，不发生成、预热、加载或卸载请求。
只读取本机进程/端口/GPU 和只读 GET 健康/模型驻留元数据。
不连接板卡，不读取对话、音频、业务数据库、身份模板或模型权重。
界面趋势只在进程内存保留 60 秒，关闭窗口即释放。
不创建自动启动或计划任务。运行快照仅在明确的 --snapshot 验证模式写出。

交付验证见 handoff.json，实际窗口截图见 dashboard_final.png。
