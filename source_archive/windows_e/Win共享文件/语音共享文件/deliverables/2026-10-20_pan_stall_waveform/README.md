# 转轴卡顿后大幅往返：隔离、波形复现与中位记录

用户确认“现在的位置就是中位”，同时报告点左右时界面卡住、随后转轴大幅来回。本轮不再让用户反复点击定位，也不把正常ACK视为实体动作验收；先停止输出，再离线复现。

## 当前实板状态与中位

首次原GUI API停止请求失败：8783接口不可达，单元正在启动。实际入口已从camera-fix-v3切到`/home/root/aura-render24-rgb565-20261020/887c4b6b2b5d/startup`；此更新并非本轮发起。后续读到trial状态COMMITTED。WorkingDirectory仍是旧目录，必须按启动config.runtime和实际GTK argv定位；真实运行根为新候选的`runtime/aura`，不能拿旧WorkingDirectory的文件哈希代表当前进程。新候选的Python/运动组件与前轮相同，原生渲染C++和库SHA改变。是否另一个会话/电脑发布、与用户所说卡顿的准确时序，仍待答复，不能仅凭版本切换归因全部异常。

临时保护进程256477仅持有`/run/aura-vsrv.lock`的同一flock独占锁，不打开/dev/mem或任何PWM设备；已用第二个非阻塞flock验证新owner被拒绝。状态文件为`/home/root/aura-pan-incident-20261020/lock-status.json`。因此即使点击重新连接，也不能取得Native写权限。不要删除锁文件来“解锁”，删除会破坏唯一锁的inode；后续恢复必须核对boot、PID/命令和保护原因，再结束该保护进程，并显式重新核验，不能自动重放旧动作。

## 已复现的关键机制

运行固件的源RTL SHA为`cc62cf5f71c2b76668417c0de49e95563d41a56f0d0fd702ac74fb465b7684f3`，与源平台14da0e60记录及共享RTL一致。普通点动结束调用STOP，RTL在STOP或租约到期时立即将servo_pwm拉低；如果当时正处于高电平，这个末脉冲会被截短。目标/实际width寄存器仍可为1420，ACK也可正常，但输出引脚上的最后一个脉冲不一定是1420µs。

Vivado 2022.2离线仿真，100MHz、默认50Hz周期、BUILD_ID参数匹配14da0e60，包含所有下降沿而不跳过STOP/expiry：

| 场景 | 请求/完整脉宽 | 实际仿真末脉宽 |
| --- | --- | --- |
| 高电平500µs附近发STOP | 1420µs | 500.02µs |
| 首次许可仅1ms后到期 | 1420µs | 1000µs |
| 低电平阶段STOP | 1420µs | 完整1420µs |
| 使用真实100ms租约，在第21ms附近续期，随后到期 | 逐帧到1440µs | 末脉冲1000µs |

这是确实复现的数字波形机制，**不是已经测得实板J2第3脚的500/1000µs**。对于位置舵机，异常短脉冲可能被理解成远离目标的位置，下一次正常脉冲又把它拉回，因而能解释“突然大幅往返”；是否就是本次机械行为，仍需断开舵机后测实际信号，并核对供电/断信号行为。

旧HDL测试仅在`!pwm && old_pwm && dut.active`时检查脉宽，停止/到期时active已经为0，正好跳过这些下降沿。此前软件测试/ACK通过不覆盖这一类末脉冲，这是本轮查出的验证缺口。手动控制仍以100ms租约运行，本轮没有放宽它；短脉冲不等于请求目标超出了1400～1600。

界面点击的处理时间也不能直接等同实际触摸时间：当前activated/request在事件被处理时才生成issued时间，没有核对原始GDK事件时间。因此GUI阻塞期间的旧点击存在被当作新意图的风险；本次重启前完整历史未回收，没有证据证明现场实际发生了这种重放，不能把它写成已确认根因。恢复运动前也应补充旧事件丢弃门槛。

## 离线修复候选，尚未部署

`candidate-v2/visual_servo.sv`是隔离候选，不覆盖生产RTL：ABI升为2、BUILD_ID故意保留0，不能用旧驱动直接加载。其改动为：

1. 新增QUIESCE（0x51554945）：正常完成先结束当前完整脉冲，再撤销许可，低电平时不多发一个周期。
2. 开始新脉冲前检查租约是否至少覆盖最大完整脉冲；过短租约拒绝。100ms租约长度保持，CPU冻结后到期前停止开始新脉冲，避免到期截短。
3. 原STOP仍立即关断；紧急切断可能截短脉冲这一物理事实没有被隐藏。独立供电舵机的急停/断信号反应、外部使能或断能方案仍须实测，不能宣称候选已消除所有机械异常。

候选五个新增场景全部通过：高电平正常完成保留1420µs全脉冲、过短租约不发脉冲、同一100ms续期场景保留完整末1440µs、低电平正常完成不多发一帧、原紧急STOP保持立即关闭。原有AXI/权限/背压/范围/斜坡/复位测试台和100MHz正常PWM测试台也通过。结果见`candidate-v2/simulation-result.json`，没有将仿真称作板级通过。

候选不是bitstream、不是已适配Native的发布包，不得部署。继续集成须更新Native ABI/命令白名单、正常完成路径使用QUIESCE并核对最终输出关闭；补过期触摸丢弃；完成实现/时序及准确固件/模型兼容检查，先断开舵机测波形，再恢复实体测试。旧Native守卫仍只接受VSRV/1/14da0e60，本轮没有修改它。
