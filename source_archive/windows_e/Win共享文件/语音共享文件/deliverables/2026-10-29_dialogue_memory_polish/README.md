# Windows 对话与记忆 r4：实现及效果验证

本轮已部署并完成自动验收，版本为 voice-dialogue-memory-20261029-r4。按用户要求，继续完善 Windows 对话与记忆，权威数据库和模型运行位置保持，板端迁移暂缓。这是本轮功能交付，不代表整个玩偶或完整长期记忆路线已经验收。

本次补齐自然语言事实查询、逐条更正历史浏览、旧写入程序与导入记录的来源保护，并完成同输入前后测量。总核验见[最终核验](release_verification.json)，当前状态见[PROGRESS](PROGRESS.json)，接续见[CONTINUE](CONTINUE.md)。

## 用户能直接使用的变化

| 场景 | 用法及行为 |
| --- | --- |
| 当前明确事实 | “记住，颜色是蓝色”“把颜色改成绿色”后，问“我喜欢什么颜色”，直接读取当前有效事实，不经过27B生成，也不猜未记住的值 |
| 区分记忆范围 | “本次对话里，我喜欢什么颜色”“个人记忆里，我喜欢什么颜色”；未指定时当前对话的同项事实优先，然后才是当前明确授权的个人档案 |
| 旧值查询 | “我以前喜欢什么颜色”读取仍有效的更正历史；只有当前值时明确说明没有旧值，不推断过去 |
| 浏览完整条目 | “查看颜色第1条记忆历史”“查看颜色第一条记忆历史”；从新到旧编号，支持1—32及对应中文数字，单条读完整存储值 |
| 历史提示 | “查看记忆历史”会提示指定哪项记忆；“查看颜色记忆历史”仍只列最近两条摘录，详细值用编号查询 |
| 继续遗忘和删除 | 忘记某项时一并移除其更正历史；按日期/字面主题删除对话仍先预览、60秒内确认，并使相关派生回复及摘要停止召回 |

自然事实直答目前限定颜色偏好、称呼、项目名的明确问法，不把任意开放问题改成固定回答。引述、假设及复合请求不强行作为事实指令。既有人脸身份查询优先级保持；“我叫什么”等可能进入现有人脸查询，应使用明确记忆范围来区分。个人查询仍需有效档案授权，访客不能读取别人的记忆；视觉观察不能自动变成个人事实。

历史日期是录入/更正日期，尚未表达事实实际生效日期；每项最多32个版本，索引值按既有最多64字符存储上限完整读出，不恢复已遗忘值。任意长篇历史分页和实际生效时间模型仍待后续。

## 优化效果

使用同一段公开合成16kHz单声道录音“我喜欢什么颜色”，前后持续使用同一个独立测试会话、同一条“颜色偏好=绿色”来源；每次移除本次查询行，保留事实，双方都没有已确认播放的对话历史。改前4次的模型输入SHA完全一致；改后走当前事实直答。测量是客户端提交后收到首段PCM的时间，未包含真人说话、物理播放及声学采样。

| 指标 | r3 改前 | r4 改后 | 测量边界 |
| --- | ---: | ---: | --- |
| 首次查询首PCM | 4.641秒 | 1.453秒 | 各1次、双方TTS未命中缓存；不是进程冷启动，回复措辞不同 |
| 重复3次首文字中位数 | 0.875秒 | 0.110秒 | 当前事实查询路径 |
| 重复3次首PCM中位数 | 2.656秒 | 0.110秒 | 改后3次均命中同一回复的TTS缓存，改前均未命中 |
| 普通聊天对照首PCM | 4.640 / 3.109秒 | 5.593 / 6.625秒 | 同一公开录音、相同模型输入SHA，各2次，均未命中TTS缓存 |

重复事实查询首PCM降低约95.86%，首文字约87.43%。这是确定事实直答与重复语音缓存共同带来的整条路径收益，不能称为27B或TTS模型本身提速，也不能推广为任意聊天都在0.11秒开口。

普通聊天这组改后反而较慢，未证明普通聊天提速。相同输入仍有不同回复，实际模型解码用时也变长；本轮没有确认具体原因，保留其他模型运行，不据此直接归因显存竞争。另一次取消恢复检查首PCM为5.594 / 2.937秒，也说明仍有波动，不用较快单例替代前后对照。

详见[比较汇总](comparison.json)、[改前原始测量](benchmark_before.json)与[改后原始测量](benchmark_after.json)。

## 自动验收与实际链路

- 267项 Windows 相关回归全部通过、无跳过，包含先前210项相关范围，不能累加为477项。覆盖事实未知/更正/范围权限、历史索引及中文数字、旧程序/导入来源、跨个人边界、删除确认、摘要失效、取消与TTS失败后的记忆提交等。见[测试结果](tests_final.log)及[JUnit](tests.xml)。
- 12步实际公开录音记忆链路通过：记住→更正→历史→自然旧值→删除预览→确认→删除后历史→中文编号完整条目→当前自然问题→遗忘→未知事实→普通持久对话。实际数据库中检查了普通回复的完整来源标记，包括来源为空的情形。见[记忆验收](live_controls_acceptance.json)。
- 7项实际语音功能检查通过：服务健康、ASR/27B/OmniVoice16输出、首文字后取消、锁释放、下一轮恢复、330帧按真实节奏发送的前端、最终健康。前端RPC P95为16ms、最大31ms、1/330帧超过20ms，严格逐帧20ms门槛未通过。见[语音验收](live_voice_acceptance.json)。
- 使用板卡当前已有 ARM VoiceChannel 经网线完成事实设置和查询两轮，首PCM为215.64 / 184.57ms，收到正确回复、完整PCM及哈希。未更新板端代码，也没有本轮ARM回归测试；服务处于热态、相同回复此前已合成且未清空TTS缓存，不与Windows改前测量混为对照。见[板端网络验收](board_probe.json)。

以上实链路只在内存接收公开PCM，没有开麦、实体发声或发送成功播放ACK，不能替代真人听音、插话、身份现场准确率和跨天体验。

板端网络测试首次收尾清理因缺少 started_unix 元数据失败，事务回滚。仅为派生摘要空缓存的时间戳补充兜底，保留原有精确会话/请求归属检查，再由独立进程重试清理通过；没有重跑网络测量。原始失败、修复前回执及恢复记录均保留，见[原始清理失败](board_probe_cleanup_first_failure.json)、[恢复前报告](board_probe_before_cleanup_fix.json)和[最终清理](board_probe_cleanup.json)。

## 数据、来源及设备保护

新增 memory_source_coverage 表。新普通持久回复在上下文组装时记录来源完整性，包括明确“无历史来源”的轮次。删除时，缺少完整标记且无来源边的旧回复/导入/回退程序新写入回复，不再仅按初次升级的序号截止判断；在受影响的授权范围内保守停止后续召回，并将数量纳入预览。已确认来源的回复按来源链传递失效；直接记忆指令按原专用标记排除。这一保护解决了 r3 对旧写入路径需要人工重建截止基线的缺口，但不声称能够还原旧回复的真实来源。

对话删除默认当前会话，最多1000轮原文、2000轮关联，个人跨会话须授权；新预览撤销旧预览，过期或来源变更必须重新发起。视觉记录及私有备份不会被对话删除一并清除，不把SQLite行删除称为介质擦除。

独立 WMI 进程使用生产文件视图完成前后私有备份与逐表内容哈希比较，原有141会话、269轮、1项明确事实、6条实时视觉观察、2条视觉时间轴事件及声纹库原始数据全部保持。摘要派生索引有测试会话的空版本屏障变化，数据库整文件SHA因新增表等而不同；没有把整库文件哈希不变作为结论。公开测试会话、事实及历史均已按精确请求归属清理，见[物理数据库核验](physical_database_check.json)与[记忆测试清理](public_probe_cleanup.json)。

正式 voice 服务仅8792及其TTS子进程按空闲门槛重载，hub仍 device-timeline-v2，其他服务及5个原有模型所有者保持。并行修复 compact_grammar=false、其他5项延迟开关true、原27B/IQ4_XS/OmniVoice16/音色和上下文预算保持。LLM与Ollama数据继续 D:\AIModels，未复制模型到共享目录。

最终只读核验板端实际入口 /home/root/aura-boundary-nav-20261029/gui-page-sync-v2/runtime、279项绑定，boot 55152f95-ea3a-4c6c-82e6-51bd553d96fd；UI PID114923、相机PID21824未重启。机械READY/1604µs、无活动运动、跟随/监听/麦克风关闭，IDLE_READY。当前人脸主链仍是板卡DPU，Windows SFace服务仅保留就绪能力。这些值只是本次快照，下次须动态核对，不能覆盖并行机械更新。
