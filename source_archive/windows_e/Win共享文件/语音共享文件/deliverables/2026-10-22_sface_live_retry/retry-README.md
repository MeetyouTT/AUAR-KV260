# SFace时隙退让重试候选

2026-10-22，软件候选、默认不启用，尚未上板运行。冻结13源合并版的真人短测已经完成，见本轮实测交付；该实测不是本重试候选的收益证明。

实际60.69秒窗口完成4次SFace、57次请求中53次未获准入，其中45次因剩余截止时间不足、8次因其他任务占用。独立准备线程供给109次，说明新供给路径已经工作。原shadow在每次未获准入后也等待完整1000ms；固定周期反复错过可用时隙是需要验证的假设，不把它当作USB故障或30ms长尾的根因。

本候选保留同一DPU owner、原调度器和30ms/5ms保护。新增结构化`DeferredIdentity.retryable`，仅在没有发起实际计算、源仍新鲜且任务未停用时为true。已实际计算后结果过期、native异常、任务停用或目标失效都不重试，不通过字符串猜测异常类型。

原`dpu_sface_shadow`内可显式增加`slot_retry={"backoff_ms":25,"max_retries":3}`。仅允许compute-only shadow；退让25～100ms、最多1～4次、总退让不超过200ms。每轮成功后仍等待原interval，未配置时维持原行为。重试保留一个最新pending，新裁剪优先，下一次执行前再次检查目标和TTL；关闭会打断等待并释放引用。不会创建第二runner、相机或身份库。

67项身份/供给/重试回归和45项计时/运行器回归全部通过。新增11项检查包括次数限制、无配置行为、截止/目标失效、新裁剪优先、关闭、配置上限，以及实际计算后的过期结果不重试。输入是合成像素/向量，native调度使用模拟对象；没有硬件收益或真人精度结论。

Ubuntu可在已有Vitis AI容器与回收依赖环境运行`python3 -B run_tests.py`。下一步是在同样主检测/保护条件下，做有自动恢复的真人短测，比较实际完成数和准入原因，再决定是否延长；不直接替换当前保留版本。
