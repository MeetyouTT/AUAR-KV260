## USB端口能力与实际尝试

只读lsusb和标准USB hub描述符均确认两逻辑集线器1-1/2-1为Microchip0424:2744/5744、四口、wHubCharacteristics=0x0009，声明支持独立端口供电。已核对：屏幕触摸WS170120/0eef:0005在1-1.1，MCP01/17ef:a03b在1-1.2，摄像头0c45:6341在1-1.3；USB3同伴端口2-1.1没有外设。

已实现并先实板只读验证libusb请求，未detach hub驱动、未扫描I2C、未写分配器或GPIO寄存器。控制使用标准USB class CLEAR_FEATURE/SET_FEATURE(PORT_POWER)，只写两个逻辑hub的端口1；目标/其他外设身份、板卡CID和boot均有守卫。主机注入检查确认一个hub恢复请求失败时仍会尝试恢复另一个。

一次恢复尝试先建立15秒独立systemd恢复定时器，再关闭屏幕口，计划保持5秒后恢复。实际记录如下：

| 项目 | 实际结果 |
| --- | --- |
| 关闭请求 | 两个逻辑hub端口1各一次，返回0 |
| 最初状态 | USB3为0x04a0、USB2为0，电源状态位均已清；0～1.316秒样本保持 |
| 保持5秒 | 未完成。后续检查发现端口电源状态已重新开启，守卫抛出Port power did not turn off |
| 恢复 | finally分别SET_FEATURE一次，均返回0；从首次OFF到主动ON约2.032秒，两个逻辑端口电源位确认恢复 |
| 独立定时器 | 恢复后检查为inactive/dead，无悬挂断电任务 |
| 外设影响 | 屏幕触摸重新枚举；MCP01地址4、相机地址5及三业务服务PID保持 |
| 显示结果 | EDID仍0；用户仍反馈闪烁，实体修复失败 |

以上证明系统内短时电源状态变化和恢复，不是完成了5秒的物理屏幕断电。没有测USB端VBUS或屏幕电压，也未确定自动重新开启的具体原因；不能据此排除供电或宣称软件重置已模拟真实拔插。之后未重复发送相同关闭请求，也未安装任何开机端口电源重置服务。

## 下一项现场对照

已请求保持HDMI、板卡电源和当前界面不动，仅将屏幕USB供电接到原配或符合铭牌的独立USB电源，观察条纹是否消失。若单条USB兼供电/触摸，移走后暂时没有触摸数据，当前界面可保持运行，不在这个对照中重启板卡或服务。

现场结果仍待用户回答；若暂时没有独立电源，先如实记录这个限制。移动供电线本身会重置屏幕，即使恢复，也只作为本次对照结果，后续仍须在确定接法下区分供电保持与重新上电的影响，不能一次恢复就宣布冷启动根治。
