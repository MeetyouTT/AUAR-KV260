# 一句话启动、开头确认、自动完成的人脸登记

用户反馈自然转头登记仍难操作，并选择使用一句话“帮我登记身份，我叫……”。此版将称呼核对与明确保存确认放在采样前，后续自动取样、验证、提交和播报结果，末尾不再要求另一条确认指令。实际是否加载以 `deployment.json` 和 `verification_summary.json` 为准。

## 用户操作

1. 点开始对话，说“帮我登记身份，我叫小林”（换成自己的称呼）。
2. 玩偶复述称呼后，新身份说“确认登记”；同名称呼更新说“确认更新登记”。
3. 正常看着玩偶，可以慢慢自然转头。系统自动挑选清晰人脸、验证并保存，最后播报结果。不用按阶段左右摆头、等验证口令或在末尾再次确认。

同意保存与称呼只需核对一次。ASR听错名字时，可在开头确认前说“不是，我叫……”。旧的分开说“帮我登记身份”再说名字也会走同样的开头确认流程。取消/结束对话会清除未完成会话。当前语音仍为半双工；采样中的直接停止用现有结束对话按钮。

## 实现与边界

- `common/voice_enrollment.py` 只接受明确登记句型加姓名，非引用、假设或附加操作文本。姓名仍受长度/字符/指令片段限制。
- 正式 `ChannelConversationJobs` 选择简化流程；兼容旧流程的类默认行为保留。开头复述姓名，未明确确认不启动取样、不写身份库。同名身份必须明确确认更新。
- 开头确认绑定本次称呼、原身份ID（更新时）、身份库修订、摄像头/服务生命周期与采样token，不能用于后来替换的新采样会话。
- 保留上一版至少15秒视频选样、RAM最多24份人脸、5份后续独立画面逐份0.85及身份间隔0.1的规则，固定起始人脸锚点检查与同一人恢复采样保持。正式视觉模型、人体DPU/ByteTrack、27B/ASR/OmniVoice16、参数与原音频播放保持。
- 本次明确同意后，监视器在取样/验证期间自动等待，不播左右/回正/验证指令。验证通过且当前严格提交条件满足，才提交带采样token的保存请求；暂时不合格继续等待同一窗口，不再要求用户重复说话。
- 只有服务明确拒绝且确认未提交的请求可等待下一帧重试；响应丢失、提交结果不明确时停止，不盲目重试或播报成功。只有操作回执与库COMMITTED修订匹配才播成功。
- 取消、超时、换人/多人、服务重启、库修订或采样token变化使原授权失效。模型门槛没有降低，简化操作不代表真人任意角度识别已通过。
- 不保存视频、默认照片或导出模板。用户身份库留在板端私有目录；LLM权重、分段和Ollama数据继续在D盘。

## 证据

`tests_pc.log` 与 `tests_board.log` 记录回归；`preflight.json`、`real_models.log` 使用公开单张图片、真实板端YuNet/SFace和临时SQLite，逻辑时钟顺序驱动完整开头确认→自动保存→重新识别→失脸清除。不注入姿态/质量，不接触用户身份库；不能代替真人转头测试。

`voice_host_probe.json` 使用历史录音和真实ASR/TTS测试开头提示、自动结果流和原27B聊天，不实际板端播放，不进行真实用户登记。`source_verification.json` 核对实际运行源码和保留配置；`deployment.json` 记录部署前后身份库哈希、数量与修订。最终真人使用/听音/离场重返仍需独立验证。

首轮公开图片预检的业务断言通过，但成功后异步取消触发了临时SQLite默认线程限制，诊断保留在 `first_preflight_cleanup_diagnostic.log`。最终版本去掉保存成功后不必要的取消请求，临时库也使用与生产相同的跨线程设置；最终 `real_models.log` 应无该异常。没有放宽身份匹配或确认条件。
