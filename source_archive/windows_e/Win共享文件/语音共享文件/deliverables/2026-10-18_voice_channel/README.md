# 电脑到KV260的流式传输第一版

日期：2026-10-18。状态：实验通道已实现，真实模型/板端接收证据见本目录JSON。当前正式GTK界面继续使用原完整WAV接口；未把新通道接入实际播放，不作为低于1秒或新声线听音验收。

## 用户约束

- 保留现有Huihui Qwen3.8-27B IQ4_XS模型、量化和电脑推理；本版保持提示词、上下文上限、采样设置一致。
- KV260不增加ASR、LLM或TTS模型，不增加语音推理FPGA加速，不替换现有视觉DPU或FPGA配置。
- 优化的是文字、控制与PCM的数据通道和生成/合成流水线。
- LLM权重与下载仍在项目外D盘，本目录只保存源码、测试和小型音频证据。

## 已实现

1. `/v1/voice/channel`：同一条HTTP/1.1连接传送带长度边界的二进制帧，避免每段音频另发GET和整份WAV下载后才交付。
2. 24kHz单声道PCM16按最多20ms一包输出，直接传输二进制，不转Base64。
3. 逐包检查代次、请求、序号、样本位置和SHA256，末包检查整个PCM摘要。文字、控制和PCM均可增量交付。
4. TCP_NODELAY、及时flush、连接复用；超时或取消关闭当前socket，过期代次不交付给消费回调。
5. 27B使用原提示词与参数流式输出，增量解析JSON中的可朗读文字，正确处理跨包Unicode与转义。
6. 按自然分句调用原OmniVoice16，LLM读取与分句合成可重叠。原参考声线及16步参数保持。
7. 原 `/v1/voice/converse` 和完整WAV接口保留兼容；相关27项测试通过。

## 尚未完成与边界

- 当前OmniVoice仍一次生成完整分句，本版不是原生音频token流式合成。第一段不能切成没有实际内容的语气词以冒充达标。
- 当前JSON的emotion可能在文字后到达；本版有控制事件运输，但没有实现预先控制声音语气，也未启用机械动作。
- 新通道目前用于独立接收验证，正式界面未消费它。现有1秒首字保护静音保持，尚未改为常驻播放设备。
- 新通道不会把“收到数据”等同“已经播放”：尚未接入播放确认，因此实验通道不提交新对话历史。旧完整WAV接口继续按原逻辑保留最近四轮。正式启用前必须完成播放确认、被打断文本归属及多轮记忆接入。
- 网络取消可停止交付并取消LLM流；已经开始的整段OmniVoice计算仍可能结束，不能宣称已实现即时TTS抢占。
- 本次因新代码需要重启电脑端8792服务；已先确认空闲，仅操作对应进程。冷启动/预热超过最初90秒等待窗口，随后已恢复READY；不计作暖机回复性能。
- 当前16GB主机显存接近满载，不将其性能当作未来5090笔记本结果。通道优化不能替代模型预填充/解码与TTS优化。

## 验证

- `tests.log`：27项相关测试，包括新通道、旧接口和原板端播放逻辑；fixture不算实际模型证据。
- `actual_host_probe.json`：历史板卡录音，经真实Paraformer、原27B、原OmniVoice到电脑接收器。两轮首PCM约6.688/4.016秒，整轮数据接收约8.157/7.016秒；TTS缓存未命中，两轮复用同一TCP连接。输出内容不同，不能与旧7.187秒单次测试计算严格加速比。
- `actual_board_channel.json`：同一真实电脑服务到KV260的独立接收探针。仅复制4个小型传输模块和历史音频到独立目录，没有语音模型、播放或板端服务改动。
- 板端两轮首PCM约5.095/4.815秒，整轮接收约8.176/9.299秒；均未命中TTS缓存，复用同一TCP连接并通过PCM摘要校验。回复不同，不作为公平固定任务速度比较。
- `legacy_endpoint_after.json`：更新后原完整WAV接口真实模型验证通过，单次约7.000秒，模型仍为原27B；不是板端新录音听音。
- `restart_before.json`：电脑服务更新前的空闲检查。
- `verification.json`：最终服务健康和源码指纹。

上述时间均从历史录音提交开始，到数据到达；不含用户说话、实际播放及扬声器声学输出。首文字与首PCM分开记录。

## 手动复现

使用现有语音Python环境，在项目根运行：

```powershell
& '<现有语音Python>' -B aura/tools/probe_voice_channel.py --wav aura/report/recording_20261016/microphone-5s.wav --rounds 2 --report deliverables/2026-10-18_voice_channel/probe.json --output deliverables/2026-10-18_voice_channel/received.wav
```

板端独立验证入口：`probe_board_channel.py`；它使用现有明确配置的SSH传输，私钥不进入共享目录。
