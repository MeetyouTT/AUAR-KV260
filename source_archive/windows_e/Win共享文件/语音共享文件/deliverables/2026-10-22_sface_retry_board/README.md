# SFace时隙重试：实际验收记录

2026-10-22，主任务串行，用户在镜头前配合。**B重试版60秒阶段目标通过，随后10分钟长测尝试在约45秒触发YuNet保护，未通过。** 当前已恢复原保留版本。

准备阶段核对原boot、服务、源/模型/单元与身份配置。三处重试源以SHA固定传送，13源A/B候选在独立目录准备；KV260上11项纯合成重试检查通过，禁止导入xir/vart和打开数据库，实际DPU调用0。部署回退8项本地检查通过。首版准备脚本把Xserver服务文件固定为/etc路径，部署前因不存在而拒绝，修正为systemd FragmentPath；原服务未动。

原版A完成60秒，主检测约9.81Hz、YuNet2.32Hz、SFace10次，但13个每5秒人脸采样只有10个为1，有效人脸覆盖不足，严格A/B对照停止并自动恢复原相机。完整失败记录保留，不计算加速比。

随后B两次在部署前因瞬时/有界30秒无脸而拒启，原相机保持。用户确认仍在镜头前后，只读获取现有预览，确认实际有人且当次人脸状态1；图像仅在私有目录，不进入共享交付。未将检测为0解释为用户离开。B启动前单点门槛改为有界等待，目标/TTL检查与实际采样覆盖统计保持，原30ms上限/5ms guard与回退finalizer不变。

第三次启动B完成60.7304秒采样：YOLO9.8139Hz、YuNet2.2229Hz、实采12.3497Hz、SFace59次成功完成/59次时效复核（0.9715Hz），80请求中21次时隙拒绝触发退让，21次重试/0耗尽；供给116个裁剪，13个人脸快照全部为1，阶段目标达到。整板CPU66.71%，没有同输入CPU收益或严格加速比结论。SFace裁剪到特征均值15.48ms、最大31.13ms，其中包含CPU准备；实际可选占用最大17.64ms，未触发30ms保护。正常计时累计136次YuNet/59次SFace完成，fault0、新USB0。

用户随后允许10分钟观察，使用同一B源/配置，只有采样窗口和监督期限延长。**长测失败**：最后健康采样45.2735秒，YuNet一次占用33.00082ms触发原30ms硬上限并禁用；准确故障时刻相对首个diagnostic快照45.2089秒，采样及快照调用端点不同。执行成功返回状态0，但出现墙钟长尾。SFace故障快照累计49次成功原生完成（含启动期），不能当600秒完成数；10个已记录健康人脸样本为1，窗口未跑满，阶段目标未验收。不自动进入30分钟或常驻。

故障trace记录：execute墙钟32.650327ms/调用线程CPU0.98375ms，wait墙钟0.078511ms；optional墙钟33.019ms/线程CPU1.337984ms。收尾waiting_primary=0、未越过YOLO guard，触发项为30ms占用硬上限。完整覆盖候选开始到后检的内核窗口没有新增匹配USB告警。它表明长尾主要发生在execute调用路径，不能据此区分Linux调度、GIL、native或硬件等待；不将墙钟减线程CPU直接当DPU硬件忙时，也不将本次故障归于新USB异常。
