# CPU / DPU 第一批实施

状态：2026-10-22第一批代码完成；三模型长测失败，已恢复双模型。用户授权开始并允许并行Codex。依据[统筹计划](../2026-10-22_cpu_dpu_roadmap/README.md)，主任务负责T2测量及T3实板验证，独立agent负责T1标定工具；只有主任务操作UART/生产。最新机器状态见[release.json](release.json)，任务结果见[tasks.csv](tasks.csv)。

以下三段为开工快照，实际完成/失败与恢复以“本轮结果”为准。开工时重新只读核验活动YuNet根/6源码/模型/manifest/单元及原库路径，boot保持，影子尚未常驻，UI空闲、镜头前1脸。最新基线YuNet最大可选占用29.63ms/估计偏差2次，真正超限0；这是此前30分钟后新进程的后续状态，不覆盖原22.07ms长测证据。全部生产操作仍受原30ms占用上限和自动回退保护。

T3复用上一轮真人短测通过的冻结6源码，新的标定接线不混入该稳定性试验。新长测脚本的覆盖/计数差/频率门槛/回退语法6项本地检查通过；30分钟及至少100次真实完成为待实板验收，不能预先称通过。CPU按/proc计数、实际相机核秒/内存/线程数记录；5秒健康快照不冒充每次推理分布。T2细分阶段工具另行实现后单独检查。

T1候选在独立目录开发：CALIBRATION_ONLY、同DPU owner、RAM有界会话、显式匿名分组/场次/目标、默认关闭，标定与独立验证隔离；不发布身份、不写库、不落人脸或特征。它目前未集成/实板验收，正式SFace仍配置WindowsCPU。Windows本轮最新接口/实际版本待回执；没有改Windows业务源码或回执。

## 接下来的关卡

先补故障时的有界观测，区分VART执行等待、主机调度和MCP01异常的时间先后，定位持续错误恢复与尾延迟；保持30ms上限。下一次长测前须恢复同条件健康基线，并核查SFace不足0.5Hz的准入/请求限制。其后独立验收测量/标定新接线，再恢复T3和正式登记验证。不要把新增代码直接装入尚未稳定的三模型版本，或通过放宽保护/降低事前门槛将失败改成通过。

本轮没有切位流、USB复位、手工关开HDMI、运动或更换语音模型；原应用启动器按原行为执行同模式配置和唤醒，不称完全没有显示命令。未采新声音/验收播放听感。共享仅包含代码、合成测试及过滤数值，不含原始UART、现场人脸/音频/向量或身份库；Windows同步与接收未确认。
