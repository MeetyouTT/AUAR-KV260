# 语音独立入口与交互候选

本目录为候选实现和测试证据，**尚未部署到 Windows 正式语音服务或板端 UI**。用户最新原则：语音对话独立于视觉；视觉只补充互动、画面问答和有明确授权的身份功能。普通对话和插话不得要求人入镜、正脸或视觉目标持续存在。

## 本次语音调整

- 新增 VoiceFirstRecordingController，沿用单一音频采集、回声核验、请求代次、取消、完整播放 ACK 和尾音保护。语音会话使用独立 audio session key，不以人脸目标作为普通语音权限。
- 免点击入口识别“汐蓝”“欸”“哎”。单说唤醒词只进入聆听，不调用 LLM/TTS、不创建对话正文；“汐蓝，你好”保留问题并走正常流式回答。对话内无需逐句重复唤醒词。
- 未唤醒的普通话语只做有界 VAD/ASR 检查，不产生回答；暂停后不自动重开麦克风；静音 30 秒退出当前会话并回到待唤醒。
- 单字“欸”“哎”仅独立出现或带空格/标点边界时触发，避免“哎呀”等词误唤醒。这一边界需要现场评估实际 ASR 标点行为。
- 无相机时也能开待唤醒监听、连续接话和经过回声核验的插话。声画归属不再作为普通语音的前置条件；唤醒不代表识别身份，也不自动解锁个人记忆。
- UI 候选改为待唤醒/聆听提示；免点击入口默认选择新控制器，插话开关仍按既有配置控制。

## 证据与限制

`voice_first_tests_final.log` / `voice_first_tests.xml`：**159 通过，2 跳过**。包括旧语音、流式、插话、连续对话与延迟回归；新测试覆盖无视觉入口、唤醒后下一句、错代次拒绝、暂停、静音退回、无脸插话，以及真实 localhost HTTP 传输。HTTP 测试使用可控 ASR/LLM/TTS 夹具，不能等同于真人录音识别率或真实模型响应时延。跳过项分别需要板端原生 SpeexDSP 和 Linux flock 采集占用机制，不能记作 ARM 声学或真实采集验收。

首次沙箱测试因临时目录权限失败，保留 `voice_first_tests.log`；在获批沙箱外执行同一隔离测试后通过。最终测试未访问真实麦克风、未播放、未向板卡发送命令。

目前唤醒使用 VAD 后 ASR，尚无专用流式 KWS。**没有“立即唤醒”的实测结论**，还需用真实短促“欸/哎”和名字测首帧聆听延迟、误唤醒及漏检。

`common/visual_social.py` 只完成独立事件策略及测试：新鲜稳定入镜 0.6 秒后提出“嗯？”；4 秒未说话提出一次招呼；30 秒冷却；语音忙碌、说话、失去画面或禁用时取消后续邀请。**尚未接实际选定音色缓存、播放和插话仲裁，不算入镜招呼完成。** 该策略不拥有麦克风/会话/机械控制权限，不能以其结果关闭或阻塞语音。

## 同目录其他候选

- 说话长帧：每次最多处理 8 个流式事件、约 6 毫秒预算；保持 FIFO、不丢 PCM。尚未板端严格帧间隔验收。
- 延迟：只缓存明确的 native runner 不兼容结果 30 秒；不放宽验证，不缓存临时超时/取消。实测重复元数据探测由约 1513 毫秒降至 0.01 毫秒以下，仅此步骤，不代表整轮语音延迟。
- 视觉问答：Qwen3-VL-2B 权重和投影均在 D 盘，官方清单哈希核对通过。独立 CPU 真实红/蓝图片回答正确，约 3.589/3.022 秒。板端帧归属/语音回传候选尚未完成联合验证或部署。
- 声画归属：TalkNet 官方固定版本源码和 D 盘权重已准备，首轮 CPU 探测因 2 秒结果期限失败；不能宣称可用或标定通过。仍需优化、对齐数据集评估、实时收集和现场校准。
