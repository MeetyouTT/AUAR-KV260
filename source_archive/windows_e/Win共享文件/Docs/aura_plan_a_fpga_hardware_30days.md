## 共同执行约定

- 项目统一名称 AURA，历史资料中的“雾镜 Lite”指同一设备。
- 周期 D1—D30，D1 为实际开工日，不代表自然月第一天或比赛截止日。用相对天数避免写死尚未确认的日期。
- D7、D14、D21、D28 为缓冲/评审日，每人约 2 小时；其余 26 天每人约 6 小时，总计每人 164 人时，三人约 492 人时。缓冲日其余时间留给休息、加工等待和必要恢复，不预先塞入新功能。
- 正常开发日建议：2 小时实现、2 小时验证/集成、1.5 小时修复或协作、0.5 小时记录和同步。当天列出的联调已包含在工时内，不能把它额外加到晚上。
- 条件：有可用 KV260、相机、屏幕、舵机及其合适电源；双麦和 USB 音频最迟 D10 可用；有能运行选定模型的主机；复用匹配的参考平台、预训练模型和成熟界面组件。
- 本月目标是可演示、可验证的首版，研究采用 Light-ASD 基线、借鉴 Streaming ASD 的有限窗口处理、借鉴 LoCoNet 的上下文选择，以及借鉴 Neural Simplex 的执行监督。简单上下文规则不能称为完整 LoCoNet，分块处理也不能直接称为严格因果流式模型。
- YOLO 和板端身份识别仍是产品能力；ByteTrack 可作基础跟踪，完整 BoT-SORT、从零训练视听网络、全双工回声消除、第二转轴均不计入本月必做。
- 默认只优先处理当前交互区域内的少量人物，人数上限 D2 冻结；不承诺无限人数和任意环境。
- A 负责硬件集成和项目协调；B 负责视觉、板端身份及唯一运动请求软件；C 负责说话人/目标选择、语音和 UI，并维护日常启动清单。每人修复所属模块，协调人不代做全部工作。
- C 发布“建议关注的对象”；B 检查轨迹、会话和时效后计算运动请求；A 提供底层访问库和 PL 最终监督。正式运行时只能有 B 的一个运动进程写控制寄存器。
- 所有人工替代输入、回放、CPU 临时后端、主机临时身份服务都要标注，不能作为对应正式板端功能的通过证据。

### 每日记录与阻塞规则

当天在本人日志中写：实际用时、版本、完成内容、原始证据、未通过项、明日依赖。每天共同同步 15 分钟，包含在记录/协作时段。

同一阻塞连续约 2 小时没有新证据时，先收集日志、最小复现和已尝试方法，再拉对应队员协作。不能靠连续改版本、改电源或调阈值盲试。阻塞超过一个开发日，调整依赖任务并记录进度影响，不擅自取消已承诺的能力。

若 D3 无可运行平台，或 D10 无真实视觉控制闭环，30 天完整目标存在明显风险；团队须明确选择延期或缩小本月交付，不能把模拟演示改名为完成。优先守住停止、时效和原始记录，再削减外观、复杂模型改造与非必要并发。

以下交付路径均为建议工程结构，不表示文件已存在。正式仓库使用英文目录与文件名；实际平台的地址、引脚、时钟、供电和命令依器件与版本核验。

## 本人责任与任务边界

A 主导平台、RTL、约束、低层访问库、电路和机构验证，维护统一硬件发布。B 主导模型量化/编译及唯一运动请求进程，C 提供音频软件参考、视听策略和界面。A 不承诺替其他人完成所有模型服务，也不将下载官方 DPU 算作自研加速器。

本月最重要的顺序是：先默认禁能与控制仿真，再真实波形，再视觉小范围动作，随后加入音频和严格故障测试。物理停止电路与驱动极性必须确认后才进行带负载动作。

## 每日执行计划

### D1 实物盘点与硬件边界

**投入：6 小时。**

- **操作：**记录 KV260 载板版本、电源、microSD、舵机标签、屏幕与相机型号；拍接口和接线照片。核对独立舵机功率支路、停止通路、驱动使能极性，未确认前保持禁能。列出缺料、借用测量设备和到货日期。
- **产出：**hardware/bom.csv；hardware/power_tree.md；report/a/d01_inventory.md。
- **当天验收：**每个供电域和信号电平有依据；未知型号明确标注，不能将旧文档示例直接当实物参数。
- **三方协作：**向 B/C 提供可用接口、器件状态和最早接入日期；收集主机/外设需求。
- **阻塞处理：**没有完整电路时先画图和检查，不连接舵机功率；避免占用 B 的相机测试。

### D2 工具链锁定与板卡首启

**投入：6 小时。**

- **操作：**记录 Vivado/Vitis、Linux 构建环境、DPU 参考设计和现有系统版本；核验它们属于同一路线。完成串口首启、网络连接、系统信息采集与恢复介质安排；制定硬件构建标识。
- **产出：**docs/platform_lock.md；board/boot_log.txt；contracts/motion_v1.md 草案。
- **当天验收：**串口与网络可用；工具能启动；没有把安装完成等同于硬件工程已可重建。
- **三方协作：**与 B 冻结 DPU 目标和模型输入约定；与 C 确认网络及设备名。
- **阻塞处理：**工具不匹配则保存诊断，优先恢复已知可运行基线；避免同时升级多项组件。

### D3 参考平台检查与最小重建

**投入：6 小时。**

- **操作：**检查匹配参考工程、板卡文件、许可和构建脚本；启动基线构建并保存日志。核对地址、时钟、复位和外设使用情况，确认自研 IP 的插入位置；制定引脚预算。
- **产出：**build/reference_build.log；hardware/io_budget.csv；docs/build_route.md。
- **当天验收：**获得参考平台可运行证据和可重建状态；未完成构建必须列明原因与预计影响。
- **三方协作：**B 使用同一平台做模型检查；C 获得首版连接说明；共同 D3 评审。
- **阻塞处理：**若无可运行基线，列为红色阻塞；可继续纯 RTL 仿真，但不得宣布平台通过。

### D4 PWM 模块与仿真

**投入：6 小时。**

- **操作：**写参数化 PWM 计数器，按周期边界更新正常脉宽；定义 reset、enable 和停止输出。用 testbench 检查最小/最大值、启停和中途改参数；使用示例时钟验证逻辑，实际频率另冻结。
- **产出：**src/rtl/servo_pwm.sv；sim/tb_servo_pwm.sv；sim/results/pwm_wave。
- **当天验收：**周期、脉宽和默认禁能符合测试定义；无未定义寄存器和异常窄脉冲。
- **三方协作：**给 B 说明目标值、单位和更新规则；C 确认 UI 中的动作状态含义。
- **阻塞处理：**先不接实物舵机；复杂滤波/速度规划留到最小 PWM 正确之后。

### D5 命令监督与恢复状态机

**投入：6 小时。**

- **操作：**按 D5 统一为 DISARMED/NEEDS_REFERENCE/ARMED/TRACKING/AT_LIMIT/FAULT 六态，到期作为事件处理；完整转移和恢复策略按对齐记录先冻结。加入范围、序号、许可倒计时和停止优先级；写旧命令、重复提交、超时、复位与释放停止的测试。会话与恢复代次字段先冻结并定义比较规则。
- **产出：**src/rtl/command_guard.sv；sim/tb_command_guard.sv；docs/fault_codes.md。
- **当天验收：**超时不能由普通心跳续期；停止释放不自动重启；所有拒绝有可观察原因。
- **三方协作：**与 B 确认命令原子提交字段；与 C 确认故障提示和人工恢复入口。
- **阻塞处理：**不追求复杂形式化工具；先用覆盖明确异常的仿真和断言验证数字规则。

### D6 AXI 接口与状态回读

**投入：6 小时。**

- **操作：**集成经过核验的 AXI-Lite 接口，实现 VERSION、STATUS、影子寄存器与 COMMIT。测试地址/数据独立握手、字节写使能和背压；为软件提供访问库接口和读版本示例，结合平台尝试上板读取。
- **产出：**src/rtl/motion_regs.sv；src/board_app/motion_hw_api.*；contracts/register_map.md。
- **当天验收：**半条命令不能改变活动输出；仿真协议通过；实际版本寄存器是否读到分别记录。
- **三方协作：**B 收到寄存器表和访问函数签名，唯一运动写入者仍是 B 的正式进程。
- **阻塞处理：**上板尚受构建阻塞时交付仿真接口与回放状态；不使用未经检查的任意物理地址。

### D7 缓冲与第一轮评审（2 小时）

**投入：2 小时。**

- **操作：**用 30 分钟整理 D1—D6 证据，参与 60 分钟三方评审，余下时间确定 D8—D10 的阻塞和设备使用安排。核查供电、停止设计是否准备好空载实测。
- **产出：**report/a/week01_review.md；更新 issue_list.md。
- **当天验收：**控制仿真、接口定义和平台状态可核查；每个未通过项有负责人和复查日期。
- **三方协作：**确认 B 检测输入已可用，C 界面能够显示硬件故障；预约 D9 波形、D10 联调。
- **阻塞处理：**本日不新增功能，保留恢复和休息时间；超过容量的问题调整后续范围。

### D8 DPU 与控制模块同片构建

**投入：6 小时。**

- **操作：**在选定参考平台中加入 motion IP、地址和复位连接，核对 DPU 与自研逻辑共存。同步设备树/访问方式，启动综合实现，查看资源与时序报告；维护可回退基线。
- **产出：**build/scripts/build_platform.*；build/reports/integrated_motion；board/releases/pre_g10_manifest.json。
- **当天验收：**最终配置包含 DPU 和控制模块，非交替加载两个完整位流；工具失败原因可定位。
- **三方协作：**与 B 用同一硬件版本运行检测和 VERSION 回读；C 更新启动清单。
- **阻塞处理：**若资源或时序不通过，先减少非必要并行度并核查约束；不假装用两个独立工程替代同片验收。

### D9 上板波形与使能电路验证

**投入：6 小时。**

- **操作：**不接机械负载，测 PWM 周期/脉宽、使能逻辑、停止和超时。验证 FPGA 未配置、软件未启动、复位时的默认状态；区分 EN 与 P-MOS 栅极极性，核对供电压降及回流。
- **产出：**report/a/pwm_measurements.csv；hardware/enable_schematic；data/scope/d09。
- **当天验收：**输出和使能实测符合电路定义，停止路径有效；禁止仅凭 LED 判断波形正确。
- **三方协作：**向 B 发布经过实测的允许脉宽、方向测试步骤和调用前置条件；C 显示禁能原因。
- **阻塞处理：**借不到仪器时不能勾选波形通过；改做接线审查、仿真和等待，真实动作顺延。

### D10 视觉随动首次联调

**投入：6 小时。**

- **操作：**与 B/C 完成小负载、低速、小范围跟随。先用固定请求确认方向，再用真实检测中心控制；测试目标丢失、进程退出和停止。记录同片硬件、模型、软件版本及原始视频/波形。
- **产出：**report/integration/g10_follow.md；hardware/servo_calibration.csv。
- **当天验收：**DPU 检测和控制在同一配置下工作；反向、超时和停止行为正确；未通过前不扩展转角。
- **三方协作：**B 负责控制误差与时效，C 展示状态；三人签收 G10。
- **阻塞处理：**若未通过，当天列红色问题；下一阶段优先修复而非继续堆模块。

### D11 I2S 时钟与接收仿真

**投入：6 小时。**

- **操作：**核对到货双麦手册、槽位、位宽和采样边沿；冻结左右与声道脚配置。实现或核验 BCLK/WS 产生与双路接收，仿真已知正负样本、左右交换、复位与启动无效段。
- **产出：**src/rtl/audio_clock_gen.sv；src/rtl/dual_i2s_rx.sv；sim/tb_dual_i2s.sv。
- **当天验收：**模拟样本完整还原；目标频率与实际可实现频率分开记；小数分频不写成等量交替。
- **三方协作：**向 C 提供格式、实际/预期 fs、位宽和窗口字段；B 提供镜头安装关系。
- **阻塞处理：**麦克风未到时继续生成式输入仿真，并标记实物链未完成。

### D12 双麦上板与原始数据导出

**投入：6 小时。**

- **操作：**测 BCLK/WS 和数据时序，捕获短段双通道 PCM。检查符号、幅度、声道、削波和样本计数；交换物理麦克风排查固定偏差。以可控调试通道导出数据，不阻塞运动监督。
- **产出：**data/audio/raw_d12；report/a/i2s_capture.md；contracts/audio_window_v1.md。
- **当天验收：**两路均有真实声音且时间对应可检查，丢样有计数；没有把全零或串位数据当成功。
- **三方协作：**C 收到第一批 PCM 和硬件采样计数，用于参考相关和时间偏移分析。
- **阻塞处理：**导出链阻塞时缩短数据段并隔离调试任务；不能为了导出而暂停停止处理。

### D13 采样同步与窗口缓冲

**投入：6 小时。**

- **操作：**实现双缓冲交接、样本编号和 DROP_COUNT；验证读写所有权、窗口连续性和 CDC。与 C 共同记录可见/可听同步事件，估计音视频以及两条音频链的偏移，不假定相同时钟。
- **产出：**src/rtl/audio_window_buffer.sv；report/a/window_timing.md；data/audio/sync_d13。
- **当天验收：**重复读取无半新半旧窗口，采样连续性可追溯；时间来源明确。

### D15 短窗相关计算 RTL

**投入：6 小时。**

- **操作：**按 C 的参考和约定窗口实现候选 lag 相关，优先少量乘加单元复用。明确取高 16 位或保留位宽、乘积/累加宽度、共同有效索引、输出缩放；对固定窗口逐项比对。
- **产出：**src/rtl/xcorr_engine.sv；sim/tb_xcorr.sv；sim/results/xcorr_compare.csv。
- **当天验收：**相关值/峰位置按约定精度一致，极值无未说明溢出，吞吐满足计划窗口率。
- **三方协作：**向 C 返回差异记录供软件参考排查；与 B 核查剩余 DSP/BRAM 预算。
- **阻塞处理：**若无法按时实现优化结构，先完成可解释的串行计算架构，不急于加 FFT。

### D16 方向质量、拒判与寄存器

**投入：6 小时。**

- **操作：**加入能量、峰可信度、削波、丢样和迟滞规则；输出 LEFT/CENTER/RIGHT/UNKNOWN。定义 DOA 快照寄存器与序号，防止读取不同窗口字段；用静音、噪声、多峰等输入测试。
- **产出：**src/rtl/doa_quality.sv；contracts/doa_v1.md；sim/results/doa_cases。
- **当天验收：**坏输入不高置信输出方向；质量和拒绝原因可读；阈值出处可追溯。
- **三方协作：**C 用相同字段接入音向候选；B 确认相机坐标方向。
- **阻塞处理：**仅完成峰值时如实标记质量门未完成，不能把简单 lag 符号作为完整方案验收。

### D17 音频、DPU、控制共同构建

**投入：6 小时。**

- **操作：**将音频模块加入最终平台，核查地址、引脚、时钟与复位；完成 CDC/时序检查，生成配套部署包。与 B 并发跑 DPU 与音频采集，观察 DROP_COUNT 和控制回读。
- **产出：**board/releases/audio_motion_dpu_manifest.json；build/reports/g17。
- **当天验收：**三部分同片存在，音频采集不导致控制计时停顿；报告资源与最差时序。
- **三方协作：**B/C 使用同一发布包，禁止各自加载不同完整硬件文件；安排 D18 标定。
- **阻塞处理：**构建失败先保留 G10 稳定版；单独音频工程只作排障，不作整机完成证据。

### D18 实物音向标定与融合联调

**投入：6 小时。**

- **操作：**固定麦距和安装几何，按左/中/右、距离和背景噪声采集；校正左右符号和固定通道偏差。与 C 用方向窗口和质量接入目标选择，与 B 检查镜头左右及时间归属。
- **产出：**hardware/mic_geometry.md；configs/doa_calibration.yaml；report/integration/g18。
- **当天验收：**音向、视觉和人物编号一致；歧义时拒判；实测结果保留失败样本和 UNKNOWN。
- **三方协作：**向 C 交付冻结阈值和适用范围；向 B 提供转动/静止状态与设备播音抑制需求。
- **阻塞处理：**结果差先检查输入与安装；不能在同一批评测数据上反复调阈值后报告独立准确率。

### D19 监督机制与故障覆盖补齐

**投入：6 小时。**

- **操作：**补齐安全代次、序号回绕策略、越界、错误会话、重复旧证据和恢复条件。审查 AXI 原子提交及状态快照；对停帧、停止释放和驱动退出执行波形测试。
- **产出：**sim/fault_suite；report/a/guard_coverage.csv；docs/recovery.md。
- **当天验收：**每类异常都有预期、实际与证据；不得用新序号给旧观察无条件续期。
- **三方协作：**B/C 共同生成错误会话与迟到输入，校对提示文案。
- **阻塞处理：**形式化证明不作为本日必需；明确当前仅验证数字接口与输出行为。

### D20 计时映射与整机输出检查

**投入：6 小时。**

- **操作：**与 B 建立 PS 时间与 PL 租约的关系和误差预算，量化提交延迟。检查音频/推理/网络忙时控制本地计数仍运行；整理上电自检、禁能和恢复流程。
- **产出：**docs/time_and_lease.md；report/a/loaded_stop_test.csv。
- **当天验收：**没有混用 Windows 与 PS 时钟；相对租约适用条件明确；负载下停止仍可测。
- **三方协作：**C 接入真实硬件状态，B 根据证据截止时间计算剩余租约。
- **阻塞处理：**若无法界定严格曝光总期限，仅报告已验证的时间边界并继续测量，不能扩大保证。

### D21 完整功能评审（2 小时）

**投入：2 小时。**

- **操作：**参与全链路演示：跟随、认人、选人、问答、取消、断主机和停止。检查实际部署与计划差异，锁定 D22—D24 必修问题。
- **产出：**report/integration/g21_checklist.md；A 缺陷清单。
- **当天验收：**每项明确通过/未通过/受限，所有替代路径注明运行位置。
- **三方协作：**与 B/C 分配前三个阻塞问题和复测时段。
- **阻塞处理：**不在缓冲日新增外设；核心未通过则讨论延期或真实缩小交付。

### D22 机构、线束与转动噪声收尾

**投入：6 小时。**

- **操作：**调整麦克风与电机/扬声器相对位置，整理线束、固定连接和散热。验证限位、线缆余量、上电惯性与供电尖峰；与 C 评估自播音和转动噪声的抑制规则。
- **产出：**hardware/assembly_final.md；report/a/power_motion_noise.md。
- **当天验收：**全允许行程不拉线或撞限位；供电和停止电路有最终图；改动后关键功能复测。
- **三方协作：**B 重测安装变化对相机/补偿的影响，C 重测声音阈值。
- **阻塞处理：**不临时增加第二轴或复杂外壳；不因改善外观破坏已验证几何。

### D23 关闭硬件阻塞缺陷

**投入：6 小时。**

- **操作：**按 G21 严重程度修复，优先停止、数据一致性、同片构建和不可恢复故障。回归受到影响的仿真与实测；清理临时约束、调试寄存器与未说明参数。
- **产出：**report/a/defect_closure.md；build/reports/pre_freeze。
- **当天验收：**无未处理的已知失控路径；剩余限制明示，不用忽略告警代替修复。
- **三方协作：**B/C 在候选版本回归；报告接口是否变化。
- **阻塞处理：**若修复扩大范围，回退稳定版并列出限制；不得拖到最后一天才说明。

### D24 硬件与接口冻结

**投入：6 小时。**

- **操作：**生成统一发布清单与文件校验值，冻结 XSA/bit 或所选平台对应工件、设备描述、地址、引脚和寄存器。保存恢复介质、启动/恢复说明和工具日志。
- **产出：**board/releases/rc1；docs/hardware_release.md。
- **当天验收：**B/C 只需按清单就能部署匹配版本；无散落在个人下载目录的必需工件。
- **三方协作：**向 B/C 发布 RC1，后续仅修缺陷并编号，不加新功能。
- **阻塞处理：**未通过模块不藏入最终包；单列未完成与替代方案影响。

### D25 硬件性能、资源与参考对照

**投入：6 小时。**

- **操作：**导出 LUT/FF/DSP/BRAM/时钟与时序报告；与 C 比较相同音频算法、相同窗口的 PS 和 PL 结果、耗时及抖动；与 B 核查 DPU 并发负载。
- **产出：**report/a/resource_results.csv；report/a/audio_ps_pl_compare.md。
- **当天验收：**算法输入和计算精度可比；不拿不同模型/不同窗口的时间直接当加速倍数。
- **三方协作：**B/C 取得最终图表数据与测量条件，统一报告单位。
- **阻塞处理：**没有可靠功率仪器时只报告可测项，不编造能效或整机功耗。

### D26 硬件故障注入正式测试

**投入：6 小时。**

- **操作：**执行停止、旧帧、重复/乱序、错误会话、进程退出、复位与未完成写入。测数字输出和使能变化，机械现象单独记录；与 B/C 对齐异常事件编号。
- **产出：**report/a/fault_results.csv；data/scope/final_faults。
- **当天验收：**每项有输入、输出、版本和原始证据；数字停止与物理停止不混报。
- **三方协作：**B/C 核对同一故障在软件/UI 中的表现。
- **阻塞处理：**发现关键失败立刻登记修复和复测，不因为处于测试周跳过。

### D27 全功能长时间运行

**投入：6 小时。**

- **操作：**三人共同执行至少 2 小时连续运行，A 监测温度、供电、音频丢样和硬件状态。剩余时间分析异常并安排最小修复；检查三次冷启动计划的执行情况。
- **产出：**report/integration/soak_test；report/a/soak_hardware.md。
- **当天验收：**长测包含真实并发和交互；出现故障保留日志，修后重新完成受影响测试。
- **三方协作：**C 记录事件时间线，B 记录 CPU/DDR/DPU，A 提供同一版本硬件信息。
- **阻塞处理：**不能只让界面空闲 2 小时代替并发长测；严重故障影响最终通过状态。

### D28 缓冲与问题复查（2 小时）

**投入：2 小时。**

- **操作：**只处理剩余高优先级证据和交付清单。核查替换器件、焊接或版本更新是否需要重测；整理 D29 冷启动复现用包。
- **产出：**report/a/week04_review.md；retest_queue.md。
- **当天验收：**每个修复有对应复测安排，没有“应该好了”的未验证结论。
- **三方协作：**与 B/C 交换复现步骤，安排他人操作。
- **阻塞处理：**剩余问题超出两小时则更新交付状态，不从休息缓冲里默认挤出无限工时。

### D29 他人复现与硬件技能包

**投入：6 小时。**

- **操作：**让 B/C 按说明部署并读版本、执行受控动作和停止；A 观察但不口头补隐藏步骤。整理 command_guard_validation 技能包的输入、步骤、失败条件和证据；完成接线与恢复指南。
- **产出：**skill/command_guard_validation；report/reproduction_a.md；hardware/final_wiring。
- **当天验收：**他人能从已声明前提复现；构建环境、下载工件、许可和恢复条件完整。
- **三方协作：**向 C 提供报告图和演示测点，B 核对硬件/模型清单一致。
- **阻塞处理：**复现失败优先改步骤或补依赖，不通过剪辑演示掩盖缺项。

### D30 硬件交付与答辩排练

**投入：6 小时。**

- **操作：**完成交付目录和版本校验，与 B/C 录制连续演示和故障片段。讲清 DPU 为复用 IP、自研模块做什么、资源与延迟如何测、当前限制。检查原理图和公开资料不含不必要个人数据。
- **产出：**report/a/final_summary.md；board/releases/final；hardware/delivery_manifest.md。
- **当天验收：**源码、脚本、波形、资源、运行文件与视频对应同一版本；未完成项准确披露。
- **三方协作：**三人共同签收功能清单和下一阶段问题表。
- **阻塞处理：**存在关键未通过项时交付状态写“部分完成/待修复”，不得改成已全部验收。
