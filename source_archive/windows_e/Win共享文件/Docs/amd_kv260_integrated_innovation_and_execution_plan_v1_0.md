## 1. 先读结论：应该增加什么

保留“能看、能听、能回答、有玩偶表情、能转头、能认出登记用户”的产品目标。围绕一次完整交互，增加四个相互配合的机制：

1. **视听协同选人：**听到声音后先确定大致方向，再用视觉确认目标；不能确认时保持或询问，不盲目转向。
2. **主动观察与证据绑定：**需要看清时受控转头，取得更新画面再回答；回答对应的画面、时间和对象可以追溯。
3. **会话绑定的身份记忆：**认出的是一个已确认的人；记忆属于这个人，迟到结果和换人不能把记忆串过去。
4. **依据有效期执行动作：**过期帧、旧会话、重复命令和主机迟到结果不能继续驱动转轴，关键执行约束在 PL 中实现。

其中，双 I2S 麦克风与 PL 粗声源方向判决提供真实自研感知负载；动作约束提供真实自研执行负载。DPU 检测为平台集成成果，Windows 主机提供视觉语言模型和语音模型。

**推荐项目名称：雾镜 Lite——具有视听目标确认与会话记忆的 FPGA 实体交互终端。**

推荐演示主线：两人站在设备前方不同位置，一人说话，设备先看向并确认对方；看不清时请求调整或进行一次小范围观察；回答时显示所依据画面；换人后不串用身份记忆；人为冻结画面或断开控制进程，旧命令失效。

这属于面向具体问题的系统设计与工程创新候选。I2S、互相关、跟踪、记忆、看门狗均有成熟先例，不能据此声称算法首创或世界首创。已有 Reachy Mini 对话应用包含记忆工具，因此“机器人会记忆”本身不足以证明独特性。[S5]

## 3. 对旧文件和上一轮评价的纠正

| 原表述或风险 | 本版纠正 | 对实施的影响 |
|---|---|---|
| USB 音频/视频不能进 PL | USB 数据可先由 PS 接收入 DDR，再通过 DMA/AXI 交给 PL；不能直接从 PL 引脚采 USB 样本，不等于不能送入 PL。[S1] | 保留 USB 摄像头，无需为论证改成 MIPI |
| 只有 PL 才能获得同步多通道音频 | MCU、音频接口和同步 USB 阵列也可支持共同采样时钟；PL 是本设计的实现选择 | 不用自选接线证明不可替代 |
| PS 看不到 PL 引脚数据 | 自研采集核可以把样本通过 FIFO、BRAM 或 DMA 导出给 PS | 同源软件基线是可实现的 |
| 两只麦共享时钟就绝对零偏差 | 共时钟避免独立时钟漂移，但通道延迟、装配误差、数据错位仍要标定 | 测通道对齐与长期变化，不空称零误差 |
| 音频同步意味着音视频采样同步 | 二者独立；USB 摄像头与 I2S 麦克风通常没有共同采样触发 | 采用时间戳关联，披露误差 |
| 全链 4.2 MMAC/s | 旧表至多估计所列音频 DSP 链，不包含 DPU、LLM、ASR/TTS 等整机计算 | 改名“候选音频算术量估算”，按最终算法重算 |
| 4.2 MMAC/s 对应约 0.001% DSP 占用 | 运算率与 DSP 个数不能直接相除；缺频率、调度及实际映射 | 用综合报告给出 DSP/LUT/FF/BRAM 占用 |
| 性能必要性已经不成立 | 目前没有证据证明 CPU 算不过来，也没有等价实现实测证明全部性能无差异 | 结论保持开放，测实际收益 |
| Python/C 不优化即可当 CPU 基线 | 用慢 Python 循环对比 RTL 会制造不公平加速比 | 用合理优化 C/C++ 或向量化实现，记录线程和编译选项 |
| PL 卸载后 CPU 占用降为零 | 驱动、搬运、轮询和编排仍有开销 | 统计整个相关进程及系统负载 |
| 端侧延迟对体验没有影响 | 采集、排队、播报取消和视觉滞后均可能影响体验 | 分段计时，不凭猜测归因于云端 |
| 同片 PL 完成整个感知到执行闭环 | 目标融合/跟踪在 PS，模型在主机；只有部分链路在 PL | 称为 KV260 PS/PL 协同闭环 |
| 数据不出设备、断网可用 | 原始音频/JPEG/人脸图可能发给 Windows 主机 | 区分板卡、局域网系统、公网三条边界 |
| FPGA 上电即守护 | PL 先要完成供电、配置及复位；启动流程可能依赖 PS | 测冷启动，配置前由电气默认状态约束动作 |
| KV260 绝对不能运行任何大语言模型 | 小模型是否可运行取决于量化、运行时和目标延迟 | 本项目选择主机运行，不冒充硬件绝对禁限 |
| 停止 PWM 就等于电机立即停住 | 舵机失去信号后的行为因型号而异；指令限速不等于机械实测限速 | 分别测数字输出与机械停止 |
| MIPI 必须替代 USB 才算 FPGA 应用 | USB→DDR→DPU 的推理仍使用 PL 中的 DPU | 不为叙事引入新的摄像头调试风险 |
| 方案 D 必然是新变更/必然只是改叙事 | 相对旧 USB 音频 V2 是增项；若未提供的 V1.2 已采用 I2S，则对该版可能只是论证修订 | 必须按实际基线做变更清单 |
| 文档格式验证等于技术正确 | 标题数量和表格一致性只能证明结构 | 把工程验收独立列出 |

**纠正后的 FPGA 理由：**本项目选择 FPGA 来实现可重建、可测量的流式音频判决与动作约束，并研究它在 CPU 负载、判决节拍、故障隔离和资源利用上的实际收益。存在其他可行实现，并不否定本作品的 FPGA 设计价值。

## 5. 最终架构与数据去向

```text
两只共时钟 I2S 麦克风
  → PL：I2S 接收 → 去直流/能量 → 短时互相关 → 方向与置信状态
  → PS：音频事件读取 ──────────────────────────┐
USB 摄像头 → PS/DDR → PL DPU 检测 → PS 跟踪 ───┤
                                            ↓
                        PS：目标选择、会话、观察与有效期检查
                                            ↓
                        PL：motion_guard_ip → 单水平转轴

USB 麦克风 → PS 录音 → Windows ASR ───────────┐
PS 新鲜画面、身份及已确认偏好 → Windows VLM ──┤
                                            ↓
                     Windows TTS → 板端音响/玩偶/字幕
```

### 5.1 为二十天可交付采用的默认选择

- 保留 USB 摄像头，避免新增 MIPI 摄像头适配。
- 保留 USB 麦克风作为首版 ASR 输入，新增 I2S 双麦专做粗方向判决。两条音频不是采样同步关系，用板端录音区间关联 DOA 事件。
- 有余力才把 I2S 音频通过 DMA 输送给 ASR，合并成一条采集链；这涉及持续传输、缓冲和音频格式，不列为首版依赖。
- 麦克风阵列与摄像头优先装在同一刚性旋转支架上，保持方向相对关系。定位仅在转轴停止并经过安定等待后使用；移动期间音频可能受电机噪声干扰。
- 若麦克风固定在底座而相机旋转，必须增加底座方向到相机方向的变换；无角度反馈时误差更大，不作为默认结构。
- Windows 主机运行 VLM、ASR/TTS 及首版身份服务。板卡独立保留检测/跟随、粗方向与动作保护，具体以实际部署通过为准。
- 首版半双工：采集时停播，播放时抑制声源跟随；用户按键可取消播报进入录音。

### 5.2 数据边界

| 数据 | 首版位置/流向 | 可准确宣称 |
|---|---|---|
| I2S 原始双路样本 | PL 内处理；调试可导出板端 | 正常定位不要求发送原始双路音频到主机 |
| USB 语音片段 | 板卡→Windows ASR | 在自带局域网系统处理 |
| 看图 JPEG、人脸图 | 板卡→Windows 视觉/身份服务 | 原始图像会离开板卡 |
| 身份向量、偏好 | Windows 本地数据库 | 不必上传公网；有明确删除入口 |
| 模型请求 | 默认仅局域网 | 模型与依赖预先下载后，测试断公网运行 |

断公网后完整交互能否工作，需要实测；断 Windows 主机后只能提供板端降级功能；断控制进程后 PL 租约失效。不得把三种测试合并称为“断网全部可用”。

## 6. I1：双麦粗定位与视听目标确认

### 6.1 物理与算法边界

双麦只提供时间差线索，不能唯一确定完整三维位置，也存在前后歧义。范围限定为设备前方、单一主说话者、相对安静环境，输出 `LEFT/CENTER/RIGHT/UNKNOWN`。两人同时说话、反射强或声音来自后方时应允许 UNKNOWN，不能声称可靠地知道谁在说话。

候选参数：48 kHz 采样；间距 50 mm；10 ms 窗口约 480 样本。以声速 343 m/s 估算，最大物理时差约 7 个样本，搜索整数 lag=-8…8。参数为设计起点，不是已确定器件配置。32 阶 FIR、IIR 等只有噪声测试证明需要才加入，首版不默认堆满滤波链。

互相关可用 `R(k)=Σ x[n]·y[n+k]`，对所有 k 采用相同有效区间，避免边缘样本数不同造成偏置。取峰值并结合能量、峰值突出程度和连续窗口一致性决定有效性；低置信或饱和返回 UNKNOWN。只按最高峰强制分类容易在噪声中误转。

对应工作量例：17 个 lag×约 464 个有效样本×100 窗口/s≈0.79 MMAC/s，仅包含相关计算。建议先复用一个或少量乘累加单元，以计数器逐项计算；无须展开为几千个乘法器。归一化/滤波/导出等额外开销单独计数。

定点起点：输入 24 位解析后，校准缩放为有符号 16 位；乘积 32 位；约 480 项累加建议至少 41 位，选 48 位留余量。截位、舍入、饱和与符号扩展必须与软件参考一致。

INMP441 仅为候选器件，应以购买模块和原厂手册核对时序、电压、左右选择及数据格式。官方手册给出了其 24 位 I2S 接口规范。[S3] 不因外观相似就认定兼容。

### 6.2 需要写的模块

| 文件/模块 | 输入输出及职责 | 验证重点 |
|---|---|---|
| `i2s_clock_ctrl.sv` | 生成满足所选麦克风要求的 BCLK/WS | 采样率、占空比、时钟来源 |
| `i2s_rx_pair.sv` | 接收两路 SD、解析 I2S 一位延迟，成对输出样本 | 位对齐、左右选择、符号、启动无效数据 |
| `sample_condition.sv` | 去直流、缩放、能量与饱和检测 | 与参考模型逐样本核对 |
| `audio_window_buffer.sv` | 双缓冲/窗口有效标志 | 运算时采集不覆盖，溢出置无效 |
| `xcorr_engine.sv` | 时分复用乘累加、输出相关峰 | 正负 lag、位宽、周期预算 |
| `doa_decision.sv` | 置信、持续窗口、迟滞，四类输出 | 静音/噪声不是默认 CENTER |
| `audio_status_regs.sv` | 原子快照、事件号、样本计数、方向、质量状态 | 软件读多个字段不跨两个事件 |
| `audio_debug_export` | 有限长度样本导出与测试向量注入 | 离线采样可用 BRAM；连续流用适配的 DMA |
| `audio_doa_ip.sv` | 集成上述模块 | 复位、禁用、故障、时钟域 |
| `doa_reference.cpp` | 定点等价 PS/PC 基线 | 同输入、同参数、可重复输出 |
| `tb_audio_doa.sv` | 自动验证正常与异常样本 | 固定时差、静音、削波、错位、复位 |

两只麦建议共用 BCLK/WS、分别使用 SD 引脚，以减轻共享总线三态排查；左右槽位按实物配置。引脚、电平和输入/输出延迟约束根据所用载板原理图填写，不在未核对时生成管脚编号。若采集时钟与 AXI 时钟不同，使用正确的 CDC/FIFO，不能把多位总线每一位各打两拍当作可靠跨时钟传输。

### 6.3 视听融合规则

1. C 开始一轮录音，标记 `utterance_id` 和板端起止时间；仅使用邻近区间内有效且转轴已安定的音频事件。
2. B 将相机中人员中心位置换算为左/中/右候选区；先进行相机与阵列方向标定。
3. 仅一个视觉目标与声音方向一致，且结果连续稳定，才切换为候选目标。
4. 同一区域多人、声音与视觉冲突或音频过期时保持当前目标并询问“请靠近一点或按键确认”。
5. 音频只能指示一个待观察方向；不直接把方向当身份，不在遮挡/交叉后继承原名字。
6. 没有看到人时，可选进行一次受限小步转动；未确认则结束，不持续追声音旋转。

需写 `audio_event_reader.py`、`av_target_selector.py`、`direction_calibration.yaml`。以视觉单独选人作为基线比较错误目标率与确认耗时。

## 7. I2：主动观察与回答证据绑定

### 7.1 必做简版

问题涉及画面时，从唯一相机采集进程取得一张新鲜图像，绑定 `boot_id/frame_id/presence_session_id/request_id`。画面过旧、目标消失或质量不足时明确提示重试；不能继续用上一轮 JPEG 回答。

UI 提供“本次观察”小图、观察时间和状态。这里展示的是实际送给模型的输入证据，不把模型生成的解释当作视觉检测证据。

### 7.2 可选主动观察

状态顺序：`REQUEST → CHECK_VIEW → MOVE_ONCE → WAIT_SETTLE → NEW_FRAME → ANSWER`；任意阶段超时进入 `ASK_USER`。

- 只有现有跟踪目标偏离中心时进行受控小角度调整；首版不要求新增物体检测模型。
- `WAIT_SETTLE` 结合命令结束等待与画面运动变化判断。没有编码器时只称“等待与视觉安定判断”，不能称机械位置已经精确到达。
- 新画面必须产生于等待结束以后；收到旧缓存帧不算重新观察。
- 每次请求最多一次调整，单次角度/整体限位由 A 标定；超过观察预算请求用户配合。
- LLM 只可发出受限的 `observe_again` 意图，由确定性软件策略审查；不得给它寄存器、PWM 或清故障权限。

需写 `observation_controller.py`、`snapshot_quality.py`、`evidence_bundle.py`。对同一组桌面问答任务，比较直接取图与观察流程的正确率、追加耗时和无效转动次数。模糊质量判断可先用 OpenCV，未证明瓶颈前不另写 HLS 清晰度核。

## 8. I3：身份记忆与防串人

### 8.1 把“记得你”定义清楚

人脸特征通常是模型输出的高维向量，不是默认三维坐标。维度由模型决定，必须记录模型版本和预处理；不同模型向量不能混用。

最小功能：用户明确登记名字；采集少量合格人脸；再次出现时可匹配或 UNKNOWN；确认后记住一条显式偏好，例如“回答简短一些”；可查看、纠正和删除。无需先建设复杂向量数据库或长期聊天记忆。

### 8.2 数据结构与规则

| 对象 | 最小字段 |
|---|---|
| 身份 | `person_id/display_name/embedding_model/version/templates/enrolled_at` |
| 偏好 | `person_id/key/value/source/confirmed_at/revision` |
| 临时会话 | `boot_id/presence_session_id/track_id/current_person_id/identity_status` |
| 异步结果 | 原始会话、帧号、请求号、数据库 revision |

- 跟踪号不是永久身份。人离开、交叉遮挡后关联不可靠时，重新确认会话。
- 登记限定画面中单一被确认目标，多人时不自动写库。
- 匹配阈值用本队登记者与陌生测试者校准；不要直接把余弦相似度当概率。
- 低置信只问“是否是某某”，确认前不取其个人偏好。
- 旧会话的识别/模型结果到达时丢弃；删除增加 revision，使在途缓存失效。
- 首版只存用户明确要求记住的偏好。保留来源、时间和纠正入口，模型推测不能自动入库。

需写 `identity_service.py`、`identity_session_gate.py`、`memory_store.py`、`memory_api.py`。数据库可用 SQLite 与向量文件；向量匹配和数据库在主机端，不声称 FPGA 加速记忆。

测试必须包含陌生人、两人换位、旧请求迟到、删除后立即重返。报告错误接受率、正确重识别率和记忆串用次数，而不只播放一次成功问候。

## 9. I4：依据新鲜度的 PL 动作约束

> **等级归属（W17-03）**：本节机制属 **P0 基础安全链**，**不计入 P1 创新主线**（P1＝双麦 PL 方向判断与视听目标确认，见 D5 第 1.3 节），避免把基础安全当作创新增量重复计分。

### 9.1 职责边界

PS 判断画面与身份是否有效，PL 判断提交的命令是否符合协议和租约。PL 不看图，不会自动知道“人已经离开”；它只能拒绝过期/非法命令。因此不能用独立心跳无限续租旧目标。

继承旧 V2 中 `motion_guard_ip` 的原子提交、会话、序号、限幅、指令变化率、停止和恢复机制。**运动 IP 寄存器以 D1 第 10.5 节的表为准**（0x000—0x05C，已冻结，含 `CONFIG_CRC`、`REJECT_REASON`、`CMD_SESSION`、`LEASE_US`、`COMMIT` 等诊断与协议项）；**本版不再推迟偏移核对**，仅保留"核对版本并冻结映射"的动作（W17-09）。另注：D2 第 6.4 节是新建独立 IP `audio_doa_ip` 的寄存器表（25 项、0x000—0x060），其 AXI 基址由 Address Editor 分配后回填，**与 `motion_guard_ip` 属不同地址段，同偏移不构成冲突**；软件须按各自基址分别访问，不得混用。

### 9.2 从画面到命令的有效期

1. 相机帧标注板端单调时钟时间。能验证驱动采集时间则使用它；只能记录出队时间时，必须称为出队时间且测缓存影响。
2. 设帧最大有效年龄 `T_frame`，PS 提交时计算剩余时间。
3. 提交租约不超过剩余帧寿命减去已标定的提交开销余量，也不超过 `T_lease_max`。
4. PL 在接受原子提交时启动本地计数器；重复序号、错误会话和无效提交不续租。
5. 对同一证据来源设绝对截止时间，不能给旧帧换新序号后无限续命。
6. MMIO 提交抖动若不能限定，则只声称“从接受命令开始的租约约束”，不声称严格端到端帧龄上界；高级版本可用共同硬件时间戳/截止时间协议。

初始调参可参考旧 V2 的帧龄 300 ms、最大租约 200 ms，必须结合检测速度实测，不能作为已实现指标。

### 9.3 需要编写与验证

`axi_regs.sv`、`command_guard.sv`、`slew_limiter.sv`、`pwm_generator.sv`、`stop_watchdog.sv`、`motion_guard_ip.sv`、`tb_motion_guard.sv`、`motion_driver.py`、`servo_calibration.yaml`。

动作状态为 `DISARMED`、`NEEDS_REFERENCE`、`ARMED`、`TRACKING`、`AT_LIMIT`、`FAULT`（2026-09-26 按 D5 W17-11 统一；原表述含 `STOPPED`）；停止优先于普通命令。清故障与重新使能分开，复位默认禁用。PWM 在周期边界更新；外部停止信号按电气要求处理。数字停止输出、停止 PWM、切断驱动电源和机械静止是不同事件，分别验证。

有限角度位置舵机是默认执行器；没有编码器就只显示“指令角度”。舵机/功放由合适独立支路供电，不能从 Pmod 电源驱动。AMD 手册列出该 Pmod 为 3.3 V、100 mA 供电能力，实物负载与接口仍需逐项核对。[S2]

## 10. I5：交互面板与完整演示

普通用户面板：待机、正在听、正在确认对象、正在观察、正在回答、需要帮助。配合玩偶眼神、字幕、取消、登记/删除入口。

演示面板单独显示：声音方向及有效性、视觉候选、当前会话、实际观察缩略图、记忆来源、动作被接受/被拒绝及原因。只显示实际数据；传感器不支持的“真实角度”“声源身份”不伪造。

推荐 3 分钟演示：

1. 已登记用户与陌生用户位于前方不同方向；单人开口，设备确认目标并转向。
2. 登记者确认身份，设备使用其明确存储的偏好作答。
3. 换成陌生用户，显示 UNKNOWN，不使用前一人的偏好。
4. 用户问当前画面，屏幕显示新采集的证据图；条件不足时请求调整。
5. 冻结视觉采集或暂停控制进程，展示命令到期和动作保护状态。

播放自己的语音时不声称还能可靠定位用户；演示如需打断，使用按键取消。

- D3 没有有效 I2S 双路数据：D4—D5 限时解决电平/时钟/格式，冻结其他新增硬件。
- D7 仍无稳定有效方向：音频降为探索附件，不再对外承诺“谁说话看谁”；保留视觉选择、记忆防串人、动作约束。不得拿 PC 演示冒充 PL。
- D10 仍不能让 DPU 与自研核共存：平台集成是首要阻塞，立即停止主动观察与扩展记忆；若最终 CPU 检测降级，报告明确 DPU 未完成。
- D12 主链仍不稳定：取消自动主动观察，保留按键重新拍摄与证据绑定。
- D15 后只修缺陷、测量、整理材料，不追加新模型或换工具链。

两天只适合已具备平台基础时做可行性预检，不保证完成 I2S、DOA、DPU 共存与性能测量。二十天也是容量估计；若三人都从零开始，优先交付降级版本。

## 14. 用哪些实验支持创新

### 14.1 公平对照设计

1. **算法等价：**同一组双路 PCM 输入软件参考和 RTL/PL，相同窗口、lag、定点规则与判决阈值，比较输出。
2. **计算卸载：**同一 I2S 采集数据导出给 PS，比较合理优化软件与 PL 算法的计算时间、搬运开销、CPU 占用和判决抖动。
3. **整机效果：**同样视觉、噪声与用户任务下，比较视觉选人和视听选人；比较有无证据/租约机制。

USB 阵列对 I2S 阵列可作为可选采集架构实验，必须控制麦克风质量、同步方式、采样率和位置，不能混入处理器加速比。不要拿两只独立 USB 麦作为所有 USB 阵列的代表。

### 14.2 验收矩阵

下列数字为建议测试规模/目标，不是赛事要求或实测结果；D3 后可按设备能力调整并记录理由。

| 实验 | 方法与建议规模 | 记录指标/通过解释 |
|---|---|---|
| T1 算法一致性 | 合成时差、静音、削波、噪声与实录集合 | 定点参考一致；容差与原因事先规定 |
| T2 音频方向 | 左/中/右各 30 次；增加噪声、后方、播放和运动条件 | 正确率、UNKNOWN 率、错误有效判决率分开；初始前方安静场景目标≥85% |
| T3 通道稳定性 | 固定布置连续 30 分钟 | 样本对齐、偏移变化、丢样；无亚采样估计器不宣称<0.1 样本精度 |
| T4 视听选人 | 两人轮流、同侧多人、交叉遮挡共至少 30 轮 | 错选率与选择耗时；不能把全部 UNKNOWN 当高准确 |
| T5 观察证据 | 固定问答集合，有/无观察各跑 | 正确率、追加延迟、失败与无效转动 |
| T6 记忆 | 3—5 名自愿登记者＋陌生测试，含迟到与删除 | 重识别、错误接受、串记忆；注入用例要求零串用 |
| T7 动作故障 | 冻帧、进程暂停、重复序号、错误会话、复位、停止键各至少 10 次 | 接受/拒绝、逻辑保护时间、机械表现；无效命令不续租 |
| T8 PL/PS 比较 | 每工况 10 分钟，空闲与正常并发负载各测 | CPU、吞吐、P50/P95/P99/max；计算与端到端分列 |
| T9 同片并发 | DPU＋音频＋运动＋显示同时运行 | 无覆盖、无溢出；资源/WNS/DRC/未约束路径 |
| T10 系统恢复 | 断公网、断主机、重启、连续 60 分钟 | 实际可用功能、恢复时间、崩溃与音频错误 |

百分位采样至少 1000 个周期，注明样本数；小样本 P99 不代表长期最坏情况。报告包含原始 CSV、环境、时钟频率、算法版本、板温/负载、失效条件。加速比不包含被省略的传输时间；分别给核时间与端到端时间。

“说话到转头”拆成声学/音频窗口等待、DSP、读取融合、命令提交、PWM 更新、机械起动。ILA 可看数字内部节点，不能单独证明声学起点与机械静止；需要外部触发、录像或相应传感器。

若没有显著加速，只报告卸载、节拍或隔离方面确有的数据；若也没有收益，记录架构代价与实现学习价值，不改换“唯一必须”话术。功能、创新、性能和可复现性可准备对应证据，但最终分值取决于官方细则和实际完成度。

## 16. 可用于报告的表述

### 16.1 设计阶段摘要

雾镜 Lite 面向固定式实体交互终端，围绕多用户环境中的目标选择、观察依据过期及身份记忆串用问题，设计视听目标确认与会话绑定机制。系统拟在 KV260 PL 中实现双通道 I2S 采集、粗声源方向判决和动作约束，在 PS 中完成视觉跟踪、音视频事件关联与目标管理，使用本地主机提供多模态对话与语音服务。作品以同源算法对照、目标选择测试和故障注入评估设计收益，并分别披露硬件性能、整机交互效果和未完成部分。

### 16.2 完成后回答“为什么使用 FPGA”

我们选择 FPGA 实现直接接入的音频流处理与执行约束，使采样处理节拍、命令有效期和异常响应具备明确的硬件实现与观测点。其他处理器也能实现类似功能，因此我们用同输入的软件版本和故障测试说明本设计的实际收益。自研部分是音频处理及动作约束，DPU 属于厂商 IP 集成，大模型运行在自带主机上。

实际答辩时在这段话后填入测得结果；未完成 PL 音频时删除该成果描述。

### 16.3 不能使用的表述

- “只有 FPGA 能取得声音”“USB 数据须先由 PS 接收进 DDR、再经 DMA/AXI 交给 PL”。
- “双麦精确知道任何位置是谁在说话”“全场景不误认”。
- “整机都在 PL”“零延迟”“绝对安全”“上电立刻工作”。
- “人脸记忆就是原创算法”“写了技能文件所以必然加分”。
- “断网所有功能正常”而没有区分断公网与断主机。
- 用模拟日志、估算资源或视频剪辑冒充实际并发与上板结果。
