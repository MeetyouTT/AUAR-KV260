## 3. 关键技术决策

| 编号 | 决策 | 理由与量化依据 |
|---|---|---|
| K1 | 用 **2 只 I2S 数字麦（INMP441 类）**，不用 USB 阵列、不用 6+1 阵列板 | USB 阵列数据被 PS 侧 ALSA 取走，PL 看不到 → 违反"多路音频必须进 PL"的硬约束；6+1 板需 5 V（Pmod 只给 3.3 V）+ 9 cm 占位 + LED 电流/电平三重代价，降为后期升级 |
| K2 | **d = 4 cm 与 fs = 48 kHz 是一对绑定参数** | 分辨率 ∝ d·fs；d 受机身尺寸限制（≤5 cm）、fs 受器件上限限制（≤48 kHz）。两者相乘得到最大 lag 仅 **±5.6 样本**；若降到 16 kHz，最大 lag 仅 ±1.87 样本，**三档判不出来** → 48 kHz 是为 lag 分辨率而非音质 |
| K3 | 判档门限 **±2.4 样本（≈ ±25°）** | 2.4 样本对应 ±25.4°，与 0° 之间远大于 1 个样本的量化步长，判据宽裕；且门限可直接写入 `THRESH_DIR_Q8` 现场调整 |
| K4 | 算法 **v0 能量差（仅自检）→ v1 时域归一化互相关（目标）**，不做 FFT/GCC-PHAT | 相关仅 17 lag × 472 样本 = 8.0 k MAC/帧（0.8 MMAC/s）；相位法需 FFT 与复数，工时成倍，而**分辨率上限由 d·fs 决定，算法换不来更细的方位角** |
| K5 | **新建独立 IP `audio_doa_ip`**，不改 `motion_guard_ip` 的寄存器表与地址段 | 遵守"严禁自行修改已约定 API"；两套 IP 各自独立 AXI4-Lite 从机，PS 侧仲裁后才走既有的 `TARGET_MDEG` + `COMMIT` 流程，安全链单一入口不被破坏 |
| K6 | 时钟用**小数分频（相位累加器交替 32/33）**，不用 MMCM | 推演：MMCM 的 VCO 必须落在 800—1600 MHz，而 3.072 MHz 需要 VCO/分频比 ≥ 261 > CLKOUT 分频上限 128；12.288 MHz 也无法由 100 MHz 整数比得到 → **MMCM 单独得不到 48 kHz 家族时钟**。小数分频逐边沿抖动 ≤10 ns，对 20 kHz 满幅信号的采样误差约 −58 dB，低于麦自身噪声底 |
| K7 | 相关累加用 **48 位（DSP48 MACC）** | 最坏 472 × 32767² ≈ 2^38.9，48 位余量充足；若为省 DSP 降到 32 位累加，需把输入右移 6 位（10 位有效）才安全，右移 4 位只剩 8% 余量 → 不采用 |
| K8 | 表述纪律：**不讲"CPU 算不动"** | 全链约 4.2 MMAC/s，对 PS 侧 A53 也不构成压力。方案 D 的真实价值是：①数据只有进 PL 才拿得到（结构约束）；②时延确定（不依赖 Linux 调度）；③CPU 零占用。三条都能出数据，正好对应"性能与资源优化"档取证 |

## 4. 纠错记录（本次编写中主动发现并修正）

| 编号 | 初稿的错误说法 | 正确结论 | 处理 |
|---|---|---|---|
| E1 | "正前方附近分辨率最粗（10.2°/样本），侧向更细"、"±45° 与 ±60° 用整数 lag 区分不开" | 角分辨率 = **c / (d·fs·cosθ)**：正前方**最好**（≈10.2°/样本），随 θ 增大而变粗（±60° 附近 ≈20.5°），接近 ±90° 时 lag 几乎不再变化（**饱和**）。±45°（3.96）与 ±60°（4.85）取整后仍可分（4 与 5） | 已改写 2.3 的结论句与 2.4 的局限表（把"正前方灵敏度低"换成"侧向分辨率饱和"），并把"lag 抖动/混响"单列为一行对策 |
| E2 | 5.2 中把 WS 写成"BCLK 二分频" | WS = BCLK / 64 | 已改为"100 MHz ÷ 33 得到 BCLK，再按 /64 分出 WS"（fs = 100/33/64 = 47.35 kHz） |
| E3 | 表格单元格内用竖线包裹 lag 表示绝对值（形如 竖线+lag+竖线） | 单元格内的裸竖线会被 Markdown/docx 解析成列分隔符，破坏表格结构 | 已改为 `−2.4 < lag < +2.4`；并用正则全表扫描确认无同类问题（42 张表列数一致） |
