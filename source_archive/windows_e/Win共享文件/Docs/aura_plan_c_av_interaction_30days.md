## 共同执行约定

- 项目统一名称 AURA，历史资料中的“雾镜 Lite”指同一设备。
- 周期 D1—D30，D1 为实际开工日，不代表自然月第一天或比赛截止日。用相对天数避免写死尚未确认的日期。
- D7、D14、D21、D28 为缓冲/评审日，每人约 2 小时；其余 26 天每人约 6 小时，总计每人 164 人时，三人约 492 人时。缓冲日其余时间留给休息、加工等待和必要恢复，不预先塞入新功能。
- 正常开发日建议：2 小时实现、2 小时验证/集成、1.5 小时修复或协作、0.5 小时记录和同步。当天列出的联调已包含在工时内，不能把它额外加到晚上。
- 条件：有可用 KV260、相机、屏幕、舵机及其合适电源；双麦和 USB 音频最迟 D10 可用；有能运行选定模型的主机；复用匹配的参考平台、预训练模型和成熟界面组件。
- 本月目标是可演示、可验证的首版，研究采用 Light-ASD 基线、借鉴 Streaming ASD 的有限窗口处理、借鉴 LoCoNet 的上下文选择，以及借鉴 Neural Simplex 的执行监督。简单上下文规则不能称为完整 LoCoNet，分块处理也不能直接称为严格因果流式模型。
- YOLO 和板端身份识别仍是产品能力；ByteTrack 可作基础跟踪，完整 BoT-SORT、从零训练视听网络、全双工回声消除、第二转轴均不计入本月必做。
- 默认只优先处理当前交互区域内的少量人物，人数上限 D2 冻结；不承诺无限人数和任意环境。
- A 负责硬件集成和项目协调；B 负责视觉、板端身份及唯一运动请求软件；C 负责说话人/目标选择、语音和 UI，并维护日常启动清单。每人修复所属模块，协调人不代做全部工作。
- C 发布“建议关注的对象”；B 检查轨迹、会话和时效后计算运动请求；A 提供底层访问库和 PL 最终监督。正式运行时只能有 B 的一个运动进程写控制寄存器。
- 所有人工替代输入、回放、CPU 临时后端、主机临时身份服务都要标注，不能作为对应正式板端功能的通过证据。

### 每日记录与阻塞规则

当天在本人日志中写：实际用时、版本、完成内容、原始证据、未通过项、明日依赖。每天共同同步 15 分钟，包含在记录/协作时段。

同一阻塞连续约 2 小时没有新证据时，先收集日志、最小复现和已尝试方法，再拉对应队员协作。不能靠连续改版本、改电源或调阈值盲试。阻塞超过一个开发日，调整依赖任务并记录进度影响，不擅自取消已承诺的能力。

若 D3 无可运行平台，或 D10 无真实视觉控制闭环，30 天完整目标存在明显风险；团队须明确选择延期或缩小本月交付，不能把模拟演示改名为完成。优先守住停止、时效和原始记录，再削减外观、复杂模型改造与非必要并发。

## 本人责任与任务边界

C 主导 Light-ASD 和有限窗口服务、说话证据与粗音向融合、对话/播放/界面。B 在 D8 提供人脸片段，D17 共同承担上下文与数据整理，D26 共同做消融；A 负责声音 RTL 和监督，C 在 D12 交付其软件参考。模型适配重训练、完整 LoCoNet 复现和严格流式新网络不是本月默认交付。

### 四项研究本月怎么落地

| 方向 | 本月可验收工作 | 不能误称的内容 |
|---|---|---|
| Light-ASD | 运行预训练基线，接入带轨迹与时间的音视频，记录失败 | 不能把双麦方向当作 Light-ASD 实现 |
| Streaming ASD | 有界窗口、上下文/等待测量、过期丢弃，借鉴流式设计 | 滑动窗口不自动等于因果模型或论文完整复现 |
| LoCoNet | 与 B 做时间保持与多人候选关系，评估其收益 | 简单迟滞不是训练后的 LoCoNet 网络 |
| Neural Simplex | C 提供失效场景与上层建议，A 做独立命令监督 | 命令 guard 不自动具有论文中的完整安全证明 |

如果用户后续要求三种网络均完整复现或训练，应重新估算研究周期，不能在现有 164 人时中默认为已包含。

## 每日执行计划

### D1 主机、模型与交互范围确认

**投入：6 小时。**

- **操作：**记录主机 CPU/GPU/显存、系统、磁盘和模型框架；核对 Light-ASD 的代码、权重、许可与依赖，检查 ASR/VLM/TTS 候选。冻结按键半双工、人数上限建议及本月四项研究的实际实现层次。
- **产出：**docs/host_inventory.md；docs/research_scope.md；configs/host_model_candidates.yaml。
- **当天验收：**未训练、未部署与已跑通明确分开；没有把三个 ASD 模型同时运行设为默认。
- **三方协作：**向 A 提供 USB 音频/显示需求，向 B 提供 ASD 人脸片段和时间要求。
- **阻塞处理：**主机规格不足先选较小模型/有限候选，不未经确认购买新显卡。

### D2 模型冒烟测试与协议草案

**投入：6 小时。**

- **操作：**用固定录音验证 ASR、固定文本验证 TTS；检查 Light-ASD 环境能否加载权重并运行作者样例，下载依赖留出时间。定义 health/asr/vlm/tts/cancel 和 request_id、会话代次。
- **产出：**contracts/host_api_v1.md；report/c/model_smoke.md；configs/host_env_lock.txt。
- **当天验收：**至少明确各模型可运行/阻塞状态及日志；固定样例不是现场效果证明。
- **三方协作：**与 B 冻结图像/片段接口、候选上限；A 提供网络与设备接入方式。
- **阻塞处理：**依赖失败先最小复现，不同时升级框架/驱动/模型；研究路线无法跑通要在 D3 暴露。

### D3 板端录放音与界面骨架

**投入：6 小时。**

- **操作：**检查 USB 输入输出和屏幕是否由 KV260 实际驱动；实现录音、播放、按钮、字幕和状态展示。验证真实采样格式，需转换时真正重采样；创建 D3 环境状态清单。
- **产出：**src/board_app/audio_client.*；src/board_app/ui；report/c/device_check.md。
- **当天验收：**板端有可回放录音、实际输出和显示；电脑临时显示必须标注。
- **三方协作：**B 提供预览/帧元数据，A 确认 USB 供电与启动环境；共同 D3 评审。
- **阻塞处理：**音频硬件未到可用文件做软件验证，硬件交互仍记未通过。

### D4 对话状态机与请求归属

**投入：6 小时。**

- **操作：**实现 IDLE/RECORDING/PROCESSING/PLAYING/CANCELLED 等状态；给每轮分配 request_id 与 conversation_epoch，定义换人、超时和服务失败。用模拟响应验证重复与迟到处理。
- **产出：**src/board_app/dialogue_manager.*；tests/dialogue/state_cases；contracts/session_v1.md。
- **当天验收：**取消能立即让旧结果失效；无重复播放；主机回传 ID 不替代本地请求上下文。
- **三方协作：**B 传当前对象与会话，A 传停止/故障状态用于 UI。
- **阻塞处理：**界面先用简单布局，不花时间做复杂角色动画。

### D5 固定图片问答与模型服务

**投入：6 小时。**

- **操作：**把固定图片和问题真实送给 VLM，检查图像被加载；完成 ASR/VLM/TTS 服务接口、健康检查、超时和错误码。限制回答长度与输入大小，记录各模型耗时。
- **产出：**src/host_services/asr；src/host_services/vlm；src/host_services/tts；report/c/service_chain.md。
- **当天验收：**图文问题确实使用图片；不会只返回预设答案；格式和采样率匹配。
- **三方协作：**B 提供可靠快照接口，A 确认模型任务不影响本地控制。
- **阻塞处理：**VLM 无法运行时列出硬件/依赖原因，文件回放回答只用于 UI 测试。

### D6 按键问答与取消闭环

**投入：6 小时。**

- **操作：**接入真实按住录音、松开提交、快照、回答和播放；播放状态驱动角色/字幕。录音或播放中取消，换会话和主机断连后拒绝旧结果；默认不把自己的播音触发为新问题。
- **产出：**tests/dialogue/end_to_end；report/c/cancel_trials.csv；docs/startup_checklist.md 初版。
- **当天验收：**能完成一轮真实交互，取消不等待远端确认；界面状态来自真实音频状态。
- **三方协作：**B 检查快照时效与对象，A 确认核心控制不等待对话。
- **阻塞处理：**响应慢先限制输入/回答并定位瓶颈，不伪造即时回答。

### D7 缓冲与交互基线评审（2 小时）

**投入：2 小时。**

- **操作：**参加三方评审，演示已有链路和未就绪模型。确认 D8 使用 B 的人脸片段，D10 全系统的 UI/记录准备；收敛接口变更。
- **产出：**report/c/week01_review.md；更新 startup_checklist.md。
- **当天验收：**各服务启动和错误行为清楚；Light-ASD 权重/依赖阻塞不能延后隐藏。
- **三方协作：**与 A/B 排定板卡、相机、屏幕使用时段。
- **阻塞处理：**不新增唤醒、全双工或复杂动效；缓冲留给恢复与休息。

### D8 构建离线视听样本与 Light-ASD 输入

**投入：6 小时。**

- **操作：**接收 B 的带时间人脸片段和人物编号，组织对应音频；先用已知对齐的录制材料跑基线。检查裁剪、帧率、音频重采样、缺脸、片段长度和模型时间上下文。
- **产出：**src/host_services/asd/preprocess.*；data/av/baseline_samples；report/c/asd_input_contract.md。
- **当天验收：**模型输入可追溯到具体人物/时间段；口型片段不是单张静态脸重复拼接。
- **三方协作：**B 负责片段归属和裁剪，A 提供双麦格式但本日不依赖其真实 DOA。
- **阻塞处理：**同步未确认的实时素材只用于诊断，不作准确率验收。

### D9 Light-ASD 离线基线与失败记录

**投入：6 小时。**

- **操作：**在轮流说话、静音、同侧两人等片段运行基础模型；保存逐人逐时段分数、原始时间、标签和耗时。记录原模型是否使用未来上下文，不把离线准确率称为实时效果。
- **产出：**src/host_services/asd/baseline_runner.*；report/c/asd_baseline.csv；data/av/failure_cases。
- **当天验收：**说话分数与人物编号对应；能够展示正确和失败案例；采样/对齐条件明确。
- **三方协作：**B 复核人物标注并预留上下文评估数据；A 获得相应事件时间线。
- **阻塞处理：**如果模型仍无法跑通，优先解决依赖并通报排期；双麦替代不等于该研究项完成。

### D10 首次整机随动配合与日志统一

**投入：6 小时。**

- **操作：**参加 A/B 的 G10 小范围视觉随动，显示目标、硬件许可和故障，不让 UI 决定运动。将录音/问答/相机/控制事件汇入统一记录；完成音频参考程序接口草案。
- **产出：**report/integration/g10_follow.md；contracts/event_log_v1.md；src/reference/audio_reference.py 草案。
- **当天验收：**实际状态与界面一致；主机推理忙时本地停止不被阻塞。
- **三方协作：**A 测硬件，B 管控制；C 录像与事件记录并发布启动顺序。
- **阻塞处理：**不在尚未通过 G10 时接自动说话人转向；先保留显示结果模式。

### D11 有限窗口和流式调度原型

**投入：6 小时。**

- **操作：**围绕基础 ASD 建立有界音视频缓存、窗口长度、步长、返回事件和候选配额。测窗口等待/计算/传输总延迟；双向模型需标明决策对应的过去时刻与未来帧等待。
- **产出：**src/host_services/asd/window_scheduler.*；configs/asd_windows.yaml；report/c/streaming_definition.md。
- **当天验收：**缓存不会持续增长；“分块推理”与“严格因果流式模型”区分；重叠窗口不重复触发动作。
- **三方协作：**B 确认视频采样和片段时间；A 提供后续硬件事件字段。
- **阻塞处理：**不承诺剪掉双向层即可保持精度；需要再训练的结构变化列下一阶段。

### D12 音频黄金参考与窗口延迟实验

**投入：6 小时。**

- **操作：**给 A 交付短窗时域相关参考、位宽/缩放、共同有效索引、峰值与质量定义，包含人工已知延迟、静音、噪声和极值。用可用 PCM 检查格式；同时跑少量窗口长度/步长对照。
- **产出：**src/reference/xcorr_reference.py；data/audio/golden_vectors；report/c/window_latency.csv。
- **当天验收：**黄金数据可重复，软件和 RTL 输入口径一致；窗口越长的等待成本进入统计。
- **三方协作：**A 在 D15 使用这些参考；B 提供真实帧时间验证窗口映射。
- **阻塞处理：**当日真实 PCM 尚未交付则先交合成测试向量，D13 补实录，绝不标合成为实测。

### D13 音视频同步与目标保持策略

**投入：6 小时。**

- **操作：**与 A/B 录制可见/可听同步事件，估计 USB 音频、图像和 I2S 方向事件的偏移及漂移。实现当前对象保持、候选连续确认、冲突拒判和换人取消，不宣称已复现 LoCoNet 网络。
- **产出：**docs/av_time_alignment.md；src/host_services/asd/context_policy.* 初版；data/av/sync_trials。
- **当天验收：**偏移估计有方法/误差范围；规则参数与模型分数分开；播放时不盲目选自播音。
- **三方协作：**A 提供样本编号与实际采样率，B 提供镜头时间和轨迹。
- **阻塞处理：**对齐不可靠时只做离线基线，自动实时切换保持禁用并列阻塞。

**投入：6 小时。**

- **操作：**接入 B 的有限人脸片段和板端 USB 音频环形缓存，只在明确交互会话中运行 ASD。传递 boot/session/track 与窗口时间，限制队列与候选数量；处理缺脸、缺音和网络异常。
- **产出：**src/board_app/av_stream_client.*；src/host_services/asd/live_service.*；contracts/asd_v1.md。
- **当天验收：**可从实时输入返回可追溯的逐人证据；静态快照接口不冒充连续视听输入。
- **三方协作：**B 提供片段并确保身份任务不抢完计算，A 保持控制独立。
- **阻塞处理：**网络/负载不足先降低已声明的人数与更新率，不省略时间归属。

### D16 ASD 负载与过期结果控制

**投入：6 小时。**

- **操作：**测实时窗口等待、排队、主机计算和回传，限制同一轨迹重复任务。返回明确决策时段和质量；结果过旧、会话变化或目标消失时丢弃。测试 VLM 与 ASD 同机竞争。
- **产出：**report/c/asd_live_latency.csv；configs/host_scheduler.yaml。
- **当天验收：**主机忙时有明确排队/拒绝，结果不因新包装而变新；有限内存得到验证。
- **三方协作：**B 记录板端帧龄与轨迹状态，A 验证许可计数不受主机负载影响。
- **阻塞处理：**算力不足可暂停非必要问答期间的自动切换并明示状态；不是静默使用旧结果。

### D17 与 B 共同加入上下文选择

**投入：6 小时。**

- **操作：**在固定测试片段上比较单时刻分数、时间保持/迟滞、加入多人竞争关系的策略。B 负责轨迹连续性，C 负责说话证据聚合与切换；保存阈值依据和失败情况。
- **产出：**src/host_services/asd/context_policy.*；report/c/context_ablation_pilot.csv。
- **当天验收：**只对已实现策略命名，简单规则不写成完整 LoCoNet；同时记录错选、拒判与等待。
- **三方协作：**与 B 共用固定回放，不各自调不同版本；向 A 说明切换会话事件。
- **阻塞处理：**收益不明显时保留基线并报告，不为凑创新强行启用更差策略。

### D18 声音方向融合与对象建议发布

**投入：6 小时。**

- **产出：**src/board_app/target_selector.*；report/integration/g18；configs/fusion_rules.yaml。
- **当天验收：**同侧多人/冲突可拒判，发声不等于必然在与设备交流；只在规定会话触发切换。
- **三方协作：**A 提供真实 DOA 标定，B 验证轨迹与运动许可；共同 G18。
- **阻塞处理：**方向模块未通过不能伪造高质量方向；可以记录缺失并单独评估 ASD，融合项未通过。

### D19 界面、登记与真实播放状态整合

**投入：6 小时。**

- **操作：**接 B 的身份登记/删除/UNKNOWN 流程；屏幕显示当前对象、听/想/说及降级状态。动画跟随实际录音/播放；自播音期间融合采用已定义屏蔽或降权，取消立即停止输出。
- **产出：**src/board_app/ui 完整初版；tests/ui_identity_audio；report/c/interaction_states.md。
- **当天验收：**名字、字幕和会话一致；登记需要明确确认；播放失败不继续显示正在说话。
- **三方协作：**B 核对身份归属，A 提供 STOP/FAULT 状态。
- **阻塞处理：**界面装饰让位于状态正确性，不新增复杂口型或全双工。

### D20 断连、换人和取消故障测试

**投入：6 小时。**

- **操作：**注入 Windows 服务关闭、网络超时、重复响应、换人、图像过旧与取消后迟到音频。保持本地身份/视觉能力真实可用时的降级显示；统一开机启动与健康检查。
- **产出：**tests/communication/fault_cases；report/c/network_cancel_results.csv；docs/startup_checklist.md。
- **当天验收：**取消先在本地生效；重连不重播旧回答；过期场景回答有正确时态或被丢弃。
- **三方协作：**B 校验对象/图像，A 校验核心控制不依赖远程服务。
- **阻塞处理：**不以自动重试无限堆请求；连续失败明确进入降级。

### D21 完整功能评审（2 小时）

**投入：2 小时。**

- **操作：**按共同清单主持一轮完整演示并记录版本、通过项、失败与限制。确认四项研究落地层次：ASD 基线、窗口处理、上下文规则、硬件监督；分派修复。
- **产出：**report/integration/g21_checklist.md；C 缺陷清单。
- **当天验收：**所有演示都标实际运行位置，主机依赖与板端独立能力说明准确。
- **三方协作：**A/B 现场核对各自结果；固定 D24 功能冻结范围。
- **阻塞处理：**核心缺项不能靠预录音或脚本提示替代后勾选完成。

### D22 同步、阈值与主机资源优化

**投入：6 小时。**

- **操作：**与 B 细化音视频偏移/漂移和窗口时效，测主机多模型内存及排队。对 ASD 候选更新、VLM 输入/输出长度、TTS 启动与 UI 刷新做少量有对照优化。

- **当天验收：**每次优化有前后相同输入对比；不能用消除困难场景提高表面成功率。
- **三方协作：**A 评估转动噪声和播音，B 提供裁剪/缓存统计。
- **阻塞处理：**模型结构大改或重新训练不在本日引入；超预算就明确降级规则。

### D23 关闭交互与研究链阻塞缺陷

**投入：6 小时。**

- **操作：**修复串会话、取消后重播、音视频不配对、队列泄漏和界面假状态。整理错误码、人可理解的提示与恢复步骤；回归最关键的几条失败场景。
- **产出：**report/c/defect_closure.md；tests/integration/regression_cases。
- **当天验收：**严重归属与取消错误得到验证修复；未达性能不藏起来。
- **三方协作：**A/B 在同一候选版本配合复测，接口变化同步到契约。
- **阻塞处理：**不新增外观或云功能；复杂问题回退稳定实现并标记限制。

### D24 交互、算法与部署冻结

**投入：6 小时。**

- **三方协作：**与 A/B 共同功能冻结，后续只修缺陷并编号。

- **三方协作：**B 复核人物真值，A 提供声音与控制状态。

### D26 消融与跨模块故障实验

**投入：6 小时。**

### D27 整机长测与冷启动记录

- **三方协作：**A 看电气/温度，B 看内存/推理，C 看交互/服务。

- **三方协作：**A/B 交付硬件与视觉章节，C 汇总但不替他人编造结果。
