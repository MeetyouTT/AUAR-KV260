## 1. 结论摘要（先看这一页）

### 1.1 赛道选择

三名大三本科生 → **初级组**（报名资格为大一至大三在读本科生；混合队伍按最高学历归组，本队不涉及）。
KV260 的 K26 是 **Zynq UltraScale+ MPSoC**，落在初级组允许的器件范围内 → **合规**。
建议提交材料中直接写明器件型号（如 `XCK26` / `Zynq UltraScale+ MPSoC`），避免评委对组别适用性产生歧义。

### 1.2 三种赛道的门槛（为什么只剩 3.3 可选）

| 赛道 | 硬门槛 | 本队条件 | 结论 |
|---|---|---|---|
| 3.1 RTL/HLS 本地智能体 | 需 AMD **Radeon** 显卡 + **ROCm 7.14.0+**；模型须装入单张 32 GB 卡 | RTX 5090 Laptop（NVIDIA） | 不可行 |
| 3.2 具身智能 | 上位机**必须是 AMD Ryzen AI PC**，软件栈 ROCm 7.14.0+；借用机器仅 10 台且需 10/9 中期报告评审 | 无 AMD AI PC | 不可行 |
| **3.3 自主选题（初级组）** | 器件落在 7 Series / Zynq-7000 / UltraScale(+)；工具 Vivado/Vitis 2026.1（推荐）或 2025.2；**对"主机"无任何要求** | K26 合规；主机可用现有 Windows/GPU 机器 | **唯一可行** |

**重要推论：** 3.3 赛道不规定上位机。因此现有 Windows + GPU 主机在本赛道是**合法资源**（不违规、不扣分、不需要 ROCm），只需在报告中**如实披露算力位置**，并把"板卡自身"的性能与功耗数据单独统计。这一条显著降低了成本压力；代价是评委不会为该主机加分，只会盯着 KV260 上做了什么。

### 1.3 切合性的真实图景

> 本作品与 3.3 初级组的匹配度是"中高"，但**当前方案的叙事重心放错了位置**：它讲的是一个"AI 应用故事"，而 3.3 初级组要看的是一个"FPGA 作品故事"。改叙事比重构功能便宜得多。

判断依据（指南 3.3 原文口径）：

- 初级组考察侧重：「**逻辑设计、状态机、时序约束、接口协议等基本 FPGA 设计能力**」；
- 选题要求：「应用方向不限…**鼓励综合考虑软硬件协同，充分发挥器件整体性能**」；
- 考察重点：「功能是否正确、设计是否经过实测验证、性能与资源数据是否真实完整、**他人能否复现**」。

**含义：** 初级组要的不是"加速器多厉害"，而是"**基本功扎不扎实、数据真不真、能不能复现**"。本队已有的工程资产（10 态状态机、三层校验、173 组正反例、环境标签纪律、md+docx 成对文档、Gate 报告）恰好就是评分要的东西；反而"塞进一个大模型"在初级组并不值钱。

### 1.4 五个评分档的现状判断

| 评分项 | 权重 | 判断 | 一句话 |
|---|---:|---|---|
| 创新性与应用价值 | 30 | 浮动 | 靠"实体交互 + 安全确定性论证"得分，不能靠"用了大模型" |
| 性能与资源优化效果 | 20 | **短板** | 只有一条构想中的对比，且零板端数据 |
| 功能正确性与设计完整性 | 20 | 设计强、证据缺 | 设计质量高于多数学生作品，但全部为 PC/SIMULATED |
| 大模型协作与技能包 | 15 | **优势** | 素材已攒了大半，只需重组形态 |
| 文档质量与可复现性 | 15 | 习惯优势 | 有硬件复现门槛，需提供无板 mock 路径 |

**结论：10 月 9 日与 3.3 自主选题赛道无关。本队材料中"10 月 9 日"是自己的内部里程碑。**

|---|---|---|

| 5 | 本队材料（`FPGA语音助手开发/` 全部 md + docx 正文表格） | `10/9` 的全部命中都是**内部里程碑 GD 板端视觉闭环**（见 `31日计划安排/README.md:69`、`11_板卡延期调整计划.md:87`、`10_历史问题审查与残留项跟进.md:60`）；而同一批材料对真正截止日的原话是「竞赛截止/提交在 **10 月中下旬或更晚**」（`11_板卡延期调整计划.md:4`），"作品提交截止时间"在宣讲记录中的状态为**待确认** |

**尚无法确认的部分（必须去官方渠道取）：** 官方站点 `fpgachina.cn` 为 JS 渲染页面，程序化抓取只能得到标题，无法取得最新报名/提交时间表。因此：

- 可以确定：**指南层面 10 月 9 日与 3.3 无关**；
- 不能确定：**本赛道实际提交截止日**（"10 月中下旬或更晚"只是本队旧文档的推断）。

**影响：** 若截止确实在 10 月中下旬或更晚，则板卡提前到货（预计 3 天后）意味着硬件可用窗口比原排期多约 2 周，属于**重大利好**；若存在某个官方硬截止（例如 10 月上旬），则须当场砍范围。这是本方案唯一"两个排期相差 2 倍工作量"的输入项。

### 3.3 三条必须写进报告的事实

1. 现有全部成果为 **PC / SIMULATED**，**没有任何板端实测**；转为板端后必须重新取证，不能沿用。
2. 原方案产品定义为「固定式多模态桌面智能交互终端（**无转轴**）」；AMD 版计划新增了水平转轴 + 舵机 + 独立供电 + 机构件，属于**范围新增**（见第 7 节）。

## 4. 概念说明（概念词典）

> 每个概念的写法：白话解释 → 在本项目里的位置 → 为什么影响评分。

### 4.1 评分机制类

**完整 FPGA 作品**
白话：在 3.3 里，"作品"= 一套**能被别人重建的硬件工程**，而不只是"一台能演示的机器"。指南要求工程包内含完整源码、仿真/验证结果、综合与实现报告、上板工程与实测输出、可复现构建脚本。
位置：本队需要从零建立 KV260 工程与构建脚本。
影响：很多队伍把机器做出来但工程不可重建，于是"可复现"15 分拿不到、"完整性"20 分只拿一半。

**可测量的证据**
白话：能被复测的数字，附原始日志、报告分位数与测量条件；"能跑""很流畅""很快"都不算证据。
位置：现有 `evidence_shots/`、`pytest`、`validator_cases_report.json` 是雏形。
影响：直接对应 20 分与 15 分两档。

**同源对比（baseline 与增益）**
白话：基线是参照组；"同源"指同一模型、同一输入、同一阈值、同一预处理，**只换执行后端**。只有同源，差异才能归因于硬件。
位置：本队计划中的 `detector_cpu.py` 与 `detector_dpu.py` 就是同源双后端设计。
影响：**20 分档的命门。**若不是同源对比，这 20 分基本作废。指南明确要求"若只能获得不同模型的结果，写成'两个系统配置比较'"，不能写加速比。

**证据的环境标签**
白话：给每条结论标注它是在什么环境得到的，防止把仿真结果当实测结果。
位置：本队已有 `PC / SIMULATED / BOARD_REQUIRED` 约定，本文新增 `ESTIMATE`（估算）。
影响：这是"数据真实完整"的直接体现，属于低成本的加分项。

**技能包 Skill**
白话：把与 AI 协作沉淀的经验显式写出来供他人复用，指南分四类：提示词工作流、案例模板、校验脚本、踩坑清单。
位置：本队的 `tools/` 脚本、技术记录踩坑章节、GPT 提示词包分别对应后三类的前两类。
影响：15 分档 + 通用 PYNQ Skill 额外加分；评价标准只有一条——"一支陌生队伍拿到该目录，能否直接用在自己的题目上"。

**通用 PYNQ Skill（加分项）**
白话：面向 PYNQ 框架、且**不与本队题目绑定**（换题目、换板卡仍可用）的技能包，指南单独加分；示例包括"通用的 Overlay 加载与校验流程""寄存器映射使用范式""**从接口契约自动生成主机侧调用代码或测试骨架的脚本**""**黄金参考比对、性能与资源数据自动采集并生成报告的工具**"。
位置：本队"契约驱动"的脚本（从合同生成资源表与 C 头文件、从用例集生成校验报告）天然属于这一类。
影响：属于可争取的额外加分，改造成本低于新建。
**可复现性**
白话：他人从零能够重建并跑出主要结果；这也是"别人能不能相信你"的唯一检验。
位置：本队的文档习惯很好，但作品的**硬件复现门槛高**（KV260 + 舵机机构 + 面板 + 主机 + 模型权重）。
影响：必须提供**无硬件的 mock 运行路径**（"没有板卡也能跑通软件链"），本队已有 MockBoard 与 Adapter，属现成优势。

### 4.2 器件与运行位置

**PS / PL**
白话：Zynq 类芯片内部有两半：PS 是 ARM 处理器（跑 Linux），PL 是可编程逻辑（"FPGA 部分"）。
位置：PS 跑采集 / 跟踪 / UI / 对话编排；PL 放 DPU 与自研 RTL。

**SOM / 载板**
白话：KV260 = K26 SOM（核心板，含 XCK26 + 4GB DDR4）+ 视觉载板（接口板）。常说的"KV260"指整套。
位置：整机集成、散热、接口、线束都要按实物核对。

**DPU（Deep Learning Processing Unit）**
白话：AMD 官方定义是"面向深度学习推理的软核加速器"，由 PL 中的 **DSP / BlockRAM / UltraRAM / LUT / FF** 构成，并拥有自己的指令集；模型由 Vitis AI 编译器编译成 `.xmodel` 后在 DPU 上执行。
位置：本队的人体检测加速。
影响：**关键概念**——DPU 是配置在 PL 里的一段电路，**不是独立芯片、不是 Versal 的 AI Engine**。因此它与自研转轴 IP **共用同一片 PL 资源**，LUT / FF / BRAM / DSP / 时钟 / 带宽必须合并核算。

**DPUCZDX8G 与配置后缀**
白话：`DPUCZDX8G` 是 Vitis AI 面向 Zynq UltraScale+ 的 DPU 配置名（官方命名表：Zynq UltraScale+ MPSoC → DPUCZDX8G；Versal AI Core → DPUCVDX8G / H）；后缀如 B4096 / B3136 表示**并行度等级**，等级越高算力越强、占用 DSP / BRAM 越多（具体数值以 DPU IP 产品指南 PG338 为准）。
位置：需选定一个配置档，并写入版本锁文件。

**模型 fingerprint**
白话：编译模型时会绑定目标 DPU 架构的"指纹"；**改了 DPU 配置就必须重编译模型**，不能沿用旧 `.xmodel`。
影响：这是"DPU 与自研 IP 共存"调试中最容易踩的坑之一，也是可写入技能包的踩坑清单。

**位流 / Overlay**
白话：位流是 PL 的配置数据；Overlay 是 PYNQ 语境下"PL 电路 + 对应软件接口"的封装包。在 KV260 上通常还需要配套的设备树 overlay 与运行包。
位置：本队要产出可重建的工程与加载脚本。

**局部重配置（DFX）**
白话：只替换 PL 的一部分电路，其余继续运行。
影响：**本队不得用"先加载 DPU 位流、再加载转轴位流"来演示共存**——那是全片覆盖，等于替换了整个设计。指南要求作品功能同时成立，交替加载不算共存（本队计划文档已明确禁止）。
### 4.3 总线与接口

**AXI4-Lite**
白话：ARM 访问 PL 里寄存器的总线协议；等价于"CPU 读写某个地址就能配置硬件"。
位置：自研 `axi_motion_regs`。这直接对应初级组要考的"**接口协议**"能力。

**AXI4-Stream**
白话：传数据流（像素、音频）的高速通道，没有地址概念。
位置：若做图像预处理或玩偶帧流搬运会用到。

**寄存器映射 register_map**
白话：一张"哪个地址偏移是什么含义"的表。
位置：本队已有完整草案（`id_version` / `control` / `target_angle` / `command_seq` / `heartbeat` / `status` / `fault_latch` / `recovery_request` / `commanded_angle` / `applied_seq` / `safety_epoch` / 时间戳高低位）。这是极好的 Skill 素材。

**影子寄存器 + 原子提交**
白话：多个字段先写入"草稿区"，最后写一个 `command_seq` 才整体生效，避免读到半成品。
位置：本队已设计。

**UIO / MMIO**
白话：UIO 是 Linux 的"用户态直接访问硬件"机制；MMIO 是把硬件寄存器映射到内存地址。
位置：这是板端软件能调用自研 RTL 的必要通路，必须在平台阶段打通。

### 4.4 时序与资源（初级组明确考察项）

**时序约束（XDC）**
白话：告诉工具"时钟频率是多少、引脚在哪里、哪些路径可以放松"。约束写错，后面所有结果都不可信。

**时序收敛 / WNS / TNS**
白话：收敛 = 所有信号都能按时到达。**WNS**（最差负裕量）为负表示未收敛。综合与实现报告里必须给出。
影响：20 分档的直接证据。

**LUT / FF / BRAM / DSP**
白话：PL 的四种"原料"：查找表、触发器、片上 RAM、乘法单元。报告要列占用率。
影响：指南 3.3.5.1 点名要求。

**跨时钟域（CDC）**
白话：两个不同频率时钟之间传信号必须加同步结构，否则偶发错误。
位置：本队"读时间戳低位时锁存高位"的设计就属于这类细节——**写进报告就是基本功的证据**。
### 4.5 控制与安全（本队差异化强项，建议重点读）

**确定性 determinism**
白话：同样输入 → 同样时间 → 同样输出。Linux 做不到（会被调度打断），PL 可以。
位置/影响：这是"为什么这件事必须由 FPGA 做"的核心论证，直接支撑 30 分的技术差异化与 20 分的优化效果。

**抖动 jitter 与 P99**
白话：抖动 = 实际周期与理想周期的偏差；P99 = 把 100 次里的最差 1 次拿出来看。**不能只用平均值**。
位置：软件定时 GPIO 与 PL PWM 的固有抖动通常相差几个数量级。
影响：这是"性能与资源优化效果"最直观、最易被评委接受的证据。

**PWM（脉宽调制）**
白话：用方波占空比表达舵机角度的信号，常见 50 Hz、脉宽 1—2 ms。
注意：`50 Hz / 1—2 ms / 180°` **不是所有舵机的通用参数**，必须按实物数据手册标定。

**看门狗 watchdog**
白话：软件必须定期"喂狗"；一旦不喂（进程死了、卡住了、被调度饿死），硬件自动进安全态。
位置：本队设计阈值 300 ms（初值，需实测冻结）。

**租约 lease**
白话：命令的"有效期"。过期命令作废，防止用旧画面驱动转轴。
位置：本队设计 200 ms（起点值，提交时租约不得超过该帧的剩余有效期）。

**故障锁存 fault latch**
白话：一旦出故障就把标志"焊死"，必须人工确认才能恢复，防止自动重启后失控。

**安全代次 safety_epoch**
白话：每次故障后"代次 +1"，旧代次的命令一律被拒绝。
说明：这是成熟的工业思路，写进报告能显著提升"工程水平"观感。

**限幅 / 限速（slew limiter）与死区（deadzone）**
白话：限幅限制单步指令变化量，防突跳；死区让目标在画面中心附近时不动作，防左右抖动。

**One Euro Filter**
白话：自适应低通滤波——目标慢动时强滤波（稳），快动时弱滤波（跟得上），比固定 EMA 更适合"静止时稳、移动时跟得上"的转向任务。

**必须澄清的一个误区**
"停止 PWM"**不等于**"舵机断力或立即停止"。如需切断扭矩，必须有经验证的硬件使能或电源门，不能只靠软件假设。急停要分别测量"输入到控制信号安全"与"机械真正停下"两个时间，二者不可等同。

### 4.6 视觉与显示

**检测 / 跟踪 / 身份（三个不同层次）**
白话：检测 = 找出画面里有人；跟踪 = 连续帧里认出"还是同一个人"（短时，`track_id`）；身份 = 跨离开返回认出"这是小林"（持久，`person_id`）。
位置/影响：本队已严格区分三者；**track_id 与 person_id 不等价**，混用会导致"把姓名错绑到下一个人"，属于必须写清的实现细节。

**letterbox**
白话：缩放图像时保持长宽比并在空白处补边；算坐标时必须"还原"回原图坐标。

**RGB565 / R5G6B5**
白话：每像素 16 位的颜色格式（红 5 位、绿 6 位、蓝 5 位），比 RGB888 省一半内存。
位置：本队玩偶帧流即采用大端 R5G6B5。

**双缓冲**
白话：前后两块画布交替使用，一块给显示、一块给绘制，避免"画一半被看到"。
位置：本队实测双缓冲占用 0.894 MB —— 属极小开销，可作为"设计克制"的证据。

**取景 / LOD**
白话：取景 = 素材裁切范围（本队锁定"腰部以上"p=0.58）；LOD = 分辨率档位。
位置：`avatar_lod.py` 与 `ui_spec` 合同，且取景在**入库阶段**完成（保证"素材即产物"的可复现性）。

### 4.7 语音

**KWS / VAD / ASR / TTS / AEC / 全双工**

| 概念 | 白话 | 备注 |
|---|---|---|
| KWS | 关键词唤醒（如"雾镜暂停"），轻量，可放板卡 CPU | 本队已有 3.3M 中文模型 |
| VAD | 判断"人有没有在说话" | 后续阶段 |
| ASR / TTS | 语音转文字 / 文字转语音 | 本队规划 sherpa-onnx 路线 |
| AEC | 回声消除，避免扬声器声音被自己的麦克风听到 | 本队 V2.0 已正确排除，第一版采用"按键说话"是明智取舍 |
| 全双工 | 边说边听、可打断 | **USB 声卡"支持同录同放"只是硬件能力，不等于实现了全双工** |

### 4.8 AI 工程

**量化（INT8）与校准集**
白话：把模型权重从浮点压成 8 位整数，速度快、体积小，但会掉精度；校准集是用于"标定量化范围"的一小批有代表性图像。
影响：指南要求**把量化带来的精度损失单独报告，不能混进"硬件加速"的功劳里**。

**golden 参考**
白话：一份"标准答案"（典型输入 + 期望输出），每次改动后自动比对，防止改坏了没发现。

**哈希（SHA256）**
白话：文件指纹，用来证明"提交的模型与报告里说的是同一个"。

## 5. 五个评分档逐档分析

### 5.1 创新性与应用价值（30 分）

**评委在看什么：** 解决什么真实问题、前人做过什么、有没有完整可展示的场景。
**本队现有：** 真实产品形态；真实玩偶素材资产（去背、统一取景、跨素材一致性核验）；清晰场景故事（看人 → 面向人 → 按键提问 → 看图回答 → 记住我）。
**缺口：** 报告缺少"前人做过什么、我们哪里不同"的论证（指南 3.3.5.3 明确要求此项）；"会转头会说话的玩偶"题材常见，必须给出差异化论点。
**建议论点：** 往届与同类作品普遍是"软件闭环 + 执行器直连"；本作品的不同在于**把"安全性"和"确定性"做成硬件责任**——停止、超时、指令时效、故障锁存全部由 PL 承担，并用故障注入实验证明"PS 进程被杀 / 视频停帧 / 网络断开"时设备仍进入可预测的安全状态；同时用同源对比量化"哪些事必须由 PL 做"。
**为什么这条更有用：** 它把"安全 + 确定性"变成创新点，而不是把"用了大模型"当创新（后者在初级组并不稀缺）。
**要交付的证据：** 场景需求说明、完整演示录像、与"固定摄像头/纯语音方案"的任务对比。

### 5.2 性能与资源优化效果（20 分）—— 最大短板

**评委在看什么：** 优化前后对比表、综合与实现报告、数据是否真实完整。
**本队现状：** 仅一条构想中的"软件输出时序 vs FPGA PWM"；零板端数据。
**必须补的三份对比（按优先级）：**

| # | 对比 | "同源"的口径 | 产出证据 |
|---|---|---|---|
| 1 | 同源模型 CPU vs DPU | 同模型、同图、同阈值、同后处理，只换后端 | 模型内耗时、搬运、后处理、总 FPS、帧龄、CPU 占用；原始 CSV |
| 2 | 软件定时 GPIO vs PL PWM | 同周期（如 50 Hz）、同脉宽命令序列，只换输出实现 | 各不少于 1000 周期的抖动分布、P99、最大值；示波器或逻辑分析仪截图 |
| 3 | 玩偶合成 CPU vs PL（条件触发） | 同帧流、同几何宏（`avatar_board_manifest.json` 已量化） | 帧率、像素率、PL 资源占用、DDR 带宽 |

**必须配套报告的数据：** DPU 与自研逻辑各自的 LUT / FF / BRAM / DSP、时钟频率、WNS / TNS、资源余量；以及"空闲 / 仅视觉 / 仅转动 / 视觉+语音+转动"四种工况的功耗，并**明确统计范围是板卡还是整机**（主机与云端算力不得计入）。

### 5.3 功能正确性与设计完整性（20 分）—— 隐藏强项

**评委在看什么：** 是否形成闭环、异常是否被处理、有没有仿真与上板证据。
**本队已有（设计层）：** 有界事件总线、10 态 FSM、三层校验、Adapter 超时与旧响应拒绝、MockBoard 故障注入。
**缺口：** 无任何板端实测；转轴安全链只有设计，没有 RTL 与波形。
**要产出的证据链：**

1. RTL 仿真覆盖：正常 / 边界 / 越界 / 超时 / 重复序号 / 复位 / 停止 / 恢复，每项留波形；
2. 上板真实波形：PWM 周期、脉宽、停止输出；
3. 故障注入矩阵：杀 PS 进程、视频停帧、网络断开、重放旧序号、越界命令，每类不少于 10 次，**全部进入规定状态**；
4. 一条端到端完整流程的 20 轮统计与录像。

### 5.4 大模型协作与技能包（15 分）—— 优势项

**评委在看什么：** 协作记录是否真实（有没有"自我纠错轨迹"）、Skill 是否可迁移。
**本队已有：** 提示词包与交付物文档、十几篇技术记录（含踩坑章节）、四类脚本。
**只需做"形态重组"：** 从"交付物 / 提示词包"改成案例格式 —— 问题背景 → 提示词 → 模型原始回答 → 人工判断 → 错误与修正 → 实测结果 → 可复用结论。
**额外加分路径：** 把契约驱动的脚本改造为**与题目解耦**的通用工具（换题、换板卡仍可用），去够"通用 PYNQ Skill 单独加分"。

### 5.5 文档质量与可复现性（15 分）—— 习惯优势

**本队已有：** md+docx 成对、ADR、Gate 报告、一致性清单、命名规范。

| 玩偶显示（复用现成 Qt/LVGL 路径） | 20—30 h | 高（观感 + 应用价值 30 分） |
| 对话链（板端 ASR/TTS + 主机 LLM + 编排与取消） | 50—70 h | 中高（创新性主力） |
| 结构 / 机构装配 + 独立供电 | 20—30 h | 中（机械件为风险点） |
| 身份记忆（登记 / 重识别 / unknown / 删除） | 30—40 h | 低（工时高、演示价值中等） |
| 玩偶帧流 PL 合成 / 缩放 | 40—60 h | 高但**风险最高**（时序 / 带宽 / 资源三挤） |
| 证据、报告、复现、英文海报、协作记录整理 | 30—40 h | 必做（与 45 分直接相关） |
| **合计** | **280—400 h** | 已超过可用产能，且前 3 天受限 |

**结论：全量必崩，必须裁剪。**

### 7.3 建议的三档裁剪方案

| 档位 | 保留内容 | 放弃内容 | 适配情形 |
|---|---|---|---|
| **A 保守档** | 玩偶显示 + 对话（板端 ASR/TTS + 主机 LLM）+ DPU 集成与同源对比 + 证据与文档 | 转轴与机构、身份记忆、玩偶 PL 合成、自动唤醒 | 截止日很早（例如 10 月上旬）时采用 |
| **B 推荐档** | A 档 + **转轴确定性安全链** + 故障注入矩阵 + 玩偶 PL 合成（条件触发） | 身份记忆整块、自动唤醒 / 全双工 / AEC | 截止在 10 月中下旬或更晚 |
| **C 激进档** | B 档 + 身份记忆（单人登记 + unknown） + 玩偶 PL 合成必做 | — | 截止更晚且人力有冗余时 |

**推荐采用 B 档，理由：** 转轴安全链是"自研 RTL + 可测量对比"的唯一稳定来源，砍掉它会直接损失 20 分档的大部分证据；而身份记忆工时高、演示价值中等，且旧方案本来就把它放在主机侧，砍掉不损伤 FPGA 主线。

### 7.4 条件触发规则（避免尾期失控）

玩偶帧流的 PL 合成 / 缩放，**只有在"安全链已上板验证、时序收敛且资源有余量"时才启动**；否则作为"未来工作"如实写入报告。比强行做完再崩要好。

### 9.1 指南 PDF 的日期核验

思路：把 PDF 逐页提取为带页码标记的纯文本，再按页检索"月/日/截止/赛程/报名/决赛"等关键词。

```python
# 依赖：pypdf
from pypdf import PdfReader
reader = PdfReader("…/全国大学生嵌入式芯片与系统设计竞赛'2026FPGA赛道选题指南-AMD.pdf")
for index, page in enumerate(reader.pages, 1):
    text = page.extract_text() or ""
    print("<<<PAGE %d>>>" % index)
    print(text)
```

核验结果：

- `2026 年 10 月 9 日` 仅出现在 **P15 / P20 / P26**，均属 3.2 具身智能赛道（AI PC 借用申请、3.2.6 赛程安排、4.2 支持申请）；
- 3.3 自主选题赛道 3.3.6（**P25**）与「六、其它」（**P28**）均为"以大赛官方公布为准"；
- 逐页字符数：28 页全部有 400—4000 字可提取文本（P1 封面 42 字、P28 为 212 字；仅 P5 / P6 各含 1 张板卡照片）→ 排除"时间表被做成图片"的漏检可能。

### 9.2 本队材料的日期溯源

思路：遍历项目全部 md / txt 与 docx 正文及表格，检索 `10月9日` / `10/9` / `截止` / `报名截止` / `作品提交` / `官方公布` / `赛程`。

```python
# 依赖：python-docx
from docx import Document
import os, re
ROOT = r"…\FPGA语音助手开发"
PAT = re.compile(r"10\s*月\s*9\s*日|10/9|截止日|报名截止|作品提交|官方公布|赛程")
for dirpath, _dirs, files in os.walk(ROOT):
    for name in files:
        path = os.path.join(dirpath, name)
        if name.endswith((".md", ".txt")):
            for i, line in enumerate(open(path, encoding="utf-8", errors="ignore"), 1):
                if PAT.search(line):
                    print(os.path.relpath(path, ROOT), i, line.strip()[:120])
        elif name.endswith(".docx") and not name.startswith("~$"):
            doc = Document(path)
            for para in doc.paragraphs:
                if PAT.search(para.text):
                    print(os.path.relpath(path, ROOT), "P", para.text.strip()[:120])
            for table in doc.tables:
                for row in table.rows:
                    joined = " | ".join(c.text.strip() for c in row.cells)
                    if PAT.search(joined):
                        print(os.path.relpath(path, ROOT), "T", joined[:120])
```

核验结果：`10/9` 的全部命中均为内部里程碑 GD（板端视觉闭环）；真正截止日相关表述为"竞赛截止/提交在 10 月中下旬或更晚"（属本队推断）；宣讲记录中"作品提交截止时间"为**待确认**。
