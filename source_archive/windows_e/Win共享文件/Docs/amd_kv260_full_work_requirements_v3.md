# 雾镜 Lite AMD KV260 项目完整工作内容与实施要求

版本：V3.0 统一工作清单版  
编制日期：2026 年 9 月 16 日  
项目方向：AMD FPGA 自主选题初级组，最终报名名称及资格以当期官方文件为准  
硬件平台：AMD Kria KV260 Vision AI Starter Kit  
文档用途：完整说明项目要做的功能、硬件、软件、算法、接口、测试与交付材料，作为后续排期和拆分任务的总基线。本文不安排个人分工。

本项目要完成一台固定式视听交互终端：它能发现来访者、通过有限角度水平转轴面向当前对象，听取问题并结合实际画面回答，用屏幕玩偶、字幕和声音反馈；能够在用户确认后记住姓名与明确偏好，在再次见面时识别用户，并在换人、画面过期、服务迟到和故障时正确处理。

在此前方案基础上，本版纳入双 I2S 麦克风采集与 FPGA 粗声源方向判断、视听协同选人、主动观察、回答画面绑定、身份记忆防串人和 FPGA 动作有效期约束。前序讨论过的物品登记、观察事件记忆、转向历史区域复查、图像加速与通用技能包也全部保留，按实施层级列出。

**本文是待执行工作清单，不是工程完成报告。所有未核验任务均保持未勾选。文中代码文件名、接口、参数和验收数值属于拟定设计；只有取得实际产物和验证证据后，才能更新完成状态。**

**本版范围调整（2026-10-02，无声源定位版）**：取消声学声源定位 —— 双 I2S 麦克风与自研音频核 `audio_doa_ip` 从自研主线移除，音频改由 USB 一体音频（MCP01，UAC 免驱）承担。因此：**第 9 章（W06）本版不实施**；**T13／T14 本版不适用**（编号与正文保留供追溯）；**T02 不再要求包含音频 IP**；Light-ASD 视觉说话人定位保留。本版范围见《AURA_KV260_完整实施方案_无声源定位版_2026-09-30.md》，本文继续作为任务与验收编号的唯一来源。

## 1 统一项目范围和旧方案冲突

### 1.1 本版采用的范围

| 项目 | 本版统一口径 |
|---|---|
| 主要应用 | 桌面或展台的来访者接待与视听交互；先把一个现场场景做完整 |
| 设备形态 | 固定底座、一个有限角度水平轴、摄像头、屏幕、麦克风和扬声器 |
| 板端职责 | KV260 PS 负责采集、跟踪、场景、融合、调度和驱动；PL 承载 DPU 与自研逻辑 |
| 本地主机 | Windows GPU 电脑运行首版视觉语言模型、ASR、TTS、人脸识别和身份库，通过有线局域网连接板卡 |
| 模型路线 | 先用现成轻量模型；有明确场景失败证据时再微调，不从零训练整套网络 |
| 首版语音 | 按键说话、松开提交、半双工、实体键取消；免按键和全双工另列增强 |
| 身份范围 | 自愿登记的小规模用户库、姓名和明确确认的偏好；不做身份认证系统 |
| FPGA 自研主线 | `motion_guard_ip`；~~`audio_doa_ip`~~ **本版（2026-10-02）已删：不再自研音频核**，音频改由 USB 一体音频（MCP01，UAC 免驱）承担；厂商 DPU 单独注明来源 |
| 开发周期 | 沿用前序约 20 个开发日作为主线规划参考，D1 是实际开工日，不是赛事日期 |
| 完整工作范围 | 必做主线、AMD 创新增项、条件增强、后续储备均列出；列入清单不等于承诺 20 天全部做完 |

### 1.2 冲突处理结果

| 原文件或前序讨论中的差异 | 本版处理 |
|---|---|
| FMQL30TAI、ICraft、原 NPU 工件 | 退出 AMD 实现基线；只继承通用产品、接口、测试和交互要求 |
| 旧版默认真实豆包云服务，后续改成本地模型 | 按后续讨论采用 Windows 本地模型主线；真实豆包作为独立可选适配器，不混称“豆包模型已部署在板上” |
| 30 天、一个月和 20 天排期并存 | 主线统一为相对 D1—D20；完整扩展清单不硬塞进这 20 天 |
| 旧稿强制 ByteTrack、后续建议简易跟踪 | 首版 IoU 关联与目标保持；交叉遮挡问题明显时升级 ByteTrack |
| 原 ArcFace 类路线与后续 YuNet/SFace | 首版优先验证 YuNet＋SFace；已跑通的其他模型可保留，但必须锁定工件和许可 |
| USB 音频与双 I2S 麦克风 | USB 音频承担首版语音对话；新增共时钟 I2S 双麦承担 PL 方向判断，明确是两条采集链 |
| 所有模型是否都在 KV260 | 本版不作此承诺；纯板端迁移作为独立工作包，需迁完整推理链而非只搬数据库 |
| 泛化心跳与画面过期保护 | 命令必须继承原始证据截止时间；独立心跳不能给旧帧续命 |
| 旧版自动回中、缓启动 | 丢目标停止追踪；无位置反馈时先确认位置，清故障与重新使能分开 |
| 原板 1 GB 内存、850 MB 上限、固定 720p60、4 路 LED、原引脚 | 不继承；按 KV260 实物、最终镜像和外设重新核验与预算 |
| 多套旧指标冲突 | 以第 16 节主线验收为本版建议基线；旧版高强度测试在增强验收中保留，不静默删除 |
| “只有 FPGA 能实现”、固定加速倍数或预计得分 | 不作为结论；改为同源对比、故障验证和资源实测 |

“豆包式”在本版表示交互体验。局域网本地模型、真实豆包云 API 和纯板端推理是不同部署方式，必须分别写清楚。

## 2 最终系统结构和运行模式

### 2.1 数据流

```text
USB 摄像头
  → KV260 PS 唯一采集服务 → DDR 图像 → PL DPU 人体检测
  → PS 后处理与跟踪 → 人员会话与 SceneState ───────────┐
                                                    │
共时钟 I2S 双麦 → PL 接收与窗口处理 → 互相关与方向码   │
  → PS 音频事件读取 → 时间关联与视听目标确认 ──────────┤
                                                    ↓
                     PS 视觉控制与时效校验
                       → PL motion_guard_ip
                       → PWM／执行器使能 → 单水平轴
                       → 相机获得新画面

USB 麦克风 → KV260 录音 → Windows ASR → 用户文字
  ＋当前实际快照、场景、已确认身份与偏好
  → Windows VLM → 经校验的回复 → Windows TTS
  → KV260 播放 → 扬声器＋玩偶＋字幕

当前目标人脸 → Windows 人脸检测／对齐／特征提取
  → 身份库匹配／确认登记 → 带会话和版本的身份结果
  → 板端校验 → 场景、问候与偏好使用
```

DPU、音频 IP、运动 IP 必须处于同一最终硬件配置中。目标融合和会话管理在 PS，语言与语音模型首版在主机，不能把整套系统描述为“全部在 PL 内运行”。

### 2.2 三种运行模式

| 模式 | 可用功能 | 验收边界 |
|---|---|---|
| `LOCAL_LAN_FULL` | KV260 本地感知与执行＋Windows 本地视听与身份 | 预下载依赖后，断公网但保留局域网，验证完整问答 |
| `BOARD_ONLY` | 板端检测、跟踪、转轴、基础 UI、停止、预录提示；P1 已上板则含粗声源方向 | 断开 Windows 后实测；未迁板的人脸、ASR、VLM、TTS 明确不可用 |
| `CLOUD_OPTIONAL` | 在本地接口之外选择真实豆包服务 | 单列网络、账号、费用、数据去向和服务故障回退 |

无论选择哪种模式，模型服务都不能直接写运动寄存器、清故障或重新使能。产品界面应能看出当前模式，不依赖操作者口头解释。

### 9.1 算法和参数起点

先实现时域短时互相关，GCC-PHAT 作为软件对照。候选起点为 48 kHz、麦距 50 mm、10 ms 窗口；按声速约 343 m/s 估算，最大物理时差约 7 个采样点，可试验 `lag=-8…8`。这些是设计起点，最终由真实麦克风、时钟和声学标定决定。

`R(k)=Σx[n]y[n+k]` 应对各 lag 使用相同有效求和区间。输入若从 24 位缩放到有符号 16 位，乘积需要 32 位，约 480 项累加至少预留相应增长位；**确定采用 48 位累加器**（D2 第 6.3 节已冻结：输入有符号 16 位、乘积 32 位、累加 48 位；右移 4 位仅余 8% 余量不可取），并在定点参考中验证。静音不能默认判成中间。

### 9.2 具体任务

- [ ] **W06-01 器件时序**：阅读实际麦克风手册，确认 I2S 而非 PDM、电平、槽位、有效位宽、一位延迟和启动无效时间。
- [ ] **W06-02 时钟设计**：两麦共用 BCLK/WS，各自独立 SD；**时钟生成采用小数分频，平均分频比 = 100/3.072 = 32.552083…，得到 3.0720 MHz 位时钟与 48 kHz 帧时钟；禁用「32/33 严格 1:1 交替」（那只有 32.5 → 3.076923 MHz → fs 48,076.9 Hz，偏高 0.16%）；推荐 192 周期块＝86×32＋106×33；整数分频仅作降级路径**（依据 D2 第 5.2 节的四方案与 MMCM/PLL 不可行推演：100 MHz 对该时钟家族无整数比），并按最终器件核验时钟质量与采样率，实测分频比回填 `CLK_MEAS`。

### 14.1 身份链与数据结构

- [ ] **W11-07 数据持久化**：原子写入姓名、模板、模型版本、同意和时间，成功后增加库版本；崩溃不能留下半条登记。
- [ ] **W11-08 识别策略**：实现 top1 阈值、top1/top2 差值、多帧一致性和 `unknown/ambiguous`；余弦相似度不当作概率。
- [ ] **W11-09 阈值标定**：使用独立登记、调参、已知新片段和陌生人数据，冻结阈值后再测最终集合。
- [ ] **W11-10 异步校验**：返回时核对 `boot_id/frame_id/track_id/presence_session_id/request_id/model_hash/gallery_revision/TTL`，旧结果不得套给新对象。
- [ ] **W11-11 偏好记忆**：支持一条明确偏好，例如“回答简短”；保存来源、确认时间与 revision，未知身份不读取他人偏好。
- [ ] **W11-12 记忆使用**：只将已验证姓名与确认偏好提供给对话编排；VLM 不直接读取特征向量或自行猜测姓名。
- [ ] **W11-13 查看纠错删除**：实现查看已存内容、纠正姓名/偏好、确认删除；处理同名条目，避免仅按姓名误删。
- [ ] **W11-14 删除传播**：删除模板、偏好、索引、缓存和受控备份条目，增加库版本，作废在途识别及包含旧记忆的对话结果。
- [ ] **W11-15 模型更换**：不同模型的特征空间不得混用；选择重新登记或有验证依据的迁移方案。
- [ ] **W11-16 问候规则**：身份首次确认后按会话与冷却时间问候，避免重复播报；过期、遮挡或身份不明时使用通用称呼。
- [ ] **W11-17 异常与重启**：测试写入中断、身份服务失联、两人换位、删除后迟到结果、数据库损坏提示及重启持久性。
- [ ] **W11-18 运行边界**：默认不长期存原始人脸，临时预览完成后清理；记录照片/屏幕重放限制，不将此功能用于门禁或支付认证。

产物：`host/identity/`、`host/memory/`、身份/偏好 API、空库模板、质量与阈值配置、事务和重识别测试。完成条件：登记→离开→返回→识别→使用本人偏好→删除的全流程真实可用，未知人、换人和迟到结果不串用记忆。
