# 本次 M3 有限板测执行范围

用户在了解“不重新烧录 SD、临时使用修复驱动、加载 M3、验证寄存器和推理、恢复原驱动及官方应用”后明确要求“那就开始做”。该授权覆盖本次单次 M3 加载及恢复；旧封存计划中的“后续须同意”停点已满足，不再请求重复确认。

当前只读预检通过：原备用卡 CID、mmcblk1p2、PetaLinux 2022.2、原驱动／运行库、原官方应用、同图输入均匹配。BusyBox devmem、/dev/mem、CONFIG_DEVMEM 具备；尚未实际访问 M3 总线。

按 `preparation.json` 冻结的顺序执行：独立备份 → 原官方分类及各线程数预热 10 秒／三次 60 秒 → 校验传输完整测试包 → 安全解包／独立安装四个 app 文件 → 退出原 app → 正常卸载原驱动 → 临时加载修复驱动 → 一次加载 M3 → 核对 DPU 与模块身份 → SCRATCH 保存／四图样写读／恢复 → 同模型同图分类和相同性能测试 → 再核对身份和 SCRATCH 原值 → 卸载 M3 → 正常卸载修复驱动 → 恢复磁盘原驱动和官方 app → 同图分类及文件哈希核验。

修复候选复用上一轮已经板测通过的精确模块，先核对哈希、复制到新目录，只 `insmod` 临时使用。磁盘原模块不覆盖，不安装开机配置。本轮未安排烧录、重启、PWM、执行器或长期压力测试。

已知原驱动退出例外仅限：底层 remove 返回 0、应用为空且设备已注销、其他检查通过；新增 `/axi/zyxclmm_drm` 的 `expected refcount 1 instead of 2` 为 0 或 1 条且无其他 ERROR／异常时可进入已验证的驱动替换步骤。原泄漏对象保留，不手工减引用。修复驱动后的新错误没有该例外。

每条命令有冻结清单及明文源代码，UART 输出逐段和完整 SHA-256 校验，按板端 uptime 审阅内核日志。非零返回码、身份不符、输出损坏或新内核异常立即停止后续测试，没有自动重试／强卸载／自动重启。停止后先只读审阅实际状态，再在既有授权范围内决定能否安全恢复。

寄存器只允许 `0x80080000/04/08/0c` 的 32 位访问，先匹配 IP_ID、ABI_VERSION、BUILD_ID 再写 SCRATCH；保存原值并确认恢复。CPU 与 DPU 并发、字节选通、完整 AXI 仿真、外围接口及长期可靠性不计为本次验收。

时序裕量 +0.009 ns、7 个输入／9 个输出约束缺口与 621 条 DRC Warning 保留，本轮验证范围限定为现有最小模块和 DPU 的有限串行功能。后续运动控制仍需独立开发与验证。
