项目已有两条可演示的成果线：Windows 侧的汐蓝角色、真实语音和实时动画；KV260 侧的视觉观察、DPU 与自研 VSRV 共存及有限运动命令测试。接下来主要缺真实输入和跨模块集成，而不是从零创建所有模型、语音或玩偶界面。机械功能按用户最新要求等 3D 模型到位后再继续。

## 算法已经怎样落到代码

电脑端链路：台词或有效 WS 回复→固定声线合成/校验缓存→音频设备播放→已处理样本时钟→音强包络→局部嘴部插值；眨眼单独调度，情绪和动作仍使用既有状态与白名单。新台词采用固定参考提示而不是每次重新生成音色。取消废止当前生成代次和音频 token，避免旧结果重新开口。

板端链路：唯一摄像头→最新帧槽→192×192 CPU YuNet→原图框/真实时间→基础轨迹关联→新鲜观察发布。正式 DPU 人体检测与 ByteTrack 路线仍需集成；轨迹 ID 不是姓名。身份图片参考链已具备检测、五点对齐、112×112 SFace、128 维特征和余弦比较。

当前最大的算法接口缺口是把板端真实轨迹/身份/画面/同期音频送入统一交互流程。Windows 实时演示中的手动事件、空场景和手动台词，不自动形成真实视觉触发、图文问答或说话人选择。

收尾仍缺少三个核心依赖：`board/runtime/character.py`、`board/runtime/audio/selected_voice.py`、`tools/facial_layers.py`。先前缺少的 realtime_metrics、selected_voice_demo 和 stage_config 此时已出现。当前 realtime_controller/realtime_dialogue 导入 selected_voice，realtime_facials 导入 facial_layers；因此仅语法通过不能保证共享目录能够启动。移机 ZIP 中可找到这些依赖，本轮仅在审阅目录提取作对照，没有恢复/覆盖共享目录。

首轮共享 dialogue_host 还是通用人设；收尾该文件已更新，人设、`HISTORY_MESSAGES=8` 和全角处理均存在，与包内版本一致。尚缺角色模块导致新版共享自检失败。共享 README 顶部仍停留在较早声线试听/509 项说明，不能优先于较新交接和包内代码。

最新下巴模块、550 项摘要、补丁移机记录均存在；收尾 README 和旧剧本 acceptance.json 也已经到位并阅读，后者明确用户接受范围为此前 47.27 秒电脑端演示。仍需区分完整实时原始证据和摘要。因此现状包含旧文件、后续更新和缺项的组合。同步/复制造成差异的具体原因未确定；本轮不推断 Windows 本机本身也缺文件。

旧语气记录中对“全角标点改善自然度”的判断属于待对照验证假设。代码可确认 NFKC 会改变全角标点，但未证明标点是自然度主要原因；不因该记录直接改规范化或令全部语音缓存失效。
