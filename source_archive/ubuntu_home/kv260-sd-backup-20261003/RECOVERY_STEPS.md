# 使用整卡镜像恢复备用卡

仅在 `IMAGE_VERIFICATION.json` 为 verified 且镜像独立回读摘要匹配后使用。当前正在制作镜像；本文件是恢复步骤，不表示已执行恢复。

1. 保存 `kv260-spare-runtime-fixed-20261003.img`、`IMAGE_VERIFICATION.json`、`IMAGE_SHA256SUMS` 及本轮报告。保持镜像为 0600，备份目录为 0700；镜像含完整系统配置和访问凭据。
2. 恢复前先回读校验镜像 SHA-256。重新识别目标 SD 卡的物理设备及容量；目标必须至少有 `31914983424` 字节。标称同为 32 GB 的不同型号卡不保证扇区数足够。
3. 确认允许覆盖该目标卡，并正常卸载其所有分区。将整卡镜像写入已确认的整盘设备；不得选择主机系统盘，不得仅写 root 分区。写入前以实际设备身份生成具体命令。
4. 写入后执行 flush/sync，并回读目标卡中前 `31914983424` 字节计算 SHA-256，与镜像匹配。安全弹出后插回断电的 KV260，再接通电源。
5. 通过串口保存新的启动日志，确认 root 设备、修复 ZOCL srcversion `9BDC942A6014BCCBD1DCB78`、修复 manager、官方 B4096 slot 0。执行 `xdputil query`，核对 1 CU、300 MHz、`0xa0010000`、fingerprint `0x101000056010407`。
6. 复跑原 ResNet18 和原萨摩耶图片，核对完整 Top-5；不要把镜像写入或启动成功当作推理验收。

当前镜像是本轮文件系统修复之前的备用卡恢复点，包含已持久启用且通过冷启动采样复测的修复运行时，以及原 26 项基线文件和板端恢复副本。恢复该镜像会同时恢复当时的 fstab 与 FAT 状态。若随后修复文件系统，应另外保留修复报告和原件；后续需要新的整卡镜像时采用新文件名，不覆盖这份恢复点。
