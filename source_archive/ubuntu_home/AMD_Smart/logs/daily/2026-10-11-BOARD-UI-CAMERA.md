# 2026-10-11 板端触屏、真实相机与卡顿修复

用户要求继续完善板端 UI/后续接口、接入已识别摄像头，并反馈界面画面比直接显示更卡、更延迟。本轮先读 ZIP README、无声源定位方案、C04/C08 与接口章节、最新方案与板端记录；A 仍负责视觉和 FPGA，机构等待 3D 模型。

实际完成五页 GTK 触屏界面和 `aura-ui-1` 状态/操作合同，接入唯一相机适配服务，复用 A 的固定 CPU YuNet/IoU 后端。预览不再等待检测；最新 RAM BGR 帧进入独立原生视频线程，人物合成及诊断保存各在后台执行。修复状态/JPEG 交接闪空、视频管线重置后另开窗口、同步诊断超时和旧 Cairo 截图崩溃。原素材、缓存声线和音量 18% 保留。

实测：原界面更新约 3.94Hz；最终两次短测视频入口约 15.88Hz / 12.59Hz，同口径 API 已发布帧龄中位数 450→235 / 210.5ms。原生入口帧龄中位数 98.33 / 76.39ms，P95 142.87 / 114.94ms；各 120 次采样无空画面。不是物理面板端到端延迟，也未证明与原直显同延迟。完整验收时相机采集约 18.87Hz、检测 9.30Hz，配置 30/10Hz 不能作为实测。

验证：118 项主机框架、2 项异步诊断、4 项 loopback HTTP、5 项模拟 EDID 回退和异步退出等待检查通过；目标板 60 项软件测试及资源预检通过。实际相机增长/时效、放大/返回、五次诊断无重启、五页原生指针操作和缓存音频暂停/继续/取消通过。主机合成视频另外验证 GTK 阻塞时独立出帧、移位窗口/换代后嵌入及过期黑屏。375 份 UART 响应长度/SHA 独立回读通过，历史六次失败及负向 503 探针保留。
