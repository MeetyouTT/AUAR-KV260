# GitHub转轴平滑方法与原代码回放

用户明确调用GitHub插件，要求寻找平滑转轴、按脸速调整且边缘快速响应的方法；后续澄清是持续人脸移动时一顿一顿，跨边界响应慢/犹豫。最新人脸速度反馈已在continuous-v2r2实现，不能沿用昨天“实时路由未接通”的状态。

通过GitHub搜索/读取OneEuroFilter作者实现、Ruckig README/速度接口/许可、ServoEasing，以及Pimoroni和两个脸跟踪参考；作者网页核对OneEuro调参。形成[共享报告](/home/ghmd/Win共享文件/协作任务/2026-10-25_转轴平滑调研/README.md)。明确Ruckig专用Tracking是Pro，开源可参考速度接口；Arduino ServoEasing不是KV260直接适配库，不挪用其他舵机死区。

原控制器静态确认：原始位置回区清零+session重建，3帧确认/2帧越界及ARM后新源/首帧dt0，因果中值+两层固定低通，每新源4µs上限、整数微秒离散；左触发已近实际图像边缘，速度含相机自运动。PS调度/测量是第一优先，不直接加大速度或宣称硬件根因。

执行纯软件回放：原continuous-v2r2/FakeDevice，4场景×40/100ms两种新源间隔，初始1425和1445各一轮。两侧1.28px交替0ARM；5出1入10轮出现10ARM/10finish、累计仅1/4µs；已有区内历史向外持续移动首次命令160/300ms，初始区外240/500ms。所有时间均合成软件端，不是现场机械测量。完整逐帧/四源SHA见[最终1445结果](/home/ghmd/Win共享文件/协作任务/2026-10-25_转轴平滑调研/current_controller_replay_1445.json)，初次1425原件保留。

建议分离感知与运动生命周期、改自适应滤波对照、区外提前减速；若采用回落滞回带需明确改变原“回区即停”的行为，不擅自改线。高频轨迹需定义原始源截止，不能拿同一帧循环续租；Ruckig输出是命令状态，不是实际轴反馈。故障STOP/行程与既有保护保持。
