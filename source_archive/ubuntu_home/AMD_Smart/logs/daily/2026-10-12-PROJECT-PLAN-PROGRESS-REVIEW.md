# 2026-10-12 项目计划与实际进度复核

## 范围与结论

响应用户“看看我们的项目计划，做到那里了”。按 ZIP README、无声源定位版范围、10 月 2 日分工、10 月 8 日初级组框架及 10 月 9 日人员更新，核对最新日志、现场报告、验证汇总和主仓配置/RTL。本轮为本地资料复核，没有连接 KV260 或 Windows，没有运行新板测、模型推理、软件回归或机构操作。

项目目前是多个子系统已上板、统一整机尚在集成。按现行 L1—L4 关卡，L1 的平台/检测/跟踪和有限运动协议已有成果，但正式机构随动等验收未闭合；L2 已有板端 UI/缓存播放及 Windows 语音基线，板端完整身份和真实问答链未闭合；L3 创新方案有设计和软件基础，未完成新版 PL 与实测对照；L4 仍为提交框架，未成为最终参赛发布。不能把它们换算成可靠的完成百分比。

## 本轮核对结果

- 读取三份独立验证 JSON：YOLO `PASS`，首次跟踪 `PASS_WITH_RECORDED_LIMITS`，后续真人选择 `PASS_REAL_NATIVE_SELECTION`。这些是历史验证汇总，本轮没有重新核验全部原始 UART 和权重字节。
- 后续现场证据 UTC 为 2026-10-12，优先于同日早期“ByteTrack 未接入/真人选择未验证”的盘点。原生点选使用 GTK/XTest，不能升级为新页面实物手指验收；旧目标失效发生在后续观测首采样前，不能宣称连续物理出入画全过程通过。
- `runtime.kv260.json` 的 DPU 模型 SHA、入口、指纹仍为空，identity/dialogue/motion 为 disabled，说明总集成尚未完成；独立相机/UI 服务已有实测成果。
- `visual_servo.sv` 仍在 COMMIT 时装入相对 `lease_left`，未据此认定源观测绝对期限监督完成。
- Windows `HANDOVER.md` 与 `acceptance.json` 明确 TTS 最新基线为 OmniVoice，不能沿用早期 Qwen3-TTS 作为当前最终选择。交接包默认 4B，用户此前报告部署 14B；本轮未查询在线主机配置。
- 提交 README 仍标记 `FRAMEWORK_NOT_FINAL_COMPETITION_RELEASE`。首次跟踪报告保留 7 项旧语音 API 回归错误，没有新的修复证据。
- 全目录发现阶段遇到旧 SD 备份 `rootfs-mount` 访问被拒；所需计划、日志和源码均可读取，不影响本轮结论。
