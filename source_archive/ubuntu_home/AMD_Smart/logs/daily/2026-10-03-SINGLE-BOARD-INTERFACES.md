# 2026-10-03：三人共用一块 KV260 的接口与验收说明

依据 ZIP 项目入口、共同部署速查表，以及个人手册第 4、6、10、11、13 章整理。本文说明现有方案的交接与评判方法；具体接口 schema、实现和性能上限仍需三人冻结。本次没有执行板端或接口测试。

## 同板职责

- A 发布统一 Linux/驱动/运行库底座、同一份 DPU＋motion PL 配置和硬件访问库。
- B 在 PS/Linux 运行相机、视觉/身份、DPU 业务调度及唯一正式运动服务。
- C 在 PS/Linux 运行 MCP01 音频、交互客户端、声画窗口、UI、启动与状态汇总。
- 当前方案中 ASR/VLM/TTS/Light-ASD 的首版重模型计算仍由 Windows 主机承担。三人均有板端交付。

一块板承载统一硬件配置与多个软件服务。硬件升级由 A 安排维护窗口，停止相关服务、处理旧 Runner/MMIO 映射和在途任务后统一切换；恢复时重新核验版本并初始化新代次。B/C 可在固定平台上并行开发和部署各自软件。

## 主要交接接口

| 交接 | 交出内容 | 接收方操作与通过证据 |
|---|---|---|
| A→B | DPU 架构/运行库；运动访问库；IP/ABI/BUILD；正常提交、拒绝、禁能/恢复语义 | B 在同一配置里运行匹配模型并读 IP；完整 motion 可用后提交命令、回读接受/拒绝，验证到期和停止 |
| B→C | 帧/快照/连续脸片段、轨迹与生命周期、身份接口、原始采集时间 | C 按 API 取得真实图像和同期脸片段，正确绑定问答/ASD；相机重启后旧帧和轨迹失效 |
| C→B | 带轨迹代次、证据窗口、到期时间与质量的对象建议 | B 复核最新轨迹；有效建议进入目标管理，过期/消失/歧义返回具体拒绝原因 |
| A/B→C | 平台/运动/视觉/身份真实状态、故障、健康探针和受控操作入口 | C UI 与实际状态一致；登记/删除由 B 执行，运动操作通过 A/B 的约定流程 |
| C 板端↔Windows | 当前音频/图片/连续片段和请求归属；转写、回答、声音及 ASD 分数 | 板上真实录音→主机处理→板上真实播放/显示；取消或断连后旧结果丢弃 |

七份合同 I01—I07 是上述内容的共同定义文件。每个接口要有维护人、输入字段、类型/单位、版本、时间语义、有效期、返回码、示例输入和预期输出。运动提交使用合同冻结的整数毫度/微秒等单位；帧和轨迹保留原采集时间与生命周期，跨机不直接相减 monotonic 时钟。

相机、DPU 视觉调度、运动正式写入、音频和数据库分别保持现有方案规定的唯一所有者。其他模块通过其接口取得数据或发起受控操作，媒体缓存和请求队列有界。

## 只有一块板时的开发与验收顺序

1. 电脑阶段：A 仿真 RTL，B 用录制输入/模拟运动接口，C 用真实离线样本开发模型/协议/UI。先验证字段、状态与异常；记录为电脑验证或模拟验证。
2. 分模块占用板卡：固定共同平台，分别验 B 的真实相机/DPU，C 的 MCP01/实屏/主机往返，A 的版本访问与无动力运动接口。接收方亲自调用交接入口并记录结果。
3. 同板联合：同一次启动、同一份有效 PL 下同时启动视觉、身份、音频/UI/网络、DPU 与运动。测量并发后的帧龄、推理等待、音频连续性、内存/队列上限、PWM 与租约响应。
4. 异常和复现：冻帧、进程退出、过期建议、取消后的旧回答、设备重插、平台重载逐项验证；新启动按相同发布清单重新运行。

A 更新 PL 需要独占维护时段；B/C 在固定平台上的模块验证可以排期轮流接实际设备，联合验收必须同时运行。各自已用过的 SD 卡可以保存不同恢复点，但最终联合结果绑定同一套发布配置。

## 怎样判定接口通过

- 格式/语义：输入正确、单位一致，输出与预先确定的结果相符。
- 接收方可用：接收者按交接包独立调用并获得真实结果。
- 异常有效：版本错、过期、目标消失、取消和模块重启按合同拒绝或降级。
- 并发有效：三人模块同时运行仍满足提前冻结的帧龄、时延、队列/内存和运动响应上限。
- 可复现：日志关联 release、boot、源 frame/window/request、命令序号、实际结果和证据；重新启动能复现。

每次验收记录“交出版本、输入、预期、实际、接收人、证据、PASS/FAIL/NOT_TESTED/PARTIAL”。性能上限在测前冻结。现有 M3 有有限版本/SCRATCH/DPU 共存证据，完整运动与其他产品接口仍需分别验收。
