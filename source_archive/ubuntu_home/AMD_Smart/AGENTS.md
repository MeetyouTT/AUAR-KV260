# AMD_Smart 项目工作规则

## 项目资料结构

- `plan/active/`：当前有效的项目方案、实施计划与架构设计。
- `plan/reference/`：仍可参考但不作为当前执行依据的方案。
- `plan/superseded/`：已被替代的方案，仅作历史记录。
- `data/`：比赛资料、硬件手册、datasheet 与参考资料，是事实依据。
- `logs/`：开发、测试、FPGA 与集成中实际发生的结果和过程记录。

## 开始任务时的阅读顺序

1. 先查看完整竞赛资料包 `/home/ghmd/下载/项目.zip` 内的 `项目/README.md`，并按 `PROJECT_BOOK_INDEX.md` 找到当前任务相关的项目书、赛题要求或技术资料。
2. 再阅读 `plan/active/` 中与当前任务相关的方案，并按任务需要查阅 `data/` 中的资料。
3. 然后查看 `logs/daily/` 中最近的日志和当前工作目录最新报告，了解最新实际状态和未解决事项；若它们晚于 ZIP 内文档，以更新的可核验证据为准。

## 证据与状态原则

- `plan/` 表示计划、设计或意图，不等于已经完成。
- `data/` 是技术参数、规则和参考信息的事实依据。
- `logs/` 记录实际发生的操作、结果、测试现象和结论；状态判断以其为准，并在必要时用可复现的检查验证。
- `simulation` 不等于 `board verified`。只有在目标板上完成并记录验证后，才可称为板级验证通过。

## 日志要求

- 每次重要工作结束后，更新 `logs/daily/` 中当天的日志（建议文件名为 `YYYY-MM-DD.md`）。
- 日志应说明完成内容、实际结果、验证方式、遗留风险或下一步；不要把计划写成既成事实。
