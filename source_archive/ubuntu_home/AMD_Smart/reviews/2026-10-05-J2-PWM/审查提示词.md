## 2. 针脚映射和电气链路

按 B03 原理图，J2 两排针号为 `1/3/5/7/9/11` 与 `2/4/6/8/10/12`，不能混用通用 Pmod 每排 1–6 / 7–12 的编号。这里的“第一排/第二排”是用户实物描述，尚不能仅凭文字独立确认其左右/上下方向。

| 功能 | B03 映射 | 目标连接 |
|---|---|---|
| 测试输出 | J2.1 → HDA11 → FPGA H12，Bank45 | ADuM1201 VIB |
| 对排对应信号 | J2.2 → HDA15 → FPGA B10 | 本测试没有把它设为第二路 PWM |
| 地 | J2.9 / J2.10 | FPGA 侧 GND1 |
| 供电 | J2.11 / J2.12，PMOD_3V3 | FPGA 侧 VDD1 |

历史接线描述为蓝线信号、紫线地、白线供电；不是独立导通验收。用户曾报告“0”作为导通回答，但没有明确单位/电阻档照片，不能写成已独立证实 0 Ω。

ADuM1201 B 通道：侧 1 `VIB`（芯片 pin 3）→侧 2 `VOB`（pin 6）。侧 1 `VOA`（pin 2）是输出，不能误接为输入。实际模块排针标注是否对应芯片脚仍需核对。侧 2 为独立舵机侧 VDD2/GND2；输入侧用 J2 GND/GND1 作测量参考，输出侧用 GND2。普通示波器通道地通常共地，不能把两侧地随意跨接。

载板路径：`HDA11 → R276（0 Ω）→ PMOD_HDA11 → J2.1`。R274（20 Ω）/C370（33 pF）是并联 RC 支路，不是正常直流分压器。U42 TPS22948 控制 PMOD 供电，不是信号输出电平转换器。J2 两个供电脚接同一 PMOD_3V3，两地脚也相连；PMOD_3V3 和 Bank45 的 VCCO_HDA 都源自 PL_3V3，但供电脚 3.36 V 不足以证明每个 SOM/Bank 局部连接正常。

测试 XDC 原文核心：

```tcl
set_property PACKAGE_PIN H12 [get_ports servo_pwm]
set_property IOSTANDARD LVCMOS33 [get_ports servo_pwm]
set_property DRIVE 4 [get_ports servo_pwm]
set_property SLEW SLOW [get_ports servo_pwm]
set_max_delay -datapath_only 20.000 -from [all_registers] -to [get_ports servo_pwm]
```

`DRIVE 4` 是驱动能力设置，不是“输出设成 0.4 V”。实现报告显示 OUTPUT/OBUF/H12/Bank45/LVCMOS33；仍需外部电压验证。

**默认程序也使用这些信号脚。** 参考 `pin.xdc` 将 H12 设为 `mclk_out_tx`、B10 设为 `mclk_out_rx`。生成 HDL 两者为 ODDR 时钟输出，TX 的参考频率约 18.433 MHz；RX 的实际连接为 `clk_wiz_0_clk_out1`，TX 为 `clk_wiz_audio_clk_out2`，不要只靠接口元数据假定两个时钟频率相同。因此“第二排没写过我的测试代码”不等于默认应用没有配置/驱动它。

## 4. 代码和接口审查要点

PWM 参数计算：

```systemverilog
localparam [63:0] PERIOD = PWM_HZ > 0 ?
    (64'd1 * CLK_HZ + PWM_HZ / 2) / PWM_HZ : 0;
localparam [63:0] PULSE =
    (64'd1 * CLK_HZ * PULSE_US + 500000) / 1000000;
```

复位/STOP 优先：pwm=0、busy=0、frames_left=0、phase=0。START 在 idle 且 config_valid 时 pwm=1、busy=1。忙时 phase 递增，非边界输出 `(phase + 1'b1) < PULSE`；周期末回到 phase=0，有限帧最后一帧结束则输出低，否则输出高。RUN_FRAMES=0 表示持续。固定电平版把合法范围由 `PULSE < PERIOD` 扩为 `PULSE <= PERIOD`，因此 PULSE=PERIOD 时跨周期持续高。忙时重复 START 不续期；AXI 包装会拒绝该请求。

| 偏移 | 功能 |
|---|---|
| 0x00/04/08 | IP_ID=0x50574D54，ABI=0x00010000，BUILD_ID |
| 0x0c | bit0 busy，bit1 **内部** PWM 位，bit2 config_valid |
| 0x10 | START=0x53544152，STOP=0x53544F50；要求完整 WSTRB=0xf |
| 0x14/18/1c | period_ticks、pulse_ticks、frames_left |
| 0x20/24/28 | CLK_HZ、RUN_FRAMES、PULSE_US |
| 0x2c | SCRATCH，可做字节选通测试 |

status=4 是 idle/内部低，5 是 busy/内部低，7 是 busy/内部高；**bit1 不是实体 pad 电压回读**。错误控制字、忙时 START、非法地址/只读写入/不完整控制写等返回 SLVERR。请同时审查“严格拒绝总线写入”的软件契约是否会触发 Linux 异常。

修正后的 C 访问器 `/dev/mem` 映射 4 KiB，`volatile uint32_t` 读写、写前后 `dsb sy`；反汇编见 `ldr w0,[x0]`、`str w1,[x0]`。Python 只校验 ELF 哈希再调用访问器，不再直接写 mmap。固件名、FPGA manager、IP_ID/ABI/BUILD/参数/boot 会话检查不符则拒绝访问或写入。**当前默认位流下不能直接运行旧测试地址的客户端。**

固定电平版 START 验证立即及 100 ms 后都为 status=7；STOP 为 4。内部实现可查完整 `rtl/pwm_burst.sv`、`rtl/aura_pwm_probe.sv`、`rtl/axi_body.sv.in`、`scripts/build.tcl`、`board/mmio32.c`、`board/probe.py`，源码都在 ZIP 中。

离线结果：有限版 WNS/WHS +6.681/+0.013 ns；连续 50 Hz +6.919/+0.012；慢方波 +6.912/+0.004；固定高 +6.612/+0.016。最终各 DRC error=0。固定高输出内部路径预算 20 ns、slack 14.851 ns。这些数值不证明输出幅度正常。

### 5.2 首次 START 的真实内核故障

2026-10-05 05:21 UTC：有限版已加载、身份/默认 idle 读回通过；首次旧 Python 客户端 START 时记录：

```text
SError code 0xbf000002
Comm: python3
Kernel panic - not syncing: Asynchronous SError Interrupt
```

旧代码使用：

```python
mem = mmap.mmap(fd, 4096, flags=mmap.MAP_SHARED,
                prot=mmap.PROT_READ | mmap.PROT_WRITE,
                offset=0x80080000)
struct.pack_into('<I', mem, 0x10, 0x53544152)
```

当时分析为普通 Python 缓冲区操作可能不能保证单次完整 32 位 MMIO，而 IP 要求控制 WSTRB=0xf、不完整写返回 SLVERR。这是**有依据的假设，未通过故障指令反汇编或总线抓取证实直接因果**。不能把它写成“确定发生字节写，因此烧坏 FPGA”。

处理：拒绝继续使用旧客户端，保存 `REJECTED_probe.py` 和 `uart.raw`；改为明确 32 位 C 访问器及反汇编核对。故障后 UART 多次零字节，JTAG 又遇电脑 USB 权限/EACCES、FTDI 初始化问题；这些不是 PWM 电压故障的证据。临时 ACL 后可枚举 K26/A53。用户按 RESET/SW2 后捕获新启动和 root，Linux 恢复。

07:33 UTC 重载修正访问器；SCRATCH、STOP、07:42/08:13/08:21 三次有限 START 控制均 rc=0，最终 status=4/frames_left=0，未再次记录该 panic。证明修正访问器本轮可控制，不证明第一次异常的唯一根因。

### 5.3 连续运行和复位/默认应用混淆

连续 50 Hz 的 START/STOP/重启输出控制通过。慢方波多次重启导致候选失效，默认应用重新加载；助手未主动触发这些重启，部分原因当时未知，最后一轮用户明确说按了 RESET。一次慢方波持续观察约 135.5 秒，同 boot ID、每约 30 秒只读检查保持 busy；不能把这一次结论扩展为所有后续时段都在运行。

慢方波只读采样 48 次/约 0.78 s，内部高/低各 24 次，15–16 次转换。采样有调度延迟，不是示波器精确时序，也不是实体引脚回读。

默认工程 H12 音频时钟可解释部分约 18.433 MHz 的历史照片；没有每张照片同一时刻的固件证据，不得逐张断言信号来源。

### 5.4 示波器使用和助手解释的局限

- 多张照片为 STOP 冻结状态；不能当作此刻实时输出。单次触发等待与 START 对齐多次不明确，PROBE COMP 检查曾提出但没有取得完成验收证据。
- 有过 ns/div 与 mV/div 标尺、小幅 MHz 波形；也有约 50 Hz 圆滑波动，不能直接当作目标慢方波。
- GDS-2204A 曾实体探头据用户为 10×、软件显示 1X，后来改为 10X。还有一次误选电流探头，显示 A/div，随后改回电压模式。
- 底部 2.48 V/3.34 V 等是触发门限，不能当作信号测量值。
- 一次用户明确只有地夹连接、尖端悬空；该图无效，不能证明无输出。
- 照片 `1111111111.jpg` 按时基格数约 10 Hz，但计数显示约 2 Hz，两者不一致；不能只采信自动频率计。
- 修正倍率后部分 10 Hz 图仍估算高低差约 0.3–0.4 V，接点/实物倍率未独立复核。示波器截图未完整验收电平、周期、脉宽和隔离输出。
- 助手曾将冻结平线说成“没有波形”，后按用户反馈修正。最近一次又因文字把“供电/信号 3 V”误按“供电/GND 3 V”分析，用户最终更正；本提示词使用最终配对，不能继续沿用“第一排供电跌到 3 V”的假设。
- 把 J2 问题直接称为“板端异常”也可能超出证据：真实针位/接触/外接负载与物理高低仍不完整。请审查此前助手结论是否过强，不要求接受既有判断。
