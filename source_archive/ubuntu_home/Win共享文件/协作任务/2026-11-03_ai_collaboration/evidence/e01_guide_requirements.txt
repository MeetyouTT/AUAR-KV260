3.3.3 设计与优化要求
3.3.3.1 工具限制
         ● 工具版本：Vivado / Vitis 2026.1（推荐）或 2025.2。如使用其他版本需在报告中说
    明并保证脚本可复现
         ● 允许使用任意公开大模型、微调后的本地模型，以及基于大模型构建的智能体应
    用。须提交体现大模型协作过程的交互记录，含提示词、模型回答与自我纠错轨迹
         ● 须将协作过程中沉淀的可复用经验提炼为技能包（Skill）
                                      ，随作品一并提交，见
    3.3.5.2

3.3.3.2 板卡与器件限制
         ● 初级组：可使用 AMD 7 Series FPGA、Zynq-7000 SoC、UltraScale 或 UltraScale+系
    列器件。
         ● 高级组：可使用任意 AMD FPGA、Zynq Adaptive SoC 或 Versal Adaptive SoC 器
    件，不设逻辑资源限制。
两组均须在提交物中声明具体型号，并应选择自身可实际获取并完成板级验证的器件。
作品须在板上跑通并提供实测输出。

3.3.3.3 开源要求
所有提交作品强烈要求在 GitHub 或 Gitee 上开源，采用允许再分发的开源协议，推荐 MIT 或
Apache-2.0。

3.3.4 优化目标
         ● 在目标器件上取得可测量的性能表现，并给出与基线的对比
         ● 合理使用片上资源，避免以显著的资源代价换取有限的性能收益
         ● 保证工程可由他人从零复现
         ● 将设计过程中的判断依据写进报告，而不只是呈现结果
         ● 将与大模型协作中获得的经验提炼为他人可复用的技能包

3.3.5 提交内容
3.3.5.1 工程包
         ● 完整的工程文件与源码（RTL、HLS、PS 侧软件等，按实际采用的实现方式提
    交）
         ● 仿真或验证结果，说明功能正确性是如何确认的
         ● 综合与实现报告，含资源占用、时钟频率与关键性能指标
         ● 上板工程、运行脚本、实测输出与参考结果的比对数据
         ● 可复现的构建脚本

3.3.5.2 技能包
置于 skill/ 目录，含 README.md 说明每一项的适用范围、使用方法与失效条件。技能包是
把与大模型协作过程中沉淀下来的经验显式提炼出来，供他人直接复用，可以是以下任意一种
或多种：
         ● 提示词工作流：一组经过验证、能稳定完成某类任务的提示词模板及使用说明，例
    如从算法描述推导软硬件划分、根据综合报告定位瓶颈
         ● 案例模板：可被下一个题目直接套用的工程骨架、脚本模板、报告模板
         ● 校验脚本：自动比对黄金参考、检查资源与时序、验证工程可复现性的脚本
         ● 踩坑清单：结构化整理的常见错误与定位方法，含触发条件与排查步骤
评价标准是可复用性：一支陌生队伍拿到该目录，能否直接用在自己的题目上。每一项须写明
适用场景、使用方法与已验证的效果，并说明是从哪些失败或观察中总结得出。
通用 PYNQ Skill 单独加分。 若提交的 Skill 面向 PYNQ 框架且不与本队题目绑定（换题目、
换板卡仍可用），在本赛道评分中另行加分，见 3.3.2。

3.3.5.3 设计报告
         ● 选题背景与创新点：为什么选这个题目，它解决了什么实际问题，前人做过什么
         ● 设计原理与功能框图
         ● 软硬件划分依据与接口设计
         ● 优化过程，含优化前后的性能与资源对比表
         ● 大模型协作记录：提示词、模型回答、自我纠错轨迹、智能体工作流设计（如有）
         ● 技能包的提炼过程：从哪些失败或观察中总结、如何验证有效、边界如何确定
         ● 复现说明：一份可供他人从零开始完整执行的操作步骤

3.3.5.4 推荐目录结构
仓库内所有目录名与文件名须使用纯英文（小写字母、数字、下划线或连字符），不得出现中
文、空格或特殊字符，以保证跨平台复现与脚本自动化。中文只出现在文件的正文内容中。

 <project_name>/
 ├── README.md        # 项目简介 + 复现步骤
 ├── src/             # 设计源码（RTL / HLS / PS 侧软件）
 ├── sim/             # 仿真或验证脚本与结果
