## 1. 本版范围与项目目标

### 1.1 一句话描述作品

做一台放在桌面的单轴交互终端：**看到人，选择交互对象，朝对象小范围转动，按授权记住身份，通过 MCP01 录音和播报，并借助局域网 Windows 主机完成中文识别与看图问答。**

KV260 负责真实传感、板端视觉与身份、交互状态和受监督的运动。Windows 负责首版较重的模型服务。Ubuntu 负责把硬件、Linux、模型和程序构建成可复现的部署包。

### 1.2 本次明确删除的部分

用户已经购买麦克风与扬声器一体设备 MCP01，并要求去掉听声辨位。本版删除以下任务，不再把它们列为交付依赖：

1. 两只独立 I2S 麦克风及对应采购、安装和共时钟接线。
2. PL 内 I2S 双路采集、声学相关/时差估计、粗方向计算。
3. `audio_doa_ip`、其寄存器、PCM 调试导出与相关测试向量。
4. 声学左/中/右方向标定，以及方向与视觉融合。
5. 双麦方向延迟、方向准确率、双麦采样稳定性等原验收项。

**USB 录音、USB 播放、中文 ASR、TTS、VLM 看图问答继续保留。**

**Light-ASD 视觉说话人判断继续作为本版目标。** 用户最新补充确认的是 MCP01 型号，没有明确取消这项既定算法，因此沿用原计划。它使用对应时间段的声音和连续人脸画面，判断画面里谁在说话；不输出麦克风测得的空间方向。

### 1.3 保留功能及完成深度

| 功能 | 本版要完成的内容 | 完成证据 |
|---|---|---|
| 人体检测与跟踪 | 相机唯一采集；人体模型适配实际 DPU；输出连续轨迹 | 同一镜像下模型输出、轨迹日志、测试视频 |
| 单轴视觉随动 | 以当前有效目标的画面位置形成运动请求 | 左右移动、失跟、冻帧、停止与恢复测试 |
| 自研 PL 运动监督 | 原子命令、范围/速率限制、租约、序号、恢复代次、PWM、停止 | RTL、仿真、波形、实际时序与故障实验 |
| 板端人脸身份 | 板上检测/特征链、匹配、登记、SQLite 数据库、删除与 UNKNOWN | 板端运行记录、重返/陌生/串人测试 |
| MCP01 对话音频 | KV260 USB 录放音；首版按键半双工 | 实机录音、回放、相机并发和重插记录 |
| 视觉说话人 | Light-ASD 基线；有限窗口；声画对齐；不确定时拒绝自动选人 | 离线和实时片段、逐人分数、选错/拒绝统计 |
| 中文语音问答 | Windows ASR→VLM/回答逻辑→TTS；板卡接收并播报 | 完整请求日志、输入图、转写、回答、实际声音 |
| UI 与取消 | 听/想/说、对象与身份、失联提示、取消和迟到结果丢弃 | 真实屏幕与取消实验 |

当前作品只有一个水平转轴；没有底盘移动、机械臂、双轴云台或经过证明的自主导航。本版不增加这些任务。

### 1.4 旧方案冲突如何处理

优先级采用：**用户最新决定 → 本文的范围调整 → 当前对齐记录与三十天责任 → 第四轮需求/验收 → 历史方案。** 赛事正式规则及后续公告仍决定正式提交要求。

- 旧双麦任务被本次范围调整取消，不把旧计划里的双麦条目继续塞给 A。
- Windows 首版运行 ASR、VLM、TTS 和 Light-ASD。录放音在 KV260，不代表语音模型也已经在板上。
- 用户此前提出的人脸上板目标保留；在 Windows 跑通身份链只能作为阶段对照。
- 采用三人分工。历史助手提出的两人合并建议不视为用户已取消三人计划。
- 旧寄存器草案彼此有地址冲突。本文给出行为合同，最终偏移、基地址和引脚仍由真实联合工程生成并冻结。
- 原第四轮 T13/T14 标记为本版不适用，保留编号便于追溯；不能写成“已通过”。

### 2.2 最重要的纠正

当前这张官方 DPU 卡运行的是 **PetaLinux 2022.2，配套 Vitis AI 3.0 运行环境**，不是 Ubuntu。Ubuntu 是你的开发电脑系统。另一条 Kria Ubuntu/应用管理路线不能直接混入此卡的构建指令。

固件文件在磁盘上、Linux 能启动、工具已安装，分别是三个进度；它们都不自动证明当前 DPU 已加载且计算正确。

`.bashrc` 为空也不等于工具坏了。先在独立开发终端显式加载已核实的设置脚本，后续写启动脚本，不凭记忆恢复一整份历史环境。

### 2.3 仍需冻结的参数

- KV260 SOM/载板具体型号和 revision；QSPI 启动固件版本。
- 当前加载 DPU 的配置、fingerprint、匹配 `arch.json`。
- 相机型号、实际支持格式/分辨率/帧率；屏幕输入和最终显示路径。
- MCP01 VID:PID、稳定声卡身份、硬件音频格式、重插行为。
- 舵机确切 SKU、180°/270°版本、负载、机构范围、供电与停止电路。
- 最终控制时钟、地址窗口、ABI、Pmod 实物针脚和 XDC。
- Windows 实际 GPU/显存、模型版本、热启动推理耗时。

这些未知项要通过日志、实物或构建报告填写，不能从方案目标反推为已知。
