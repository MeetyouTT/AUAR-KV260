## 0. 一页结论

### 0.1 总体判断

报告的结构纪律明显高于同类参赛材料：三组证据分层、`[E]/[L]/[S]` 索引、附录 A 完整寄存器表、5.7 结论适用范围表、9.2 限制清单，这五项在同类作品中少见，**修订时任何一条都不要删**。

问题不在"做了多少"，而在三处：

1. **卖点密度低于证据密度**：38.41×、bit-exact、100 ms 周期超时 0、98.63% CLB 下 0 时序失败，全部埋在表注和从句里；摘要只剩两个毫秒数。全文自我限定词 66 处（"不能"38 / "只"22 / "不代表·不等同·不构成"6）。
2. **跨材料数字冲突**：报告与工程包在资源、时序、网络数、组件数上是两套数，评委同时持有 PDF 与 RAR，一比对就是矛盾。
3. **两项核心指标缺失**：任务闭环成功率（PASS/FAIL 计数）与长稳时长。这直接对应"功能正确性 20 分"。

### 0.2 本轮最重要的好消息（V6 可以翻案的一条）

工程包 `Vivado原始报告/implementation.json` 明确记录：

```
{"wns_ns":0.002,"whs_ns":0.010,"drc_errors":0,"old_checkpoint_used":false,"board_verified":false}
```

配合 `check_timing.rpt` 的日期 `Tue Nov 3 07:40:42 2026`、`Tool Version: Vivado v.2022.2`、`Design: kv260_ispMipiRx_vcu_DP_wrapper`，可以确认：**今天已经用当前源码完成了一次完整的综合 + 实现 + 布线，没有复用旧检查点。**

这意味着报告 V5 里最被动的两句话——

> 5.4「对应已保存宽版布线检查点 **不是本次重新布局布线**」
> 8.4「本次报告工作**没有重新执行综合实现**」

——**在 V6 里可以整段删除并改写为正面陈述**。这是本轮最大的一处得分转化，且不需要任何新的测量。

同时必须写清边界：`board_verified: false`，即新位流**没有烧写、没有上板**；板卡仍运行历史固件。这句边界不写，反会被追问。

### 1.2 证据体系评价

三层分级（已保存固定输入 / 本次当前板卡自然负载 / 本次 Ubuntu 重跑 RTL），并显式声明"不跨窗口拼接整机性能"。这套做法在答辩时是**防守利器**：任何"你这个数是不是那个数"的提问，都能落到具体编号上。

代价是**可读性**：38 页里出现 30+ 处"不能/不代表/另验"，评委的第一印象会从"做了很多"变成"没做全"。

**结论：保留体系，改造附着方式。** 具体规则见 4.3。

### 8.1 摘要（整段替换）

桌面交互终端需要同时回答三个问题：当前关注谁、当前回答是否仍有效、当前动作是否仍有执行条件。AUAR 雪妃以 AMD Kria KV260 为感知、状态与执行中心，在单核 B4096 DPU 上分时共存三个视觉模型，并由自研 PL 监督 IP 以 32 位寄存器事务、会话代次、连续序号与租约强制"过期结果不得驱动动作"。

团队完成 YuNet 卷积子图重构与 SFace 激活、全连接头的等价改写，使公开模型进入目标编译链：固定输入路径上 YuNet 中位 124.02→61.41 ms（2.02×）、SFace 520.86→13.56 ms（38.41×）；INT8 化后 YuNet 的 399,500 个输出整数与 SFace 的 4 组输出向量均与主机参考逐整数一致，1000 对独立人脸测试中 FP32 与 INT8 准确率同为 98.8%。

生成式部分由主机 27B 语言模型与 OmniVoice 承担，板端以请求代次、取消与完整播放回执把关交付：采集结束到 SPEAKING 为 5.04 s / 5.29 s，两轮均留存完整回执，TTS 实时率 0.253 / 0.260；局域网往返 P50 为 1.010 ms，约占台词就绪时间的 0.04%。联合平台在本轮源码重建实现中占用 66,887 个 LUT、710 个 DSP，CLB 站点占用 98.63%、URAM 87.50%，199,333 条可布线网络全部布通、路由错误 0、setup/hold 失败端点 0（WNS +0.002 ns / WHS +0.010 ns）。当前板卡自然负载 59.99 s 观察内主检测 9.89 Hz、YuNet 9.85 Hz，主任务超周期增量 0。

上述结果分属固定输入对照、公开集质量、短窗运行观察与 RTL 仿真四类证据，合并口径见 5.1；机械标定、声学首声与同版长稳见 9.2。

### 8.2 1.4 三条贡献（整节替换）

**贡献一：把"模型能跑"推进到"多模型能按时共存"。** 单 DPU 上"谁先用、结果何时作废"没有现成答案。项目在 KV260 单一 B4096 上分时运行 YOLOX-Nano、YuNet 与 SFace，把图像转换、排队、推理与结果接受分开检查。固定输入三模型切换测试中，100 ms 周期超时 0 次，submit/wait 中位数为 6.78 / 2.36 / 8.41 ms；实板自然负载 60 s 内三模型计数持续推进，主任务超周期增量为 0。

**贡献二：把运动请求做成可拒绝、可确认、会到期的事务。** 上层停顿、命令重放与旧会话迟到，是嵌入式动作控制的真实故障源。PS 检查目标与源帧时效，PL 独立校验绑定、参考、使能、连续序号、范围与租约（4–500 ms），非法状态返回四类 reason，STOP 与到期均收回许可。四套 RTL 测试台、12 个阶段在独立目录重跑全部通过，源码 SHA 前后一致，并保留迟到完成、边界租约与总线背压反例。数字输出与机械响应分别命名，不以脉宽读回代替机构到位。

**贡献三：把大模型输出接进 FPGA 终端的真实交互闭环。** 主机只产出文本与 PCM，板端以请求代次、取消与完整播放回执决定"是否交付"。旧、新格式各 4 次的台词就绪中位数为 2762.88 → 2287.70 ms，首正文 1754.07 → 1344.27 ms；两轮真人交互从采集结束到 SPEAKING 为 5.04 / 5.29 s，均有完整播放回执。系统由此可以区分"模型生成过"与"用户已经听到"，并把接口调试中沉淀的规则提炼为可复用的 PYNQ Skill。

### 8.3 5.6 末尾加段（把瓶颈数字转成 roadmap）

> 历史 30.004 s 窗口中 DPU 驱动 CU 忙时为 6.27%，即 B4096 仍有约 15.9 倍的计算余量；同期 CPU 占用为 78.65%，本次同法观察为 79.43%。两组数据共同定位了当前瓶颈：不在 DPU 算力，而在 PS 侧的 NMS、对齐、轨迹与业务线程。这同时构成下一阶段的优化依据——把后处理中的确定性算子下沉 PL，比继续增加模型数量更有收益。

### 8.4 5.4 表 5-3 表注（替换现有表注）

> 两列对应不同实现批次：「历史联合宽版」为设计冻结时的布局布线结果（E02），「本轮源码重建」为 2026-11-03 07:40 以同一源码重新综合、实现与布线的结果（未复用旧检查点）。两者资源量级一致、均全部布通且时序为正；CLB 站点占比由 95.41% 升至 98.63%，反映本次重建的布局分布更集中于 CLB，而资源用量未增加（LUT 反而少 73 个）。新位流未烧写，板卡仍运行历史固件，上板验证状态见 8.8。

### 8.5 答辩 30 秒口播

> 我们做的不是"KV260 上跑三个模型"，而是**在单 DPU 上让三个模型按时共存，并且让任何过期结果都失去驱动动作的资格**。YuNet 2.02×、SFace 38.41×，INT8 输出逐整数一致，1000 对测试准确率持平；自研 PL 监督 IP 用 32 位事务保证租约到期即失效；27B 与 OmniVoice 放在主机，是因为板端 4 GB 内存、实测可用 2.679 GiB、CPU 已 79%，物理上放不下——这不是取舍，是约束下的划分。器件 CLB 已用到 98.63%，我们仍然全部布通、时序为正。
