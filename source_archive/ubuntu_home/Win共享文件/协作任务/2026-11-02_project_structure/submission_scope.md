# AUAR·雪妃：哪些交、哪些不装进工程包

按用户指定 AMD 指南 3.3.5 和本机《2026FPGA创新设计赛道作品上传要求.pdf》整理。工程文件名按英文组织，下面的文件类型按实际采用的实现提交。这份清单不沿用现有 RAR，也不表示已经打包或上传。

**当前采用方案A及老师补充口径：src对应原aura运行根，完整源码＋重建脚本＋精简关键说明。** 具体树和路径以[方案A修订结果](rar_source_layout.md)为准；下面只说明内容类型，不要求携带生成工程和预编译工件。

## 1. 放进 200M 内的工程 RAR

| 内容 | 本项目应收齐什么 |
| --- | --- |
| FPGA 源码和工程输入 | 实际 RTL、自研 IP、BD、XDC、IP 配置、创建/构建/导出 Tcl；有使用 HLS 才交相应源码 |
| KV260 全部实际业务源码 | 相机和真实入口链、三模型运行/调度、跟踪、人脸身份、运动、USB 音频/ASR、角色/UI、对话业务、记忆/存储、公共协议；原生 C/C++ 库须有源码与构建方法 |
| Windows 实际源码 | LLM/TTS 服务、模型适配、请求/取消/超时、实例/GPU 管理、启动/停止/健康检查；固定依赖与配置模板 |
| 部署定义与工件生成 | 固件导出、原生编译、systemd 本体及有效 drop-in、设备规则、部署/启动清单和脚本；固件与SO等由脚本重建 |
| 模型与运行资源 | 三模型固定来源、量化/编译输入及脚本、目标指纹；实际使用且有权分发的小型角色/纹理/动作/字体/参考音色/提示音，或其固定取得与校验方法 |
| 正确性证据 | 测试台、验证脚本、小型公开样例、黄金参考；精简关键结果、失败和局限，保留复现方法和来源索引 |
| 综合实现和性能证据 | 资源/时序/关键性能摘要及必要原报告片段、优化对照、数值、统计方法、实验条件与版本；大原始记录留本机 |
| Skill 与 AI 协作记录 | 可复用工作流/模板/校验工具、范围/用法/失效条件、真实提示词/回答/纠错与验证来源；不要求固定三个 Skill |
| 文档、版本与许可 | README、架构/协议、双端安装运行和从零复现、依赖来源、版本/SHA、许可和第三方声明；报告正文源稿或对应索引 |

只选实际使用的一个发布版本，不把所有历史方案、候选模型和重复导出混在一起。若某个历史文件仍被当前构建或启动流程读取，它就仍是依赖，不能因为日期旧而省略。

## 2. 按后台栏目单独交

| 材料 | 格式或条件 |
| --- | --- |
| 最终设计报告 | PDF，50M 内，按上传页模板；覆盖 AMD 七类内容，单报告栏时组织成一份完整 PDF |
| 作品演示视频 | MP4，AVC(H.264)，建议 3 分钟内、300M 内；以实际作品演示为重点 |
| 作品照片 | 整机全局、开发板高清特写；可补内部接线和运行界面 |
| 作品承诺及使用授权书 | 使用官方表单签署；签署件不默认放进公开代码仓库 |
| 开源工程地址 | 按企业要求准备 GitHub/Gitee，登记 tag、commit 和许可；后台实际链接字段以页面为准 |
| 海报 | 按企业通知；AMD 指南明确进入决赛后需一页英文模板海报及不含队伍信息的 A4 彩色打印件 |

代码 RAR 的 200M 是该代码附件的限制；上述材料各按其栏目提供，不需要把视频、高清照片和签署件重复装入代码 RAR。实际后台字段及后续通知仍需核对。

## 3. 建议作为外部依赖准备，不整套装入代码 RAR

| 依赖 | 工程内仍须提供 |
| --- | --- |
| 27B LLM、OmniVoice 等大权重与 tokenizer | 精确仓库/版本或 revision、必要文件清单、量化格式、SHA、许可、下载/准备和校验方法 |
| 公开 ASR/VAD/降噪/声纹权重，如因体积采用外部准备 | 同样登记精确版本、来源、SHA 和安装位置；不得只写模型名称 |
| 官方 SD 系统镜像、SDK、工具链和公开运行依赖 | 来源、版本、SHA 或可核验版本标识、安装步骤与适配条件；自定义系统修改另交配置/源码/补丁 |
| 公开第三方源码，如按固定来源获取 | 固定 commit/revision、取得与校验方法、原许可；项目修改过的补丁或实现必须保留 |

按本次老师明确的源码复现方式，脚本须能取得、校验并准备必要依赖；不能缺少自研源码、项目真实修改或无法取得的必要设计输入。大语言模型权重继续放共享目录之外，不创建共享目录内的副本或目录联接。

## 4. 留本机，不放公开工程 RAR

- Windows/Python 虚拟环境、软件安装目录、Vivado/Vitis 整套工具、Docker 镜像和下载缓存；提交其版本/来源/依赖锁。
- 生成工程、IP cache、综合/布局布线输出、DCP/XSA/位流、预编译SO/xmodel和全量波形；包内提供相应源码、定义及已验证的重建步骤。
- 旧版本整包、重复备份、历史废弃模型、未使用的预渲染画面、无关文档与工作记录。
- 个人 SQLite、人脸/声纹模板、真实个人录音/对话、令牌、密钥、本机身份配置和缓存；提交表结构、迁移、公开用例与示例配置。
- 整张带个人数据的 SD 卡备份、Windows 盘备份和电脑全部文件。

以上只说明导出取舍，不要求删除本机原件。保留与报告结论有关的原始输入、失败和实测证据。

## 5. 本项目特别要保留的边界

- **DCP：** 按老师口径，目标为源码重建，包内不带约125.1MB旧参考DCP。实际整理时须修正当前脚本对它的强制依赖，并在干净目录验证构建；不能只删文件而保留依赖引用。该验证尚未由本轮目录工作完成。
- **角色资源：** 实际渲染依赖的角色模型、纹理、动作及其授权不能漏；已不用的历史预渲染序列无需收录。
- **独立入口：** 相机服务、GUI/业务、Windows 模型服务和原生库分别收齐，不能只交主界面文件夹。
- **没有使用的技术：** 没用 HLS、裸机 ELF、PYNQ 或声源定位，就不为提交额外制作这些模块。通用 PYNQ Skill 按实际提交，是可选加分项。

官方条款已重新直接核对本地 PDF；以上为提交范围清单，没有执行构建、压缩、板测、模型调用、开源发布或比赛上传。
