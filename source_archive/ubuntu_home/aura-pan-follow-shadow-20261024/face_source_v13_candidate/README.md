# 人脸输入独立审查与 v13 离线候选

本目录只在 Ubuntu 主机读取源码、合成图像和隔离 Fake Service 上操作。没有访问 UART、板端 HTTP、相机/DPU/MMIO，没有部署、重启或输出转轴动作。主 agent 保持唯一板卡操作权。本目录不是现役代码。

## Windows 交接审查

- Q01成立：历史实测有未确认/锚老化/模板拒绝，不能把NDJSON包数当独立图像频率。现役v12已支持独立锁、原始capture优先入口；本候选不把已修复项重复当新缺陷。新增flow逐类原因计数、独立有效源/检测锚刷新数、最大有效源/完成间隔，常量空间，无原图日志。
- Q02结构事实成立：底层默认TTL为1000ms，motion检测锚为500ms；实际入口周期100ms且扣除round耗时，不能错误声称仍额外睡200ms。没有分段板测证实DPU准入/执行/后处理各自的责任，不能凭此缩TTL、抢占DPU或减少SFace请求。新增 `face_timing.py` 是只读数值包装，每次process附其真实frame_id/source时间；仅在本轮生成新native report时记录native字段，防止把前轮报告错误归到当前拒绝/CPU轮。`before_native_start_ms`合并CPU准备和准入等待，`native_lease_ms`是原生lease占用而非纯DPU子图时间，`after_native_release_ms`包括后处理/发布/回调，均不冒充分离的纯核耗时。
- Q03已独立复现：同一固定合成人脸纹理，平移并6°/1.08、10°/1.12、8°/0.92、0°/1.12等尺度/旋转时，v12平移NCC均拒绝。拒绝后清template/box/binding直到新实检测锚，源码确认。候选增加固定原锚LK仿射fallback，不降低原NCC门槛，不滚动模板，不延长锚，仍需现场鲁棒性与AArch64成本验证。
- Q07核查成立：r10的filter_tau_ms/velocity_filter_tau_ms仅校验/报告，OneEuro初始化另有实际参数；主agent负责控制候选修正，本分支没有修改控制代码。

## 固定实锚 LK fallback

优先保留原full NCC与既有边缘双固定块；两者失败后才运行。原检测图ROI最多40个特征，始终从该原图到当前真实图计算LK，再反向验证；不会将当前帧裁片成为新模板。至少12个匹配点、前后误差≤0.75低分辨率px、≥70%特征有效；部分仿射估计≥12内点/≥80%内点、至少3象限和宽高35%空间支撑。尺度限0.85..1.18、转角≤15°，相对上一测量中心位移仍限原搜索半径16..64px。

候选对当前图逆变换回原锚crop，要求该crop全部可见、纹理标准差≥8、与原固定模板NCC≥0.80；单眼/局部遮挡不足以放行。原锚500ms、当前图250ms、多脸/错误/换代约束和最少可见55%宽、60%高不变。几何限制仍不能证明真实遮挡下零误跟，必须保持不确定停止。

协议 `face_tracking.version=11` 保持兼容，额外 `algorithm_version=13` 区分实现。READY的 `measurement_details` 提供与该源绑定的具体测量方法/分数/LK支持量；不能使用另一次diagnostics的method当作该packet的来源证明。

## 验证与代价

48项主机回归通过：原39项加9项固定锚仿射/负例/期限/诊断相关检查。涵盖随机背景、无脸、局部遮挡、大旋转/缩放、单眼支撑拒绝、多次变形不滚动锚、500ms截止、逐类原因、逐source原生lease关联、旧报告不复用、诊断不吞业务异常。最初新增测试import顺序缺common路径，修正为与原套件一致后完成，不算板端故障。

`HOST_COST.json`是Linux x86_64固定合成图微基准，每组30次。普通平移v12/v13中位约0.874/0.873ms；6°/1.08变形v12中位0.868ms但0接受，v13中位3.174ms/最大3.606ms且30接受；无像素v13中位1.681ms、0接受。上述不能换算KV260负载或人体精度。新增seed特征提取成本尚应在板机量测，不把fallback计算放在DPU lease内。

候选启动新增6个运行源，含继承v12的锁/raw hook，合计8个manifest pins（另2个是既有扩展/operator依赖）。`deployment-manifest.json`为拟部署路径，不表示文件已经在板端存在。建议先由主agent审查并在执行器保持停止的板端隔离微基准加载同一代码，确认成本/依赖后再决定是否切入真实人脸源；不能直接据软件测试数宣称跟随已修好。
