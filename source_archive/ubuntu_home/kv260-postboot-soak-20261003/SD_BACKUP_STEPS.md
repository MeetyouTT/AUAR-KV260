# 备用 SD 卡整卡备份与后续处理

前提：本轮冷启动后复测完成并检查证据。当前备用卡 CID 为 `0353445345333247805558c00401a100`，板端 `mmcblk1` 容量约 29.7 GiB，两个分区为 `/boot` vfat 和 `/` ext4。Ubuntu 已有 `dd`、`sha256sum` 和 `fsck.fat`；准备时根分区可用约 148 GiB。当前 Ubuntu 还没有检测到插入的 SD 读卡器磁盘。

1. 通过板端控制台执行 `systemctl poweroff`，等控制台报告关机/断电完成，再切断板卡供电、取出备用 SD 卡。
2. SD 卡插入 Ubuntu 读卡器。用 `lsblk`、USB 设备身份、磁盘容量、分区布局及此前设备清单核对新出现的整盘设备。USB 读卡器可能无法暴露 SD CID，不能用读卡器自身 serial 代替 CID。
3. 正常卸载自动挂载的该卡两个分区；确认该设备不包含 Ubuntu 根分区且没有活动挂载。
4. 将已确认的整盘设备读入主机的新镜像文件，保存 dd 完整日志和设备身份记录。不得对分区名制作所谓整卡镜像，不得选择主机 NVMe 系统盘。实际设备路径确定后再形成执行命令。
5. 比较源设备字节数与镜像字节数，并分别计算源整盘与镜像 SHA-256；两者完全一致后确认完整备份。镜像是当前修复版备用卡的恢复点，不是全新的官方原版镜像。
6. 保存镜像及摘要后，对未挂载的 FAT 启动分区先执行只读 `fsck.fat -n` 并留存日志。只有确认具体问题和修复范围后才执行修复；另行备份 rootfs 的 `/etc/fstab`，根据分区身份保留一个有效的 `/boot` 挂载条目。
7. 安全弹出卡，回插板卡并重新启动，核对 boot、服务、DPU、同模型同图片分类，再保存证据。

如需恢复镜像，重新识别目标卡、确认允许覆盖，再将整卡镜像写到容量不小于原卡的目标设备，执行 sync 并回读验证。恢复写入会覆盖目标卡，不应在设备身份未确认时执行。

现有板端目录备份和主机运行时文件包均不等同整卡镜像。当前整卡镜像尚未创建，FAT 告警和重复 fstab 条目尚未修复。
