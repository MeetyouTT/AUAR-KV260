# 启动探针的核日志滚动比较修复

确认此次第一轮失败来自测试控制器的日志连续性判断，而不是时钟 IP、
修复版 ZOCL 或 DFX manager 的新失败。失败位置为原 `10_start.py:15`，
原管理器正常 remove 官方应用后，控制器要求整个旧日志仍是新日志前缀。

## 实际证据

完整回收的原日志分别为 645 行、67014 B 与 645 行、66989 B。
旧日志前 4 行已滑出；`old[4:] == new[:641]` 实际核对为真。
旧尾 16 行在新日志中唯一出现于索引 625，结束于 641。
新增 4 行完整保留，其中只有 1 条原 ZOCL 已知的 `/axi/zyxclmm_drm`
`expected refcount 1 instead of 2` 退出错误。

worker 的 finally 恢复完成。候选 manager 日志不存在，当前 ZOCL 为原
`0991D1B457855C8987936E6`，官方应用活动，修复版尚未在这轮加载。
不从 dmesg 文本字节数推断内核 ring 的精确容量。

## 新比较

新源为 `10_start.py`，SHA-256
`50fbc57e6d60dcd83a629a6e2ae7d8a806efdf9ed4ebba1acce84fe7d4711761`。
unified patch 为 `10_start_kernel_ring.patch`，原包及原失败记录保留。

将其结束位置之后的行作为增量。没有 anchor 或位置有歧义时拒绝；
记录原日志路径/哈希、行数、anchor/位置、增量及错误分类。

原驱动退出只允许此前同一目标的已知引用错误 1 条。
候选启动后的任何新增引用错误、ERROR、error、BUG/Oops/Call trace 等均拒绝。
其它模块、服务和应用操作顺序不变；不修改厂商源码、规则或参数。
