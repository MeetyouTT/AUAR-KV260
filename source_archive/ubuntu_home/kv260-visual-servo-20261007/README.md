## 已实现与已验证

- `rtl/visual_servo.sv`：VSRV/1 可写目标、显式参考脉宽、严格序号和 session/epoch、回读、有限租约、STOP、寄存器 PWM。启动从确认的参考脉宽开始；正常目标在周期边界逐步应用，停止/到期优先截断输出。
- `vsrv_driver.py`：通过注入寄存器 transport 访问；只读身份核对后才能使用明确的参考/授权。ACK、目标、会话、代次和状态一致才认定 ACCEPTED；源帧时间决定许可预算。不打开 `/dev/mem`，不加载 PL，不自动恢复许可。
- `face_servo_control.py`：原图 640×480 水平误差，五次连续高置信度观察后初始化，实际 dt 滤波/死区/限速；初次台架范围参考值 ±40 μs（同时受硬件 1400—1600 μs 限制）、每次最多 4 μs。重复观察不续租；丢失、换目标、过期或未知接受停止，重现不自动恢复。
- `physical_motion_service.py`：推理回调、轮询、状态和退出停止的桥接接口。显示/状态轮询不续租；脉宽偏移以 μs 表示，不冒充实测角度。
- `realtime_visual_servo.py`：复制现有已验证的相机程序，在推理线程直接提交观察，增加物理 PWM 状态/来源日志，退出先停止再关闭视频。物理服务必须由显式 `physical_factory(boot, camera_epoch)` 注入；命令行默认仍不启用真实动作。没有新增 `/dev/video0` 消费者，板端原预览保持运行。

本地 35 项 Python 测试通过，涵盖真实 `FaceTracks` 数据合同到协议测试替身的集成、首次观察不提交、方向、限幅、拒绝不推进、错误 ACK、冻结后的许可到期、目标丢失和重现不恢复，以及运行中硬件身份变化不向未知模块写入、身份读取延迟不延长源观察期限、独立摄像头的蓝线/位置映射/回线/不持续漂移与标定代次检查。源码与测试均通过语法编译；快照、原始输出和 hash 见 [CURRENT_HOST_TESTS.json](CURRENT_HOST_TESTS.json)。上述测试替身不是板端硬件。

HDL 协议仿真通过：[原始结果](evidence/20261007T111114.188185Z-sim/status.json)。标准参数仿真通过：[原始结果](evidence/20261007T111949.424705Z-sim/status.json)，100 MHz 测试时钟下周期 20 ms，首个脉宽 1450 μs，之后 1454/1458/1460 μs，STOP 清除输出。实际板端时钟、周期与脉宽尚未测量。

第一次 xsim 在 sandbox 内异常退出且返回 0，因缺少 PASS 标记被 runner 正确判失败；使用已批准的执行权限重跑通过。标准参数第一次仿真已经通过，但 runner 写指针时局部变量重名导致失败；修正 runner 后完整重跑通过。失败目录保留，不将它们计作完整通过。

本轮构建标记 `0x14da0e60`，核心 SHA256 `cc62cf5f71c2b76668417c0de49e95563d41a56f0d0fd702ac74fb465b7684f3`；源码在构建开始时保存快照，构建期间有变化即不能判通过。实时进度见 [CURRENT_BUILD.json](CURRENT_BUILD.json)，完整日志见 [构建 console](evidence/20261007T111257.242565Z-joint-build/console.txt)。**构建通过也不等于 deployable：匹配 BD/XSA/HWH、删除旧音频设备树节点、DT/XCLBIN 配套审计和无动力板测仍未完成。** 不能将旧 HWH 直接作为新平台描述。

端口重命名只改变 Vivado 内存设计及后续 checkpoint，不自动修改原始 BD，参见 [AMD Vivado 2022.2 rename_port 文档](https://docs.amd.com/r/2022.2-English/ug835-vivado-tcl-commands/rename_port)。因此本轮 netlist 候选不能宣称正式平台重建完成。

## VSRV/1 台架寄存器合同

| 偏移 | 内容 |
| --- | --- |
| 0x00 / 0x04 / 0x08 | ID 0x56535256 / ABI 1 / exact build ID |
| 0x0c | reason[7:4]、bound[3]、referenced[2]、armed[1]、active[0] |
| 0x10 / 0x14 / 0x18 | 影子 session / epoch / seq |
| 0x1c / 0x20 | 影子目标 μs / 租约 ms |
| 0x24 | BIND / REFERENCE / ARM / COMMIT / STOP 命令 |
| 0x28 / 0x2c / 0x30 | accepted seq / 有效脉宽 μs / 剩余许可 ms |
| 0x34 / 0x38 | 已绑定 session / epoch |
| 0x3c | 影子基准脉宽 μs |
| 0x40 / 0x44 | 已确认基准 μs / 已接受目标 μs |

命令常量见 `vsrv_driver.py`；业务拒绝用 status reason 回读，协议命令写返回 AXI OKAY，避免 userspace 在到期竞态中遭遇 SIGBUS。非法地址/部分 WSTRB 返回 SLVERR。ACK 为接受序号，不是轴运动到位反馈。有效脉宽更新可晚于接受目标，不将二者混用。

名义 100 MHz 时钟、分频 100，周期 20000 μs、范围 1400—1600 μs、每周期最多改变 4 μs、许可 1—500 ms。该 ABI 属台架单轴扩展，不是完整六态监督、物理急停输入、双轴、角反馈或竞赛正式发布。

## 启动真实随动前仍缺的事实与验收

1. 摄像头已确认尚未装在舵机上，本轮采用独立摄像头模式。需先保持外部视角稳定并实测位置映射；不能直接套用随轴摄像头的图像误差积分控制。蓝线及约定见 CONTROL_REFERENCE.md。
2. 当前机械零点对应的实测脉宽、左右极性和两侧余量；此前暂停/断电/手动移动历史不足以推算。`PhysicalReference` 不接受缺失值，不自动采用 1500 μs。
3. 匹配平台描述、独立时序/DRC/路由/时钟/pad 审核，通过后在舵机动力断开的实际条件下完成身份、PWM 周期/脉宽、ACK、停止/冻结到期和 DPU/相机/显示共存板测。
4. 真实单写方 transport、访问所有权、实测提交延迟预算，以及轻载极性/小偏移现场验证。当前 20 ms 提交余量是设计参数，未当作板端延迟实测。

只允许对这些已核验事实生成物理 profile；不得手工将 `deployable=false` 改为 true 绕过缺项。随后以当前位置为参考，单人居中/左右移动/离开/恢复逐项验收，不能把单元测试或旧 sweep 动作当成视觉闭环验收。

当前采用 YuNet 人脸 + IoU 目标关联的 CPU 演示，不是人体 YOLO/ByteTrack、身份识别、ASD 或全部项目算法完成。停止 PWM 只停止新控制信号，实际惯性/保持/失去扭矩行为由舵机和机构决定。
