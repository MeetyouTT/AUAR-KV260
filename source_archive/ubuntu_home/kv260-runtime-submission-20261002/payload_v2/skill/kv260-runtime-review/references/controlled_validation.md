# 接板后的受控验证

本附件不带自动安装器。先取得本次实时卡号、根分区、kernel/boot ID、源码锁对应的原文件与库哈希、活动应用、service/PID/exe、模块参数/refcnt/holders 和 DRM 客户端。历史 boot ID 不用于新的执行授权。值不匹配时查明差异，不直接切换。

1. 在独立板端目录建立新的恢复点：原 daemon、client、unit/配置、VART、原 ZOCL、活动固件、模型/图片哈希、原始 dmesg 与恢复步骤。传输已板测输入并检查哈希。
2. 正常移除活动应用，确保无活动包、无 DRM 客户端、无模块持有者或引用；正常卸载原 ZOCL，再用原参数装载修复模块。使用独立临时配置启动候选 manager，按源码协议检查就绪。记录原驱动本次退出产生的诊断，不能从后续日志中隐去。
3. 核对官方 DPU CU 数量、B4096、300 MHz、地址与架构指纹，再用哈希相同的 ResNet18 与原样图确认完整 Top-5。socket 通过不能替代这一步。
4. 计划 30 轮受控重载及同图推理，随后至少 30 分钟推理与 RSS/MemAvailable/slab/inotify/驱动引用采样。每次卸载前重新确认无客户端。为每次运行保存命令、退出码、时间、完整原始输出与内核日志。新目标引用错误、异常或 manager ERROR 时停止，不盲目重试。
5. 留存 M3 查询及同图结果。当前模块只有最小 AXI-Lite 寄存器，不据此声称 PWM 已完成。
6. 临时测试完成后按当时状态恢复：移除应用；用原 SIGINT 刷新候选日志并停服务；恢复原服务，随后正常恢复原 ZOCL 和原 VART/官方应用；逐项检查原文件哈希、模型结果、boot ID 和活动状态。

永久启用需另行准备启动顺序和可恢复方案，用户确认范围后再执行。此技能不自动重启、烧录 SD/QSPI、force 卸载或连接执行器。缺少板卡时记录“计划未执行”，继续不依赖板卡的准备。
